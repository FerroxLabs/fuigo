# Changelog

Each release has its own notes under `docs/`. Binaries and npm platform packages are attached to the matching [GitHub release](https://github.com/FerroxLabs/fuigo/releases); the npm package is [`fuigo`](https://www.npmjs.com/package/fuigo).

| Version | Notes | Highlights |
| --- | --- | --- |
| 1.0.36 | [release notes](docs/release-notes-1.0.36.md) | A launching program can give Fuigo a permission policy for one run (`FUIGO_POLICY_PATH` with its required `FUIGO_POLICY_SHA256`) or for one ACP session; its deny and ask win in every mode, including always-approve, a bad policy exits with code 78 and one JSON error line, `fuigo policy check` tests a file, and a governed process runs without a shared leader (unset changes nothing); leaving `browser_use` restores the session's own prompt and the mode is reported truthfully; model switches and `default`/`ask` keep session rules and memory context; a bare `Read` rule covers file reads and listings only, not to-dos and other bookkeeping; a tracked file that fails to copy into a worktree stops the create, untracked ones warn, and the warning also shows on fork and resume; MCP tool schemas missing a type, properties or items are completed for Chat Completions providers that rejected them. |
| 1.0.35 | [release notes](docs/release-notes-1.0.35.md) | Folder trust now covers commands: you decide once per folder (its repository), and in a folder you have not trusted no project settings load and no shell command runs unless your approval or grant covers it (read-only lists, Auto mode and sandbox auto-allow approve nothing there, and Fuigo runs no git of its own); a folder's trust covers the commands that start there (naming another folder in a command does not change the answer, as in other coding agents); trusted folders behave as before (and a trusted repository's own git configuration, hooks and tool configuration no longer turn the Auto mode model's allow into a question), a trusted repository covers its linked and `fuigo -w` worktrees, a nested non-submodule repository is asked about on its own, and always-approve runs in any folder. Background marketplace refreshes work as before, and a hub serves project config, skills and instructions only for folders it trusts. Folders trusted before 1.0.35 are asked once more, folders without project settings and outside git are asked too, `$HOME` and `/` can never be trusted, and headless runs need `--trust` or `[folder_trust] trusted_folders` in your own config. Shell permissions: without a grant from you, only plain-text commands run without asking (no `~`, globs, braces, `$`, wrappers, `cd` or redirects other than from or to `/dev/null`; pipes between plain commands are fine), so in Auto mode `cargo test 2>&1 | tail -5` now goes to the model (write `2>/dev/null` to keep the fast path). Commands the classifier cannot fully model (a tool in a mode that runs a program, `/dev/tcp` redirects, environment dumps, kubectl Secret reads, `printf -v`, path-qualified program names, shell-expanded arguments) now also ask under a broad grant or sandbox auto-allow. Fuigo's `grep` and `find` are judged as the ugrep and bfs they run. Every list-approved program's options were audited: forms that write outside the project, change clock, repository, registry or toolchain state, or read an unnamed file now ask (`git branch -D`, `uniq - out`, `date -s`, `cargo install`, `npm config`, ...), and build-tool options that run another program (`make --eval`, `cmake -E`, `cargo --config`, `pytest --pdb`, `kubectl get -f`, ...) ask under broad grants too. Repository-controlled configuration (a git alias for a non-git subcommand, a repository file your git config includes) now makes the command ask (in a trusted folder Auto mode's model decides it); so does a relative or in-project `PATH` entry, or any set variable that steers which program runs (`LD_PRELOAD`, `GIT_SSH_COMMAND`, `RIPGREP_CONFIG_PATH`, ...), for every command without a grant, and npm-family routine forms accept only exactly spelled options. On Windows under PowerShell or cmd.exe every command without a grant asks (use grants, `--allow`, or Git Bash via `FUIGO_SHELL=bash` to avoid prompts). Functions and aliases named like safe-listed programs or the wrapper's builtins, zsh global/suffix aliases, `TRAP*` and hook functions no longer persist between agent shell commands; an approved command runs with your full authority, so approve only what you would run yourself. Modes and agents: `session/set_mode` accepts only `default`, `plan`, `ask` and `browser_use` and sessions advertise their current mode; repository agent files load only in trusted folders, never replace a built-in agent and must have plain names; plugin agents are callable, and plugin skills load, only from trusted plugins; plugin and project skills, commands and agents that symlink outside their own folder are skipped (counted in `/plugins`), checked again on the file actually read, and the same now holds for project instruction, rules and config files and for plugin manifests, hooks, MCP and LSP files and repository plugin folders, with each folder resolved once and every project MCP route, agent memory, tool guidance, read-time Cursor rules, roles, personas, workflows, `repos.json`, the `.github_repo` export mapping and imported project hooks held to the repository; a repository's `[plugins].paths` loads as project plugins (contained, not auto-enabled or auto-trusted); new personal always-approve lock in your own `config.toml`. Windows: shell commands no longer fail at random with "program not found" when both `Path` and `PATH` are set; the shell is started by its full path, found on `PATH` (never the current folder) or in the system folder; a failed start logs the error code and program. `inherit = "core"` matches names exactly on macOS and Linux. |
| 1.0.34 | [release notes](docs/release-notes-1.0.34.md) | New `FUIGO_MANAGED_HOOKS_ONLY` switch lets an app that embeds Fuigo run only managed hooks for one run; the docs now say that on Windows Fuigo's home folder comes from `USERPROFILE`. |
| 1.0.33 | [release notes](docs/release-notes-1.0.33.md) | Hooks stay off in untrusted folders until you trust them; worktree refs and names starting with `-` are refused; one switch turns off every background model-list fetch for embedding apps; `--permission-mode plan` starts in plan mode; a stray key can no longer approve a plan; fixes for the `/fork` model, failed session starts, web-search events and a macOS-over-SSH hang. |
| 1.0.32 | [release notes](docs/release-notes-1.0.32.md) | One sign-in picker for ChatGPT, Grok, Flux Router and provider keys, and one ranked model list that names the route each model uses; opt-in per-command sandbox; smaller install; new welcome screen; many MCP, hook, permission, worktree, goal and terminal fixes. |
| 1.0.31 | [release notes](docs/release-notes-1.0.31.md) | Fix: switching provider with `/model` no longer replays reasoning the new provider rejects; `/remember` reports the real file it wrote or that the note was not saved; session rules survive a model switch; MCP tool progress reaches the client; untrusted-folder tests; project-rules guide corrected; new README, brand and community files. |
| 1.0.30 | [release notes](docs/release-notes-1.0.30.md) | Shared leader: one owner per session, prompts go only to the owner; project and `npx` copies no longer update the global install; more global-install layouts recognised. |
| 1.0.29 | [release notes](docs/release-notes-1.0.29.md) | Shared leader: only the window that owns a session can change its permission mode; npm 11 install and upgrade fixes; two fixes for messages between sessions. |
| 1.0.28 | [release notes](docs/release-notes-1.0.28.md) | Fixes for messages between sessions: refusals are reported, text-only replies are no longer treated as refusals. |
| 1.0.27 | [release notes](docs/release-notes-1.0.27.md) | `bearer_token_file` for HTTP MCP servers works on Windows with the same owner-only rule as macOS and Linux. |
| 1.0.26 | [release notes](docs/release-notes-1.0.26.md) | Loud warning when a sandbox profile is set on Windows; MCP bearer token from a file; `/context-window`; one shell wait setting; larger Windows stack. |
| 1.0.25 | [release notes](docs/release-notes-1.0.25.md) | Named sessions that list and message each other (off by default); headless warning when an MCP server fails to start; parked sessions for host applications. |
| 1.0.24 | [release notes](docs/release-notes-1.0.24.md) | Security and reliability: permission and admin-policy rules hold in more places; multi-window Windows fixes; far fewer requests after a key or sign-in stops working. |
| 1.0.23 | [release notes](docs/release-notes-1.0.23.md) | Build and shipping only: signed Windows and macOS programs; Linux builds run on older distributions; Linux ARM crash fixed. |
| 1.0.22 | [release notes](docs/release-notes-1.0.22.md) | Subscription sign-in fixes: repeated ChatGPT replies, and Grok and ChatGPT subscription models being refused. |
| 1.0.21 | [release notes](docs/release-notes-1.0.21.md) | Workspace memory moves to a new folder on first use; cumulative notes for 1.0.18 to 1.0.20 apply when upgrading from 1.0.17. |

Releases before 1.0.21 are listed on the [releases page](https://github.com/FerroxLabs/fuigo/releases). The release process itself is described in [RELEASE.md](RELEASE.md).
