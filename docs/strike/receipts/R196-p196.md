1. HIGH, cancel-resend: mechanism = captured finite boundary, `StaleStateFence` in `event_loop.rs`. When the resend (or the
   turn-end reconcile, item 2) is first seen due, it captures `processed + buffered` (receiver `len()` plus the peeked
   message). The handler waits until that many ACP messages have actually been processed (`note_processed` in the ACP arm
   and its drain loop: progress, not attempts). Unrelated timers keep running; the ACP-first pass is retained only to give
   the ACP arm the next turn. Cap: 2 s past the first due observation; released at once if nothing is buffered. The cap is safe
   because before this packet nothing protected the resend at all, so after 2 s it is never worse than the old behaviour.
   Messages arriving after the capture are not waited on. The round-2 `AcpFirstHold` (8-pass count) is removed.
   Not done: fencing the cancel at the sender by prompt id (not small: needs a per-prompt id on the session cancel path).

3. Reverse fairness: `TimerStreak`, N = 8 consecutive timer wins; the next pass disables the five timer arms, so ACP, tasks and
   input are polled first, and a lowest-priority always-ready arm (before the voice arm) restores the timers if nothing else was
   ready (a due timer is delayed by at most one pass). Intervals: animation `1000/fps` with `fps: u8` is at least 3 ms; status
   refresh is clamped to the config minimum in seconds; deferred draw and resize clear their deadline when fired; the scroll
   deadline derives from state. I added a 1 ms floor in `schedule_tick` (`MIN_TICK_INTERVAL`) for any other caller.
4. Wheel stream: `ScrollGate`; after one processed input batch the scroll clock and `tick_with_input` run even if more input is queued.
   Wheel events inside that batch are processed before the clock advances (order kept).

## Round 4 (Astra r3)

Code tip `6f518d49` (receipt commit follows; no code after the runs). Lane `p196r4`. Merged `hub/strike/integration` `2328e4f4` cleanly (no conflicts).

### Changes
1. **Panic.** `priority_wake_with` gets an `else => pending` arm, so when every branch is disabled the inner future never resolves and never panics; the outer input arm or the timer-restore arm runs.
2. **Cap escalates, never releases.** `StaleStateFence::hold_requests` no longer looks at time. At `CAP` (2 s after capture) `escalated()` turns on `WakeGates::acp_escalated`: the ACP arm is enabled although input is queued, and the 32-message drain ignores queued input, until `processed >= boundary`. The fence releases only on boundary reached, nothing buffered (queue empty or closed), or request gone. Other timers (deferred draw, scroll, status, resize) keep their normal place in the select; the animation arm is held (as before) so redraw/ACP alternate.
3. **Fence per request.** `dispatch::stale_request_keys` returns one `StaleRequestKey {kind, agent, subagent, at}` per due request (`at` = `sent_at` of the cancel, `received_at` of the turn-end). The fence keeps one `(since, boundary)` per key: a re-issued cancel (new `sent_at`) is a new key and gets a fresh boundary; keys no longer due are dropped. Several agents (and subagent panes) can be overdue at once, each with its own boundary.

### Item 1 guard table (T=timers, I=input_empty, S=scroll_ok, E=acp_escalated)
| T | I | E | live branches (priority order) |
|---|---|---|---|

| 0 | 1 | any | ACP only |
| 0 | 0 | 1 | ACP only |
| 0 | 0 | 0 | none: stays pending (was the panic) |

### Escalation bound
ACP passes during escalation = ceil(remaining boundary / 32), fixed at capture. Worst realistic backlog 10,000 messages: 313 ACP passes; each may be interleaved with at most 8 timer passes (TimerStreak) and one animation hold pass; input is deferred only for those passes and resumes the moment `processed >= boundary`. Messages arriving after capture are not counted, so a flood cannot extend it.
