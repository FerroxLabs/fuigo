## 1. What was built

### F3 — fair cross-process lock with a progress-based give-up (`fuigo-config/src/fs_atomic.rs`)

`lock_at_within` now has three stages (`lock_config_for_write_within` docs):

1. the in-process FIFO turn (P49), whose give-up time restarts whenever `serving` OR a new `progress` counter moves;
2. **a cross-process FIFO ticket queue** (`mod xq`): `.<lock name>.queue/` beside the lock file; a ticket is
   `<arrival ns, 32 digits>.<pid>.<nonce>.t`, created under a private name, `flock`ed, then hard-linked to its ticket
   name (so a visible ticket is always locked while its writer lives) and unlinked-then-closed on drop. A writer is
   at the head when no LIVE ticket sorts before its own; an unlocked ticket is a dead writer's and is removed. The
   stamp is `max(clock, latest stamp in the queue + 1)`, so a clock step cannot put a newcomer ahead. Every ticket
   ahead that goes away (including the last one) is progress: it restarts the waiter's stall time and bumps the
   in-process `progress` so this process's threads behind it restart theirs. The queue directory is removed by the
   last writer out, and on a failed registration (no hard links → unordered fallback, as before);
3. the `flock` itself (mutual exclusion; blocking helper thread, unchanged).

`CONFIG_LOCK_MAX_WAIT` is now 10 s of **no progress**, not 2 s total. Bound: a writer's whole wait is at most
(writers ahead of it when it queued + 1) × 10 s. Test seam: `<lock>.trace` (only if it exists, `test`/`test-seams`)
gets `Q <pid>` / `G <pid>` lines.

Also: `lock_path_in` (the P61 identity rules, moved from the shell; the shell's lock names are unchanged),
`state_lock_path` (`~/.fuigo/locks/state-<hash>.lock`, following a final symlink chain), `edit_state_file`,
`Snapshot` + `commit_if_unchanged` (the commit step of `edit_locked`, public for callers whose edit must stay on an
async task), `loader::parse_user_config_layer`.

### F1 — plugin install registry (`fuigo-agent/src/plugins/install_registry.rs`)

`InstallRegistry` keeps a baseline (`repos` as loaded or last saved). `save()` computes the per-key changes against
it and applies them, through `edit_state_file`, to the registry file as it is NOW: read → slow git/copy work (no
lock) → re-read under the lock, merge, verify unchanged, write. Same key changed by both: this save wins for its own
key. Unchanged + file exists: nothing written. Unparseable file: replaced (as a load of it starts fresh); unreadable:
refused. ~20 callers unchanged.

### F4 — settings save (`fuigo-shell/src/util/config/persist.rs` `update_config`)

`f` (now `FnMut`) runs on the settings loaded from a `Snapshot` of the file; the result is rendered, staged and
synced with NO lock held, and committed with `commit_if_unchanged` (rename under `config.toml.lock` only if the file
is still that version). Overtaken → `f` runs again on the newer version; after 2 passes the whole cycle runs under
the lock (old behaviour). So a read-dependent change (consent version bump, skill path append) always decides from
the version it replaces. Cancellation: an optimistic commit validates under the lock; the locked cycle's locks move
into its commit task. Call sites switched from move to clone: `settings_writes.rs` (15), `consent.rs`,
`campaigns.rs` (`persist_user_choice` is `FnMut` now), `extensions/skills.rs`, `fuigo-update/src/auto_update.rs`.
