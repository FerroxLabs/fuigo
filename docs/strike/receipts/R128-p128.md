# R128 - P128: leader custom notifications lacked the ACP extension `_` prefix

Base 33a84c2939ee8e0490b105cc0147e2686d520c19 (strike/p124). Red tests 4cc64700, fix 2cd61199 (tip). Lanes p128a, p128b (Hetzner).

## Proof of the bug
agent-client-protocol 0.10.4 `decode_notification` only turns a custom method into an ext notification when it starts with `_` (and strips it). The leader sent `fuigo/leader/version_mismatch` bare, so the pager handlers (acp_handler/mod.rs, headless/ext_protocol.rs) never ran in production; existing tests called the handlers directly.
End-to-end tests (real `run_leader_server` -> real `LeaderClient` -> real `bridge_channels` ClientSideConnection decoder -> real handler): `real_leader_version_mismatch_reaches_pager_toast` and `real_leader_version_mismatch_reaches_headless_handler`. At 4cc64700 they fail ("notice never reached the pager", 6 pager-lib + 2 shell-lib + 1 shell-int + 1 pager-bin tests red; log /root/fuigo-builds/p128a/red.log sha256 433cd4a380bab03b...). At 2cd61199 all pass.

## Fix (2cd61199)
- Leader sends `_fuigo/leader/version_mismatch` (server.rs `VERSION_MISMATCH_WIRE_METHOD`).
- Same bug found and fixed for `fuigo/config_changed` (agent/app.rs, now `_fuigo/config_changed`) and `fuigo/leader_reconnected` (fuigo-pager-bin main.rs, now `_fuigo/leader_reconnected`); a test each.
- Pager bridge `normalize_legacy_leader_line` rewrites a bare `fuigo/leader/version_mismatch` notification (no id) from an older leader; both pager handlers accept the bare and prefixed names.
- Sweep of every other leader/agent to client sender: typed ExtNotification/ExtRequest paths are prefixed by ACP itself; internal methods already prefixed. No other omission (Astra r1 independently agrees).
