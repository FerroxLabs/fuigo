## 0. Read first: what is NOT met or not verified

1. **macOS and Windows code is compile- and clippy-checked only** (§5.5): `fs_atomic.rs` and `write_through.rs` at the
   tip pass `cargo clippy` for `aarch64-apple-darwin` and `x86_64-pc-windows-msvc` (with and without `test-seams`) in a
   scratch crate, 0 warnings. Nothing ran on either OS. New there: macOS `O_SEARCH` directory handles and the staging
   directory created/opened/removed through its parent handle; on Windows the stale-temp sweep does nothing and temps
   are still created and removed by path (no directory handles).
2. **The moved-directory LOW is fixed on unix only where a directory handle can be opened** (Linux: `O_PATH`, always;
   macOS: `O_SEARCH`, else read-only). If neither open works the temp is created and removed by path, as before P61.
   Tests run as root, so the "directory without read permission" case (Astra r1 #4) has no test.
3. **Not every inventoried writer is migrated** (§1.3): the plugin install registry, `pager.toml`, personas,
   announcements, slash MRU and prompt-history truncation live in crates outside the brief's ownership or need a
   restructure (the registry does slow git work between its read and its write). They are proposals P61-F1/F2.
4. **`update_config` (settings save) is on the shared lock + atomic commit + temp cleanup, not on `edit_locked`'s
   optimistic pass**: its edit is a `FnOnce` over the loader's view, with ~60 call sites. Its fsync still runs under the
   lock. Same for `campaigns_state.json` (side effect in the edit).
5. **Cancellation fix has no discriminating test** (Astra r1 #1: the locks now move into the committing blocking task).
   It is a two-line ownership change; no mutant row.
6. **Cross-process lock waits are still not FIFO** (R046 §0.2). The five-process test retries a write that is REFUSED
   with `TimedOut` (never a lost update); one such refusal was seen in the first focused run (§5.2). And the P49 test
   `fs_atomic::tests::concurrent_edits_lose_no_update` (8 threads, no retry) times out on the loaded build host **at the
   parent too**: 4/25 at parent, 2/25 at tip, run alone and alternating (§5.3). Proposal P61-F3.
7. **Error-behaviour changes (deliberate, all toward refusing)**: `add_hooks_path_to_file` and `disable_hook` now refuse
   a file they cannot read (they treated it as empty and appended; a replacement built from "empty" would erase it);
   `campaigns` refuses when its lock cannot be taken (it wrote unlocked); the dashboard persist keeps the config's owner
   bits instead of resetting it to the umask default; a cancelled settings save now completes its commit instead of
   leaving a temp behind.
8. **Sweep residual race**: between the sweep's checks and its `unlink`, a new process that reused the dead writer's pid
   AND drew the same nonce AND found the name free (another sweeper removed the stale file in between) could lose a
   fresh temp. Needs two sweepers and a pid+nonce collision inside microseconds; accepted.

## 2. The change

### 2.1 Helper (`fuigo-config/src/fs_atomic.rs`, `write_through.rs`)

- **`edit_locked_with_lock(path, lock_path, stage, edit)`** (:1282) — `edit_locked` on an explicit lock file;
  `edit_locked` is now this with `config_lock_path(path)`. **`lock_file_for_write(lock_path)`** (:832).
- **`edit_under_lock(path, lock_path, stage, edit)`** (:1350) — the locked pass alone, `FnOnce` edit run exactly once
  under the lock: for writers whose edit cannot be repeated.
- **`stage_atomically_keeping_mode`** (:84) — a stage that keeps the replaced file's mode EXACTLY (what the shell's
  `atomic_write_string` did): the temp stays `0600` until the commit, which reads the target's mode under the lock and
  `fchmod`s the temp through its creation descriptor. A looser mode of another version can never sit on a temp holding
  these contents before validation.
- **Temp cleanup through a directory handle (P49 accepted LOW, P49-F2)** — `DirHandle` (:204): the directory is opened
  before the temp exists, the temp is created with `openat(O_CREAT|O_EXCL)` and removed with `unlinkat` on that handle
  (drop, failed `finish`, failed rename). `write_through` temps too; the macOS staging directory is created
  (`mkdirat`), opened and removed (`unlinkat(AT_REMOVEDIR)`) through its parent's handle.
- **Exact requested mode**: `create_staged_temp` (:130) `fchmod`s the temp to the requested mode, so a restrictive umask
  cannot publish an unreadable config (Astra r1 #3). A leftover temp name is skipped (16 attempts) instead of failing.
- **Stale-temp sweep** — `sweep_stale_temps(path, min_age)` (:1456), run by `edit_locked*` / `edit_under_lock` once per
  path per process with `STALE_TEMP_AGE` = 1 h (:1403). An entry is removed only if: its name is one of our temp names
  for that file (`<name>.<pid>.<nonce>.tmp`, `.<name>.<pid>.<nonce>.tmp`, the two names the replaced writers used:
  `<name>.tmp.<pid>.<nanos>`, `<name>.dashboard.tmp.<pid>`); it is a regular file; its mtime is at least `min_age` old;
  and the pid in the name is not ours and `kill(pid, 0)` says `ESRCH` (:1612). A macOS staging directory of a dead
  writer loses only that writer's own old temps, then itself if empty. Unix only.
- Test seam `stage_fault::fail_writes_under(dir)` / env `FUIGO_TEST_FAIL_STAGE_UNDER` (cfg `test` / feature
  `test-seams` only).

### 2.2 Migrated writers

See §1.1. Shell-side glue is in `util/config/persist.rs`: `edit_config_file{,_with,_blocking,_raw}` (:204) =
`SAVE_LOCK` (moved into the blocking task) + `edit_locked_with_lock` on `rmw_lock_path(path)` (:149). `rmw_lock_path`:
`<path>.lock` for the user's `config.toml` (unchanged, so older Fuigos still contend); for any other file a lock under
`~/.fuigo/locks/config-<sha256(identity)[..12]>.lock`, the identity being the directory resolved component by
component (existing prefixes canonicalized, `..` after a missing component lexical) plus the file name.

Modes kept per writer as before: settings save, Claude import, pager writers = owner bits (`& 0o700`), `0600` new;
MCP / marketplace = exact mode, `0600` new; `hooks-paths`, `disabled-hooks`, JSON fallbacks = write-through (symlink
written through, owner/mode/xattrs kept), new file `0o666 & !umask`; `mcp_preferences.json` = `0600`. toml_edit
writers (marketplace, sticky flips, pager) still preserve comments and layout.
