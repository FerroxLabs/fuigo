## What changed
- `leader/protocol.rs`: `FrameReader<R>` keeps a `BytesMut` across reads; the only await is `read_buf`, so a dropped
  read loses nothing. Same EOF semantics as `read_frame` (EOF inside the prefix = `ConnectionClosed`, inside a body =
  `UnexpectedEof`); the 64 MiB cap is checked from the prefix before reserving. `read_frame`/`read_message` stay (pub
  API, one-shot callers, tests) and are now documented as NOT cancel-safe.
- `leader/server.rs` `run_client_session`: one `FrameReader` for the whole session (registration timeout read and the
  loop `select!`).
- `leader/client.rs` `register`: one `FrameReader` for the connection, moved into the read task, so frames buffered
  during registration (`Registered`/`LeaderReady` arriving with later frames) reach the read loop.
- kanal -> tokio mpsc (`server.rs` only user): taken although the reader change does not need it, because kanal
  documents its `recv()` future as unusable in `tokio::select!` (kanal-0.1.1 `src/lib.rs` "Cancellation and Polling
  Considerations"; `ReceiveFuture::drop` drops a value a sender already handed over). Both leader selects use it: the
  session loop (cancel vs outbound `server_rx` vs read) and the server loop (`event_rx`: Registered/Message/
  Disconnected). Red test `1c1d739f2` shows a queued outbound message lost when cancel wins. Unbounded semantics are
  unchanged (kanal unbounded `try_send` never returned `Ok(false)`, so the removed "channel full" arms were dead).
  P142 notice acceptance is now `send(..).is_ok()` (same meaning). `broadcast_shutdown` is now sync (sends are).
  This is a separate commit; it can be dropped without touching the reader fix.
- `leader/test_support.rs`: fake-leader variant `CoalescedRegisterReadyAcp`.
- Security posture unchanged: socket bind/permissions, the Register-first handshake and its 30 s timeout, client
  10 s registration and readiness timeouts, P142 `leader_notices` gating, protocol/binary version checks.

   scheduling a regression could pass (never a false failure). The red run shows it does catch the bug. Also fixed
   from the same review: the oversized-prefix test now has a timeout (`7cb02744c`).
`7cb02744c` is test-only and was not re-audited (round 2 not needed).
