## Limitation (release note / K row)
Clients older than this build (1.0.20 and earlier) keep the old eviction behaviour at both baselines: after an explicit downgrade to a version
older than such a client, that client can still evict the lower leader and respawn it. Not fixable from this code. The futile record only bounds
clients that carry it. Real two-client ping-pong through `connect_or_spawn` with a real binary swap was not run (fake leaders only).

## Release-note text
- Updates: after `fuigo update --version X` (or `--force`) installs an older version, a running newer shared session is asked to stop and restarts on the installed version. A client that meets a newer shared session says so and names `fuigo leader kill`.
- Memory: `fuigo memory clear` lists a legacy folder an older Fuigo left behind as not cleared, with its path; start-up no longer hashes or locks for a legacy folder that holds no notes. Removes the F3 and "memory clear clears only the new folder" K rows.
