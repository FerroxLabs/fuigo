### Design chosen and why
Two layers, with the boundary on the field and the filter only as a backstop.
1. **One adaptor for untrusted values: `fuigo_tty_utils::untrusted(v)` / `Untrusted<T>` (`display_char.rs`).** Displaying it applies `scrub_unsafe_display(.., Some(' '))` to the value alone, before it joins a line. It REMOVES: ESC and every other C0 control, DEL, C1, CR, LF and tab (each becomes a space, the line separators U+2028/2029 too), and the hidden or bidi format characters (soft hyphen, ALM, U+200B-200F, U+2028-202E, U+2060-206F, BOM, interlinear marks, tag characters and the other `is_unsafe_display_char` ranges, which are dropped). It KEEPS: all printable text, the remaining characters of an escape sequence as inert visible text (`ESC [ K` shows as ` [K`). Padding and precision apply to the scrubbed text. `untrusted_stdout_data(v)` is the same on a terminal but exact when stdout is a pipe or file (a path a script captures).
   Why a wrapper: the audit's attack worked because the line filter had to keep Fuigo's own colour and layout, so it could not tell Fuigo's SGR from the field's. Scrubbing the field first removes the ambiguity.
2. **The whole-line filter `scrub_terminal_text` (CLI macros and stderr line writers) is tightened.** It KEEPS: printable text, newline, tab, and SGR (`ESC [ params m`) limited to colour and weight: 0-4, 9, 21-24, 29, 30-39, 40-49, 90-97, 100-107, and 38/48 with `5;n` (n at most 255) or `2;r;g;b` (each at most 255); at most 16 parameters and 48 bytes, digits and `;` only (no `:`). It REFUSES (the sequence becomes visible text): conceal (8), reverse (7), blink (5, 6) and their offs (25-28), any other final byte, so `ESC [ K` and every other CSI, OSC, DCS, charset escape are gone; a lone CR, backspace, C1 and the line separators become a space; hidden format characters go. Newline and tab are kept only because Fuigo's own multi-line text uses them: the layout an untrusted field could use is why fields must be wrapped first.
3. **Trusted path for Fuigo's own erase-line.** `best_effort_stderr::eprint_trusted(&'static str)` and `cli_eprint_trusted!` write a compile-time constant exactly. The only user is the sign-in spinner (`fuigo-shell/src/auth/flow.rs:764`, `"\r\x1b[K"`). Fuigo's colour (login success mark `\x1b[1;32m...\x1b[0m`, help and markdown output) still goes through the filtered path because it is inside the allowlist. Clap help is printed by clap itself, not by these macros, and is unchanged. Pinned by `best_effort_stderr::tests::trusted_control_text_is_exact_and_the_filtered_path_refuses_the_erase` (trusted bytes `\r\x1b[K` exact, the same bytes through the filtered path lose the erase, the green `Signed in` line survives byte for byte).

### Facts from source
- clap 4.5.53 (`Cargo.lock`): `Error::exit` calls `print`, which writes `formatted()` through `Colorizer`; `StyledStr::iter_text` strips ANSI only for the plain `Display`, and nothing escapes or sanitises the argument value in the message. `ansi()` returns the raw string. The code base had no custom error formatter; it called `parse_from`, i.e. clap's own `exit`. So raw bytes reached a terminal. Same for help text that shows an env value.
- tracing-subscriber 0.3.23: `fmt/format/escape.rs` `EscapingWriter` escapes ESC, BEL, BS, FF, DEL and C1 as `\xNN` text, and is applied to the message. The first run of the new test showed a field recorded with `%` came out with its raw ESC (`a ESC ]0;x`), so the escape is NOT applied to every field value in this configuration. CR, LF, U+2028 and bidi are never escaped. Hence the record filter.

### What model text can and cannot do on a terminal (plain headless)
Cannot: emit any escape sequence (no colour, no cursor, no title, no OSC), a bare CR, a C1 control, a bidi override or hidden character. A pasted `ESC[31m` shows as the inert text ` [31m`. Can: words, newlines and tabs, and print the text `fuigo: permission granted` on stdout. What distinguishes a Fuigo line: it goes to stderr, begins after a trusted `ESC[0m` when stderr is a terminal, carries `Denied by rule` and the remedy, and the model can no longer style itself or restyle what follows. What does not: a model can still write a line that starts with `fuigo:` on stdout; a person who merges the two streams (`2>&1`) sees them interleaved with only the reset and wording to tell them apart.

### Final SGR allowlist of the line filter (`scrub_terminal_text`)
`ESC [ params m` with params from: 0, 1, 3, 4, 22, 23, 24, 30-37, 39, 90-97, and `38;5;n` / `38;2;r;g;b`; at most 16 parameters and 48 bytes. Everything else (including every background, faint, strikethrough, conceal, reverse, blink) is refused whole and the ESC becomes a space. Known limit: a foreground set by the allowlist can still match a terminal background colour (for example `30` on a black terminal) for text that did not pass through `untrusted` and `scrub_model_text`; the only untrusted prose on a terminal is model text, which can no longer use the allowlist.

### Where Fuigo emits its own reset
`best_effort_stderr::eprint_line_reported` (all `eprint_line` callers) and `write_fuigo_line`, only when the stream is a terminal, on the trusted path, before the line. Not on `cli_eprintln!`/`cli_println!` lines.

### Appearance changes for users
1. Plain headless output on a terminal is now monochrome: markdown colour or bold from a model no longer renders (decision for Sean below).
2. Clap errors and help are rendered through the line filter; colour is kept (bold, underline, foreground) when the stream is a terminal and `NO_COLOR` is unset.
3. `fuigo inspect`: quoted, 60-column paths and names; the denial line quotes the tool title and brackets the call id.
4. Debug log lines on stderr: only sequences the formatter itself writes are kept; a forged one in a message or field is shown as inert text.
5. A panic with a hostile payload prints without the "run with RUST_BACKTRACE" note.

## Round S6 (Grok r5)

Findings: audit `grok-p181-r5.md` (two MEDIUM, three LOW). Code tip `f14fc26e`.

### Design (M1, L1, L2)
`display_char.rs` has no escape-then-cap-then-repair any more. `delimited` = strict scrub, combining cap, user U+2026
becomes `...`, then UNITS (`build_units`): one per cluster (base + following combining marks + VS16, or a regional-
indicator pair); the unit text is the escaped form (`\\` first, then the delimiter and its look-alikes per `Delim`),
the unit width is the width of that text (2 for any escaped unit; cluster width otherwise). `cap_core` keeps whole
units to head budget and tail budget with one U+2026 between; a unit is never split. `cap_display_middle` (so
`Untrusted`, `capped`, inspect `cell_within`) uses the same `cap_core` (no delimiter; the user ellipsis becomes `...`
only when the text is actually capped, so uncapped text is unchanged).
Property (tested on the exact output string): exactly one opening and one closing delimiter not preceded by an odd
number of backslashes, at the two ends; width <= max + the two delimiters (for max >= 3).
Width: U+FE0F after a base makes the cluster 2; a regional-indicator pair is 2; U+2190-21FF and U+2500-257F count 2.

## Round S6 addendum (main-binary clap rendering)
Gap: `render_clap_error` (main binary) found each echoed argv value verbatim in clap's render; clap strips ANSI from
echoed values, so a value with an escape sequence AND a newline was not found and the newline survived as a forged line.

Rule (version chosen: raw plus escape-stripped lookup; the line-count backstop was not added, the byte-exact twin tests
below cover the class; a whitespace-only form, e.g. the stripped `ESC[2J LF`, is replaced only between clap's single
quotes because a global replace of `LF` flattened clap's own newlines, found by the first green run): for every kind except help, version and help-on-missing, each `ContextValue::String`/`Strings`
that contains LF, CR or TAB is replaced in the render in BOTH its raw and its escape-stripped form (CSI, OSC, two-char
escapes) with LF/CR/TAB each turned into one space; remaining TABs become spaces; then `scrub_terminal_text`. Help and
version keep their own newlines. Exit code and stream stay clap's (callers use `use_stderr`, `exit_code`).
