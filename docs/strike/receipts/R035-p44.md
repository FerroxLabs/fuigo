## 1. The defect

`FUIGO_MAX_MODEL_CALLS` / `FUIGO_MAX_RUNTIME_SECS` refusals reached ACP as:

| refusal | before | after |
|---|---|---|
| durable deadline passed (`admit_attempt`) | `-32603 api` "invalid client configuration: execution admission denied or could not be persisted" | denial `execution_runtime_limit` |
| work request with only the final call left / completion with every call spent (`admit_attempt`) | same `api` | denial `execution_model_call_limit` |
| child's call grant spent (`ChildAdmit`) | same `api` | denial `execution_model_call_limit` |
| execution opened with no call left (`Change::Open max_calls 0`, `reserve_completion` `CALL_LIMIT`) | `-32603 session_storage` "Execution state could not be made durable" | denial `execution_model_call_limit` |
| sampler process budget `CALL_LIMIT` / `WALL_LIMIT` | `-32603 api` "invalid client configuration: execution budget: …" | denial of that limit |
| prompt after runtime expiry (`acp_agent::prompt`) | `-32602 invalid_request` "execution budget: wall deadline exhausted" | denial `execution_runtime_limit` (class changes to `-32603`) |

Denial = P02e's shape: `-32603`, `error_kind: execution_incomplete`, `data.code: execution_budget_denied`, `data.rule`,
`data.remedy`, the token figures (the refusing execution's counters; `null`/`0` via
`ExecutionBudgetDenial::without_token_figures` when no execution is at hand).

## 2. Design and judgments

- **Two rules, not three.** `ExecutionBudgetRule::{ModelCallLimit, RuntimeLimit}` = `execution_model_call_limit`,
  `execution_runtime_limit`; `ALL` grows 3 → 5. The brief's example `execution_deadline` was not added: the durable
  execution's only deadline source is the mirror of `FUIGO_MAX_RUNTIME_SECS` (`turn.rs` `Execution::open` call site), and
  its only call cap is the mirror of `FUIGO_MAX_MODEL_CALLS`, so one rule per variable gives a script one id and one
  remedy per limit, whichever layer refused. Audit round 1 checked and agreed.
- **`ExecutionBudgetDenial` is unchanged** (no call/deadline figures): P02b's tests construct it as a struct literal in
  three places, so a new field would break P02b at merge. Call/deadline figures are therefore not on the wire.
- **Same clauses, same order, same refusal set** in `admit_attempt`; only the deadline and call-count clauses became
  typed. Terminal phase, wrong phase and `completion_admitted` stay plain messages (not operator limits). The old
  combined "terminal or expired" clause is split, terminal first.
- **Sampler-side classification by exact rendering** (`process_limit_rule`): there is no typed channel across the
  sampler boundary; the message is compared with `SamplingError::InvalidConfiguration(CALL_LIMIT | WALL_LIMIT).to_string()`
  built from the sampler's exported constants, gated on status-less `api`. Round 1 had a substring match (finding M1);
  fixed to exact.
- **Pager (P02b) with new rules:** `finish_turn` keys on `data.code`; `from_acp_error` knows both new rules (same
  enum), so the record is `ExecutionBudget(rule)` with the rule's own id and remedy and exit 3 — the correct record,
  proven by P02b's `a_budget_denied_turn_exits_three_with_the_denial_record` iterating `ALL` on the combined tree
  (`pager1`, §6). `ExecutionBudgetUnrecognized` (generic `execution_budget_denied` id) is reached only by a rule the
  build does not know — not these. The follow-up only rewords "token budget" → "execution budget" in the stderr line and
  the unknown-rule remedy, and adds the doc rows.

## 9. Proposals (outside ownership)

- **`fuigo-sampler`:** export the two deadline strings (`execution deadline exhausted before transport`, `… during
  subscription authentication`) as constants, or give `SamplingError` a typed budget variant, so the shell can type them
  (closes "NOT met" 2).
- **`/btw`:** classify a process-side refusal with `process_limit_rule` in `recap.rs` (one match arm); left out because
  no test can reach it without the process budget in the lib binary.
- **Partial receipt from the call limit:** consider adding `data.code`/`rule` to the in-turn finalization receipt so a
  script sees "the call limit ended this turn" too (Sean's call; it is not a refusal today).
- **`Change::Tools` / `Change::Grant` deadline refusals** ("execution actions unavailable", "parent execution cannot
  grant child work") refuse tool rounds and spawns, not model requests; untouched and untyped.
