## 1. Read first: what is NOT met, and the decisions

1. **Astra's final verdict is LAND-WITH-FOLLOWUPS, not LAND** (rounds 1–3 DO-NOT-LAND, every finding fixed except one;
   rounds 4 and 5 LAND-WITH-FOLLOWUPS). **One HIGH stays open, by decision, not fixed:** a `LocalRef` is the agent's
   address, so an agent MOVED after it has spawned background work leaves that work pointing at the old place. That is the
   pre-existing invariant of the old `LocalRef` ("never moved"), unchanged by this packet; Astra (r3, r4) found no production
   owner that moves an agent and judged it **not blocking this packet**. Enforcing it needs the agent's state in storage
   that never moves (a handle + state split of `MvpAgent`, ~16 impl blocks in 13 files and ~46 external `MvpAgent::` call
   sites, incl. fuigo-pager). **Coordinator decision: new packet** (proposal 1). I tried a cheap mitigation (abort when the
   task set has moved with work pending, `ccb7e389`); it aborted on plain `drop(agent)` (a by-value move copies), killing
   the `p83_` and `agent::mvp_agent` filters at that commit (§9 `dev2`), so it was removed (`2a2bcc35`).
2. **The brief's premise "production never tears the agent down" is contradicted by the code.** The pager runs the agent
   in-process (`fuigo-pager/src/acp/spawn.rs` `spawn_agent_thread_direct`: `drop(local)` when the agent thread ends) for
   the TUI, headless runs, `fuigo models` and the worktree command. `fuigo models` (`fuigo-pager/src/models.rs`) is exactly
   the reproducer: spawn the agent, `initialize`, list models, exit — the LocalSet is dropped well inside two seconds of
   `initialize`, with the settings-reapply task still in flight. I did not run `fuigo models` end to end (no live backend;
   §11), but the path is the measured one. **Before this fix, that command could corrupt the heap at exit (SIGABRT, or a
   silent write into freed memory).** No release-note decision is needed for the fix itself: no behaviour changes while
   the agent is alive (§4).
3. **The glibc symptom is timing-dependent; the defect is not.** With the reproducer alone on the final integration
   commit, 19 of 20 runs aborted and 1 exited 0 (§9 `dev5`); ASan reports the use-after-free every time it runs (6 of 6).

## 2. Root cause (proven)

**Stack (ASan, `asan-a1-r1.log`, 3 of 3 runs identical; first invalid access):**


**Mechanism.** Background tasks on the agent's `LocalSet` reached the agent through `LocalRef<MvpAgent>`, a raw pointer
whose stated contract was "the LocalRef does not outlive the LocalSet". That contract is not enough: the agent is owned by
the ACP connection's `handle_incoming` task (an `Rc`), and tokio's `LocalSet::drop` shuts its tasks down **oldest first**.
The connection's task is older than every task `initialize` spawns, so it is dropped first and frees the agent; then the
settings-reapply task is cancelled, and its future, suspended inside `SettingsManager::fetch` as the leader, drops its
`LeaderGuard`, whose `Drop` does `self.manager.state.borrow_mut()` and `st.in_flight = None` — a read and a write into the
freed agent (and a second drop of a `watch::Receiver` read from freed memory). The write corrupts a freed chunk in the
thread's tcache; glibc notices at thread exit (`tcache_thread_shutdown(): unaligned tcache chunk detected`).

**Why ~2 s.** The reapply task (`spawn_settings_reapply`, spawned by `initialize` when remote settings are absent) is a
leader only while its settings fetch is in flight; once it completes, the guard is gone and dropping the set is harmless
(P81: 3 s and 8 s settle → clean).

**The defect class is wider than this one guard:** any `LocalRef` task (announcements, heap profile, tier re-check, session
supervisor, deferred recovery, subagent coordinator and its child runs, synthetic traces) whose future holds a
destructor-bearing borrow of the agent when its owner drops it first; and an embedder that aborts the agent's task while
the LocalSet keeps running (`leader::in_process::spawn_agent`, used by the pager's leader-cluster test harness) left those
tasks to be POLLED later on the freed agent. The fix addresses the class, not the one guard.

## 3. The fix (`0088c279`, hardened by `89085c78`, `2a2bcc35`, `74da241b`, `d042e473`)

New `crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs`:
- `LocalRef` can now be created **only** by `MvpAgent::spawn_bound(|agent_ref| future)` (its field is private to the
  module). The future is parked in an `Rc<RefCell<SlotState>>` slot, weakly registered in `BoundTasks`, and polled by a thin
  `Driver` task on the LocalSet.
- `BoundTasks` is the **first field** of `MvpAgent`. Dropping the agent drops it first (declaration order), which drops
  every pending bound future while every other field is intact, then wakes their drivers (their `JoinHandle`s complete).
  A LocalSet that drops a driver first drops its future with the agent still alive (`Drop for Driver`).
- Panic-proof drain: each future's drop under `catch_unwind`; later panic payloads are forgotten (dropping one may panic);
  wakes run only after the drain, each under `catch_unwind`; the first panic resumes at the end.
- Re-entrancy: the driver polls and destroys its future with the slot borrowed, so an agent dropped from inside one of
  its own bound futures finds the slot busy and calls `std::process::abort()` (fail-stop; nothing runs before it).
- Every former `LocalRef::new(self)` + `tokio::task::spawn_local` site moved to `spawn_bound`: `initialize`'s 2 s
  announcement (`acp_agent.rs`), `spawn_coalesced_settings_task` / `spawn_settings_reapply` / `spawn_post_auth_settings` /
  `spawn_announcements_refresh` (`agent_ops.rs`), `spawn_heap_profile_monitor` (`heap_profile.rs`), `spawn_tier_recheck`
  (`mod.rs`), `ensure_session_supervisor` (`session_lifecycle.rs`), `finish_deferred_recovery` (`session_setup.rs`), the
  subagent coordinator (`subagent/spawn.rs`: `spawn_subagent_coordinator` → `subagent_coordinator_task` returns the future)
  and the synthetic-trace loop and each trace (`subagent_spawn.rs`). `git grep LocalRef::new` → nothing.
- No behaviour change while the agent is alive: the same futures run on the same LocalSet; `finish_deferred_recovery`'s
  handle now completes with `Ok(())` if the agent drops its task (before: it was left to run on a freed agent).

## 12. Proposals (outside this packet)
1. **New packet: make the agent's address stable** (r1–r4 HIGH 1): split `MvpAgent` into a movable handle and private
   heap state (or an enforced pinned API), so `LocalRef` points at storage that never moves. Astra notes that returning a
   plain `Rc<MvpAgent>` is not enough (`Rc::try_unwrap`).
2. P81's bridge test (`strike/p81-s20`) ends with `std::mem::forget(local)` and a comment about this abort; once P83 lands
   it can drop the set normally (one-line change there).
3. Consider a clippy/review rule that no `tokio::task::spawn_local` future captures an agent borrow outside `spawn_bound`.
