## Design: separate `sign` job between `build` and `publish`
Per-matrix `environment:` could not be proven to accept an empty value for Linux entries, so signing is its own
job (`environment: release`, `id-token: write`), which also keeps cargo build scripts away from signing credentials.
`build` uploads Windows/macOS binaries as `unsigned-fuigo-<platform>` (Linux keeps `fuigo-<platform>`). `sign`
downloads that, signs, runs gates and uploads `fuigo-<platform>`. `publish` needs `[build, sign, security]`.
Every `download-artifact` uses pattern `fuigo-*` (publish, github-release) and that glob does not match
`unsigned-fuigo-*`, so no consumer can read an unsigned binary.

Switches: Windows signing is unconditional. macOS follows `workflow_dispatch` input `mac_sign` (default true;
absent on tag push = true, expression `github.event_name == 'workflow_dispatch' && inputs.mac_sign == false && 'false' || 'true'`).
mac_sign=false: `::warning::` + job summary line, today's behaviour (arm64 ad-hoc verify, x64 unsigned).
Dry run (`dry_run` true) still signs and notarizes. No `pull_request` trigger exists; signing needs the `release` environment.

## Binary path trace (all four signed files)
build `Build` (cargo) -> `Smoke test`/`Verify macOS binary` (unsigned) -> upload `unsigned-fuigo-P` -> sign: download,
sign (azure signing action | `macos-sign-notarize.sh`), gate (`windows-verify-signature.ps1` | codesign verify, TeamIdentifier,
runtime, notarytool Accepted), smoke, `check-signed-binary.py` guard, upload `fuigo-P` -> publish: download `fuigo-*`,
`check-signed-binary.py` (Linux tripwire), `npm run assemble` reads `FUIGO_*` env paths under `artifacts/fuigo-P/` into the
platform tarballs, `Verify release archives`, `github-release-assets.sh` (raw binaries, SHA256SUMS, release-manifest.json from
those same tarball/artifact bytes) -> github-release: registry tarballs (the signed bytes published by npm) -> assets,
`verify-release-digests.js` compares with verify-published. No step reads `unsigned-fuigo-*`.

## Fail closed
Missing secret => error; a failed sign/gate step fails the job, so `fuigo-P` is never uploaded and `publish` (needs `sign`) does not run.
Guard step in `sign` and tripwire in `publish` run `scripts/release/check-signed-binary.py`. It checks presence and identity
only: PE security directory non-empty and a certificate subject containing "Ferrox Labs" (via `openssl pkcs7 -print_certs`);
Mach-O LC_CODE_SIGNATURE, CodeDirectory non-ad-hoc, runtime flag, team id. It does NOT validate signatures, chains, timestamps or digests.
spctl is informational only: it rejects bare CLI Mach-O files as "not an app". No stapling (not possible for bare Mach-O).
Not done: post-signing smoke for win32-arm64 (cannot execute on the x64 signing runner); verify-published runs it natively later.
