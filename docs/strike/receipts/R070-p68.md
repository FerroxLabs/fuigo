## 2. Fix

- **`fuigo-tty-utils/src/best_effort_stderr.rs` (new)**: `cli_eprintln!` / `cli_eprint!` (type `()`), `eprint_fmt`,
  `eprint_bytes`, one-attempt `eprint_line` / `eprint_line_reported`, `write_line`, flags `reader_gone()` /
  `hard_failure()`. Policy: `BrokenPipe` → text dropped, `reader_gone`; `WouldBlock` → retried (25 × 10 ms, shared
  helper with stdout) and once one call has waited out its whole budget the stream is "stalled" and later calls stop
  waiting until a write succeeds again (a one-attempt refusal does not mark it stalled); anything else → text
  dropped, `hard_failure`. The line is rendered once and written under the stderr lock.
- **What a hard stderr failure does (justification, also in the module docs): nothing.** No panic, no exit, no
  changed exit code. Stdout carries the command's *result* (truncation = wrong answer → exit 1 per R060); stderr
  carries *commentary*: the outcome is already in the exit code and side effects, which a diagnostic nobody could
  read does not alter. Promoting it would make success depend on where the caller pointed fd 2, and there is no
  channel left to report it on (stderr failed, stdout is the command's data, `tracing` lands on the same stderr in
  CLI modes). GNU tools behave the same (`ls 2>/dev/full` exits 0). Proven by the `/dev/full` test below: every
  command keeps its live-stderr exit code.
- `best_effort_stdout.rs`: `write_all_bytes_within(w, bytes, budget)` (the old `write_all_bytes` is that with the
  default budget), `classify` / `WOULD_BLOCK_RETRIES` `pub(crate)`. Behaviour unchanged.
- **Sweep: 188 sites** → `fuigo_tty_utils::cli_eprintln!` / `cli_eprint!` — fuigo-pager-bin `main.rs` 55 (+ the

## 4. The fuigo-agent test (`an_overrun_scan_still_populates_the_cache_for_the_next_session`)

**Root cause is not the sleep.** The failure (R068: `left: 2, right: 1` on "served from the cache") is a *second
scan*. The cache key carries `fuigo_home()`, which `fuigo-dirs` re-resolves from `$HOME` on every call, and the
fingerprint stamps HOME-relative vendor roots. Twelve fuigo-agent tests under `#[serial(home_env)]` repoint `$HOME`
process-wide; one of them running between the test's two discoveries turns the second into a cache miss. The fixed
sleep only widened the window. (If the scan is still in flight the second discovery *joins* it via the in-flight
registry, so no amount of slowness alone rescans.)

Fix: the test takes `#[serial_test::serial(home_env)]`, and the fixed 1200 ms sleep is replaced by
`overrun_scan_landed`: wait (≤ 60 s) on the scan's in-flight watch channel, which the owner signals after the cache
write, then require the cache entry for the exact key (so a key mismatch cannot pass vacuously).
