## 2. The fix

- **One registry of provider key variables:** `fuigo_tools::util::shell_env_policy::provider_key_env_vars`
  (FLUXROUTER = `FUIGO_API_KEY`, `FUIGO_CODE_API_KEY`, `FLUX_API_KEY`; ANTHROPIC; OPENAI; GOOGLE; XAI; GROQ;
  OPENROUTER; DEEPSEEK; MISTRAL; DOCUMENTED_ENV_KEYS = `ANTHROPIC_AUTH_TOKEN`, `LC_ANTHROPIC_AUTH_TOKEN`).
  `key_discovery::PROVIDERS[*].env_vars` now point at these constants (it cannot be the other way round: `fuigo-shell`
  depends on `fuigo-tools`, and the hooks and MCP crates do not depend on `fuigo-shell`). A test fails if a provider is
  added with an inline list (`p86_every_provider_key_variable_is_denied_to_child_processes`).
- **Configured names:** `register_credential_env_names` (grow-only, process-wide, case-insensitive, names kept exactly;
  empty names, names with `=`/NUL, and both platforms' core variables are refused). Fed by
  `Config::new_from_toml_cfg` (every `[model.*]` / `[model_providers.*]` `env_key` and `env_http_headers` variable, so
  every loader path), by `EnvKeys::resolve_value` (remote-catalogue env_keys), and by `ConfigReloader::reload_config`
  on the new global and effective config before any notification.
- `is_provider_credential` consults both; every existing filter already called it (`create_env_from_vars`,
  `ShellEnvironmentPolicy::allows` for request/login env, `parse_login_env_capture`, LSP `create_env`).
- **Persistent shell:** the capture scrub uses the full list, quotes every non-alphanumeric character (any name is a
  literal pattern; no injection), resets IFS in its subshell. A denylist generation counter makes a persistent shell
  whose snapshot predates the current generation start over (same directory) before its next command, dumps carry
  their generation, and a fence (`DENYLIST_FENCE`) closes the check-to-spawn window.
- **Explicit choices still honoured** (unchanged mechanism, now tested): a stdio MCP server's `env`, a hook's `env`,
  an LSP server's `env`, and `[shell_environment_policy] set` are applied after the policy base.
- **Release gate:** `.github/workflows/release.yml` `security` job, added lines (the job already runs `--lib t05_`):
  ```
  cargo test --locked -p fuigo-extra-ca --test credential_redirects -- --test-threads=1
  cargo test --locked -p fuigo-sampler --test credential_redirects -- --test-threads=1
  cargo test --locked -p fuigo-mcp --lib http_policy:: -- --test-threads=1
  cargo test --locked -p fuigo-shell -p fuigo-tools -p fuigo-mcp -p fuigo-hooks --lib p86_ -- --test-threads=1
  cargo test --locked -p fuigo-tools --lib default_shell_policy_ -- --test-threads=1
  cargo test --locked -p fuigo-shell --test p86_configured_credentials_stay_out_of_children -- --test-threads=1
  ```
  No full suites. Results on Hetzner in section 6.
- User guide `18-sandbox.md`: the always-on denylist, the exceptions, how to pass a key explicitly, `!` unaffected.

P70a collision: none. P70a touches `fuigo-shell/src/extensions/{terminal,mcp}.rs`, `util/config/mcp.rs`,
`fuigo-hooks/src/config.rs`, `fuigo-tools/.../lsp/config.rs`; P86 touches none of them (it touches

## 4. Behaviour changes for Sean (each needs a yes)

**B1 — more credentials are kept out of what the model runs.** `FLUX_API_KEY`, `ANTHROPIC_AUTH_TOKEN`,
`LC_ANTHROPIC_AUTH_TOKEN`, and every variable a config names in an `env_key` or `env_http_headers`, no longer reach
the model's bash tool, hooks, stdio MCP servers, LSP servers or the login-shell capture (the 12 old names already did
not). A hook command that uses `$FLUX_API_KEY` without its own `env` now sees it empty (it is not refused: the
"required env var not set" check looks at Fuigo's own env, proposal 6). First-party dependency: none found — no
checked-in hook, MCP server, plugin or bundled config uses these variables (searched all non-Rust files; the only
mention is the `env_key` example in `11-custom-models.md`); the nested `fuigo agent leader` spawn
(`leader/mod.rs:1734`) does not go through this policy and is unaffected (Astra r1-r5 agree).
Release note: *Fuigo no longer passes your provider keys — including `FLUX_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and any
variable your config names as an `env_key` — to the commands the model runs, hooks, MCP servers or language servers;
to give one of them a key on purpose, put it in that server's or hook's `env`, or in `[shell_environment_policy] set`.*

**B2 — a persistent shell starts over when a config change adds a credential name mid-session** (same directory;
exports, functions and aliases from earlier commands are gone). Only on that event.
Release note: *If you add a model key variable to your config while a session's persistent shell is running, that
shell restarts in the same directory before its next command.*

**B3 — a configured name stays hidden for the life of the Fuigo process**, even after it is removed from the config;
core variables (`PATH`, `HOME`, `USER`, `LANG`, `TMPDIR`, `APPDATA`, …) are never hidden this way.
Release note: *A variable you once named as a key in your config stays hidden from tools until Fuigo restarts.*

**B4 — a model-supplied environment for a command cannot set these names** (the request-env filter already dropped
the 12 old names). Release note: none needed (not user-facing).

**Not changed:** `!` commands and client terminals (section 0.2).
