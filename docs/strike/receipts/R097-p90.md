## 1. Read first: what is NOT met, and the decisions

1. **Astra's last verdict (round 5, on `e7ac917d`) is DO-NOT-LAND with two HIGH and one MEDIUM, all in F6, not fixed.**
   They belong to one pre-existing class: **helper sampling clients are built once and never rebuilt** when the session's
   model or the catalog changes. (a) The session-summary/title client is built at session setup from the creation-time
   config and kept across a model switch (`agent_ops.rs build_summary_client`, `session/summary.rs`): an API session that
   switches to a subscription before its first prompt titles it on the old (paid) route. The parent does exactly the same
   (pre-P90 stamping also ran once at build time). (b) An explicit classifier slug that was off the catalog when the
   worker was wired (so resolved on the gateway) and is later added to the catalog by a models reload is still served by
   the cached gateway client. (c) MEDIUM: the three round-4 call-site changes are covered by unit tests of the functions
   they call, not by caller-level tests. Closing (a)/(b) means rebuilding helper clients on model switch and catalog
   reload (session setup, summary persistence, classifier wiring, `model_switch.rs`): the "large refactor" the brief
   tells me to report rather than ship partially. **Proposal 1.** F2, F3 and F5 were clean in Astra rounds 4 and 5.
2. **Decision for Sean — session-summary fallback.** When a user's EXPLICIT summary helper cannot be used, titles fall
   back to the active session model (the subscription). Image description fails the turn instead, and the classifier
   answers "unavailable" (which asks the user). The summary client is built during session setup with `?`, so refusing
   would refuse the whole session; and it only summarises the session's own conversation, which the session model
   already receives. Documented in the user guide.
3. **Decision — F3 unknown IPv6 errors fail closed.** The ruling names EADDRNOTAVAIL/EAFNOSUPPORT → IPv4-only and
   EADDRINUSE → abort. Any other `[::1]` bind error also aborts (we cannot tell nobody else holds the address).
4. **Decision — F2 has no request-count cap.** Codex aborted the login after 32 ignored requests, which let any web page
   end it with 32 `<img>` tags (the very F2 harm). Ignored requests are never counted; the existing 600 s deadline bounds
   the wait; at most 32 connections are read at once, each bounded by a 5 s read timeout.
5. **Behaviour change beyond the brief.** Image description now reads its helper slug and provenance from the
   `ModelsManager` config (one snapshot), so a `[models] image_description` reload now reaches open sessions (before, a
   session kept its spawn-time slug). Fallback to the spawn-time slug when the config carries none.
6. **Not my code, failing:** `agent::config::tests::hidden_default_web_search_resolution_is_explicit_and_responses_only`
   fails when run alone (the session token is not attached). See §6 for its result at the parent.

## 4. The fixes
- **F2** (`flow.rs read_callback`, `callback`, `parse_request_target`): every request that is not this attempt's
  callback is answered (400; 404 for another path; 400 best-effort for unfinished/too-long/too-slow) and ignored. A
  well-formed head is `GET <origin-form> HTTP/1.0|1.1`, CRLF, header names RFC 9110 tokens, values without controls but
  HTAB; the target rejects what a browser always percent-encodes (controls, space, non-ASCII, `"`, `#`, `<`, `>`; not
  strict RFC 3986, so a raw `|` or `{` from a real browser is never refused). Only this attempt's state ends the wait
  (code → exchange; state with error/no code → abort). Connections are read concurrently (`FuturesUnordered`, ≤ 32),
  accept errors from a peer reset are ignored.
- **F3** (`bind_callback_listeners`, seam `LoginAttempt::bind_with`): `127.0.0.1:port`; for ChatGPT also `[::1]:port`;
  EADDRNOTAVAIL/EAFNOSUPPORT → IPv4-only (logged); EADDRINUSE or any other IPv6 error, or any IPv4 failure → abort with
  the address named. xAI binds IPv4 only.
- **F5** (`storage.rs logout_all`, `main.rs`, `cli.rs`, guide): plain `fuigo logout` deletes `credentials.json` and
  orphan `.tmp*` under the same lock every refresh holds for its whole exchange window; nothing outside
  `$FUIGO_HOME/subscriptions`; nothing revoked. Output: "All subscription credentials removed locally; provider tokens
  were not revoked." Help and guide say exactly that (and that a copy taken before logout stays valid until expiry or
  revocation in the account settings).
- **F6**: provenance — `ExplicitHelperModels` (config-file key judged against the campaign-free config of the SAME read,
  env var, CLI flag = explicit; remote settings, campaigns, compiled defaults = not), carried by
  `load_effective_config_with_campaign_free` → `RuntimeResolutionContext.campaign_free_config` /
  `re_resolve_runtime_fields` / settings-refresh reapply / models reload; classifier provenance = the `[auto_mode]`
  file value. Routing — `HelperModelChoice`; stamp: a Default helper follows the active subscription (any provider or
  account), an Explicit one keeps its route; an explicit keyless helper on a non-Ferrox-bearer URL resolves to its own
  route with no credential (not the gateway + a stray key); `explicit_helper_route`: an explicit off-catalog helper in
  a subscription session is unusable; `explicit_helper_fallback_refused`: unusable explicit image helper fails the turn,
  classifier answers Unavailable; `cached_helper_route`: the classifier's cached route is re-judged per request;
  `ModelsManager::image_description_helper`/`publish_helper_models`: slug and provenance from one snapshot, republished
  after a settings refresh.

## 12. User-visible changes (release notes for Sean)
- Sign-in no longer fails because another page or program sent a bad request to the callback address; Fuigo answers it
  with an error and keeps waiting for the real one.
- ChatGPT sign-in now also holds `[::1]:1455` so no other program can receive the redirect; on machines without IPv6
  loopback it continues on `127.0.0.1`, and it stops with a clear message if either address is taken.
- `fuigo logout` now deletes every subscription account stored on this machine and says that the provider tokens are
  not revoked.
- A helper model you chose yourself (image description, session titles, auto-mode classifier) keeps its own route
  during a subscription session; defaults follow the subscription. If your chosen image or classifier helper cannot
  be used, Fuigo stops or asks rather than quietly using the subscription.
- Changing `[models] image_description` now takes effect in open sessions after the config reload.
