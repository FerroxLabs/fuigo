## What changed
- **S8** `fuigo-workspace/src/trust.rs`: `read_doc_strict` — only a genuinely absent entry (no-follow probe NotFound /
  ENOTDIR) is Missing; empty file is an empty doc; unreadable / invalid TOML / directory / dangling link is an error.
  `TrustStore.disk_readable=false` then trusts nothing and every write returns `Unreadable` (nothing written; the file
  keeps its bytes). The locked re-read uses the same strict read. Relative home → no store path. Legacy hook-trust
  migration does not consume into an unread or path-less store. Owner-only atomic write unchanged (0600 asserted).
  A failed read after a clean probe is Missing only if a fresh no-follow probe still finds nothing.
- **S9** `fuigo-workspace/src/folder_trust.rs` (grant path only; P166's presence checks untouched; tests in the new
  `folder_trust_grant_tests.rs`): `grant_folder_trust(cwd) -> GrantOutcome`, `grant_folder_trust_key(shown_key)`,
  `grant_folder_trust_key_in(home, key)`, `GrantRefuse{InertBuild,UnsafeRoot,NoHome,Unreadable,KeyMoved}`,
  `PersistStatus{Durable,ProcessLocalOnly}`, `GrantResolution{Trusted,SessionLocal,Unrecorded}`,
  `report_cli_trust_grant`. Pre-check: existing key must equal its canonical form; a missing key is granted as written
  only when absolute and lexically normal (standalone worktree whose source repo is gone, as before). Callers:
  - `--trust` (pager-bin agent + pager, pager app, headless): not-saved / refused grants print the reason on stderr.
  - TUI accept (`dispatch_trust_folder`): grants the shown key; Trusted → resolve; SessionLocal + embedded agent →
    resolve and queue a one-off session note (the `--sandbox` case: never quits); SessionLocal under a leader or
    Unrecorded → question stays with the reason (welcome toast + `AppView.trust_error`, rendered by the minimal view).
  - GUI prompt: shown key; not-saved grants sent as `NotifyConfigNoticeIfNew` to every covered session; Unrecorded
    stays gated and releases the dedup key.
  - `/hooks trust` and `/trust` slash: Unrecorded → error; SessionLocal → success with the note.
  - stderr prompt: reports; an Unrecorded grant no longer allows project config (fail closed).
- **S17** `fuigo-shell`: `auth::auth_json_path(home)` (exactly the auth manager's prior rule: `FUIGO_AUTH_PATH` as
  given, else `<home>/auth.json`) used by `AuthManager::new` and by `read_active_team_auth`,
  `team_principal_signed_in`, `active_team_id_any_expiry` (one `read_team_principal`). `back_up_unsynced_policy_files`
  and its removal-path call are unchanged.

`--sandbox` bug check: Fuigo 1.0.21 did not have upstream's exit (its TUI accept always resolved); the upstream bug was
introduced by 75810042's quit-on-non-durable and fixed by a28ee2b2. P167 ports the `SessionLocal` resolution so the
new reporting cannot reintroduce it; `p167_trust_folder_with_denied_store_write_continues_for_this_session` pins it.

## Release-note line (S)
- **S** Folder trust and managed policy keep your data: an unreadable or corrupt `trusted_folders.toml` is never
  rewritten (your existing grants survive; Fuigo trusts nothing until it is fixed), a relative `FUIGO_HOME` gets no
  trust store, `--trust` and the trust question now say when a grant was not saved instead of continuing silently
  (under `--sandbox` the folder is trusted for the session and Fuigo keeps going), and a login at a custom
  `FUIGO_AUTH_PATH` no longer makes startup delete your organisation's policy files. (P167; upstream 75810042,
  a28ee2b2, 1.0.19)
