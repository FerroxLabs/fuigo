## 2. User-visible behaviour changes, with release notes

1. *Credentials Fuigo sent, and the API key it holds, now read `<redacted>` in the session event log (`events.jsonl`)
   and in every file of a `/feedback` trace archive, including raw bash output.*
2. *Fuigo's own secrets (`FUIGO_AGENT_SECRET`, `FUIGO_AUTH`, `FUIGO_AUTH_PATH`, the deployment, extra-auth, OTLP header
   and telemetry keys) are no longer passed to the bash tool, hooks, MCP and language servers, search tools or an
   auth-provider helper; name one in a server's `env` to pass it on purpose.* (OTLP: an OpenTelemetry-instrumented
   program the model runs no longer sees `OTEL_EXPORTER_OTLP_*HEADERS`.)
3. *A variable named by an MCP server's `bearer_token_env_var` or OAuth client-secret setting is no longer passed to
   other child processes* (for example a `GITHUB_TOKEN` used for an MCP server is hidden from `gh` in the bash tool).
4. *The search tools now run with the same filtered environment as other child processes.*
5. *A user name or password in `HTTPS_PROXY` no longer appears in relay logs or errors; a relay proxy URL with `@`
   after a `/`, `?` or `#` is refused (percent-encode such characters in the password).*
