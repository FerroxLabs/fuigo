## What changed

**D1, `session/persistence.rs` (sweep).** Before: every file older than the TTL inside every session folder was
deleted, so a session used today lost the compaction checkpoints, prompt offloads (`prompts/`), rewind points and
history that an older turn wrote. Now a session is judged as a unit:
- a session whose newest top-level file is younger than the TTL keeps everything except stale files in its
  disposable caches `images/ videos/ downloads/ terminal/` (upstream's list);
- the live session of this process is never removed, only its caches pruned;
- a session nobody used for the TTL is removed whole (the old per-file sweep reached the same end state file by
  file), but only while the sweep holds `turn_owner.lock` (live actors hold it shared for life) and a new `sweep.lock`
  exclusively, only if it still looks unused under those locks, and by first RENAMING it to a dot-named sibling
  (`.fuigo-sweep-removing-*`, never listed) so nothing can be opened at its path once removal starts. A leftover is
  finished by the next sweep;
- every attach (`session/load`, `session/resume`) and `session/new` first calls `mark_session_live`, which holds
  `sweep.lock` shared and bumps `summary.json`'s mtime; it waits asynchronously (never on an interrupted-turn
  recovery's lock), and if a sweep in another process holds the session past 5 s the load fails with a retry message
  instead of loading a session being removed. The initialize-time sweep with no live session (`acp_agent.rs`) is gone;
  the sweep runs once per process from the first `session/new` / attach (`spawn_session_sweep`).
- Fuigo posture kept / added: the 30-day default TTL stays (upstream sweeps only when configured); symlinks are never
  followed: the cache prune is descriptor-relative on Unix (`openat(O_DIRECTORY|O_NOFOLLOW)` + `fstatat`/`unlinkat`
  with `AT_SYMLINK_NOFOLLOW`), `symlink_metadata` checks elsewhere; `mark_session_live` and the lock files open with
  `O_NOFOLLOW|O_NONBLOCK` / `FILE_FLAG_OPEN_REPARSE_POINT`; lock files are created owner-only (P145) and the Windows
  ACL is applied only to a regular file; `remove_dir_all` removes links, never their targets.

**D2, `session/helpers/replay.rs` + `acp_session_impl/rewind.rs`.** Before: replay failed "Compaction checkpoint file
missing" on ANY missing checkpoint, including an older one a newer compaction supersedes, and a pre-compaction target
failed when its checkpoint was gone although the raw transcript is all it needs. Now (upstream's base stack, extended):
- only the base still installed for the target at the end of the transcript is required; a superseded, abandoned or
  after-target checkpoint is skipped with a warning; a pre-compaction target is rebuilt from the raw transcript and
  uses the checkpoint only for `original_user_info` (falls back to the current preamble);
- a loaded base keeps the conversation it replaced when a later rewind marker can still abandon it (first pass over
  the markers), and a marker that pops it restores that conversation: the older base (or the raw turns) is rebuilt
  exactly, and a missing older base fails the replay (Astra r1 HIGH) instead of silently using the abandoned summary;
- reads stay `read_contained_checkpoint` (contained, no-follow, P146); schema other than 1 is refused (`Unsupported`);
- the rewind error names what is missing, the prompt range, the prompts that still work, and keeps the P146/P111
  wording: `Cannot rewind to prompt #6: the compaction checkpoint for prompts #5 onward is missing
  (compaction_checkpoints/x.json); pick a prompt before #5, or one at or after the next compaction. Nothing was
  changed: no file was reverted and the conversation was not rewound.`
- Damaged sessions (checkpoints already deleted by the old sweep) still load and resume: `load_light` and the
  copy / chat-rebuild / witness callers keep their fallbacks; `compacted_resume_history_acp` ("checkpoint file missing")
  passes; `replay_if_latest_compaction_active` now rebuilds from the latest checkpoint even when an older one is gone.

Existing test changed: `failed_cross_compaction_rewind_changes_no_project_file` (P111) now rewinds to #6 (past the
compaction whose checkpoint is gone) and asserts the exact message; its old target #3 (before the compaction) now
SUCCEEDS by design (D2) and is covered by the new `pre_compaction_rewind_succeeds_when_the_checkpoint_is_gone`.

## Unverified

- Windows: nothing here was compiled or run on Windows (`FILE_FLAG_OPEN_REPARSE_POINT` opens, rename of a folder
  with open lock handles, the `cfg(not(unix))` cache prune). The code is cfg-gated and mirrors existing Fuigo Windows
  patterns (`storage/mod.rs` uses the same flag), but it is source-only.
- Inherited (not new, Astra r1–r3 agree): the sweep's ancestor path components (`sessions/<cwd>/`) are not pinned by
  descriptor, and the non-Unix cache-folder check→open window remains; both existed in the parent.
- Residual by design: an attach that marks AFTER the session was renamed away finds no session (load fails
  "not found"), the same outcome as resuming a session the TTL already removed.

## Release-note text (for `docs/release-notes-1.0.22.md`)

- **F/B (data loss, fixed):** "The 30-day session cleanup no longer deletes compaction checkpoints, prompt offloads,
  rewind points or history of a session you still use: it now removes a session only when nobody has used it for the
  whole period (and never while it is open or being resumed), and otherwise only ages out cached images, videos,
  downloads and terminal logs." (D1)
- **F/B (data loss, fixed):** "`/rewind` no longer fails because an older compaction checkpoint is missing: only the
  checkpoint the chosen prompt is rebuilt from is needed, and a prompt before a compaction is rebuilt from the
  transcript. When the needed checkpoint is missing, the error names it, says which prompts still work, and nothing is
  changed." (D2)
- **K:** no 1.0.21 K row covers D1/D2 (they were found in the 1.0.22 upstream review); nothing shrinks. Windows
  behaviour of the new sweep locking is source-verified only (see Unverified).
