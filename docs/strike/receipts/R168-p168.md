## What changed
**S6** — `crates/codegen/fuigo-workspace/src/permission/shell_access.rs` (redirect-detection functions only; the
protected-edit paths that P166 edits are untouched) and `exec_risk.rs` (`is_accepted_long_option_prefix` became
`pub(crate)`). `shell_output_flag_values` is now one left-to-right walk driven by a per-program `OutputFlagSyntax`:
- long output options in full or as any abbreviation down to 3 characters (`--out=f`, `--outp f`, `--o f`). An
  ambiguous abbreviation still counts as a write: sort/go/git `--output`, git `--output-directory`, rustc `--output`
  and `--out-dir`;
- `-o f`, glued `-of`, and `-o` inside a short-option cluster for getopt-style parsers: GNU sort (`-ro f`, `-rof`),
  rustc/getopts (`-go f`), and `git archive` and `git format-patch` (`-vo f`, `-kno f`). A letter that takes a value
  ends the cluster, so `sort -to f` and `git status -uno` stay non-writes. git's optional-value letters
  (`-M -C -B -U -X`) never consume the next word, so `format-patch -M -o dir` still writes `dir`;
- Go reads `-o=f` as `-o f`. git and getopt programs write the literal `=f`;
- `rustc --emit TYPE=PATH[,…]` writes each PATH (new);
- a missing value (`sort a -o`) is an empty-path write rather than nothing, as upstream does. Auto-mode sees a
  non-sink write and does not auto-allow it;
- the git walk starts after the verb, past global options and their values. Values of known value-taking options are
  not rescanned as flags: sort `--key`/`-k`…, git `--grep`/`-S`/`-pS`…, rustc `--remap-path-prefix`…;
- `--` ends options only where it cannot be an option's value. After a bare long option such as `sort --temp`, or a Go
  flag such as `-tags`, it may be a value, so scanning goes on (over-report, not under-report).

**Fuigo divergences from upstream:** upstream clusters `-o` for `sort` only and keeps the first two items of the list
above. P168 also clusters rustc, git archive and git format-patch, as the brief requires ("every command the
detector covers"). Go is unclustered because Go's `flag` package has no clusters. The value-consumption and `--`
rules, `--output-directory` and `--emit` come from Astra rounds 1–3.

**S14** — `crates/codegen/fuigo-agent/templates/prompt.md` gains upstream's `<dangerous_actions>` block before
`<work_policy>`, unbranded (upstream's text has no Grok/xAI words; the Fuigo identity line is unchanged). Fuigo
addition: in a headless session (`is_non_interactive`), "With no human operator to confirm with, take such an action

Verdict NOT-LAND-OK: Grok confirmed the round-3 fixes and found 2 HIGH, both regressions against 532e913 (the base
reported these writes):
1. A `--` among git's global options (`git -C repo -- format-patch -o .env`, `git --git-d /repo -- archive -vo .env`,
   …) dropped later output flags. **Fix (07b66c304):** a `--` that is not a global option's value ends the globals and
   the next word is the verb. Long globals match by abbreviation (`--git-d /repo` skips its value), and the
   `--git-dir=path` form carries its own value. git 2.43 and 2.50 actually reject `--` and abbreviations here
   (`unknown option: --`, `unknown option: --git-d`), so those commands never run. Reading past them only
   over-reports, which matches the base.
2. format-patch value letters were all optional, so `-S --` ended the scan. **Fix, deviating from Grok's literal fix
   on evidence:** git 2.50 probes in a scratch repo show:
   - `format-patch -v -- -o od` writes `od` (`-v` takes even `--`), so `v` moves to `arg_letters`;
   - `-S -o od`, `-G -o od`, `-I -o od`, `-O -o od`, `-U -o od`, `-X -o od`, `-M/-C/-B -o od` all write `od`. Those
     letters never take a following option word, so they stay optional. Grok's `vUlSGOXI` would hide these real
     writes; that is mutant M26, killed;
   - a `--` that follows a cluster holding any value letter may be that value, so the scan goes on. `-S -- -o .env`
     and `-pS -- -o .env` are reported (git itself errors there, so this over-reports).
3. `git log -1 -pS --out Cargo.toml` was added to the auto-mode test (no write) and to a new deny-side test

## Known limits (recorded, not defects)
- Git aliases are not resolved. An alias to `archive`/`format-patch` gets exact `-o` matching, without clusters.
  Astra r2 accepted this limit.
- Value-taking options are modelled for common free-text options only. An unknown option whose value looks like an
  output flag over-reports a write (fails toward a prompt), and an unknown long option before `--` keeps the scan going
  (also over-reports). Neither under-reports.
- rustc/getopts long options are matched with abbreviations even though getopts does not accept them (over-reports only).

## Release-note text (for `docs/release-notes-1.0.22.md`)
**S (security):** Shell write detection now catches every spelling of an output option: abbreviated long options
(`sort --out=f`, `git log --outp f`, `git format-patch --output-directory=d`), `-o` inside a short-option cluster
(`sort -ro f`, `rustc -go f`, `git archive -vo f`), Go's `-o=f`, and `rustc --emit link=f`. A managed `Edit` deny or ask,
and auto-mode's write check, can no longer be dodged by respelling the flag, and read-only spellings such as
`git status -uno` stay read-only. The main-agent system prompts gain a `<dangerous_actions>` section: the agent
confirms before destructive, hard-to-reverse or shared-system actions, treats an approval as covering only its stated
scope, and, in headless sessions, takes such actions only when the task explicitly authorizes them. (P168; upstream
48271133.)
