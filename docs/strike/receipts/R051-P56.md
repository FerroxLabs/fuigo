### 2.1 Tests (`auth/cross_process_race_tests.rs`)
- **Hostile, two real processes** (6 tests, one per writer: `update`, `save_without_enrichment`, `store_api_key`,
  `store_api_key_async`, `clear_api_key`, `clear_api_key_async`). The test binary re-runs itself twice (`race_child`,
  env-isolated). Each child owns one scope and writes 100 versions while the other child writes the other scope. Before
  each write a child checks its previous write is still on disk. Only it writes that scope, so anything older is a
  rollback by the other process. The parent reads the file throughout and requires that every read parses (never torn
  or missing) and that versions never go backwards. Both children's last writes must be on disk at the end. Overlap is
  proven: a ready handshake, a halfway rendezvous on the peer having written, and contention reported by the children
  (`contended=` > 0 is required). Typical run: `role=update rounds=100 lock_timeouts=0 contended=188`.
- **Held lock, one process** (9 tests): another open file holds the lock. Each writer must wait out
  `AUTH_LOCK_TIMEOUT`, return `TimedOut`, and leave `auth.json` byte-for-byte unchanged. Covers the devbox purge and both
  snapshot writers.
- **Same scope, snapshot writers**: a sibling's rotation lands while the writer waits on the held lock (`*_keeps_a_rotation_that_landed_while_it_waited`).
  Disk lagging memory (`edit_stored_credential_keeps_a_fresher_in_memory_mint`,
  `update_unless_superseded_writes_a_copy_fresher_than_disk`, `update_unless_superseded_keeps_a_newer_unpersisted_memory_mint`).
  Acknowledged edit reaches memory on a lock or write failure.
- `flock_wait::tests::a_wait_cancelled_before_its_thread_starts_still_deposits`.

## 7. Proposals (outside P56)
- **P-8:** `fuigo-workspace/src/hub_auth/mod.rs:206` waits 15 s for the shared lock, not the shell's 10 s. Its comment at
  `:221` still describes unlink-based stale-lock recovery, which the shell no longer does.
- **P-9:** `FUIGO_AUTH_PATH` is not in `OWN_PROCESS_KEYS`, yet `cli_models.rs` and `manager_tests.rs` set it in the shared
  process. Any test that builds `AuthManager::new` can be pointed at another test's file in that window. P56's tests use
  `AuthManager::new_at_path`. The older tests do not.
- **P-10:** a starved writer. Under sustained contention (a sibling re-taking the lock every few ms) a writer can wait
  out its 10 s budget and fail rather than write unlocked. That is the intended trade, and production writers are rare.
  The race children saw 0 lock timeouts in the recorded runs.
