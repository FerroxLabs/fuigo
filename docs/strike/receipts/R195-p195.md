### U11: why it is left unimplemented
The shell tool's input (`BashToolInput`, `fuigo-tools/src/implementations/fuigo_build/bash/mod.rs:265`) has `command`,
`timeout`, `is_background`, `description` and no `block_until_ms` field. `grep -rn block_until_ms crates/codegen` finds it only
in a config ceiling (`max_block_until_ms`, bash/mod.rs:198, "Shell model" wording inherited from upstream), a comment
(bash/mod.rs:2117), one shell test arg (`wait_interrupt_tests.rs:387`, a different tool) and the guard test. A model call
cannot carry it, so there is no wait to compare against and nothing to implement. The pager's detection
(`is_bg_tool`, `fuigo-pager/src/acp/tracker_tests.rs:3889-3913` pins it) deliberately treats `block_until_ms: 0` and
`timeout: 0` as foreground; the test `only_the_is_background_flags_defer_an_execute_call_as_a_background_task` is the guard.
Making it real needs a new tool field plus a background hand-off after the wait (the existing `foreground_block_budget_ms`
auto-background in bash/mod.rs:186 is the nearest mechanism). That is a feature, not an ~80-line fix; left for a decision.

### JSON transcript shape (U17, `--output-format streaming-messages-json` and the assistant frames)
- Before: consecutive thinking blocks of one response were merged into a single `thinking` block (one signature); a
  `redacted_thinking` block was dropped. After: each thinking block is its own `{"type":"thinking","thinking":...,"signature":...}`
  with its own signature, in order; each redacted block is `{"type":"redacted_thinking","data":"<opaque>"}` in its position
  (no `thinking`/`signature` keys; an empty blob is skipped). With `--include-partial-messages` each opens its own
  `content_block_start`/`stop` at its own index. Consumers that expect at most one thinking block per message, index the
  content array positionally, or reject unknown block types will see a difference. Replaying a transcript to the API now keeps
  every signature valid.
