## Where the fix lives
Every scrub of known credentials reads one registry, `fuigo-secrets::sent_credentials` (headless output via
`scrub_owned`, `events.jsonl` via `scrub_json_strings` + `scrub_bytes`, `/feedback` archives via `scrub_record`/
`scrub_bytes`, the P149 upload `payload_filter` (shell `scrub_upload_text`, workspace `workspace_upload_scrub`), trace
export via `scrub`, log writers via `ScrubWriter`, telemetry via `redact_secrets`). Astra r1 confirmed this by source
tracing. So the change is made there once, and every path gets it:
- **base64**: each recorded spelling carries its base64 forms, computed once when it is recorded (re-recording reuses
  them; at most `MAX_ENCODINGS` = 10): standard and URL-safe, padded and unpadded, and the key-determined characters at
  each of the three byte alignments inside a larger blob (HTTP Basic `user:key`, an encoded JSON document). An in-blob
  form checks the key bits its neighbouring characters carry (`Edges`), reading an escaped neighbour as what it decodes
  to, so the base64 of a different value is not taken for the key.
- **percent-encoding and JSON escaping**: decoded, not enumerated (Astra r1 showed an encoder may escape any subset of
  characters). Each view (`%XX` either case; `+` as space only when a recorded spelling has a space; JSON escapes incl.
  `\uXXXX`, `\/`, surrogate pairs; JSON escapes decoded twice) is decoded token after token in one pass over a text that
  holds a `%` or `\`, 64 KiB of source at a time with a decoded tail carried between pieces (bounded memory, no state lost
  at a piece boundary), and every spelling, base64 forms included, is searched in it. A match is reported once, with the
  source range it was decoded from.
- One-pass multi-needle search (`find_all`, bitmap of 2-byte prefixes) replaces the per-needle scan, so the extra
  spellings do not multiply the cost; `safe_cut` streams matches (no per-occurrence storage). No regex anywhere.

## Residual / unverified
- After r3 there is no independent re-audit (cap); the r3 fixes are verified by the tests and mutants above only.
- A key-bearing base64 blob cut exactly at an alignment boundary and followed by literal text that is a valid escape
  (`%41`, `\n`) is checked against that escape's decoded byte on the right, so it can stay unredacted (LOW; the blob is
  also missing its last key bits). The left side accepts either reading, so a value within 4 bits of a key whose left
  neighbour is escaped may be redacted (LOW; protective: such a value reveals the key up to 16 guesses).
- Not covered, by design (module docs): case changes of the key, base64 wrapped across lines, double percent-encoding,
  other encodings, a key split across two separately written log records, a key never recorded.
- Cost: no native benchmark was run. Each scrub call builds the needle index (an 8 KiB bitmap + sort) and, only for a
  text holding `%` or `\`, decodes up to four views linearly (Astra r3 estimate for 8 MiB of `\n`-escaped JSON: ~20 MiB of
  decoder input, bounded scratch). Memory per recorded spelling: at most 10 base64 strings.
