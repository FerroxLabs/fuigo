## 2. Finding 2: how Fuigo now establishes cross-process liveness, and why

**I searched for an existing mechanism first.** In `fuigo-shell` the only fs2 locks are
`managed_config/store.rs`, `util/config/campaigns.rs` and the `config.toml.lock` writer. Elsewhere
there are `fuigo-workspace` `trust.rs` and `hub_auth`, and the workspace daemon's pidfile
(`fuigo-workspace-daemon/src/daemonize.rs`). None of them is per session. There was no session lock,
no pid file and no heartbeat, so nothing could be reused.

**I chose a lock, not a fail-safe.** Failing safe would mean never declaring an interruption, because
liveness is never known, and the feature would be dead. So I implemented a lock:

- Every session actor holds a **shared** fs2 lock on `<session_dir>/turn_owner.lock` for its whole
  lifetime. It is the `SessionActor::_turn_owner_lock` field, taken in `spawn.rs` next to the
  `EventTracker` for the same `session_dir`, before any `turn_started` can be written. When a process
  dies the OS releases its lock, so a crash, a kill and a restart all free the session.
- Recovery takes the **exclusive** lock without waiting, and holds it through detection, the durable
  append and the closure:
  - `Acquired` means no live actor anywhere, so recovery proceeds.
  - `HeldElsewhere` means the turn is running, so nothing is declared.
  - `Unknown` (the lock file cannot be opened or locked) is treated as "do not declare". That is the
    fail-safe for liveness that cannot be established.
- The exclusive holder is the only possible recoverer, so two concurrent loads cannot both append a
  marker. That was the second half of Astra's finding.
- The file is empty and never read or written, so Windows' mandatory `LockFileEx` semantics cost
  nothing.
- The calls use UFCS (`fs2::FileExt::try_lock_shared(&file)`) because Rust 1.89+ has an inherent
  `File::try_lock_shared` with a different error type.

**Residual risks, stated plainly:**

- **Mixed versions.** A process running a Fuigo from before this change holds no lock. While both
  versions run the same session, the new one can still mistake the old one's turn for lost.
- **Race at actor spawn.** ~~An actor that spawns while another process holds the exclusive recovery
  lock polls for up to 2 s (`OWNER_WAIT`) and then runs without its lock, with a warning. The window is
  one durable append long.~~ **Corrected (Fable audit, N2):** this statement was wrong. After the 2 s
  deadline the v2 actor ran without its lock for its *whole lifetime*, not for one append, so a later
  recovery in any process could declare its live turn lost. The wait was also a blocking
  `std::thread::sleep` on the agent's LocalSet (N1). Both are fixed in v3; see R017a.

## 3. Other design points worth auditing

- **Detection** (`interrupted_turn.rs` `scan_lines_backwards`):
  - Reads 64 KiB chunks from the end and visits lines newest first. It stops at the first
    `turn_started`/`turn_ended`.
  - Memory is one chunk plus one line capped at 8 MiB. A longer line is skipped unparsed. Turn events
    are a few hundred bytes, so a skipped line cannot hide one (tested).
  - An unterminated last line is visited like any other.
  - `the_backward_scan_visits_every_line_newest_first` checks every line across many chunk-boundary
    offsets, with and without a trailing newline.
- **Idempotency** (`newest_turn_completed`): the newest `turn_completed` in `updates.jsonl` decides.
  - Same prompt with `interrupted`: an earlier recovery committed the marker and died before closing.
    Reuse it: no append, close the log, return the on-disk line so resume can forward it.
  - Same prompt with any other stop reason: the turn ended and only its closure was lost. Close it with
    that outcome (`error`/`rate_limit` → `error`, `cancelled` → `cancelled`, otherwise `completed`)
    and report nothing.
  - Anything else: append a new marker.
  - If `updates.jsonl` cannot be read (other than not-found), recovery declares nothing, because an
    earlier marker cannot be ruled out.
- **Events dir.** Detection, closure and the lock all use `persistence::session_dir(&session_info)`,
  the same dir the actor's `EventTracker` writes to. The port used `updates_file_path.parent()`, which
  the storage trait documents may differ for non-default storage modes.
- **`EventTracker::close_open_turn`** writes only when `begin_turn` ran and the turn is not already
  ended. A fresh tracker therefore never writes a `turn_ended` with no `turn_started`, and a turn the
  outcome handling already closed is not closed twice.
- **Rewind closure** carries no `cancellation_category`, so the `MidTurnAbort` dashboards do not count
  rewinds. `a_rewind_reports_nothing_but_still_settles_the_session` and
  `no_output_rewind_cancel_emits_no_turn_completed` still pass: no hooks and no terminal record.
- **Compaction trust boundary.** Any session under the same `<FUIGO_HOME>/sessions` qualifies, which
  is the same user's own data. Each directory from the root down to `assets/` must be a real directory
  per `symlink_metadata`. The root itself is trusted, since it comes from `FUIGO_HOME`. The call site
  derives the root as `session_dir.parent().parent()`. That derivation is verified by reading, not by a
  mutant.
- **Dependencies and lockfile.** Neither changed. `fs2` was already a `fuigo-shell` dependency.
