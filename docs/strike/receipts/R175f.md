## Item 2: cache staleness
The alias is reused for 2 s. A link retargeted inside that window is seen up to 2 s late. CORRECTION (Round 2): the
claim that this was not weaker than integration `38954e80` was FALSE: integration resolved on every check, so a link
retargeted or created under a deny/ask prefix was denied at once there, but allowed for up to 2 s with the cache.
The cache is removed in Round 2. No timeout was added: `resolve_following_symlinks`
is synchronous (like its other caller at policy.rs, the ancestor walk) and `canonicalize_with_timeout` is async; a
timeout would need a worker thread per call. Error means no alias (base behaviour). Item 3 resolves at filter build, once per tool call.

- Finding 1 (HIGH): the 2 s alias cache (`alias_cache`, `ALIAS_CACHE_TTL`, the Mutex, `AliasCacheEntry`) is removed;

- Finding 2 (MEDIUM): `ReadDenyFilter::new` resolved every absolute deny glob unbounded. New
  `physical_alias_pattern_string_bounded` (path_match.rs) runs the resolution on a thread and waits at most the limit;
  the filter build shares ONE 250 ms budget across all rules. policy.rs is deliberately not bounded (unbounded in

  integration); the as-written rule still applies.
- Tests: `bounded_alias_tests::a_slow_resolver_yields_none_within_about_the_limit`, `a_prefix_through_a_link_returns_the_alias`;
  round 1 read_deny assertions unchanged.

## Round 3 (P175h)
- MEDIUM: the bounded resolver left one parked thread per search behind a hung mount. Now a process-wide count
  (`ALIAS_STUCK`) of resolver threads that timed out and have not returned: while it is non-zero no new resolver is
  spawned and `bounded_alias` returns `None` at once, so at most ONE thread is parked. The thread releases the count when
  it ends (also after the caller gave up, also on panic), so a recovered mount is used again on the next search.
  Resolvers that finish in time never count, so concurrent searches do not affect each other.
- LOW: the hide is stable while a prefix is stuck (no alias, no added wait) instead of flipping with load. The single
  250 ms budget per filter build is unchanged. policy.rs untouched.
- Tests (red `44b3328c`, a failed at "call 2 while stuck"): `a_stuck_resolver_is_the_only_one_ever_spawned`,
  `a_recovered_mount_is_used_again`; earlier two kept, serialised by a local mutex.
