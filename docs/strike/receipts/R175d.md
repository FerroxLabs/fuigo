# R175d: branch-switch check follows a `.git` file (linked worktree, submodule checkout)

Branch `strike/p175-gitfile` on integration `0b25a762`. Crate: fuigo-workspace only (`permission/exec_risk.rs`).

## Compared before and after
- Before (P175 part B): a write target is "in the repository git dir" when it lies inside the nearest ancestor
  `.git` that IS A DIRECTORY (`exec_risk.rs`, branch-switch planner). A `.git` file was skipped, so the check
  found no directory (or an outer repository's).
- After: the same directory, PLUS, when the nearest `.git` is a regular file (not a symlink): the `gitdir:` it names
  (first line, relative to the checkout root, canonicalised) and the `commondir` named inside it (relative to the
  gitdir, canonicalised). Reads are capped at 4096 bytes. Any failure (malformed, missing target, empty, symlink,
  oversized) adds nothing, so the set never shrinks. Tighten only: the only change is a kept prompt.
- Sandbox crate untouched; no new dependency edge (the sandbox helper is not callable from this crate).

## Tests (`manager/p175_tests.rs`, hand-built fixtures, no git binary)
- `p175d_linked_worktree_write_into_gitdir_or_common_dir_unsettles_the_switch`
- `p175d_submodule_relative_gitdir_write_unsettles_the_switch` (relative `gitdir:` leaving the tree; the ordinary
  in-tree submodule was already caught through the superproject `.git` ancestor, kept as a row)
- `p175d_gitfile_guards_keep_today_verdicts` (no git-dir write, other repo's `.git`, `git ... && cp` order, malformed,
