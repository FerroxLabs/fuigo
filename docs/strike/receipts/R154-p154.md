# R154 - P154: Windows parent-swap race in the no-follow checkpoint read

Branch `strike/p154` on `strike/p153` (9479d07b). Tip: see "Commits". Toolchain: rustc 1.94.0 (4a4ef493e 2026-03-02), from inside the tree
(`b-*.log` line 1). Date: 2026-10-05/06 UTC. File: `crates/codegen/fuigo-shell/src/session/storage/mod.rs` only.

## Result
The Windows branch of `open_beneath_nofollow` no longer checks folders by path and then opens by path. It holds a handle per folder
(share read only), requires each folder to be a directory and not a reparse point from its own handle, requires each folder's FINAL
path to be directly inside the one above (base's final path for the first), keeps every handle until the leaf is open, and requires
the leaf's final path to be directly in the last folder. Final paths are compared as UTF-16 units (exact parent, case-insensitive last name).

## Where the brief was wrong (evidence beat the design)
1. `access_mode(FILE_READ_ATTRIBUTES)` + no `FILE_SHARE_DELETE` does NOT stop a rename of the held folder: an open that asks only for
   attribute access is not share-checked. Windows Server 2022, red/green: `vm-green1.log` (rename of the held leaf folder succeeded).
   Fixed by adding `FILE_TRAVERSE` (e9c50ace).
2. Share mode alone cannot stop an in-place conversion of an EMPTY held folder to a junction (`FSCTL_SET_REPARSE_POINT` through an open
   with `FILE_WRITE_ATTRIBUTES` only): the VM shows the conversion SUCCEEDING at tip (`P154 ... conversion succeeded: true`,
   `vm-r4-tip*.log`). The defence is the final-path location checks, not the share mode. (Astra round 1 found this; round 2 and 3 found the
   mid-walk and case/lone-surrogate variants of the same attack.)

## Release-note text
K2: the Windows parent-swap remainder is closed. Checkpoint reads are now no-follow on every platform: on Windows each folder on the path is
held open and verified (not a link, and really inside the folder above) until the file is open and verified, so a folder swapped for a
symlink or junction between the check and the read can no longer redirect it.
