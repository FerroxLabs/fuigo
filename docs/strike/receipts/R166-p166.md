## What changed (by item)
- **S5** (`fuigo-workspace` `permission/shell_access.rs`, `permission/manager/mod.rs`):
  - Protected edit targets: `mcp.json`, `lsp.json` in any `.fuigo` dir or directly under `$FUIGO_HOME` (new reason
    `McpConfig`); the grant stores `{home}/sessions/<scope>/permission.toml` / `permission_<client>.toml`
    (`FuigoConfig`, as upstream). **Fuigo-way addition:** Fuigo also loads and hot-reloads vendor MCP lists, so
    `.mcp.json` (anywhere), `.cursor/mcp.json` and `.claude.json` are `McpConfig` too, and the directories that hold
    protected files (`.fuigo`, `$FUIGO_HOME`, `.fuigo/sessions[/<scope>]`, `.cursor`, `.claude`) are protected as write
    targets.
  - Every write path: the edit/write tools (`AccessKind::Edit`) already went through `edit_target_protection`. The
    shell floor only checked `mkdir`/`touch` operands; it now checks redirect targets, writer operands, `-t DIR`,
    `DEST/<source name>` for directory destinations and, for a directory source, the copied tree
    (`ShellWriteFacts`, walked at evaluation time, ≤10k entries). Relative targets resolve against the cwds they can
    run in (only `cd`/`pushd` that precede them in scope, after the cd's own redirects); an unpinnable `cd` still
    fails closed.
- **S7** (`fuigo-tools` `read_file/mod.rs`, `types/resources.rs`): the read tool denies when the logical path the
  model named OR the physical target is ignored (`GitignoreFilter::is_logical_path_ignored`: lexical spelling plus
  every physical-prefix + logical-tail spelling; a `..` spelling is not fed to the ancestor matcher).
- **S12** (`fuigo-tools` `util/file_reader.rs`, `computer/*`, read tools; `fuigo-workspace` `file_system/adapter.rs`;
  `fuigo-acp-lib` `stdin_reader.rs`): tool reads accept regular files only — stat before open, `O_NONBLOCK|O_NOCTTY`
  open, fstat after open — so a FIFO, device or socket is refused at once with "is not a regular file: it is a FIFO
  (named pipe) …". `read_file` (and the codex/opencode/hashline reads, image/video references) cap sources at
  256 MiB (`MAX_READ_SOURCE_BYTES`, acquisition capped at max+1 bytes). ACP-backed reads refuse over-cap responses and
  the ACP stdin reader stops at the 64 MiB frame cap instead of buffering an endless line. P146's no-follow session
  reads and owner-only writers are untouched (separate code path).
- **S13** (`folder_trust.rs:376`, `claude_settings.rs:393`): presence uses `symlink_metadata`, so a directory or a
  (dangling) symlink at `.cursor/hooks.json` or `.claude/settings*.json` gates the folder.

## Release-note text (docs/release-notes-1.0.22.md)
- **S (P166):** Edits, writes and shell writes (redirects, `cp`/`mv`/`install` into a directory, tree copies including
  dereferencing `cp -L`, archive extraction with `tar`/`unzip`/`7z`/`cpio`, `rsync`/`ditto`, `perl -i`/`ruby -i`) to

### The tripwire in plain words
Every word of a command that is not a known reader is cut into path-like tokens (at whitespace, quotes and `= , ; : | < > ( ) { } & !`;
a short option with an attached value, `-oX`, also yields `X`; `$HOME` is already `~`). Each token is judged by the same protected-target
matcher and cwd resolution as any write target. So any non-reader command naming a protected path literally, in any word, gets the
protected floor, even if no classifier knows the program. Readers are exempt for their input operands; a reader's output option
(`less -o/-O/--log-file`, `tree -o`) is still scanned. Code: `tripwire_tokens`, `tripwire_word_tokens`, `reader_output_values`.

### The two allowlists (copied from `shell_access.rs`)
`TRIPWIRE_READERS` (every argument is an input; a protected path among the operands is a read):
- `cat bat less more head tail grep egrep fgrep rg ag ls stat file wc diff cmp sha1sum sha256sum sha512sum md5sum cksum du tree
  realpath readlink basename dirname echo printf test [ jq true false type which cd pushd popd source .` : read, print or compare
  their operands; none writes a named file (`less`/`tree` output options are scanned separately).
- `chmod chown chgrp` : metadata only, no content write; unchanged by the floor since round 5.
- `sed gsed awk gawk mawk nawk find xargs sh bash zsh dash ksh` : judged by their own classifiers (script writes, `-exec`/`-fprint`,
  nested shells, launched commands), so a protected path as an input operand must not prompt.

`TRIPWIRE_OPTIONS_ONLY` (specific classifier places the plain operands; only words starting with `-` go through the tripwire):
- `cp rsync scp install ln ditto cpio pax patch` : source versus destination operands are classified by position.
- `docker podman kubectl` : `cp` has a source and a destination; a container-side path is not a local write.
- `git` : pathspecs are reads (`git add .mcp.json`, `git diff .mcp.json`); writing verbs are in `git_worktree_writes`.
- `tar gtar bsdtar zip unzip 7z 7za 7zz 7zr` : archive members and sources are inputs, `-C`/`-f`/`-d` are classified.
- `curl wget` : URL operands are inputs, output flags are classified.
- `yq` : plain operands are read inputs; `-i` is classified (reads stay silent, c761d4d5).

### The decoded-view rule (shell_access/tripwire.rs)
A non-reader command that names a protected path literally gets the protected floor. The tripwire now judges a DECODED view:
- ANSI-C `$'...'` is decoded (`\n \t \xHH \NNN \uXXXX ...`), also as a piece of a concatenation (`-o$'.mcp.json'`, `$'.mcp.json'.gz`).
- Brace expansion is expanded (nested, comma groups only) up to `BRACE_CAP = 256` words. Over the cap the word is not expanded; it
  protects (unpinned) only when the fragments joined contain a protected first component (`.git`, `.mcp`, `.fuigo`, `.claude`, ...).
  Brace words are also expanded into separate words for the real classifiers (`cp a {zz,.git}/hooks/pre-commit` writes the last).
- Same-command `NAME=value` assignment values and `env NAME=value` values are scanned (quote removal + ANSI-C decode).
- `env -C DIR` / `--chdir DIR`: the directory is a token and every relative token is also judged as `DIR/token` (readers included,
  for their output options such as `less -o`, `tree -o`).
- Here-string and here-document bodies are scanned for the programs that read stdin as input (`ScanAll`, `Skip`, `Script` shapes).
- Options-only programs (the old `TRIPWIRE_READERS`/`TRIPWIRE_OPTIONS_ONLY` lists are replaced by a `Shape` per program plus a per-program value-option table `opts_of`):
  the SEPARATE value of a known value option is scanned (`scp -o X`, `rsync -e`, `--temp-dir`, `curl --output-dir`, `wget -P`,
  `tar --index-file`, `docker -H/--context`, `docker run -v/--mount`, `less -o/--log-file`, ...); known input values and operands
  that are inputs are skipped. `less +cmd` is scanned as an option word.
- Undecodable word rule (a word with `$x`, `` `..` `` or other expansion left after decoding): not scanned as text; it takes the
  protected floor only when a protected name (`PROTECTED_NEEDLES`: `.git/hooks`, `.mcp.json`, `.ssh`, `.bashrc`, ...) remains in it.
- Glob rule: a word with `* ? [` is matched component by component against the protected NAMES the matcher knows (`GLOB_NAMES`;
  dot-names only when the pattern starts with a dot), at most `GLOB_CAP = 64` paths; any match is judged like the literal path
  (`touch .git/hook?` blocks, `ls src/*.rs` does not).
- Remote `scp`/`rsync` destinations (`host:path`) are left to the remote machine (they were silent before; the colon split made
  `host:.mcp.json` look protected: caught by `grok_r4_protected_write_targets` and `grok_r5_patch_scp_pax_git_write_targets`).

### Feature 1: branch switches under a narrow git grant

Rule: when a narrow policy allow (`Bash(git:*)`) is about to clear the FileWrite floor (`narrow_allow_clears_write_floor`) of a listed verb, git is asked read-only whether any tree the command involves tracks a protected name; yes or undetermined keeps the floor (normal prompt); no behaves as before. The git calls run only when ALL hold: `exec_risk::branch_switch_plan` found a listed verb, the assessment is FileWrite-only without a redirect, and a narrow allow authorizes it (`narrow_allow_would_clear`); every other command makes no git call. Local manager: `branch_switch_floor_kept` (async; `spawn_blocking` plus `tokio::time::timeout` 8 s, a join error or timeout keeps the floor). Hub: `hub_needs_default_prompt` calls `branch_switch_floor_kept_blocking` (that function is documented blocking) and `narrow_allow_clears_write_floor`, the same pair; nothing differs except sync versus async execution. Test `p166_r13b_hub_branch_switch_follows_the_local_check`.

Verbs and trees (cwd tracked through `cd`, `pushd`, `git -C`, as the ambient scan does; a retarget flag, `popd`, a dynamic path is undetermined):

| Form | Trees |
|---|---|
| `checkout <ref>`, `switch <ref>`, `merge <ref>`, `rebase <ref>` (one plain word) | `HEAD`, `<ref>` (both required) |
| `checkout -`, `switch -` | `HEAD`, `@{-1}` |
| `pull` with only boolean flags (`--rebase`, `--ff-only`, `--autostash`, ...) and at most `<remote> [<branch>]` | `HEAD` (required); `@{upstream}`, `refs/remotes/<remote>/<branch>` (optional: skipped when they do not resolve) |
| `stash pop|apply [--index] [<n>|stash@{n}]` | `HEAD`, the stash (required), `<stash>^3` (untracked part, optional) |
| `switch -c|-C|--create <name>`, `checkout -b|-B <name>` (a new branch at HEAD) | none: decided HARMLESS, no probe, no prompt (rewrites nothing) |
| `stash` (push, list, ...) and every other verb | none: not listed, behaviour unchanged |
| everything else of a listed verb (`--detach`, `--orphan`, `-b new <start>`, `-m`, pathspec forms, `HEAD~2`, `ref:path`, bare `merge`/`rebase`/`checkout`, flags not listed, a URL remote) | undetermined: floor kept, no git call |

Important fact found while wiring: `merge`, `rebase` and `stash apply` already carry the `unpinned` protected floor (`shell_access.rs` ~3377, round 8B), which asks in every repository whatever the grant. The new check therefore changes real outcomes only for `checkout`, `switch <ref>`, `pull` and `stash pop`; for `merge`/`rebase` it is correct but moot (they prompt before and after). `hub_needs_default_prompt` alone shows them as changed in a tracked repo, the full hub verdict shows `PROTECTED_PATH` in both.

Protected name: each path of `git ls-tree -r --name-only -z --full-tree <tree>` is joined to the repository root (`git rev-parse --show-toplevel`) and judged by the packet's lexical protected-path matcher (`shell_access::lexical_path_is_protected`, the same `protected_edit_reason` as the bash floor, with no filesystem access so a big listing stays cheap); first hit wins. A repository that lives under a protected directory itself (for example below `~/.ssh`) therefore always prompts (conservative, stated).

Bounds: output cap 16 MiB per listing (`MAX_LISTING_BYTES`, the child is killed and the answer is undetermined), 2 s wall clock per git child (`GIT_CHILD_TIMEOUT`, killed), 8 s for a whole check on the actor side.

Hardened child (`branch_switch::run_git`): `git` spawned directly (no shell), stdin and stderr null, `env_clear()` then only `PATH`, `HOME=/nonexistent`, `LC_ALL=C`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`; arguments `--no-pager -c core.fsmonitor=false -c core.hooksPath=/dev/null -c protocol.allow=never -c core.alternateRefsCommand=`; commands only `rev-parse --show-toplevel`, `rev-parse --verify --quiet --end-of-options <ref>^{tree}` (the ref is a plain word, never starting with `-`) and `ls-tree -r --name-only -z --full-tree <40-hex sha>`. No network.

Conclusion on (a), from git documentation and from the tests: `git ls-tree` and `git rev-parse` read objects and refs only. Programs named in a repository's own `.git/config` run only for other operations: `core.fsmonitor` (documented under index refresh: `status`, `diff`, `checkout`; neither command reads or refreshes the index), hooks (`githooks(5)`: fired by commit, checkout, merge, receive-pack, ...; none by these two; and `core.hooksPath` is forced to `/dev/null` anyway), `core.pager` and `pager.<cmd>` (only for commands that page, and `--no-pager` is passed; `rev-parse` and `ls-tree` do not page), `alias.*` (`git-config(1)`: an alias never overrides a built-in command, and the child invokes built-ins by name), `diff.external`/textconv/`filter.*` (diff and checkout machinery; `ls-tree` prints names only), `core.sshCommand`/`gitProxy`/`credential.helper`/`core.askpass` (transport and credentials, no network is used), `core.alternateRefsCommand` (`git-config(1)`: used when git advertises alternate refs for fetch, push and upload-pack; blanked on the command line as a belt), `uploadpack.packObjectsHook` (pack-objects, not used). I found no repository config key that makes these two commands execute a program, so the feature ships. Backed by `p166_r13b_hostile_repository_config_runs_nothing`: a repository whose `.git/config` sets `core.fsmonitor`, `core.pager`, `core.hooksPath` (a directory of marker-writing hooks), `core.sshCommand`, `core.askpass`, `core.alternateRefsCommand`, `core.editor`, `alias.ls-tree`, `alias.rev-parse`, `diff.external`, `uploadpack.packObjectsHook`, `gc.auto`: marker file NOT created, verdict unaffected. Limits of that evidence: it proves these keys on this git version (see Unverified), not every key of every git version.
