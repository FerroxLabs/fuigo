## 1. Read first: what is NOT met, and the decisions

1. **Two HIGH findings stay open, both PRE-EXISTING and judged by Astra not introduced or widened by this change**
   (r3, r4). They are D.4 token-accounting gaps of the bounded-execution layer, not the latch, and need their own
   packet (proposal 1):
   - **Rewind cancel** (`cancel.rs:218`, byte-identical to the parent): an Esc after a request was dispatched but
     before its first output rewinds the turn and never terminalizes, so the dispatched attempt stays `pending` on the
     goal's Working record forever. Under a token budget its usage is never counted; and since it stays pending, a
     token-budgeted goal that is LATER interrupted cannot be resumed (§3, fail closed).
   - **Superseded attempts on a Working record** (`supersede_attempt`): a resend that takes over an attempt that
     reported no usage does not set `unknown_usage`. That is the deliberate empty-reply policy, pinned by
     `empty_replies_leave_the_execution_token_budget_usable`; P89 keeps it for Working records and fails closed only on
     a terminal one (the widened case Astra found in r3, fixed).
2. **Decision for Sean (behaviour, budgeted goals only).** A goal started with a token budget (`/goal <objective>
   --budget <tokens>`) whose turn is interrupted while a model request is in flight cannot be resumed: that request's
   token usage is unknown, so the budget can no longer be enforced, and P89 fails closed (`TokenUsageUnknown`), as the
   execution already does when a provider reports no usage. `/goal resume` says so and tells the user to clear the goal
   and start a new one. The refusal lifts by itself if the late usage arrives. The alternative (charge a worst-case
   amount reserved before dispatch, as Astra suggests) is a larger change in the sampler's accounting: proposal 2.
   Goals WITHOUT a token budget (the default) always resume after an interruption.
3. **Coverage limits (LOW, Astra r1–r4).** The dropped-future cancel path is tested by calling `emit_turn_completed`
   exactly as `cancel_running_task` does (`cancel.rs:806`), not by aborting a running prompt over ACP; and the
   reservation-ownership lock is tested for a sequential same-key handoff, not a concurrent one (a reintroduced
   unlock-before-release race would survive). Astra found no current race or lock-order cycle (r2–r4).
4. **Pre-existing, observed while testing, unchanged:** under any tracked execution (an active goal, `--max-turns`,
   `FUIGO_MAX_MODEL_CALLS`), a turn that COMPLETES without `EndTurn` (a refusal, a max-tokens cut) issues a partial
   receipt and `handle_turn_input` rewrites it to `-32603 execution_incomplete` instead of `StopReason::Refusal`/
   `MaxTokens` (turn.rs, `receipt.partial && Completed`). The goal-loop tests accept either shape. Proposal 3.
5. **Gate:** per the coordinator's process change for LOW packets, no own two-sided re-proof on the final base; the
   coordinator runs one combined `rp.sh` for P88–P92 on `e0145e0f`. An `rp.sh` gate DID pass on the earlier base (§8).
   **Astra:** 4 rounds (run before the one-round cap arrived); final verdict (r4): no BLOCKER/HIGH introduced or
   widened by this change.

## 2. The defect, verified

The audit's H-2 (`codex-audit/efficiency-continuation.md`) is **confirmed, and wider than reported**.

- `turn.rs` (parent 733–735): the execution root is the active goal's `goal_id`; `execution_state.rs` `Execution::open`
  keys the record `blake3(session \0 root)`.
- `execution_state.rs` `should_terminalize(active_goal, completed, phase)` is `!active_goal || !completed || phase !=
  Working`: any goal turn that does not end `EndTurn` writes `Terminal`. `GoalTracker::resume` keeps `goal_id`.
- The next turn's open adopts the Terminal record (`Change::Open` on an existing file is a no-op read), and
  `process_conversation_turn` returns the receipt error before the model (`turn.rs` "state.phase == Terminal ||
  completion_admitted"). Every admission is refused (`admit_attempt`: "execution is terminal or expired").
- **Wider (by reading):** also a turn that SUCCEEDS while the goal pauses itself (the verifier's `Blocked`, back-off,
  no-progress pauses happen inside the turn loop, so `active_goal` is false at terminalization) latches the goal;
  `/goal resume` of those fails the same way. And the dropped-future cancel path (`emit_turn_completed`) latches identically.
- **Reproduced on the real prompt path** (red, §6): with an ACTIVE goal, turn 1 ends by each cause; `/goal resume`
  (`resume_goal`); turn 2 fails `-32603 execution_incomplete` with the old partial receipt and 0 model requests. The
  first red attempt passed 2 of 4 cause tests for a fixture reason, not the product: the test actor has no goal
  harness, and `maybe_reconcile_active_goal_without_harness` pauses an active goal at its first turn, so turn 1 was not
  a goal turn at all. The fixture now marks that one-shot reconcile done (as in any session with the harness);
  `red.log` vs `b2-red.log`/`b4-red.log`, §6.
- **L-2 confirmed** (red): under `FUIGO_MAX_MODEL_CALLS=3`, a goal execution of a closed session and one displaced by a
  plain prompt of its own session keep their completion reservations: with the live one, the limit is spent and a
  fourth session's open is refused. Only `terminal()` released (`execution_state.rs` parent 937).
- P03 (`2cbcbd36`) only reconciles a crash-poisoned record's `abandoned` set and deliberately never reopens; that is
  unchanged. Its fixtures stay terminal (pinned).

## 3. The fix (`55c5e5ae`)

- **The turn says how it ended.** `TurnEnd::{Succeeded, Interrupted, Stopped}`. `turn.rs turn_end_of`: `EndTurn` →
  Succeeded; a completed non-`EndTurn` (max tokens, refusal), `Cancelled`, `StationarityEnded` → Interrupted;
  `MaxTurnsReached`, a budget denial, or any `execution_incomplete` error → Stopped; any other error (provider) →
  Interrupted. The dropped-future cancel path (`turn_end.rs`) maps `Ok(EndTurn)`/`Ok(_)`/`Err` the same way.
  `Execution::terminal(bool)` keeps its meaning (a non-success is Stopped).
- **The record decides once**, at receipt issue (`issue_terminal`): `reopenable = end != Stopped && !(phase ==
  Finalizing && !recall_finalization)` — a finalization entered on a limit (or forced by crash recovery) is a stop.
- **Reopen** (`Change::Reopen`, via `Execution::open_goal`, used only when the turn's root is an active goal):
  allowed iff `may_reopen` = Terminal, a receipt, `reopenable` (or, on a pre-P89 record, `legacy_reopenable`: nothing
  unresolved and no non-recall finalization spent), and no `exhaustion`: deadline passed, a token budget spent or
  unknown usage, the model-call cap (no work call left), `--max-turns` rounds spent, and — on a terminal record under a
  token budget — ANY attempt still pending (its usage is unknown; optional ones too). Reopen keeps every counter, the
  call debits, tool rounds, deadline and grants; moves the receipt to `earlier_receipts` (cap 16, plus a `reopened`
  count); settles the interrupted turn's pending required attempts and tool calls into that receipt (never re-run);
  raises `total_tokens` to the goal tracker's own count. Both the registered-instance path (`terminal_issued`) and the
  fresh path reopen; the completion reservation is retaken BEFORE the record changes (a refused reservation leaves it
  terminal). A plain `open` never reopens.
- **Refusals say why.** A spent budget refuses with its own typed denial (`execution_budget_denied`, rule, remedy —
  `Exhaustion::Budget`), otherwise `GoalExecutionEnded` → `-32603 execution_incomplete` with the reason and
  "/goal clear, then /goal <objective>". The transition itself refuses typed, so a limit that runs out between the
  check and the write still reads as that limit. `/goal resume` checks the record first
  (`Execution::goal_resume_blocker`) and answers "Goal cannot resume. <reason>" instead of resuming.
- **Late usage.** A terminal record still accepts a late `Settle` (lifts the in-flight refusal, charges the usage). A
  `Supersede` with no usage on a TERMINAL record now sets `unknown_usage` (Astra r3), so a background child's retry
  cannot lift the refusal without reporting usage.
- **L-2.** `Drop for Execution` gives back its completion reservation if this instance still owns it
  (`RESERVATION_OWNERS: key → instance`, lock held across the sampler's reserve/release, order owners → budget);
  `terminal()` releases as before. `make_room` drops the registered executions of closed sessions and the session's
  own displaced execution BEFORE a new one reserves.
- **Serde.** `Snapshot` gains `reopenable: Option<bool>`, `earlier_receipts`, `reopened`, all `serde(default)`,
  skipped when empty; version stays 1; P03's fixtures and every baseline file load. An older binary ignores the new
  fields (and drops them if it rewrites the record; a record it rewrote is then judged by the legacy rule).

## 4. User-visible behaviour changes (release notes for Sean)

1. **An interrupted `/goal` keeps going.** Pressing Esc, a provider error, an answer cut off at the output limit, or a
   refusal now ends only that turn; `/goal resume` (or the goal's next turn) continues the same goal. Before, any of
   these silently killed the goal for good and only `/goal clear` recovered.
2. **A goal that ran out of budget says so.** When a goal's token budget, the model-call or runtime limit, or
   `--max-turns` is spent, `/goal resume` now answers which limit stopped it and what to do, instead of resuming into a
   turn that fails with a generic "Execution stopped with bounded capacity or unresolved work" error; the next turn
   fails with the limit's own `execution_budget_denied` error (rule and remedy as data).
3. **A goal with a token budget interrupted mid-request cannot be resumed** (decision §1.2): its last request's token
   usage is unknown, so the budget can no longer be enforced; `/goal resume` says so and to start a new goal.
4. **Long-running engines with `FUIGO_MAX_MODEL_CALLS` no longer leak model calls**: a session closed while its goal
   was working, or a goal set aside by a later prompt, now gives its reserved final-answer call back to the other
   sessions.

## 11. Proposals (outside this packet's files or scope)

1. **D.4 accounting packet:** (a) a rewind cancel (`cancel.rs` `RewindIfNoOutput`) should settle or record its
   dispatched attempt (unknown usage) instead of leaving it pending on a goal's Working record; (b) decide whether a
   resend superseding an attempt that reported no usage should count as unknown usage on a Working record under a
   token budget (today deliberately not, `empty_replies_leave_the_execution_token_budget_usable`); (c) audit L-5
   (token budgets on providers that send no usage) together.
2. **Budgeted goals after an in-flight interruption** (decision §1.2): reserve a worst-case token charge per attempt at
   admission and settle the difference, so an interrupted request can be charged conservatively and the goal resumed.
3. **Refusal / max-tokens under a tracked execution** reported as `-32603 execution_incomplete` (the partial-receipt
   rewrite in `handle_turn_input`) rather than as `StopReason::Refusal` / `MaxTokens`: decide whether a completed-but-cut
   turn's receipt should be partial at all.
4. An ACP-level goal test (pager or harness with `/goal` over the wire, Esc via `session/cancel`, `/goal resume`) once a
   goal-capable mock (planner/verifier subagents) exists.
