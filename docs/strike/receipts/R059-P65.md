## Verdict: (a) the product correctly refuses; the TEST was fixed
- First bad commit (first-parent bisect, c2d0de14..90c5a4af): **8616559c "P42: session-token delivery has one predicate"**.
- That commit makes `OaiModelSource::fetch` (`src/remote/model_source/oai.rs`) withhold a session credential from any URL failing `session_delivery::session_may_reach`, which requires a configured `https` origin and never loopback.
- `tests/common::start_seeded_mock` pointed `[endpoints].cli_chat_proxy_base_url` at `MockInferenceServer`'s `http://127.0.0.1:PORT/v1`. The session-auth `/v1/models` fetch therefore failed closed with `BackendError::Auth` before any request left the process. `/v1/settings` still went out, because that path does not consult the predicate (see Proposal 1).
- Observed `(models, settings)` = `(0, 1)` against the expected `(1, 1)`.
- Why the product behaviour is right: P42's stated contract (R034, `docs/destination-trust-policy.md`) is that a session bearer never reaches `http://` or loopback, because a co-located process could read it.
- The startup prefetch still runs. Model discovery is invoked, and a refusal becomes `ModelsPrefetch::Unavailable`.
- The production ordering installs the trust set before `begin`: the pager parses its config before `begin`/`begin_with_auth`, and ACP `spawn_fuigo_shell` receives a parsed `Config` before `begin_before_policy_gate`.
- The fixture relied on a session token reaching loopback, and it also never installed a trust set: `Config::default()` publishes none, so even an https URL would have been refused.

## Fix (tests only)
- `crates/codegen/fuigo-shell/tests/common/session_front.rs` (new) is the non-`cfg(test)` twin of P42's `test_support::session_wire::SessionFront`. That module compiles only into the unit-test binary, so integration tests cannot import it.
  - It is a CONNECT proxy, on its own thread and runtime, that TLS-terminates `api.fluxrouter.ai:443` with a throwaway CA (`FUIGO_EXTRA_CA_BUNDLE`) and forwards the bytes unchanged to the mock.
  - `NO_PROXY` keeps loopback direct.
- `tests/common/mod.rs` `start_seeded_mock`:
  - starts the front (single use per binary, asserted);
  - writes the fronted URL `https://api.fluxrouter.ai/v1` into `config.toml`;
  - installs the trust set the way a boot does, with `Config::new_from_toml_cfg(&load_effective_config())`;
  - asserts that the fronted origin IS a session destination and the mock's loopback URL is NOT.
- All five `test-support` binaries use this helper. The three `(0,0)` negative tests (overlap, policy, repair_skip) are no longer vacuous for `/v1/models`, because the positive path now really reaches the mock.

## Proposals (outside P65 ownership)
1. **Settings fetch still delivers the session bearer to http/loopback (HIGH, P42 gap).**
   - `remote/client.rs` `add_cli_chat_proxy_headers_blocking` and `fetch_settings_blocking_with_attempts` attach `auth.key` with no `session_may_reach` check.
   - Evidence: at 90c5a4af and f82e6e33 the mock saw `/v1/settings` = 1 from the loopback URL while `/v1/models` = 0.
   - Owner per Astra and R034 §4b: P47. It needs allowed and refused destination wire tests.
   - The P65 fixture stays correct either way, because it goes through a configured https origin.
2. **fuigo-shell `local-workspace` does not compile.**
   - `crate::gateway_bridge` has never existed in this tree.
   - Every `default-bazel` build of fuigo-shell, fuigo-pager and fuigo-pager-bin is therefore red.
   - Either drop `local-workspace` from those `default-bazel` sets or gate the call sites.
3. **`config_docs::tests::page_is_the_user_facing_field_list` (config-docs, in CI's set)** needs `crates/codegen/fuigo-shell/AGENTS.md`, which is absent from the tree. It fails 100% whenever config-docs is on. Either ship the page or make the test skip-with-reason when it is missing.
4. **fuigo-fast-worktree `worktree-lifecycle-bench`** (`lifecycle-bench`) references the `grove` and `grove_git` crates, which are not dependencies, so the bin cannot build.
5. **fuigo-workspace `hub_auth::proactive::tests::rate_limit_429_zero_retry_after_uses_backoff`** failed once under host load ("first 429 attempt should still run (hits=0)"). It is not feature-gated (workspace `default` = `default-bazel`), so it is a load flake. It is not in P60's list.
7. **fuigo-pager `views::settings_modal::tests::rebuild_rows_drops_voice_settings_when_gate_turns_off`** failed in the full test-support run with "voice_stt_language should be listed with gate on". It passes 3/3 alone, which points to an order dependence on the process-global voice gate. It needs a serial or pinned guard, like P60's `pin_theme` class.
6.
