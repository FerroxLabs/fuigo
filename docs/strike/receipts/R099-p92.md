## What is NOT met / open
- **Sean decides:** dream now drops flagged lines from the live MEMORY.md (the original bytes stay in
  `.memory-recovery/`), including false-positive lines; before P92, dream refused to run at all.
- **Accepted trade-off:** a short all-lower-case word after an unquoted credential name (`password: letmein`) is
  admitted; it reads like `password: hidden`. The old rule (any value longer than 3) was the R4 false positive.
- Heuristic limits remain: homoglyphs (Cyrillic `о`), paraphrases outside the override family, and unbounded rewording.
- Pre-existing flake (not P92, outside ownership): `dream_lock::tests::{exclusion_and_cancellation_preserve_success,
  marker_failure_keeps_retry_open}` fail under load. Prior sightings: `p43g-tip`, `p47rp2-parent` failsets. It also
  failed once on clean dev6 and under unrelated mutants. Likely cause: `flock` via `File::try_lock` is shared with a
  child forked by a concurrent test until exec. Proposal: an OFD lock (`F_OFD_SETLK`) or retry in the test.
- Proposal for P91 (owns `fuigo-shell/src/session/helpers/memory_context.rs`): a flagged session file name reaches the
  injected `File:` field unfiltered (Astra r5 LOW).
- Declined (Astra r1 F7): `ensure_initialized` writes the workspace path into the scaffold without `validate_entry`.
  Reads filter it; validating would stop a strangely named workspace from initializing memory.
- P91 conflict expected in `fuigo-memory` (storage.rs ~816-895, index.rs ~266). P92 did not edit those regions.
  `chunk_source_revision` now hashes the filtered view, because `read_file` filters. Keep both sides on rebase.

`fuigo-secrets` (deps only regex, serde_json and url, so no cycle). It reuses the shared secret detector
(`redact_secrets`). Cargo.lock diff: three dependency edges, no new packages.

## Release notes (user-visible)
- Memory filtering now catches reworded override instructions, spacing and zero-width tricks, and GitHub/AWS/Slack/
  Google tokens, while ordinary notes ("password: min 8 chars", "ignore the flaky test", security writing about
  exfiltration) are kept.
- One rejected line no longer breaks a memory file: new writes are checked on their own, and recall and search skip
  only the rejected lines.
- `/dream` says why it skipped ("session content excluded by the memory content filter", or "existing memory exceeds
  the dream input limit") instead of always "no readable session content".
- Dream consolidates around rejected lines and leaves them out of the rewritten MEMORY.md. The previous version is
  kept in `.memory-recovery/`.
