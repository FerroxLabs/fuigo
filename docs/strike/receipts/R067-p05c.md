## 7. For P11 — musl build id (proposal 1; `.cargo/config.toml` not touched here)
Symbols across restarts need a nonzero binary identity. The glibc links carry `NT_GNU_BUILD_ID` (checked on the test binary); whether the musl release link does is unverified. Without one, release crash reports show `fuigo+0x…` offsets only (`UnverifiedBuild`). Exact proposed diff:
```diff
--- a/.cargo/config.toml
+++ b/.cargo/config.toml
@@ [target.x86_64-unknown-linux-musl]
     # ensure equivalent linker hardening is applied to production binaries.
-    "-C", "link-arg=-Wl,-z,relro,-z,now,-z,noexecstack",
+    "-C", "link-arg=-Wl,-z,relro,-z,now,-z,noexecstack,--build-id",
 ]
@@ [target.aarch64-unknown-linux-musl]
     # ensure equivalent linker hardening is applied to production binaries.
-    "-C", "link-arg=-Wl,-z,relro,-z,now,-z,noexecstack",
+    "-C", "link-arg=-Wl,-z,relro,-z,now,-z,noexecstack,--build-id",
 ]
```
Check on a release artifact: `readelf -n fuigo | grep 'Build ID'` must print an id. If the post-build strip step runs `strip`/`objcopy`, confirm it keeps `.note.gnu.build-id` (plain `strip` does; `--remove-section=.note*` would not).
