## Design (`crates/codegen/fuigo-shell/src/session/storage/jsonl/rewind_reconcile.rs`, module doc has the full rules)

**Rewind side.** Before its durable copy, the rewind now writes a journal `rewind_points.jsonl.pre-rewind.journal`
(atomic, owner-only): the rewrite (`TruncateFrom`/`MergeFrom` + target), SHA-256+length of what `rewind_points.jsonl`
held and of what the rewrite writes, of `chat_history.jsonl` before the rewind (read no-follow), of the conversation it
saves (serialized exactly as the save writes it; a conversation that cannot be serialized refuses the rewind, nothing
changed), the `created_at` of its `RewindMarker` (chosen up front, so that marker and no other is evidence), and the
length of `updates.jsonl`. Order: journal, copy, swap, conversation save (commit), marker, remove copy, remove
journal. The P153 fallback removal and the put-back path remove the journal too.

**Load side.** `load_light` calls `reconcile_interrupted_rewind` **before it reads anything of the session** (r3). Fast
path: no copy and no journal → nothing. Otherwise, holding (all tried, never waited on for long):
the exclusive turn-owner lock (no live actor in any process: else skipped), the rewind's rewrite lock (held → a rewind
is running → skipped; unusable → both kept and told), the `rewind_points.jsonl` append lock, and for a conversation
rewind the `updates.jsonl` append lock (bounded 2 s). Every file is read with `open_beneath_nofollow`. Decision:

| evidence | outcome |
|---|---|
| journal: own marker after `updates_len`, or `chat_history.jsonl` exactly the saved conversation; points = written (+appended) | **finished**: copy and journal removed; the marker appended if missing and nothing moved the conversation after it (prompt, compaction, other rewind) |
| journal: no own marker, chat starts with the pre-rewind bytes, transcript checked and quiet; points = written (+appended) | **undone**: `rewind_points.jsonl` = copy + rows appended after the swap |
| journal: swap never landed (file still starts with the whole copy) and not saved | **undone** with nothing to write (lossless): leftovers removed |
| FilesOnly journal | finished when the swap landed, undone (lossless) when not |
| no journal (1.0.21 copy) | removed only when it equals `rewind_points.jsonl`; else kept |
| anything else (prefix-only match, later activity, transcript unreadable, lock unusable, link/FIFO, changed copy) | **both kept**; session uses `rewind_points.jsonl`; the note names both files and what each holds; rewinds stay refused as before |
| journal without copy | removed silently |

Every outcome reaches the user as a `history_repaired` note (TUI system block), joined with the P96 repair note when
both fire. **P178 / deadlock:** the reconcile never takes the sweep lock; the sweep only *tries* the turn-owner lock and
never takes the rewrite lock; the reconcile only tries or briefly bounds its locks, in the order turn-owner → rewrite →
points append → updates append, the same direction as a rewind (rewrite → appends). No cycle (Astra r1–r3 concur).

## Release-note text (for `docs/release-notes-1.0.22.md`)

**F-line:** **A rewind cut short by a crash is sorted out when the session is opened again.** If Fuigo is killed in the
middle of a rewind, loading or resuming that session now finishes or undoes it, under the rewind's own lock (a rewind
still running in another Fuigo is left alone). If the rewound conversation had not been saved, the saved file history
(`rewind_points.jsonl`) is put back from its safety copy and the conversation is as it was; if it had been saved, the
safety copy is removed and the transcript records the rewind. When Fuigo cannot tell, it keeps both files, uses
`rewind_points.jsonl`, and says which file holds what; rewinds stay refused until one is removed. Each outcome is shown
as a note when the session opens. A safety copy left by 1.0.21 is removed only when it matches `rewind_points.jsonl`.

**K19:** delete its last sentence ("If Fuigo is killed in the middle of a rewind, … (B30)."). The rest of K19 (a
rewrite by a Fuigo older than 1.0.21, or with an unopenable lock file, is not excluded) stays.
