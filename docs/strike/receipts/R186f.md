# R186f: P186 follow-up (three Grok findings on row 197)

Base: integration cd903597. Branch strike/p186-followup. Enforcement (the loaders) is untouched: only the notice and a test seam.

## Changes
1. Lift notice. `fuigo-config` now reports each admin file's class for the notice (`AdminFileClass`: Locked / Valid /
   Other; `admin_policy_states_at`). `admin_source_state` gained a read-only sibling that records whether the file read
   as a valid document; the decision it returns is the same. The watch says "valid again" only for Valid, else
   "Admin policy file <f> changed and is still not valid. The lock-down has ended and the last valid policy is in force
   again." Chosen: after that, becoming valid later gives no second notice (the lock-down already ended).
2. Bounded turn-start read. `AdminPolicyWatch::check(budget)` is async: the read runs in `spawn_blocking`, waited
   200 ms (`TURN_START_BUDGET`). At most one read outstanding per session (a `busy` flag cleared by a drop guard, also on
   panic); while it runs, check returns at once. "Told" is updated only inside a completed read; a late result is shown
   at a later turn. The admin-root override (per thread) is captured on the session thread and re-set on the blocking one.
3. Test seam. Under the `test-seams` feature (non-`cfg(test)`) the process uid stands in for root only while
   `admin_root_override` is set; otherwise root. `cfg(test)` of fuigo-config is unchanged. The existing watch tests now set
   the override (helper `turn`); expectations unchanged.
