## 26-6a: managed policy compromise reason (upstream C#14)
Upstream files read: `xai-grok-config/src/managed_cache.rs` (`ManagedPolicyCompromise`, `compromised_reason`, `marker_compromise`, `managed_policy_compromised_decision` returning `Option`), `managed_policy_trust.rs`, `lib.rs`, `managed_cache/tests.rs`, `xai-grok-cloud-config/src/managed_config/{policy,store}.rs`.
Finding: upstream's user-facing refusal sentence (`MANAGED_POLICY_MISSING_MSG`) is byte-identical to Fuigo's existing one. The upstream change is an internal refactor of the bool into a reason enum; upstream never shows the reason to the user (`ManagedPolicyTrust` has no consumer outside tests). Fuigo has exactly ONE gate on `managed_policy_compromised_for`: the session-start gate `managed_config::managed_policy_gate` (fuigo-shell/src/managed_config/mod.rs), whose refusal reaches the terminal, a headless run (stderr) and an ACP host through `BootstrapError::PolicyRefusal`. There is no per-tool-permission or config-write gate on this predicate, so there are no further refusal paths to cover.
Taken: the `ManagedPolicyCompromise` enum with its four fixed `Display` strings, `Option` returning decision, `marker_compromise`, `compromised_reason` (key change outranks a missing file). Added for Fuigo: `fuigo_config::managed_policy_compromise_for`, and `ManagedPolicyRefusal::Compromised(reason)` which appends `\nReason: <fixed sentence>.` to the existing text.
Fuigo rules: the bool `managed_policy_compromised_for` is kept and now means `.is_some()`; the decision table is unchanged row for row (fail closed stays fail closed, nothing loosened); no network; reason strings carry no path, signature or claim value (the warn logs still print booleans only).
Not taken: `ManagedPolicyTrust` (no consumer), the `Serialize` camelCase derive is kept but unused by callers.
Tests: `compromise_reason_is_named_per_row_and_absent_when_healthy` (fuigo-config; SignatureInvalid, SignatureMissing via claim, PolicyFileMissing, DeploymentKeyChanged, none when healthy/Trusted), `compromised_refusal_names_one_fixed_reason_sentence` and `gate_blocks_only_managed_principal_with_compromised_policy` (fuigo-shell). The existing decision tests run through bool helpers. `identity_body_guard` count for managed_cache/tests.rs 47 to 49 (fixture literals).

## 26-6e: config_write_symlink test (upstream A#30)
Upstream file read: `xai-grok-shell/tests/config_write_symlink.rs`. Upstream expects the user-level writers (settings save, mcp add/remove, import marker) to write THROUGH a symlinked `config.toml` and keep the link; a project link is replaced at the link name.
Fuigo differs: its config writers go through `edit_config_file` / `stage_atomically_keeping_mode` / `stage_atomically_from_existing`, which REPLACE a symlink at the path (documented in fuigo-config/src/fs_atomic.rs "Replaces a symlink at `final_path`" and fuigo-shell/src/util/config/persist.rs "replaces a symlink at `path`"), keeping the 0600 posture. Behaviour not changed.
Ported test: `fuigo-shell/tests/config_write_symlink.rs` pins Fuigo's behaviour: for the user file (settings save, mcp add, mcp remove, import marker) the link is replaced by a regular file holding the edit plus the keys read through the link, and the link target is never written; the project-link case matches upstream. `#[cfg(unix)]`.
