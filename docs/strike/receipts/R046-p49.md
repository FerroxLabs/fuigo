## 0. Read first: what is NOT met or not verified

1. **macOS and Windows code is compile- and clippy-checked only.** `fuigo-config/src/fs_atomic.rs`
   and `fuigo-config/src/write_through.rs` pass `cargo clippy` for `x86_64-pc-windows-msvc` and
   `aarch64-apple-darwin` (with and without `test-seams`) in a scratch crate (§4.6). Nothing ran
   on either OS. New on macOS: extended-attribute carry-over via `fcopyfile(COPYFILE_XATTR)` and
   the "no staging directory for a new ordinary file" rule. New on Windows: `edit_locked` makes no
   optimistic pass (fully locked, fsync inside the lock, as before P49).
2. **Cross-process fairness is not FIFO.** In-process waiters are strictly FIFO. Between
   processes, a waiter blocks in the kernel and is woken on every release, but Linux does not hand
   the `flock` to the oldest waiter. No test can show the wake-on-release property
   deterministically; it is covered by liveness tests only (§3).
3. **Loaded-run discrimination is partial.** Under the same load, the lost-update test without
   the retry passes 60/60 at the tip. At the PARENT, with only the retry removed, it fails 1/30
   with exactly the old starvation `TimedOut` (§4.4). With only the lock reverted to the pre-P49
   poll (mutant M1, rest of the tip) it passes 30/30. The tip's writer holds the lock for much
   less time (fsync outside), so the poll's starvation does not show there. The FIFO property is
   proven by unit tests and mutants (§4.3).
4. **Item 3 (one shared replace helper) is partial, by decision** (§1.3): the commit protocol and
   the write-through replacement are shared; the remaining writers are unchanged.
5. **Accepted LOWs from the final audit:** a temp staged inside a directory that another lock
   holder moves away and back is left in the moved directory; the macOS xattr copy has no
   discriminating test (no macOS host).
6. **Tests run as root** on the build host, so permission-refusal paths that depend on a non-root
   user (read-only target, `chown` failure) are exercised through fault seams, not real EACCES.

## 1. The change

### 1.1 Item 1 — fair config lock, fsync outside it (`fuigo-config/src/fs_atomic.rs`)

**Lock (`lock_config_for_write`, same signature, same 2 s cap).** Two stages share one deadline:

1. **In-process FIFO turn** (`mod turn`). A ticket queue per lock file (keyed by the resolved
   lock path). A holder that releases and re-requests goes to the back. A waiter that times out
   leaves an abandoned ticket that is skipped. An idle queue is removed.
2. **Cross-process `flock`, blocking.** Only the turn holder asks. On contention it waits on a
   helper thread that blocks in `flock(LOCK_EX)`; there is **at most one helper per lock file**,
   reused by later turns. A grant that arrives when nobody waits is dropped at once, before the
   queue can be seen idle.

**`edit_locked` (new)** — the read-modify-write driver used by the migrated writers:

- **Optimistic pass**, only on unix, only for a path with no symlink in any component (checked
  every pass and again under the lock). It snapshots the file (bytes and inode identity, through
  one handle, plus the full link chain), runs `edit` on **exactly those bytes**, then stages the
  temp (written and `fsync`ed) **with no lock held**. It then takes the lock and commits (rename +
  directory `fsync`) only if all of these hold: the staged target is the edited path, what staging
  saw at the path (`StagedReplacement::source`) is the file `edit` was given, and the snapshot is
  unchanged.
- **Locked pass** after two overtaken passes, for unreadable files, for paths through links, and
  always on Windows. It is the pre-P49 behaviour: read, edit, stage and commit, all under the lock.
- `StagedReplacement` (new): a staged temp whose commit does only the lock-side work. It takes an
  optional `finish` hook run at commit, under the lock. It has an in-place variant
  (`written_in_place_at_commit`) for devices and FIFOs.
- `stage_atomically` / `stage_atomically_from_existing` (new). `write_atomically` = stage + rename,
  with unchanged behaviour (still no directory fsync).

**Test-side retry removed.** P17-F1's retry-on-`TimedOut` in
`config::atomic_write::tests::concurrent_writers_do_not_lose_updates` is gone (§4.4).

### 1.2 Item 2 — pager config writers off the input thread (`fuigo-pager`)

- The CTA `[x]` dismissal, the agents-modal `s`/`t` and `/provider` now return Actions. Each
  becomes an Effect, and the effect runs the write on **one ordered worker**
  (`config_write_queue`): writes run one at a time, in the order the user made them.
- Agents modal: a write carries a ticket. While a write is in flight, `s`/`t` are refused
  ("Still saving…"). Only the modal waiting for that ticket, or an idle (reopened) modal, applies
  the result, and it re-reads both the agent list and the default.
- Each deferred write resolves its `config.toml` to an absolute path when it is accepted, so a
  relative `FUIGO_HOME` cannot follow a later `/cd`.
- A failure stays pending until the code that shows it acknowledges it. At exit the pager drains
  the queue (bounded 3 s) and prints unacknowledged failures after restoring the terminal.

### 1.3 Item 3 — shared replace helper: what is shared, what is not

- **Shared:** the commit protocol (`StagedReplacement` and `edit_locked`, in `fuigo-config`).
- **Shared:** the shell's write-through replacement, **moved** from `fuigo-shell/src/config/atomic_write.rs`
  to `fuigo-config/src/write_through.rs`. It keeps symlink write-through, owner/mode/xattr/ACL
  preservation, Windows DACL and the macOS staging directory. The shell now re-exports it.
  Test seams sit behind feature `test-seams`, enabled only from `[dev-dependencies]`.
- **Migrated to `edit_locked`:** shell plugin-list writers (`edit_config_string_list`, 7 writers);
  `remove_hooks_path_from_file`; pager `set_hint_at`, `write_provider_at`, agents-modal
  `edit_config_at`.
- **Not migrated (reason):** these still take the (now fair) lock with fsync inside it:
  - `persist::update_config` and the five MCP writers: async, holding the process-local
    `SAVE_LOCK` in a fixed order;
  - marketplace ×3, `claude_import` ×2, pager `plugin_cmd` ×2, ACP connect and dashboard persist:
    rare paths whose bodies have side effects.

  The **replace semantics** were not unified either. `fs_atomic::write_atomically` replaces
  symlinks and masks the mode to `0o700`; `persist::atomic_write_string` keeps the exact mode;
  `write_through` writes through and keeps ACLs. Unifying them changes behaviour for existing
  callers (P17-F1c).
- **Write-through on unix (changed in P49):**
  - the temp stays `0600` and carries no metadata until its commit;
  - at commit, under the lock, it re-probes the target and applies that file's ACL, owner, xattrs
    and mode, through the temp's creation descriptor;
  - if the owner/group cannot be kept, the write is **refused** (`PermissionDenied`);
  - a non-regular target is written in place by the commit;
  - temp names carry at most 64 bytes of the target's name.

### 1.4 Item 4 — `worktree::apply_file_content` atomic (`fuigo-workspace`)

Uses `write_through::replace_file_contents(.., NewFileMode::Default)`:

- the whole old file or the whole new one, never a truncated one;
- mode/owner/ACLs kept, symlinks written through (dangling too), and a read-only file refused;
- a new file gets `0o666 & !umask`, as `tokio::fs::write` gave it;
- a device behind a symlink is written in place, not replaced.

Runs on the blocking pool.

### 1.5 Item 5 — loader stable-read for a blank user layer (`fuigo-config/src/loader.rs`)

Only `load_user_config_layer` (user `config.toml` and `managed_config.toml`) is affected. A blank
read is re-read after 15 ms:

- now non-blank: that content is used;
- blank with unchanged identity: accepted (a deliberate reset);
- blank but changing on every one of 3 re-reads: **`ResourceBusy`** rather than "no settings";
- deleted: empty, as before.

Other TOML reads are unchanged.
