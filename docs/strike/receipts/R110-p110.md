## User-visible changes (release notes)

- Memory: if an older Fuigo wrote notes under a repository's old memory folder after 1.0.21 moved it, Fuigo now says so
  once, naming both folders, and leaves both untouched so the notes can be moved by hand.
- gh-release installs: updates are downloaded to a temporary file and checked against the release's SHA256SUMS before
  replacing the installed binary, so an interrupted or corrupt download no longer breaks `fuigo`.
- gh-release installs: "latest" is now the highest released version, and automatic updates never move to a lower
  version; `fuigo update --version X` or `--force` can still downgrade (a release removed after shipping no longer rolls
  gh-release clients back automatically).

## Proposals (outside this packet)

1. `fuigo memory clear` (fuigo-pager `memory_cmd.rs`) should list a stranded legacy folder as "not cleared, from an older
   version" so the user is not told memory is gone while notes remain. Needs a fuigo-pager gate, so not done here.
2. Leader/client version handshake (fuigo-shell `leader/mod.rs`, fuigo-pager-bin `main.rs` ~2880): an explicit
   gh-release (or internal) downgrade leaves a newer leader running; relaunching it down loops (Astra r2 #1). Needs a
   pager-side design.
3. release.yml's "not the newest release" warning should fail the job (audit follow-up 2), and the release notes should
   say: do not run 1.0.20 on the same `~/.fuigo` after upgrading.
