## Test interference

- **Mechanism (confirmed).** The park table is process-wide, keyed by session id: `session/quiesce.rs:145` (`Inner.parked`), `:167` (`REGISTRY`). Gates reading it: `is_self_quiesced` (`:488`) at `notification_drain.rs:124`, `:509`, `laziness.rs:296`, `agent/park_hold.rs:167`; `is_parked` (`:513`) / `wait_model_allowed` (`:543`) at `reverse_ticket.rs:61`, `park_hold.rs:173,313`. `SessionGuard::drop` (`quiesce.rs:627`) removes the entry for its id; `run_session` creates one per actor (`run_loop.rs:347`). Every actor from `create_test_actor*` has the id `test-actor` (`acp_session_tests/support.rs:277,313`). `a_queued_kill_is_dropped_once_its_park_is_withdrawn` was the only park test using that id (the other park tests, `park_hold_tests`, `p189_park_round3_tests` and the compaction park tests already use unique ids): while it held `test-actor` parked, any unrelated test actor saw `is_self_quiesced` true (turn start, drain and peer wake gated: the `peer_admit` and `parent_message` failures), and any other `run_session` test exiting dropped its guard and wiped the kill test's park (its own flake).
- **Red.** New test `parking_one_test_actor_leaves_an_unrelated_test_actor_alone`, with the unique-id line removed: `park_tests.rs:257: a park on test-actor quiesced an unrelated test actor (test-actor)`.
- **Fix (test side only).** `run_loop_actor` helper gives the `run_session` kill test a unique `p189-actor-<uuid>` id; `UnparkOnDrop` clears its park on any exit. No product code changed.
- **Proof (tip fc33e3bd).** Full `cargo test --locked -p fuigo-shell --lib` x12: 12/12 `ok. 8440 passed; 0 failed; 10 ignored` (the known env-dependent credentials test did not fail either). `... --lib park` x20: 20/20 `ok. 70 passed; 0 failed`. `fuigo-extra-ca` and `fuigo-auth --test secret_debug_guard` pass; clippy shows no warning in `park_tests.rs` (existing warnings elsewhere untouched).
- **Real sessions.** A park keyed on the root session id is deliberate: a park covers the whole subagent tree (`quiesce.rs:187` `effective_phase` walks `parents`; `:606` doc; subagents have their own ids linked to the root by `SessionGuard::new(id, parent)`). Production ids are fresh UUIDs (`acp_agent.rs:1226`), and a `session/load` of an id is the same session by definition (`acp_agent.rs:1025-1031` handles a parked load explicitly). No way for two different real sessions to collide, so no product bug.
