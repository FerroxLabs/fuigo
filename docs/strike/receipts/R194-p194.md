## User-visible changes (release-note text)
1. U12 (fix, no visible change): hook runs no longer leave a tracing span entered on a worker thread while they wait, which
   could mis-attribute log lines of other work to a hook. Before: spans held across `await`. After: spans attached to the future.
2. U13 (behaviour change, truncation): the per-turn session archive now keeps at most 1 MiB of each terminal log and each MCP
   stderr log (first 512 KiB and last 512 KiB around a `[... trimmed for the session archive ...]` marker), and at most
   16 MiB of terminal logs per archive, newest first (older logs beyond that are left out). Before: whole logs, however
   large, were copied at every turn end. A user restoring or reading an archived session sees trimmed or missing old logs; the
   live files under `~/.fuigo` are untouched. Symlinks in `terminal/` are still never followed.
3. U15 (behaviour change, model request): compaction now sends the session's `reasoning_effort` (Chat Completions, Responses,
   Messages); unset stays unset. Before: compaction requests omitted it and ran at the provider default. After: same effort
   as the turns, which matches the prompt-cache prefix and can change compaction cost, latency and summary quality.
4. U15 (visible in model input): an MCP tool result whose text already contains its `structuredContent` JSON is no longer
   followed by a second copy. Before: the JSON was sent twice. After: once (fewer tokens). A structured payload not
   present in the text is still sent.
5. U16 (new wire message): when a turn drops an MCP tool call, or a call times out, Fuigo sends `notifications/cancelled`
   (reason "client cancelled", with the request id) to the server; the notification write is bounded to 3 s. Before: the
   server was never told and kept working. A server that ignores the notification sees no other change. Timeouts are still
   reported as timeouts, now once.
6. U16 (hub): computer-use/hub tool results keep their `_meta` (for example the target app name and bundle id) for hub
   clients; the model never sees it. Before: `_meta` was dropped.

### U16 change
`call_tool_cancel_aware` (`fuigo-mcp/src/servers.rs`) now sends the request with no rmcp options and races
`handle.await_response()` against `tokio::time::timeout` itself. On the deadline it returns `ServiceError::Timeout`
at once, whatever the server does. The cancel (`notifications/cancelled`, reason `request timeout`) goes out from the
spawned `CancelOnDrop` task, bounded by `CANCEL_NOTIFY_TIMEOUT` (3 s). The guard is consumed in the same step that
returns the error, with no await in between, so a later drop cannot add a second note: one cancel per abandoned id.
A completed call still disarms the guard first (no cancel).

1(c), rmcp finding: rmcp 3.2.0 cannot abort an in-flight notification write. `Peer::send_notification`
(`service.rs:829-840`) waits on a oneshot ack; the serve loop spawns `transport.send(...)` into a private
`send_task_set` JoinSet (`service.rs:1527-1533`) with no handle returned, and dropping the waiter or the responder does
not cancel that task. The mutex is held inside the transport's `send` future. Fuigo owns the stdio transport
(`ResilientRwTransport`), so the bound is placed there: a `notifications/cancelled` write that does not finish within
`CANCEL_NOTIFY_TIMEOUT` is dropped (releasing the mutex), the connection is marked broken and its writer is closed (the
server sees EOF), and every later send fails at once with `BrokenPipe`. Choice: mark the connection broken and close
the writer. Stdio has no restorable transport (`reset_transport` is `false`), so the server stays unavailable until it
is restarted; a server that stopped reading its stdin needs that anyway. Later calls fail fast instead of queueing.

### Known limits (round 2)
- A request that wins the transport mutex before the timeout cancel and then stalls is an unbounded write, as on
  integration; only cancel writes are bounded. A second call issued within microseconds of a timeout can therefore
  still wait on a dead-stdin server.
- After the bound fires, the stdio connection stays closed until the server is restarted.
- The race-the-deadline path skips rmcp's progress-watcher cleanup on timeout (only used with progress tokens).
- A cut at a char boundary applies when each piece is valid UTF-8; a log that is invalid elsewhere is cut at bytes.

### Release-note text
A tool call that times out now always returns at its deadline, even if the MCP server has stopped reading input; the
cancel notice is sent in the background and a server that does not take it within 3 seconds is disconnected. Session
archives no longer lose a log that is rotated while the archive is built, keep UTF-8 text intact at the trim, and no
longer follow links or wait on pipes among MCP server logs.
