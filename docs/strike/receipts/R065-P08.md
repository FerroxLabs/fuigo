## What changed
- **Wire (Contract E.2, additive in `fuigo/*`):** `authenticate {methodId:"fuigo.api_key", _meta:{"fuigo/apiKey":{key?, persist?}}}`.
  The channel is advertised as `agentCapabilities._meta["fuigo/capabilities"].authenticateApiKey = {"metaKey":"fuigo/apiKey","persistOptIn":true}`.
  `authMethods` is unchanged: it is still empty for a credential-less start (E.3). A reply to a request that carried the
  carrier is `{"_meta":{"fuigo/apiKey":{"persisted":bool}}}`. Murage's plain `authenticate` still gets exactly `{}`.
- **Store** (`agent/auth_method.rs`): `RUNTIME_API_KEY` is held in process memory. It is never written to the environment.
  `read_fuigo_api_key_env()` reads it ahead of `FUIGO_API_KEY`, so every env-key consumer treats it as an env key that is not
  in the environment: inference credentials, the AuthManager static key, the advert predicates and ModelFetchAuth.
  With no runtime key the read is byte-for-byte the old env read (E.2).
  - `read_named_key_env` covers a model `env_key = "FUIGO_API_KEY"` mapping.
  - The sampler's `env_http_headers` resolve through an installable resolver (`fuigo-sampler`).
- **Persistence is opt-in.** `store_api_key` runs only on `persist:true`, and this applies to the env key too.
- **Errors.** A malformed carrier gets a fixed-text `-32602` that never quotes the request. The no-key `-32000 "Authentication required"`
  keeps its message. Its `data.message` is now addressed to the client and names `_meta["fuigo/apiKey"]`, plus
  `data.metaKey`. This is the same typed shape as `auth_flow_error`.
- **Readers / clear:** `fuigo/getApiKey` returns only the environment key. `fuigo/auth/getBearerToken` filters the runtime key
  on every branch. `fuigo/setApiKey` clears the runtime key only after its write succeeds, and then:
  - drops the agent's `sampling_config` copy;
  - re-derives the AuthManager process static key.
- **Catalog.** A runtime-key `authenticate` calls `models_manager.on_auth_changed()`.
- **Logging hardening** (raised by Astra; applies to env keys too):
  - `fuigo-telemetry` `install_firehose` installs a registry-level `Targets` filter. It drops `agent_client_protocol::rpc` at
    every level, because the SDK logs raw client lines (trace) and malformed ones (error).
  - The `session/new` debug dump of the sampler config is removed. Its derived `Debug` printed `api_key`.
  - The sampler's `sampling_log` now logs fixed labels, never key prefixes or suffixes.
- **Not zeroized:** the sampler and session credentials hold ordinary `String` clones, so the key is not zeroized. "Session
  scope" here means the ACP connection or process. It is process-global like `FUIGO_API_KEY`, so in leader mode every
  attached client shares it.
- **Files outside the brief's ownership** (all needed for the store to be correct): `extensions/auth.rs`, `agent/config.rs`
  (one line), `agent/mvp_agent/session_setup.rs` (one log line), `fuigo-sampler/src/{client,sampling_log}.rs`,
  `fuigo-telemetry/src/debug_log.rs`. `shell_env_policy.rs` is untouched (§3).

**Release note (behaviour change):** "`authenticate` with `fuigo.api_key` no longer writes the key it used to `~/.fuigo/auth.json`.
To keep the old behaviour, send `_meta: {"fuigo/apiKey": {"persist": true}}`. `fuigo/setApiKey` still persists as before.
Embedders can now pass the key in `authenticate` instead of the agent's environment. Fuigo still honours `FUIGO_API_KEY`
when you inject it. Debug logs no longer include raw ACP messages from the SDK's `agent_client_protocol::rpc` target."

## Residuals and non-claims
- A key replaced by a later `authenticate` does not reach sessions spawned before it: they keep the credential copied at
  spawn, exactly as with an env key. Subagents and model switches re-resolve.
- The catalog `on_auth_changed()` path has no end-to-end test (MEDIUM, accepted).
- No claim that Murage adopts the channel (P00 must ask), that `auth.json`'s format changed, or that subscription auth is
  addressed. Nothing here protects against a local attacker who can read process memory.

## Proposals (not fixed here)
1. **rp.sh:** run the tip half in a fresh target, or `cargo build -p fuigo-pager-bin` before the tip tests. Otherwise every
   binary-driven integration test (`murage_conformance_acp`, the other `*_acp.rs`) silently tests the parent binary.
   `fuigo_binary()` should also rebuild when stale.
2. `auth/attribution.rs` (≈274/292/388) logs the last 12 characters of a credential that got a 401, to the unified log and
   tracing. Short keys leak whole. This predates P08 and applies equally to env keys. (Astra LOW.)
3. `SamplerConfig` derives `Debug` including `api_key` and `extra_headers`. P08 removed the one dump, but a redacting
   `Debug` impl in fuigo-sampler would stop the next one.
4. `initialize` still copies a persisted `auth.json` key into the process environment (`acp_agent.rs` `set_var("FUIGO_API_KEY")`).
   It could use the runtime store instead.
