# R189 — P189: ACP session park / quiesce (`_fuigo/session/park`, `_fuigo/session/unpark`)

Branch `strike/p189`, base / rp parent `6221893ca0ab30b611b1e46305a8a791a859e37b`. Red tests `3cf2af24f`, fix
`adf070e8d`; later commits are listed under "Commits". For Murage, which keeps one Fuigo process warm between user
messages (evidence: `muragemobile/FUIGO-LIVE-EVIDENCE.md`). Murage does NOT SIGSTOP Fuigo today and does not call
park on any OS; its ACP pool keeps the idle process and closes it on idle (verified by the Murage maintainers on
Murage 1.0.0). The park is requested for Murage's warm pool.

## The problem (1.0.21)
After `end_turn`, background commands (`run_terminal_command background:true`), background subagents, monitors and the
scheduler keep running for up to 60 s. When they finish, Fuigo starts a NEW turn on its own (a `<system-reminder>` /
`<monitor-event>` wake), calls the model again, and sends `session/update`, `_fuigo/session_notification`
(`task_completed`, `monitor_event`, `subagent_*`, `last_turn_summary`, `session_summary_generated`) and
`session_info_update` frames. Murage's idle driver closes a pooled process on any such frame, so the warm process is
never reused. Red test `background_work_finishing_after_end_turn_starts_a_self_started_model_call` reproduces it
against the real binary.

## Wire spec (for Murage)

Method names on the wire carry ACP's leading underscore. Both are JSON-RPC requests to the agent. Murage's use
(reviewed by MurageMobile): after `end_turn` `park`, with a `mode` taken from the advertised `modes` for the running
OS (Murage reads them per platform); never a bare `unpark`; the next `session/prompt` unparks implicitly.

`modes` is per OS: `["hold","stop"]` on Linux, `["hold"]` on Windows and macOS (the JSON below shows Linux). A mode
not advertised for the running OS is refused with -32602.

### Capability (in `initialize`)
`result.agentCapabilities._meta["fuigo/capabilities"].sessionPark`:
```json
{
  "version": 1,
  "methods": ["_fuigo/session/park", "_fuigo/session/unpark"],
  "modes": ["hold", "stop"],
  "defaultMode": "hold",
  "defaultTimeoutMs": 30000,
  "maxTimeoutMs": 600000,
  "errorCode": -32010,
  "promptWhileParked": "implicitUnpark",
  "loadWhileParked": "staysParked",
  "loadReplyMcpReady": true,
  "releasedMetaKey": "fuigo/released",
  "unparkedUpdate": "unparked"
}
```

`implicitUnpark` applies to prompts the client sends on its own behalf only. A scheduled-task fire never un-parks: it is folded into the next prompt. (Owner decision 45, 2026-10-11. A `session/prompt` whose `promptId` starts with `scheduler-fired-`, verified or not, gets a normal `end_turn` reply, starts no turn and makes no model call while the session has a park entry.)
`_meta["fuigo/capabilities"]` is the ONE shared capability object (it already carries `toolOverrides` and
`authenticateApiKey`). Shape rule for every entry, which P190's interject/queue flags must follow: one camelCase key
per capability, value an object with an integer `version` (bumped on any breaking change) plus the facts a client
needs before calling. Absent key = unsupported. P190 adds its keys to `fuigo_capabilities()` in
`fuigo-shell/src/agent/mvp_agent/acp_agent.rs`, next to `sessionPark`.

### `_fuigo/session/park`
Params:
```json
{ "sessionId": "<id>", "mode": "hold" | "stop", "timeoutMs": 30000 }
```
- `mode` optional, default `"hold"`. `timeoutMs` optional, default 30000, clamped to 1..600000.
- `stop`: kills every running background command and monitor of the session, cancels its running subagents
  (and closes subagent spawns until unpark), closes the tool spawn gate for the session and its subagents, then
  finds every process the session's tools started and kills it, including process-group and `setsid`
  descendants and ones re-parented away from their command. Each is confirmed dead (gone, or a zombie) before the
  reply. If any cannot be confirmed dead within 5 s, park fails with `reason: "stop_incomplete"` and the session is
  left unparked. Only the parked session's lineage (it and its subagent sessions) is swept: other sessions in the
  same process keep their tools. Per-OS mechanism and guarantee: see "STOP guarantee per OS" below. (Tool-env
  markers, not wire: every agent terminal child carries `FUIGO_AGENT_TOKEN=<random per Fuigo process>`,
  `FUIGO_AGENT_SESSION=<owning session>` and, under a nested Fuigo, `FUIGO_AGENT_OUTER`.)
- `hold`: background commands and monitors already running keep running to completion; their completion events are
  held and the wake turns they would start are deferred. Background subagents keep running until their next model
  call, where they wait.
- Both modes: no timer fires while parked. A `scheduler_create` task (or any scheduler fire) that comes due waits;
  with no prompt it waits forever. Workflow completions are queued wakes (deferred like the others).

The reply is sent only once the session is idle: if a turn is running, park waits (up to `timeoutMs`) for it to end;
from the moment park arrives no self-started turn may begin. Success:
```json
{
  "parked": true,
  "sessionId": "<id>",
  "mode": "stop",
  "alreadyParked": false,
  "deferred": { "queuedInputs": 2, "pendingNotifications": 1, "turnSummary": true, "titleRefresh": false },
  "running": { "backgroundTasks": 0 },
  "stopped": { "backgroundTasks": 1 }
}
```
- `deferred.queuedInputs`: queued wake turns (task / subagent / workflow completions) and queued prompts held by the
  park. `pendingNotifications`: monitor events and completions the idle drain would have turned into a turn.
  `turnSummary` / `titleRefresh`: the post-turn summary (`last_turn_summary`) or title refresh was aborted (or never
  started) and will run at unpark.
- `running.backgroundTasks`: background commands/monitors still running (always 0 after `stop`);
  `stopped.backgroundTasks`: how many background tasks `stop` killed.
- Parking an already parked session is idempotent: same shape with `"alreadyParked": true`, the current
  `deferred` counts, and the `running.backgroundTasks` count recorded when the park was acknowledged.

**Guarantee:** after the park reply, Fuigo writes nothing on that connection for the parked session (or its
subagents), and nothing process-wide, except replies to the client's own requests, until unpark or a prompt. That
covers `session/update`, every `_fuigo/*` notification (`last_turn_summary`, `session_summary_generated`,
`task_completed`, `monitor_event`, `subagent_*`, `scheduled_task_*`, announcements) and agent-to-client requests
(`session/request_permission`, `_fuigo/ask_user_question`, fs/terminal requests): requests stay unsent and the tool
or subagent that asked blocks. No model call starts in the session or its subagents. A model request already in
flight when park arrived completes; its frames are held.

Clean-park latency (nothing running), real binary on Hetzner, 3 runs (`clean_park_is_fast`, `P189-CLEAN-PARK-MS`):
`hold` 1 / 1 / 1 ms, `stop` 35 / 25 / 41 ms. Murage's planned 5 s bound has a wide margin.

Errors:
- `-32602` (`invalid_params`, `data.error_kind: "invalid_request"`): unknown `sessionId`, unknown `mode`, bad params.
- `-32010` `"Session park failed"`, typed `data`:
  `{"message", "error_kind": "session_unavailable", "reason", "sessionId", "timeoutMs"}`, `reason` one of
  - `"timeout"`: the running turn did not end within `timeoutMs`, or a step of the park did not answer within its
    bound (each step <= 5 s and <= `timeoutMs` + 5 s in total; e.g. the session's scheduler did not acknowledge
    its pause). Left UNPARKED; it resumes normally. Murage closes the process (per-turn path).
  - `"stop_incomplete"`: `mode: "stop"` could not confirm every tool process dead. Left UNPARKED. Close the process.
  - `"park_in_progress"`: another park of this session has not replied yet (it is waiting for its turn to end or
    still sweeping), or a prompt's implicit unpark is in progress.
  - `"withdrawn"`: an unpark or a `session/prompt` arrived before the park completed. Not parked.
  - `"session_closed"`: the session actor went away.

### Released frames and the `unparked` marker (both unpark paths)
- Every frame written because of an unpark (held notifications and, on explicit unpark, held requests) carries
  `_meta["fuigo/released"]: true`: in `params._meta` for `session/update`, `_fuigo/*` notifications and ext requests,
  in `params._meta` of `session/request_permission`. They are frames of the turn before the park.
- After the released frames, exactly one marker notification is written:
  ```json
  {"jsonrpc":"2.0","method":"_fuigo/session_notification",
   "params":{"sessionId":"<id>","update":{"sessionUpdate":"unparked","released":{"frames":7,"droppedFrames":0}}}}
  ```
  It is always written at unpark (also with `frames: 0`), before the unpark reply (explicit) or before the first
  frame of the prompt's turn (implicit).

### `session/prompt` on a parked session (Murage's path)
Implicit unpark, then the prompt runs normally (no error). In order: held requests of the old turn
(`session/request_permission`, `_fuigo/ask_user_question`, fs/terminal) are answered cancelled to their askers
(permission: outcome `cancelled`; others: error) and are never sent; held frames are written, marked released; the
`unparked` marker; then the prompt's turn. Queued completion wakes do not run ahead of the prompt: their completions
are delivered into the user's turn as `<system-reminder>`s. Scheduler fires that came due while parked are folded
the same way: one reminder ("While the session was parked, N scheduled task(s) came due. They were not run...",
listing task_id, schedule and prompt), and each such recurring task's next run is one interval from now (a
one-shot, durable or not, is removed). The fold is two-phase: a task is advanced only once the reminder that
names it has been queued for the prompt's turn; if that fails, nothing is advanced and the fire runs as usual. The previous turn's owed summary is dropped; an owed title refresh still runs. A
park still waiting when the prompt arrives fails with `reason: "withdrawn"`.

### `_fuigo/session/unpark` (explicit; Murage does not use it)
Params `{ "sessionId": "<id>" }`. Reply:
```json
{ "resumed": true, "sessionId": "<id>", "wasParked": true, "released": { "frames": 7, "droppedFrames": 0 } }
```
- Held frames (marked) and the `unparked` marker are written BEFORE this reply. Held requests are sent after the
  marker, marked released. Then the deferred work runs in order: queued wake turns, the idle drain of held notifications, the owed
  turn summary / title refresh; due scheduler fires fire as usual.
- `droppedFrames`: frames beyond the hold cap (50,000) that were discarded; 0 in practice.
- Not parked: no-op, `"wasParked": false`, no marker. Unknown `sessionId`: `-32602`.

### `session/load` on a parked session
Allowed; it does NOT unpark (the implicit unpark happens only at `session/prompt`). It may replace and reconnect the
session's MCP servers (fresh per-turn tokens). Written: only the load reply and, with `noReplay: false`, the replayed
history frames, which answer the client's own request and carry `_meta.isReplay: true` (not marked released). Nothing
else: no held frame is released, no notification (no `_fuigo/mcp_initialized`, `servers_updated`,
`available_commands_update`; they stay held and are released, marked, at the next prompt), no wake turn, no model
call. Because the MCP-ready notification may not be written, a parked load's reply is sent only once every
configured MCP server AND every in-process SDK server (`_meta["fuigo/mcp/servers"]`) is ready or failed (each bounded by its own startup timeout, 30 s default; an outer 35 s cap
reports any still pending as `timeout`) and carries:
```json
{ "_meta": { "fuigo/mcpReady": { "servers": [ { "name": "good", "status": "ready" }, { "name": "bad", "status": "failed" } ] } } }
```
During the load's window the SDK servers' reconnect exchanges reverse `fuigo/mcp/sdk_call` requests with the client
(they answer the client's own request and go out unmarked). A reverse `sdk_call` created before the window began, or
outside it, stays held until the unpark and then goes out with `params._meta["fuigo/released"] = true`.
`status` is `"ready" | "failed" | "timeout"` (`failed` includes a server waiting on auth or setup). Unparked sessions
keep today's behaviour (reply, then `_fuigo/mcp_initialized`), without the field. Advertised as
`sessionPark.loadReplyMcpReady: true` (and `loadWhileParked: "staysParked"`).

### Other notes
- The park belongs to the session: a session that closes while parked is forgotten.
- Process-wide frames are held only on the connection that parked; session-scoped frames are held on every
  connection (leader mode).
- `session/cancel` on a parked session is a no-op (no turn runs).
- Residuals (also in the K line): see "STOP guarantee per OS".

## Murage driver change (for reference)
After `session/prompt` returns `end_turn`, send `_fuigo/session/park {sessionId, mode:"stop"}` and treat the process
as parked only once the reply arrives (bound it, e.g. 5 s; on timeout or a `-32010` error close the process). With
the guarantee above, `idleLine` needs no `TRAILING_FRAME_UPDATES` allowance after the park reply. For the next message
send `session/prompt`; frames with `_meta["fuigo/released"]` up to the `unparked` marker belong to the previous turn.

## Design (code)
- `fuigo-shell/src/session/quiesce.rs` (new): process-wide park registry keyed by session id, with phases `Parking`
  (waiting for the running turn) and `Parked` (acknowledged), the work a park owes the session, and parent links of
  subagent actors (`SessionGuard`, registered at the top of `run_session` and dropped on actor exit) so a parked root
  quiesces its subagent tree. `wait_model_allowed` blocks while the session or an ancestor is `Parked`.
- Gates (all read the registry, no actor round trip):
  - `maybe_start_running_task`, `maybe_drain_notifications`, `maybe_fire_laziness_check`: return while the session
    itself is parking/parked. Subagents of a parked root are still admitted (their spawner's 30 s admission wait must
    not time out), then wait at their first model call.
  - `prepare_chat_completion` (every side call: turn summary, title refresh, recap, compaction, memory, goal,
    laziness) and `submit_turn_request` (every turn model request): `wait_model_allowed`.
  - Persistence-level first-title task (`summary.rs`): `wait_model_allowed` before its model call.
  - `restart_turn_summary` / `maybe_refresh_title`: while parking/parked, record the work as owed instead of starting.
- Session actor (`acp_session_impl/park.rs`, `SessionCommand::Quiesce` / `QuiesceRelease`): the probe aborts a
  running summary/title refresh and owes it, cancels subagents for `stop`, and reports counts; release reopens spawns
  (`stop`), re-runs owed work, then promotes the queue and drains notifications (`kick`).
- Frame hold (`fuigo-shell/src/agent/park_hold.rs`): `ParkHoldClient` wraps the connection's `acp::Client` at every
  production gateway receiver (`app.rs` x3, `server.rs`, `leader/in_process.rs`). Notifications for a parked session
  (or process-wide ones while this connection parked a session) are queued; requests wait; any frame let through first
  writes the queued frames that are no longer held, so order is kept. Single-threaded: the check and the
  connection's enqueue have no yielding await between them, and the park reply is enqueued after the hold is armed, so
  no frame can follow the reply.
- Ext handlers `fuigo-shell/src/extensions/session_park.rs`; dispatch in `acp_agent.rs`; implicit unpark at the top
  of `prompt` after the session handle resolves.

## Round 4 (mechanisms; Astra r3)
Round 3 guarded call sites; Astra r3 found the guards leaky. Round 4 replaces them with five mechanisms. Four packages
(A registry, B operation identity, C dispatch gate, D reverse-MCP ticket) were built in parallel and merged D, C, A, B.

- **M1 ownership registry (A).** `fuigo-tools/src/util/tool_registry.rs`: a process-wide registry of every tool process
  (pid + start time -> owner, root flag; registered pgid/sid -> owner), filled right after `spawn()` under the spawn
  read guard at the three `terminal.rs` sites. `tool_reaper` attributes a process by (1) its own entry, (2) its nearest
  registered ancestor, (3) a registered pgid/sid inside Fuigo's tree, else (4) unowned; adoption of descendants is a
  derived upsert on every scan and orphan-reaper pass. A marked but unattributable process fails the stop
  (`stop_incomplete`) and is never signalled; `kill_verified` re-verifies start time and registry entry (pidfd on
  Linux). Replaces `TOOL_CHILDREN`, `ORPHANS`, `note_orphan` and the marker-based selection. In stop mode the park
  runs one `orphan_reaper::pass` before killing tasks so late grandchildren are observed.
- **M2 operation identity (B).** Every park carries a `ParkOp`; side effects (task kills, stop probes, owed-work records,
  scheduler pause/resume, title/summary aborts) run through `run_if_current` / `with_current_owed` / an `OpFence`, which
  check and act under one lock, so a withdrawn or replaced park's queued command does nothing. `begin_implicit_unpark`
  takes the expected op; `KillBackgroundTask` carries its park; one deadline from `handle_park` entry bounds the load
  wait (F7); `FamilyDebt` records a model switch against the origin family (F8). `op_is_current` stays as an early-exit
  hint only. Modes are a pure `modes_for(ParkOs)` table.
- **M3 model dispatch gate (C).** `fuigo_sampling_types::DispatchGate`, awaited in `SamplingClient::dispatch_request`
  and again in `subscription::dispatch` right before `client.execute`; `ParkGate{session_id}` (shell) waits on
  `quiesce::wait_model_allowed`. Set on every session, subagent and helper `SamplerConfig` and on the title client. A
  call cancelled while waiting ends `Cancelled` and never dispatches. Replaces `GatedSamplingClient` and the waits in
  compaction, summary and session_compact.
- **M4 reverse-MCP ticket (D).** `session/reverse_ticket.rs`: a call gets its ticket at creation (id in
  `params._meta["fuigo/internal/ticket"]`, stripped before the inner client); the ticket decides once whether it was
  created inside a parked load window, so a call queued before the park is not let out by another session's load.
  Dropping the guard cancels the held request. Replaces the `mcp_call_*` checks (deleted at integration:
  `mcp_call_allowed`, `mcp_call_would_wait`, `parked_load_active`). F9: `get_task` log tail is bounded (2 s).
- **M5 fold transaction (B).** `FoldTxn{id, commit}` / `FoldReply{id, fires}`: the scheduler's fire is folded into the
  next prompt only on a commit with the matching id and a queued release; a timeout or undeliverable reply commits
  nothing.

### K lines (deduplicated)
- ACP-terminal kill is a frame to the client and cannot be recalled once written.
- The kill fence is a start-of-execution snapshot, not a lease across the kill await.
- One `/proc` pass is not interruptible mid-pass.
- `setsid foo &` whose launching shell dies before any observation is not attributed (fail closed); the park-time
  observation narrows but cannot close the window for a process spawned and orphaned between observation and kill.
- While parked, `_fuigo/task/list` may report a finished ACP-terminal task as running until unpark.
- A ticket created while parked reads "load window" from two lock acquisitions; a load beginning between them counts as
  no window (fails closed).
- Tool-internal HTTP (web search, image/video generation, web fetch) does not pass the model dispatch gate; a tool
  running in a hold-parked session can still make those calls.
- The gate is `None` on any `SamplerConfig` literal not listed in M3; route configs used without
  `stamp_session_local_sampler_fields` have no gate.
- Intermittent (sightings, not reproduced): `park_holds_background_wakes_and_frames_until_unpark`,
  `reverse_mcp_calls_are_held_by_a_live_park_and_marked_released`.
