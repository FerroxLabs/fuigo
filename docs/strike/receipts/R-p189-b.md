# R-p189-b: session cgroup module (P189 packet B, 1.0.25)

Module `crates/codegen/fuigo-tty-utils/src/session_cgroup.rs` (+ `session_cgroup/imp.rs`, `session_cgroup/tests.rs`). Nothing calls it yet. Linux real; other OSes get stubs (`probe()` -> `Unavailable::NotLinux`), compile-checked nowhere here: macOS/Windows stubs UNRUN.

## API
- `probe() -> Result<&'static ParkHost, &'static Unavailable>` (OnceLock cached); `probe_with(&ProbeEnv)` uncached; `ProbeEnv { cgroup_root, own_cgroup, lock_dir, require_cgroup2 }`, `ProbeEnv::system()`.
- `Unavailable`: NotLinux, NotCgroup2, OwnCgroupUnreadable, OwnCgroupMissing, OwnCgroupNotDomain, LockDir, MkdirRefused{errno}, NoCgroupKill, ProcsNotWritable, RoundTrip, Panicked (panic caught; release is panic=abort so that only protects test/debug).
- `ParkHost::create_session() -> SessionCgroup`, `sweep_stale() -> SweepReport`.
- `SessionCgroup::{place(&mut Command) -> PlaceLease, record_spawn_error(&io::Error), is_breached, close, reopen, kill_and_wait(deadline) -> KillOutcome{Emptied,NotEmptied,Refused(Breached|SelfInCgroup|Io)}, teardown() -> TeardownOutcome{Removed,LeftPopulated,Failed}}`. `place` is the single async-signal-safe `write(fd,"0")`; sentinel errno 131; must be the first `pre_exec`. The procs fd is moved to >= 3 if it landed on 0..2.
- Own-pid guard: refuses if our pid is listed in the session subtree's `cgroup.procs`, or if our own `/proc/self/cgroup` is the session cgroup or below it.
- Lock file: `$XDG_RUNTIME_DIR/fuigo/fuigo-park-<uuid>.lock` (if set and a dir), else `/tmp/fuigo-run-<euid>/`. Deliberately not under HOME/FUIGO_HOME (lanes have private homes but share one cgroup). Taken (flock, CLOEXEC) before the cgroup dir is created. Sweep also removes free lock files older than 60 s whose dir is gone.
- Lint: the raw-spawn ban is clippy `disallowed_methods`, not an extra-ca test; the probe spawn and the tests carry `#[allow(clippy::disallowed_methods)]` with a reason (child killed and reaped on every path). `fuigo-extra-ca` tests pass untouched.

## Probe on the build box
Usable. Kernel 6.8.0-137-generic, cgroup2fs mounted rw (nsdelegate, memory_recursiveprot), own cgroup `0::/user.slice/user-0.slice/session-N.scope` (the ssh login scope, root-owned; root can write). The scope held 12-15 processes (other ssh/shell procs). Tests created only `fuigo-park-*` dirs under it and removed them (the cached-probe dir of a finished test process is empty and unlocked: the next sweep, or scope end, removes it).

## Settled NOT VERIFIED items
- Zombies and `populated`: SETTLED on 6.8. A killed, unreaped child (`/proc/<pid>/stat` state Z) is NOT in `cgroup.procs` and `populated` is 0 (`P189-ZOMBIE outcome=Emptied waited~10ms state_after=Z zombie_listed_in_cgroup_procs=false`). So `stop` does not depend on reaping.
- Writing `0` to `cgroup.procs` from a forked pre_exec child with an fd opened by the parent works as root; setsid + double-fork daemons stay in the cgroup and die on `cgroup.kill`; a sibling session in the same process dir survives.
- A placement write to an fd that is no longer valid fails and surfaces as the sentinel errno from `spawn()` (tested with a read-only fd).
- NOT settled: fork-vs-`cgroup.kill` race, open-time credentials for non-root writers, bwrap/userns, Murage delegation, non-root `rmdir`/`mkdir` behaviour, other kernels (only 6.8 run), macOS/Windows.

## Plan notes

- Lock location is the builder's choice per plan; chosen above, with the cross-HOME reason.
