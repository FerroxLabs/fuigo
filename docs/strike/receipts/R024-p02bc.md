## 1. Not met / caveats, first

   It becomes true when `strike/p02fg` (`RUNTIME_STARTUP_FAILURE_EXIT_CODE = 4`) lands.
2. **The Messages format carries no `rule`/`remedy` for a permission denial** (packet §3.1). The
   schema entry is `{tool_name, tool_use_id, tool_input}`, and fuigo adds no key. For a **budget**
   denial it carries **no `permission_denials` entry**, because no tool was refused. There, `rule` and
   `remedy` exist only in prose (`errors[]`, the agent's message). D.5's "without parsing English" is
   fully met on `json` and `streaming-json`, and only partly on `streaming-messages-json`.
3. **An unrecognized budget rule in `plain` writes two stderr lines**: the agent's message, then

   It is documented, not changed (audit round 2, finding 1).

6. The ACP permission outcome stays `Cancelled` (packet §3.2, Contract E).

## 2. Design, per format (D.2.2)

| `--output-format` | permission denial | token-budget denial (D.4, via P02e) |
|---|---|---|
| `plain` | stderr line (`main`) + exit 3; stdout unchanged | same; stdout empty |
| `json` | `permissionDenied` on the single document | `permissionDenied` on the `error` document, `endedRun:true`, `exitCode:3`, `toolCallId:null` |
| `streaming-json` | the **same** `permissionDenied` object on the terminal `end` line (or the `error` line); no new line type | same object on the `error` line |
| `streaming-messages-json` | schema's own `result.permission_denials` (previously "always empty, omitted"), filled from the transcript's `tool_use` block; `stop_reason:"cancelled"` | `is_error:true`, `stop_reason:null`, no `permission_denials` entry; `errors[]` = agent message naming rule + remedy |

- The shape was checked against `@anthropic-ai/claude-agent-sdk@0.3.220/sdk.d.ts:4159`
  (`SDKPermissionDenial`). The field is emitted only when there is a denial, because fuigo does not see
  deny-rule or hook refusals (R010 P02h) and must not claim `[]`.
- `Reducer::permission_denied(&HeadlessDenial, ended_run)` is a **required** trait method. The
  emitter calls it immediately before `finish`/`error`.
- **`endedRun` / `exitCode`:** P02a's record always said `exitCode: 3`, but a recovered denial exits
  `0` and a denial followed by an error exits `1`. Now `exitCode` is present only when `endedRun` is
  true. `endedRun` is true in two cases: the turn ended at the refusal (`PermissionCancelled` with no
  run-level error), or the turn ended at a budget denial. One residual case is documented: a
  memory-flush *failure* after a permission block exits `1` with a record that says `3`. ("Trust `$?`".)
  A budget denial now skips the flush entirely (`should_run_memory_flush`).
- **Remedies named nonexistent flags** (`--allow-rules`/`--deny-rules`). They are now `--allow`/`--deny`
  (`app/cli.rs`), pinned against `PagerArgs::command()`. "Trust the folder" now reads "trust a folder
  whose project config allows it", because trust alone approves nothing.
- **P02e patch (`R032-p02e-pager-proposal.patch`)** applied with `git apply -3` and reconciled:
  - the JSON key stays `permissionDenied`, and `rule` distinguishes the cases (P02e's recommendation);
  - `on_error` now uses the latched `denial_ended_run`, not `false`;
  - `toolCallId` is `null` for budget denials;
  - the Messages reducer skips the entry for budget denials;
  - the flush guard is extracted into a testable fn.
- Ownership: beyond `headless.rs:2290-2306` and `reducer/`, the change touches
  `HeadlessEmitter`/`wire_record`/`finish_turn`/`emit_completed_response` and the remedy strings in
  `headless.rs`. That is the same Contract D surface. `docs.rs` is untouched.

## 3. Side effects (D.2.4)

`fuigo-shell/.../tool_calls.rs:1775-1782`: `Decision::Cancelled` leads to `handle_tool_not_executed`
and then `ToolLoop::Cancelled`, so the tool **never executes**.
- **Written:** nothing of the refused call; the conversation gets a "not executed" result.
- **Left:** everything done before the refusal.
- **Rolled back:** nothing, because nothing of the refused call was applied.
- **Evidence:** the real-binary tests assert the fixture file is still `old line\n`, in the json test
  and in all four per-format spawns.
- A budget denial refuses the *model request* before it is sent, so no tool is involved.
