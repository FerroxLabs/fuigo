## 1. What changed (owned files only)
| # | brief item | change |
|---|---|---|
| 1 | default ON | `resolve/crash_handler.rs`: `CRASH_HANDLER_DEFAULT = true`, precedence unchanged (requirement > env > user > managed > remote > default). `FUIGO_CRASH_HANDLER=0` / `[diagnostics] crash_handler = false` still turn it off. A delivered remote `crash_handler_enabled` is persisted atomically to `$FUIGO_HOME/crash/remote-gate` (sticky; `None` leaves it) and read at the remote tier by `load_crash_handler_enabled_sync`, so an org kill switch reaches the install decision from the next start (Astra R3-3). Docs: config reference row, `RemoteSettings` field doc, crate README. |
| 2 | per-process slot | `crash-<pid>-<start token>.bin` (Linux `/proc/<pid>/stat` field 22, macOS `proc_pidinfo` start time, Windows `GetProcessTimes`), `O_CLOEXEC`, 0600; Windows opens with `FILE_SHARE_READ \| FILE_SHARE_DELETE`. Readers act only on slots whose owner is provably dead (pid gone, or start token differs = recycled pid). Live and unverified (no token) slots are never touched, at any age. Claims are atomic renames to `<slot>.claim-<pid>-<token>`. The blob is deleted only after its report is written (tmp + rename); on failure the claim is put back. Clean exit deletes the empty slot (`atexit`, Unix). Every non-interactive start runs `sweep_dead_slots` (empty dead slots only), which also covers Windows, where `std::process::exit` uses `ExitProcess` and skips CRT `atexit` (verified with a probe binary on the SeanDesktop Windows host). Fork safety: the handler writes only when `OWNER_PID == getpid()`, and a child's `install()` first detaches the inherited fd, then publishes its own fd, and only then sets the owner pid (Astra R5-1). Scan budget: 4096 owner checks counted over our own names only, at most 32 reports per start. Reports produced by this scan, and any report younger than 1 h, are never pruned. Handler path stays async-signal-safe (atomics, pre-built statics, `getpid`/`time`/`pthread_self`/`write`/`lseek`/`close`). |
| 3 | ASLR symbolication | Blob format v2 (`HEADER_SIZE` 156): main-image base/lo/hi, a 16-byte identity (GNU build-id, `LC_UUID`, or PE stamp + size; zero = unknown, including PE stamps 0 and 0xFFFFFFFF), exe length, start token, kind, class, thread name. All of it is computed at install time, not in the handler. The reader re-bases in-image frames (`ip - crashed_base + own_base`) only for the same build (version, span, nonzero identity, exe length); otherwise it prints `fuigo+0x<off>` (`DifferentBuild` / `UnverifiedBuild`). There is no partial-file fingerprint fallback (Astra R2-2). The address adjustment matches `backtrace` 0.3.76 (`-1`, MSVC `-2`), with frame 0 pre-compensated. v1 blobs parse and are reported raw (`LegacyFormat`). An empty legacy `last-crash.bin` is never deleted. |
| 4 | benign panics | A panic hook (installed by `install`, chained in front of existing hooks) classifies in normal context into 8 per-thread records: class (`Broken pipe`/`os error 32`, `No space left on device`/`os error 28`, the Sentry `is_broken_pipe_panic` strings), thread id, and thread name (32 B; any name containing `/` or `\` becomes `<path-like name>`). The message is never stored. A SIGABRT on the recorded thread = `Panic`; a guard-page SIGSEGV/SIGBUS near SP = `StackOverflow`; else `Signal`. Benign panics keep the report but produce no notice. |
| 5 | notice | `startup_notice`: "Fuigo crashed during your last session." + what (e.g. `Rust panic on thread 'x'`) + version + report path under `~/.fuigo/crash/history/` + "The report stays on this computer; nothing was uploaded." The report text says the same. `main.rs` claims and announces only when stderr is a terminal; headless, editor (ACP) and leader processes record their own crashes but only sweep. Output goes through `best_effort_stderr` (no panicking `eprintln!`). |
| 6 | release note | No 1.0.21 changelog exists (last is `fuigo-shell/changelogs/1.0.13.*`). Line for P11 below. |

**Release note line for P11 (1.0.21):** "Crash reports are now on by default and stay on your machine: if Fuigo crashes, the next start tells you where the report is (`~/.fuigo/crash/history/`). Nothing is uploaded. Several open sessions no longer overwrite each other's reports, reports name the actual function across restarts, and a closed terminal or full disk no longer triggers a false 'Fuigo crashed' notice. Turn it off with `[diagnostics] crash_handler = false` or `FUIGO_CRASH_HANDLER=0`."

## 6. Proposals (outside P05a ownership)
1. **musl release builds need a build id.** Symbols across restarts require a nonzero identity. Ubuntu gnu links carry `NT_GNU_BUILD_ID` (verified on the test binary). If the musl `release-dist` link does not, those reports will show `UnverifiedBuild` offsets only. Add `-C link-arg=-Wl,--build-id` to the musl targets in `.cargo/config.toml` and check a release artifact with `readelf -n`.
2. **Factor the benign-panic classification.** `fuigo_crash_handler::panic_info::classify_panic_message` mirrors `fuigo-telemetry` `sentry.rs::is_broken_pipe_panic` string for string. Make Sentry call the shared function (needs a telemetry → crash-handler dependency) so the two cannot drift.
3. **Live remote disable.** A mid-session remote `crash_handler_enabled = false` applies from the next start. Applying it live would need fuigo-shell to call `fuigo_crash_handler::release_slot()` (new dependency edge).
4. **Strengthen the fork-reinstall test** (Astra R6 LOW): assert `install()` returns true in the child, crash the reinstalled child, and verify its own blob next to the untouched parent slot.
5. **Windows/macOS runtime runs.** The new Windows (`GetModuleHandleExW`/PE parse, `GetProcessTimes`, share mode, MSVC `RESOLVE_ADJUST = 2`) and macOS (`dladdr`/dyld slide/`LC_UUID`, `proc_pidinfo`) code was compile-checked with clippy for those targets but never run. Run the crate's suite on a Mac (where builds are allowed) or in Windows CI.
