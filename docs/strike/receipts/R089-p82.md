## 1. Read first: what is NOT met, and the decisions

1. **NOT MET — Astra never returned LAND; the last round (3) is DO-NOT-LAND with one HIGH left open on purpose.** Rounds 1–3
   found six HIGHs; five are fixed (§6). The sixth (round 3, finding 1: `_fuigo/skills/add` with a path containing
   `${FUIGO_API_KEY}`, then `_fuigo/skills/config` returns it expanded) is one instance of a class this packet cannot close
   with response filters, and I stopped there instead of patching instances. The evidence:
   - **`_fuigo/fs/read_file` hands any file to whoever sends it.** `extensions/fs.rs:123-135` takes absolute paths as they
     are; `confine_local` → `fuigo-workspace/src/handle.rs:1947` confines only when `confine_fs_to_workspace_root` is on,
     "off by default". A relay that is not FluxRouter-operated reads `~/.fuigo/auth.json` (session token, **refresh token**,
     stored API key) or `/proc/self/environ` in one request, no model, no terminal. That is a stronger credential getter
     than the two methods this packet refuses.
   - `_fuigo/terminal/create` runs commands; `_fuigo/mcp/upsert` with `bearer_token_env_var` sends any environment variable
     as `Authorization: Bearer …` to a URL the caller picks, during the upsert itself (`fuigo-config-types/src/mcp.rs:443-450`,
     `extensions/mcp.rs:2145-2171`); `_fuigo/plugins/action` Install and stdio `mcp/upsert` execute code; the user config
     layer is env-expanded on load (`fuigo-config/src/loader.rs:694`, `$VAR` and `${VAR}`), so every config write a relay
     can make and read back is an oracle (skills/add → skills/config; marketplace AddSource → marketplace/list; full list in
     §3.3); and in headless mode the relay is the ACP client that answers the agent's own permission requests.
   - So **P82 protects against a passive or honest-but-curious relay** (nothing it is sent unasked carries a credential:
     leader mode's copies of local answers, catalogs, notifications, the agent's own terminal requests), and refuses the
     explicit credential API. **It is not a boundary against an active hostile relay**, which today has local-client powers.
   - **Decision for Sean (needed before this can be audit-clean):** (a) accept P82 as passive-leak protection and write
     into the policy that a non-FluxRouter relay is trusted to drive the agent (then round 3 finding 1 and its class are
     documented, not fixed); or (b) a follow-up packet that restricts what a non-FluxRouter relay may drive (refuse host
     access — `fs/*`, `terminal/*`, config-writing methods — or refuse to bridge one at all without an explicit opt-in).
     Both are product decisions; (b) breaks remote control through self-hosted relays. I recommend (b) with an opt-in, and
     (a)'s policy sentence in the meantime.

## 4. What changed (production)

1. **`agent/relay_credentials.rs` (new).** `CREDENTIAL_METHODS`; `gate_relay_message` (request side): not a JSON object →
   dropped; a credential method (any number of leading `_`) with an `id` → `-32600` refusal carrying that id and typed
   `data`, without one → dropped; anything else → forwarded as `Value::to_string()` of the parsed value (one line, no
   duplicate keys, escapes resolved). `withhold_credentials` (response side): a FluxRouter relay gets `msg` itself; any
   other relay, when the frame contains one of 10 quoted keys or `\u`, has it read one level at a time with a
   duplicate-rejecting object reader along the §3.2 paths, the fields removed (whatever their value), everything else
   carried as raw text; undecidable (not an object, duplicate key on a path level) → not sent.
2. **`agent/relay.rs`.** `relay_outbound_frame` calls `withhold_credentials` first (P81's filter then runs on its result).
   The reader: for a relay that is not FluxRouter-operated, every text message goes through `gate_relay_message` (after the
   existing error handling and `declare_relay_client_capabilities`), and a binary frame is split on `\n` as the agent's
   reader splits it and each line gated; a refusal goes to a channel the writer drains through the socket's one text
   writer and the same filter. A FluxRouter relay: the old code paths, byte for byte.
3. **`agent/server.rs` (`fuigo agent serve`).** `validate_auth` compares through `secret_matches`: SHA-256 of both sides,
   all 32 bytes folded; an empty server secret admits nobody.
4. **`docs/destination-trust-policy.md`:** "Credentials over the relay bridge (P82)".

Unchanged: `agent/app.rs`, every producer, the local stdio / IPC path, relay sync.

## 5. `fuigo agent serve` (brief item 5)

- **Credential methods reachable?** Only after authentication (the check runs before the upgrade, `server.rs:142`); once
  admitted, a peer has the local client's powers, getters included, by design (R086 §12).
- **Fixed here (contained, `server.rs` + its test file):** the `==` compare (early exit) → constant-time over digests; the
  empty-secret bypass. Astra: "functionally correct"; the timing property is source-level only (no compiler guarantee, no
  timing measurement).
- **Proposals (not changed), severities as Astra round 1 gave them:** HIGH when exposed across an untrusted network — plain
  `ws://` listener (`server.rs:630`), so a captured secret is full agent access (default bind is loopback,
  `fuigo-pager/src/app/cli.rs:373`); MEDIUM — the secret is printed at startup and accepted in the query string
  (`fuigo-pager-bin/src/main.rs:172`), landing in URLs and logs; MEDIUM — the generated secret is 12 hex characters (48
  bits, `cli.rs:387`) with no rate limit. Recommended packet: refuse a non-loopback bind without TLS unless
  `--allow-insecure-bind`, header-only secret, 128-bit generated secret.

1. **The relay trust decision** (§1 item 1): restrict what a non-FluxRouter relay may drive (host access: `fs/*`,
   `terminal/*`, config writes, plugin / MCP / marketplace installs), or refuse to bridge one without an explicit opt-in.
   Until then, say in the policy that such a relay is trusted to drive the agent.
2. **`fs/*` confinement default** (`fuigo-workspace/src/handle.rs:1947`, off by default): with it off, any ACP client reads
   any file, `auth.json` included. Worth an independent look even for local clients.

   `config.toml`, turning `${SECRET}` into the plaintext secret on disk.

   the producer as the persisted summary already does (`fuigo-workspace/src/session/git.rs:386`). Same for marketplace
   source URLs.
5. **`fuigo agent serve` transport** (§5).
6. **Body guard row for `p83_teardown_tests.rs`** (2: `email:`, `team_id:` of a test session fixture) on integration.
7. **`mcp/upsert` `bearer_token_env_var`** reads any variable at upsert time and sends it to the configured URL; restrict
   the variable names (e.g. an allowlist or a prefix) whatever the caller.
8. R086's proposal 5 (a typed bridge that carries each response's method, or separate relay / IPC channels) would let the
   backstop decide per method instead of by shape.
