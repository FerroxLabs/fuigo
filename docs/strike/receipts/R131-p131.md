# R131 (P131): Windows environment for the pinned npm verifier, and recovery after a failed verify

Branch `strike/p131`, base 15c21ddf. Fixes Fable final audit MEDIUM-2 against P126. No Rust touched, no cargo anywhere,
no push/tag/publish/workflow run. `release.yml` is unchanged (so no actionlint run was needed).

## Finding and fix
- `pinned-npm.js` ran npm with an empty environment. P126 already copied SystemRoot, ComSpec, PATHEXT, TEMP, TMP and set
  USERPROFILE on win32; still missing: `windir`, `APPDATA`, `LOCALAPPDATA`. Without them npm's cache and global prefix fall
  back to paths outside the private home on Windows.
- `pinnedEnv(home, extraEnv, platform = process.platform, source = process.env)`: win32 copies only
  `SystemRoot, windir, ComSpec, PATHEXT, TEMP, TMP` (case-insensitive lookup, so SYSTEMROOT works) and points `APPDATA`,
  `LOCALAPPDATA`, `USERPROFILE` and `HOME` at the private home. POSIX is unchanged (PATH, HOME, two npmrc pins).
  `NPM_CONFIG_*`/`npm_config_*` are never copied and `extraEnv` now throws on them. Both registries stay pinned on the
  command line. Justification: Microsoft environment-variable docs (SystemRoot/windir, ComSpec, PATHEXT, TEMP/TMP),
  libuv `uv_os_homedir` (USERPROFILE on Windows), npm cache under LOCALAPPDATA and global prefix under APPDATA.
- Other empty-env users on Windows: none. `verify-published-platform.js` runs the installed binary with `{...process.env}`
  (not an isolation boundary); `registry-release-inputs.sh` (`env -i`) only runs on ubuntu.
- Recovery: `release.yml` has `workflow_dispatch` (`dry_run`, `replace_release_assets`) but a rerun or dispatch on the tag
  runs the TAG's workflow and scripts, so it cannot pick up a script fix; `github-release` also requires a tag ref.
  Smallest correct change: documented manual recovery in `RELEASE.md` ("Recovering when verify-published fails after npm
  published"): run the fixed verifier per platform, `registry-release-inputs.sh`, `github-release-assets.sh`,
  `verify-release-digests.js`, then `gh release create`. No republish.

## Unverified
- Not run on a real Windows runner. The tests mock `platform`; real node/npm behavior on windows-latest and
  windows-11-arm with this variable set is unproven. Recommended before the first real tag: dispatch the `release`
  workflow on the branch with `dry_run` true is NOT enough (verify-published is skipped on dry runs); run a throwaway
  Windows job that executes `node crates/codegen/fuigo-pager/npm/fuigo/scripts/verify-published-platform.js win32-x64`
  against an already published version (a one-job workflow_dispatch workflow, or a Windows machine).
- The manual recovery procedure was reviewed against the scripts but not executed end to end.
