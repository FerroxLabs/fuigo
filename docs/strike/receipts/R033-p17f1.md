## 1. The change

### 1.1 The eight writers (R013 §1.5)

`crates/codegen/fuigo-shell/src/config/mod.rs`. The packet named eight writers. Only seven of them
write `config.toml`: `remove_hooks_path_from_file` writes `~/.fuigo/hooks-paths`. All eight now
replace their file atomically.

- The seven `config.toml` writers are `add_plugin_path`, `remove_plugin_path`,
  `add_disabled_plugin`, `remove_disabled_plugin`, `add_dismissed_plugin_cta(_to_file)`,
  `add_enabled_plugin` and `remove_enabled_plugin`. They collapse onto one
  `edit_config_string_list`. It holds `fuigo_config::fs_atomic::lock_config_for_write` across the
  whole read-modify-write: the same lock every other user-config writer takes, so no lost updates.
- Each writer has a path-parameterized `_in` entry point, so tests drive the real writer.
- Only `NotFound` reads as empty. An unreadable file, such as invalid UTF-8, is now an error. It
  used to be treated as empty and rewritten down to one list.
- A removal from a missing file returns `Ok` before taking the lock. It creates no directory and
  no lock file. The lock is re-checked once taken.
- `hooks-paths`: add and remove both take `hooks-paths.lock`. Removal replaces the file
  atomically. Add still appends, now as one `write_all`.

### 1.2 `config::atomic_write::write_file_atomically` (new)

The temp file goes in the target's own directory (or the macOS staging directory, §1.3). Each step
in order:

1. **Create the temp.** It is created `create_new`, mode `0600` on unix. On Windows it is opened
   with share mode 0 and `WRITE_DAC`. Its name is unique per process and call. A taken name is
   skipped (16 attempts) and never deleted. Only a temp this call created is ever removed.
2. **Copy the platform ACL (macOS, Windows).** This happens before any content, see §1.3.
3. **Write the content.**
4. **Apply the original's metadata, after the content.** Unix order: owner/group (fchown,
   best-effort), then the Linux xattrs/ACL, then the exact mode (`0o7777`). Applying the mode after
   the write keeps setuid and setgid bits.
5. **Sync and swap.** `fsync` the temp, `rename` it over the target, then `fsync` the directory
   (unix, best-effort).

Two more rules:

- **Symlinks are written THROUGH, which is the current behaviour, kept.** `std::fs::write`
  followed a symlinked `config.toml`. The helper resolves the link chain (up to 40 hops, the kernel
  limit) and replaces the final target, so the link survives. A dangling link creates its target,
  as before.
- **A read-only existing file is still refused.** A write-access probe opens the target for write
  without truncating it. Without it, the rename would only need write access to the directory.
- **New files are now created `0600`**, not `0666 & !umask`. This is a deliberate change that
  matches every other `config.toml` writer.

### 1.3 ACLs

- **Linux (tested).** Every xattr is copied from the original through the probe fd (`mod xattrs`).
  Failing to copy the access ACL refuses the write. An access ACL the temp inherited from a default
  ACL on the directory is stripped when the original had none, including when the original's ACL
  vanishes between list and read. Zero-size and growing xattrs are handled.
- **Windows (scratch-run, §4.3).** The original's DACL, inherited ACEs included, is set on the temp
  as a PROTECTED DACL. The replacement therefore grants exactly what the original granted.
  Trade-off: later changes to the directory's ACL no longer flow to the file.
- **macOS (compile-only).** The temp is created inside a fresh `0700` staging directory whose
  extended ACL is cleared first. So it inherits nothing, and no other principal can look it up
  before its ACL is set. The ACL copy is exact, via `acl_get_fd_np`/`acl_set_fd_np`. If the
  original has none, the temp gets an empty ACL. A filesystem without ACL support makes both a
  no-op.

### 1.4 Reactor safety

The session runs on a current-thread runtime, so the lock's sleeping wait must not run inline. The
plugin, hook and install edits now run on the blocking pool:

- `config::off_reactor`: 12 session call sites in `hooks_plugins.rs` and `slash_exec.rs`.
- `post_install_plugin_off_reactor`: the session install site and the three `marketplace.rs`
  install/update sites.
- The session's `/plugins install` runs `plugin::install_plugin` under `spawn_blocking`.

## 2. Tests and mutants

New tests are in `config/atomic_write_tests.rs` and `util/config/mcp_write_tests.rs`. Each property
is checked across all eight writers.

- **Concurrent reader never observes a partial file.** `a_concurrent_reader_never_observes_a_partial_file`
  uses 512 KiB padding, at least 100 writes and at least 300 reads, and checks parse plus sentinel.
  `concurrent_server_saves_neither_tear_nor_lose_updates` covers the MCP writers.
- **Permissions preserved.** `each_writer_replaces_the_file_and_keeps_its_permissions` covers modes
  0640, 0604, 0600 and 04640, and checks that the inode is replaced and the uid/gid kept. Related:
  `a_new_file_is_created_owner_only`, `an_access_acl_survives_the_replacement`,
  `an_inherited_default_acl_is_not_added_to_the_replacement` and
  `a_vanished_original_acl_still_strips_the_inherited_one`.
- **Failed write leaves the old file intact.** `a_failed_write_leaves_the_old_file_intact` uses a
  `cfg(test)` thread-local fault seam that writes 64 bytes and then errors. It checks the old file
  is byte-identical and that no temp is left.
- **Other tests:** symlink write-through, the 40/41-hop limit, a dangling link, unreadable-file
  refusal, lost updates, the temp-name collision and exhaustion cases, missing-file removal, the
  current-thread starvation test, and refusal of an unparseable MCP config.

Mutants were applied to `src-tip` one at a time. The command is `cargo test --locked -p fuigo-shell
--lib -- config::atomic_write util::config::mcp::write_tests`, through `slot-run.sh`. The script is
`/root/fuigo-builds/p17f1/mutants.sh` and the results are in `logs/mutants-summary.txt`. The final
round on `a6a1df96` is in §4.2. The "non-atomic" mutants are M1 (in-place truncate+write through
the same fault seam) and M2 (literal `std::fs::write`). Both fail the reader, failed-write,
new-file-mode and permission/inode tests.

The permission test catches M1 and M2 only through its inode check. A plain in-place write keeps
the mode, so the permission property has its own mutant, M3, which drops mode restore.

## 6. Proposals (out of packet)

- **P17-F1a, pager config writers off the input thread.** This covers §0.3 and all pager writers.
- **P17-F1b, lock fairness.** `lock_config_for_write` polls every 20 ms, so a waiter can be
  starved past 2 s by a writer that re-acquires back to back (seen in `flake-19`). Consider a
  blocking `flock` with a timeout thread, or a ticket.
- **P17-F1c, one replacement helper for every `config.toml` writer.** Today
  `fs_atomic::write_atomically`, `persist::atomic_write_string` and `config::atomic_write`
  disagree on symlink handling (replace vs write-through), mode policy (mask `0o700` vs exact) and
  ACLs. Unify them; it needs Windows and macOS hosts.
- **P17-F1d.** `worktree::apply_file_content` writes tracked files in place.
- **Loader half of R013's P17-F1 (stable-read check on a blank user layer).** Not done here. It
  was proposed as separately gated and changes every config load.
