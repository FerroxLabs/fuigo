## Design
The turn (`turn.rs`, before its first echo) creates `SnapshotTurn::begin`; its drop sends `SnapshotEnd{turn_id}` on every exit
(success, invalid prompt, failed image save, cancel, panic). The chat commit moves the guard into a spawned task that drops it
after the chat item is handed to persistence. The actor takes `snapshot.lock` on Begin and releases on the matching End (flushing
buffered echoes first); a new Begin releases an old hold; chat items that do not start a turn never touch the hold; a prompt chat
item with no hold takes the lock itself. Fork snapshot unchanged (stats under the lock, reads after release).

## Round 3 (Astra r3 HIGH, tip below)
Astra r3's BLOCKER (a stray `0` at bb387e63) was already removed in 87468b12.
HIGH: `run()` checked expiry right after `recv`, before processing the message. With the deadline past and the turn's Chat and End
still queued (guard dropped after Chat was queued), the actor saw an expired deadline and a dead turn, released the lock, and only
then wrote Chat, so a waiting fork could take the lock first. No lost End was needed.
Fix (persistence.rs): the per-message check is removed; expiry runs only from the `timeout_at` arm, and only when `rx.is_empty()`.
`tokio::time::timeout_at` polls the inner future before the deadline (tokio 1.53.1 `time/timeout.rs` line 216, "First, try polling the
future"; doc line 24), so a ready message wins even with a deadline already in the past. The only other expiry path is that arm. The
`expire_snapshot_hold` doc comment now says expiry happens only when the channel is drained.

## Release-note text
- B30 (replaces the P123 sentence): a fork copies one snapshot of its source, and a turn's prompt echo and chat item are written under one
  lock that lasts exactly as long as that turn start: an invalid prompt, a cancelled turn or a failed image save no longer leave forks
  refused (they failed after 10 s until the next prompt in 1.0.21 builds before this fix; 1.0.20 had no lock).
- K17 shrinks to: a prompt is in both or neither unless the source is rewound at that moment, a writer that does not use the lock (an
  older Fuigo) is active, the lock is stuck for over 10 s (a fork then refuses as retryable), or a turn vanished without its end and the
  120 s limit released its lock; text streamed within one turn is not covered. A fork taken during a long image description waits up to 10 s and
  is then refused as retryable.
- Notes: the goal-directive prune note no longer says the change is applied again on resume; the snapshot lock and the rewind-points lock
  files are created owner-only; RELEASE.md's manual recovery step works without a release-notes file.
