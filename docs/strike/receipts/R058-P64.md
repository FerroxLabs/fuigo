## Finding and fix
The integration Astra audit of P42 × P46 × P56 (`stack8-integration-astra.txt`) raised one LOW. `AuthManager::update_unless_superseded` and
`edit_stored_credential` could return a sibling's session bearer read from disk without calling `note_session_bearer`.
That leaves P42's "held or handed out" invariant (`is_session_bearer`) incomplete.

- `7e36f78d`: both methods now record the disk credential they return (`manager.rs:1064`, `:1099`).
  `note_session_bearer` only inserts a digest. It never writes `inner`, so a fresher in-memory credential is kept.
- `d2ce97eb` (P64 round-1 Astra LOW): `read_disk_auth_with_state` (and through it `read_disk_auth`) records what it
  returns (`manager.rs:1589`).
  - `read_disk_auth_silent` stays registration-free. Its two callers only compare keys or test refreshability, and the
    method's doc now says so.

Tests (`auth/cross_process_race_tests.rs`, end of file). Memory holds round 1, and disk holds a sibling's round 2 that
the manager never loaded. The precondition asserts round 2 is not yet a known bearer. Each test checks three things:
the returned credential is the sibling's, `is_session_bearer` recognises it, and memory still holds round 1.
- `update_unless_superseded_registers_the_sibling_bearer_it_hands_out`
- `edit_stored_credential_registers_the_disk_bearer_it_hands_out`
- `read_disk_auth_registers_the_sibling_bearer_it_hands_out`
