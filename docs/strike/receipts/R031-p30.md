## 1. What is NOT met (read first)

- **A pre-existing session-token delivery defect is recorded, not fixed.** The pre-gate audit found it.
  Three `fuigo-shell` paths deliver the session token by the broad refusal matcher `is_fuigo_api_url`, or
  without checking the destination at all. That puts the token on cleartext, other-port and loopback URLs,
  all of which `session_may_be_sent_to` refuses. A narrow fix was built, tested and mutant-proven
  (`730a4323`). Audit round 2 then showed two problems with it. `NotByok` and a buffered-token fallback get
  around it. And it introduced a regression: removing the resolver also removed its hard-expired-token
  stripping, while the buffered key stayed. So `b4ebbbc8` withdrew it. P30 now changes no behaviour. The
  four-part defect and a recommended packet are in `docs/destination-trust-policy.md` ("Known defect:
  session-token delivery") and at each call site. **This needs a coordinator decision.**
- **Identity-class `x-fuigo-*` writers outside the inference sampler** (`inject_proxy_headers` → web
  search / image / video; `fuigo-workspace` `build_proxy_headers`; `fuigo-voice` STT; auxiliary
  `remote/*` clients sending `x-fuigo-agent-id`, `x-userid` and `x-email`) are recorded as a known
  boundary with a recommendation, not changed. All of these are pre-existing.
- **`fuigo-shell` test function names that contain `first_party` were deliberately NOT renamed.** Examples:
  `a_reloaded_endpoint_becomes_first_party`, `embedding_session_credentials_scopes_to_first_party`. The
  strike's failsets and sightings are keyed by test name, so renaming would break that continuity. Their
  messages and comments are updated. Names were changed only in packages with an empty failing set
  (`fuigo-extra-ca`, `fuigo-sampler`, `fuigo-shell-base`).
- Full `-p fuigo-shell` runs are **labelled `--skip session::workflow::manager::tests`**, per the
  coordinator's P29/P38 rule. Both parent and tip lack P38.

## 3. Policy decision (the packet's question)

**A user on their own configured remote HTTPS gateway gets the session bearer and no identity headers.
That is correct, and it is the recommended policy. Behaviour is unchanged.**
- The user chose the destination, so the user chose to send it a credential. Fuigo did not choose it, so
  Fuigo does not volunteer a cross-provider identifier to it.
- The correlation headers still reach the gateway (P15-R). What it loses is FluxRouter's proxy-side version
  gating and telemetry.
- When the config carried an identity to withhold, the withholding is logged at `warn` with the remedy
  named.
- No opt-in is added. If a managed deployment ever needs one, it should be an explicit per-origin setting,
  separate from `[endpoints]`, delivered in its own packet.

Two qualifications:
- The intended session policy keeps the bearer off loopback and cleartext even when they are configured.
  Today only the static credential path enforces that. See §1.
- A configured `http://localhost` gateway gets `FUIGO_API_KEY`, not the session bearer.

### An inadmissible run, reported (A.2.1: report every complete run)

The first tip gate at `22a8cbaf` (logs in `logs/void-tip1/`) showed `fuigo-extra-ca` exit 101 with two unit
failures and one doctest failure. Those failures are exactly mutants M1 and M4. The source tree was clean.
The cause was that the mutant worktree and the gate shared one `CARGO_TARGET_DIR`. Cargo hashes path
packages by their path relative to the workspace root, so two worktrees of the same workspace produce
artifacts with identical names, and the gate reused mutant binaries. I aborted the session with
`pkill -s`, voided the whole run, deleted `target/`, gave the mutants their own `target-mut` and re-ran
the gate from a fresh target. Those results are the table above.

Void log sha256s:
- extra-ca `ade4b98f…62f18c3`
- sampler `36cf4648…94779c`
- shell-base `8dbaa142…6d859`
- shell, partial and killed: `a765f4a2…1a7`

The same hazard may have affected `focused2.log` (fuigo-shell, at `730a4323`), which ran in `src` after
M1–M5 had built in the shared target. Its 31 tests do not exercise the mutated items, and that commit's
behaviour was withdrawn, so I make no claim from it. **Lesson for the protocol:** a mutant worktree needs its
own target dir. Proposed as a LANE-PROTOCOL amendment.

## 8. Proposals (outside P30's charter)

1. **Session-token delivery has one predicate.** This is the recommended packet. Every path that can put
   the session token on the wire should decide the destination by `AuthBackend::may_receive_session`.
   `NotByok` and `Unknown` would then decide only whether the token is wanted. The packet needs
   wire-level tests with a buffered token (valid and hard-expired), parent and subagent. It is a
   behaviour change: a session user on a cleartext, other-port or unconfigured-loopback URL starts getting
   401s.
2. **Reclassify `x-fuigo-client-version` and `-client-identifier`** as product disclosure (the P15-R
   `client-mode` reasoning), or give every writer an `IdentityDisclosure`. Recommendation: reclassify.
3. **Auxiliary Ferrox-service clients** that send per-user identity should go through `IdentityDisclosure`,
   or a third class should be named explicitly.
4. **LANE-PROTOCOL:** mutants must use their own `CARGO_TARGET_DIR` (§6).
5. **Rename the remaining `fuigo-shell` test functions** that use `first_party` in the destination sense,
   in a strike-end sweep once failset continuity no longer matters.

  is covered at the predicate level (shell-base pin test) and at the sampler level (loopback wire test plus

- The two `compile_fail` doctests prove that the specific spellings do not compile. They do not prove that
  no other construction path exists. The audit found none by inspection.
- `fuigo-shell` ran with `session::workflow::manager::tests` skipped, so P30 has no evidence about those tests.
- No other workspace crate was test-run. `fuigo-tools` and `fuigo-workspace` were built in the gate as
  dependencies of `fuigo-shell`. `fuigo-voice` and `fuigo-pager` were not built at all. A grep shows that
  none of them references `is_first_party_url`, `endpoint_is_first_party`, the sampler's private fields
  or anything else P30 renamed. P30 changes no public signature they use, and `is_fluxrouter_url` is
  unchanged.
