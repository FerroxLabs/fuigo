# R142: P142, leader-mode one-off notices reach the user's client exactly once (e2e A1 T1)

Branch `strike/p142`, parent `71a99f8d7562261793ad0a938e7710e83db16d2e`, bundle base `e3139a99`.

## Bug
`fuigo_file_utils::destination_gate::announce_notice` and the withheld-upload notices (`announce_once` →
`announce_through`) print to the stderr of the process that hit the condition and record the text for
`replay_notices_since_last_replay`, which only the TUI's own process calls. In leader (shared-session) mode the agent
runs in the leader process, whose stderr is `~/.fuigo/leader.log`, so the user never saw F13 (Stranded), B1
(NotAdopted / MoveFailed) or the S4/B10 withheld-upload notices. Live evidence: `.ijfw/memory/e2e-1021/A1/RESULTS.md`
observation 1, TRIAGE T1.

## (2) Design
- `destination_gate`: every recorded notice bumps a process-wide `tokio::sync::watch` (`subscribe_notices`);
  `notices_from(cursor)` lists them. Independent of the TUI replay cursor. Printing is unchanged.
- Leader IPC server (`leader/server.rs` `forward_process_notices`): its own cursor; on each new notice and on each
  client registration it sends every unsent notice, oldest first, as the extension notification
  `_fuigo/leader/notice {"message": ...}` to every registered client that declared the new
  `ClientCapabilities.leader_notices`. The cursor advances per notice only when a client accepted it, so a notice
  recorded before any such client attaches waits and goes to the first one (once overall, not once per client); a
  notice recorded while such clients are attached goes to each of them in one delivery.
- Who asks: the TUI (`acp::tui_leader_capabilities`). The `fuigo agent stdio|headless` bridge (raw ACP editors,
  remote headless) does not, and is sent nothing; older clients (no field) are sent nothing; the notice waits for a TUI.
  Raw ACP clients: agent-client-protocol 0.10.4 `Client::ext_notification` defaults to `Ok(())` for unknown `_`
  methods, so even a forwarded notice would be ignorable; it is not sent to them at all.
- TUI: `fuigo/leader/notice` (and the `_`-prefixed spelling) queues the text; it is shown once as a system note in the
  session on screen once that session is idle, not in a running/wake turn, not into the hidden home session behind
  the welcome screen, not into a parent hidden by a fullscreen subagent. A pending notice asks for a slow tick while
  a session is on screen. Notices still unshown when the TUI quits (normal or error exit) are printed after the
  terminal restore, only when the writer thread joined (a stalled terminal is never written to).
- Residual by design (Astra accepted): a notice the leader queued for a client that disconnects before the socket
  write is lost for that client (no ack protocol); the leader keeps notices only for its own lifetime.
