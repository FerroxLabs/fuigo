# R-xs-p12: TUI for peer messages (partial)

Module `fuigo-pager/src/peer_ui.rs` (tests `peer_ui_tests.rs`), one hook in `acp/tracker.rs::handle_user_message`. Everything is behind `features.peer_messaging` (`peer_ui_enabled()`: requirements pin, env, user config; the remote tier is not read by the pager). Flag off: the tracker branch, rows, notices, marker and dialog all return nothing and the TUI is unchanged.

## Done
- Preview row (wired). A `UserMessageChunk` whose prompt id starts `peer-message-` (the id the shell gives an admitted peer row) is parsed from the `<cross-session-message>` wrapper and drawn as ONE system row: `↪ Message from another session "<name>" [<ref>]: "<first line>"`. The model-facing note and wrapper are not drawn. Source: the existing user echo of the peer turn. Name, ref, first line go through `fuigo_tty_utils::quoted/bracketed`: control, bidi and zero-width characters removed, line breaks become spaces, capped (40/16/120 columns). First line only (LF, CR, NEL, U+2028, U+2029 end it).
- Held row text `held_row_text`: sender, reasons, `sender_denied` kinds and counts only (`bash x2`), expiry. Pure builder, tested; not wired (see below).
- Notice rows `notice_row_text` (delivered, released, refused, expired, integrity warning, laundering refusal): fixed text plus escaped names or path; released notice says "No tool call was approved." Builder only.
- Influence marker text `influence_marker_text`: `peer-influenced  /peers clear-influence`. Builder only.
- Hold dialog `PeerHoldDialog` (state, keys, `lines()`, `render_peer_hold_dialog`): sender, its reported mode vs this session's, reasons, denial note, first line, expiry, and the fixed sentence "Accepting delivers the message to this session. It does not approve any tool call." Keys: `a` sends exactly `/peers release <id>`, `r` exactly `/peers refuse <id>`, Esc/d/q dismiss (stays held), everything else (Enter, y, digits, ctrl-a) is ignored. `tick(now)` turns it to "expired" and accept/refuse then send nothing. `open` refuses an id that is not `[A-Za-z0-9._-]{1,128}` (it goes into a command).

## Needs a shell event, therefore NOT wired
The shell sends the pager nothing structured about peer state. Holds, releases, expiries, integrity and laundering notices live in the admission notice ring ("no transport", R-xs-p4/p6b2/p7) and are readable only as `/peers held` text. So these cannot be fed from real data without inventing a protocol:
- held row and hold dialog open (needs a held-message event carrying id, sender name/ref, sender mode, own mode, reasons, denial counts, expires_at, first line);
- notice rows (needs a notice event: kind + name/path);
- influence marker (needs a peer-influenced state event/meta);
- dashboard `[ref]` for listed sessions (needs the ref in the session roster data);
- human-authored send from the dashboard: needs a shell entry point for a human peer send (none exists; `/peers` has list, status, held, release, refuse, clear-influence only).
- The dialog is also not yet placed in `AgentView` key routing and `blocking_card`; when the held event exists, that is the only remaining wiring.
- PTY test for the dialog: not done (dialog not reachable from the real app yet).

## 12b: connected to the shell (packets 9 and 13)

Code: `fuigo-pager/src/peer_ui_state.rs` (state, event parse, request build, error text; tests `peer_ui_state_tests.rs`), `app/agent_view/peer.rs` (keys), `app/dispatch/peer.rs` (dispatch), app-level tests `app/acp_handler/tests/peer_ui.rs`. Flag off: the notification hook, the key hook, the reserved row, the dialog and the opt-in all return before doing anything.

### Connected
- **Event intake** (`acp_handler/session_notification.rs::handle_peer_event`, before the typed parse): `peer_held` adds a held row; `peer_released` / `peer_refused` / `peer_expired` remove it and show one notice line; `peer_reheld` brings the row back (from the last known row, else a bare one) and closes a dialog holding its dead token; `peer_warning` shows one notice line. A `heldId` must be `h-<32 hex>`; unknown `peer_*` names and malformed payloads are ignored. Every string goes through packet 12's `name_field` / `ref_field` / `quoted` / `capped` (one line, no control or bidi characters). Nothing from an event is executed, expanded or put in the prompt.
- **Held row**: one row reserved under the transcript (`render.rs`): count, newest sender / reasons / expiry, `[Alt+h] review`.
- **Hold dialog**: `Alt+h` (acts only while something is held; Alt+h had no other binding) calls `fuigo/peer/list_held`, so every open has fresh tokens. The token lives only inside the open dialog and is consumed by the one decision; `Debug` of a token is redacted. `a` = `fuigo/peer/release` with `heldId`, `token`, `action:"release"`; `r` = same with `action:"refuse"`; Esc / d / q dismiss (token dropped, message stays held). While the dialog is open every key is swallowed (nothing reaches the prompt). Errors are one plain line each (`unavailable`, `no_operator`, `not_opted_in`, `expired`; stale `bad_token` / `not_found`: the list is refreshed ONCE without opening the dialog and the user chooses again). A release is never re-sent. The dialog shows the shell's `detail` as the denial note for a `sender_denied` row, and the sender's reported mode.
- **Operator presence (item 3)**: packet 9's TUI opt-in is internal (`peer_inbox/driver.rs::admission_for`: pager = opted in, operator `Present`). That path starts NO event pump: the pump is started only by `fuigo/peer/configure` (`extensions/peer.rs::handle`). So after a session is created or loaded, a terminal TUI sends exactly one `fuigo/peer/configure {optIn:true, operator:"attended"}` (no policy, so the default `accept`, the same admission the pager driver already holds). Sent only with the flag on and stdin and stdout both a terminal. It is not a second competing admission: same values for the pager driver.

### Not connected / limits
- **Influence marker**: unconnected. The shell sends the client no influence state (`peer_influenced` is internal and in hook payloads only). `PeerUiState::influenced` stays false; `influence_marker_text` is still a builder only.
- The wire does not carry this session's own mode, the first line of the held body, or denial counts. The dialog leaves those lines out (no invented text); the held row has no body preview.
- Behind a leader: the configure says `attended` while this window is attached; nothing sends `may_return` on detach or an opt-out on exit (limit; the shell session keeps the last configure).
- A remote client attached to a leader makes all four methods answer `unavailable`; the user sees the plain line when opening the dialog.
- Dashboard `[ref]` and the human-authored send stay as listed above (no shell source).
- Opening the dialog shows the first row only; after deciding it, press `Alt+h` again for the next.
- No PTY test: the app-level tests (above) drive `AgentView::handle_input`, `dispatch`, `effects::execute` and a fake ACP agent.

### 12b round 2 (audit fixes; pager only)
- **Hold dialog, fixed layout** (`peer_ui.rs::render_peer_hold_dialog`): no `Paragraph`, no wrapping. Inner rows top to bottom: body rows (each peer value on its OWN single line, after a fixed label, inside quotes or brackets, cut to the inner width with an ellipsis: `From: "..." [..]`, `Sender mode (its claim): "..."`, `Held because: <labels>`, `Note: ... "..."`, `Starts: "..."`, expiry), then the three last inner rows drawn from Fuigo constants only: sentence part 1, sentence part 2 ("It does not approve any tool call."), legend. Body rows are clipped by count, never the fixed rows. Minimum size 52 columns x 6 rows (`DIALOG_MIN_WIDTH`, `DIALOG_MIN_HEIGHT`: 2 border + 1 body + 3 fixed). Smaller: one "Terminal too small to accept" line, and `a` is ignored (`r` / Esc still work). `a` also does nothing until one frame has shown the fixed rows (`fits` is set by the paint, starts false).
- **Reasons** are pager labels (`mode mismatch`, `loop guard`, `sender denied`, `integrity`, `policy hold`, `held again`), unknown name = `other`, at most 4 then `+N`. Same in the held row. Denial kinds and the shell note are quoted.
- **Ingest caps** (`peer_ui_state.rs::hold_from`): name and ref 64, mode 32, detail 200, 8 reasons of 32 characters. **Notice rate limit**: 20 peer notice rows per 60 s window per view, then ONE "more peer notices suppressed" row until the window passes (`apply_event_at`).
- **Notices are one row**: the peer notice row uses a new `SystemMessageBlock::single_line` (`RenderBlock::system_single_line`): first line only, cut to the width with an ellipsis, never wrapped, so no second visual row can start with peer text. `peer_warning` text is now quoted too (`Warning from a peer notice: "..." about "..."`).
- **Paste** is swallowed while the dialog is open (`agent_view/peer.rs`).
- **Configure** (audit NOT-CHECKED): yes, a create followed by a load (or a repeated load) of the same session sent `configure` twice, and the second voids an open dialog's token. Now `PeerUiState::note_configure` sends it at most once per session id per agent view; a different session id while a dialog is open closes the dialog with a one-line notice. Limit: "per connection" is the agent view's lifetime; a reconnect that rebuilds the view configures again, and a reconnect that keeps the same view and session id does not.
- Tests: `forged_legend_cannot_displace_or_imitate_the_fixed_rows`, `reasons_are_pager_labels_at_most_four_then_a_count`, `too_small_terminal_shows_a_notice_and_does_not_accept`, `warning_text_is_quoted_not_bare`, `hold_fields_are_capped_at_ingest`, `notice_rows_are_rate_limited_then_one_suppressed_row`, `configure_is_sent_once_per_session_id_and_closes_an_open_dialog`, `single_line_system_note_never_wraps`, `paste_is_swallowed_while_the_dialog_is_open`.

### 12b round 3 (audit fixes; pager only)
- **Exclusivity** (`agent_view/peer.rs::other_overlay_active`): the peer hold dialog and any other overlay are never active together. The helper lists: permission card, cancel-turn panel, question, MCP elicitation (`blocking_card()`), rewind, jump, btw panel, `active_modal`, line / image / video / block viewers, `/gboom`, agents / extensions modals, persona detail, goal detail, workflows, plan approval, a fullscreen subagent, `@` file search and history search. It is pinned by `other_overlay_list_matches_the_draw_overlays` (reads `render.rs`: every listed render call must still exist and be tested by the helper, and any new `render_*_overlay|modal|panel|detail` call not in the table fails). `Alt+h` with another overlay up: no dialog, one notice "finish the open prompt first". If another overlay becomes active while the dialog is open it is closed (token dropped, same notice) at the top of `peer_input`, before any key is handled, again at the start of every draw, again when a `list_held` reply lands, and a `Decide` action re-checks before it takes the token. Flag off or no dialog: all no-ops.
- **Draw order** (`agent_view/render.rs`): `draw` is now a thin wrapper around `draw_layers` (the old body, unchanged); the wrapper paints the dialog after `draw_layers` returns, so it is the last thing painted in the agent view. The AppView layers painted after the agent view (import-Claude modal, tutorial, fps overlay, scroll debug panel) mark the dialog unpainted (`app_view.rs`), so `a` waits for a frame without them.
- **Freshness** (`peer_ui.rs`): `fits` now means "this frame painted the fixed rows inside the rect used, and no resize since". Cleared by `begin_frame` (start of every `draw`) and by `note_resize` (called from `AgentView::note_terminal_resize`, which `AppView` runs when it first sees `Event::Resize`, before any key of the batch). Set only at the end of `render_peer_hold_dialog`, and only if the dialog rect lies inside the buffer actually flushed.
- **Screen disturbed** (generalises the resize rule): `AppView::note_screen_disturbed` (`app_view.rs`) is the one hook (it clears `fits` of every peer dialog, `PeerHoldDialog::note_screen_disturbed`). The event loop calls it at the top of `handle_one` for every non-key event (focus gained / lost, resize, paste, mouse), before any later key of the batch, and `handle_input` calls it again for the same events. `event_disturbs_screen` is an exhaustive `match` on `Event`, so a new variant fails to compile.
- Also called on every path that forces a full clear or leaves the screen to another program: the forced-repaint `terminal.clear` in `present_if_dirty`, return from `$EDITOR` / `$PAGER` suspend, and `reseed_screen_mode` (mode switch). After any of these `a` needs a frame painted afterwards; `r` and Esc are not gated. No peer dialog open (flag off): all no-ops, no existing event handling changes.
- Tests: `focus_gain_then_a_in_the_same_batch_is_not_accepted_until_the_next_draw`, `focus_lost_then_focus_gained_then_a_is_not_accepted_until_the_next_draw`, `mouse_then_a_is_not_accepted_and_r_still_refuses`, `every_non_key_event_reaches_the_screen_disturbed_hook`. The `note_resize` hook of the Freshness bullet is now `note_screen_disturbed`.
- **Width** (`peer_ui.rs::fit_line`, `line_width`): cut by grapheme cluster (`unicode-segmentation`), cluster width = max(tty-utils `display_width`, unicode-width), at least 2 for a multi-scalar non-ASCII cluster. Never splits a cluster. `scrollback/blocks/system.rs::cut_to_width` uses it. `fuigo-tty-utils` is unchanged.
- **Delivered preview** uses `RenderBlock::system_single_line` (`acp/tracker.rs`). **`peer_warning`** text is capped at 200 chars (subject 64) when parsed.
- Tests: `permission_card_gets_a_and_no_release_is_sent`, `alt_h_does_not_open_over_another_overlay`, `list_reply_after_an_overlay_opened_does_not_open_the_dialog`, `resize_then_a_before_the_next_draw_is_not_accepted`, `dialog_is_painted_last_with_the_fixed_rows_on_screen`, `other_overlay_list_matches_the_draw_overlays`, `a_waits_for_a_fresh_frame_and_a_resize_clears_it`, `a_dialog_that_does_not_fit_the_flushed_buffer_is_not_accepted`, `cut_by_cluster_never_overflows_or_splits`, `dialog_with_emoji_clusters_keeps_rows_in_width_and_fixed_rows_intact`, `delivered_preview_is_a_single_line_block`, `peer_warning_text_is_capped_when_parsed`.
- **Stated limits**: the cluster width is a safe over-estimate (a ZWJ family counts as the sum of its members, so such text is cut earlier than needed), not an exact terminal width. A terminal that renders a cluster wider than both tables say is not covered. The dashboard-popup draw path is covered by the same wrapper but the AppView layers there are not enumerated. Whether ratatui's flush wraps a wide glyph onto the next row (audit NOT-CHECKED) was not changed. Which foreground widgets bind `a` is no longer relevant: they are exclusive with the dialog. The remaining `a` hole is a terminal that does not honour what was painted (e.g. a screen the OS composites over the terminal).

#### After the focused audit (decision 60)
- **Children own no peer state** (the audit found the dialog of a subagent view could be released with a stale paint). `AgentView::owns_peer_ui()` is false for a view marked `is_subagent_view`; `mark_as_subagent_view` also resets its `peer` state. Gates: `peer_input` (no `Alt+h`, no `a`/`r`), `draw` (no `begin_frame`, no dialog), `handle_peer_event` (a `peer_*` event for a child is ignored), `startup_effects`, `on_rpc_done`, `dispatch_peer_ui`.
- **Any key the dialog did not take clears the painted proof**: `AppView::handle_input_at_with_paste_provenance` is now a wrapper around the old body. After it, a key event for which no dialog's own key handler ran (`PeerUiState::key_taken`, set in `peer_input` when the dialog is open) calls `note_screen_disturbed`. So a key handled by the tutorial, the import modal, any overlay or the composer needs a fresh frame before `a`. Keys the dialog itself swallows (other letters) keep the proof. The non-key hook stays.
- **View changes**: `open_subagent_fullscreen` / `close_subagent_fullscreen` call `AgentView::peer_view_changed` (disturb, close an open dialog, token dropped, the same one-line notice). `dispatch` and the input wrapper compare `AppView::focus_signature` (active view plus the active agent's fullscreen subagent) before and after and do the same for every agent on a change.
- Tests: `a_child_view_gets_no_peer_state_row_or_dialog`, `tutorial_dismissed_then_a_in_the_same_batch_is_not_accepted_until_the_next_draw`, `a_key_the_dialog_ignores_keeps_the_painted_proof`, `close_then_reopen_fullscreen_then_a_in_one_batch_is_not_accepted`, `the_focused_view_changing_through_dispatch_closes_the_dialog`.
- **Stated limits (NOT CHECKED by the audit)**: the order in which a terminal resize and a key are polled; inline-mode output written above the viewport; a child process writing to the terminal outside the `$EDITOR`/`$PAGER` suspend; other signals; the painted flag is set before the terminal writer acknowledges the flush.
