# R175c: deny/ask rules written through a symlinked directory (MED-2)

Defect: `Deny(Read(<link>/secrets/**))` was not applied to `<real>/secrets/x`. Only the ACCESS path was followed to
its physical form; the RULE's literal directory prefix was compared as written.

Change (tighten only): `policy.rs` `CompiledPolicy` keeps, per Deny/Ask rule with an absolute pattern, the literal
directory prefix (`alias_prefix`). In `evaluate_rules_with_base`, when such a rule does not match as written, the
pattern with that prefix canonicalised (`dunce::canonicalize`) is tried too (`alias_pattern_matches`). Allow rules
never get it; a prefix that does not canonicalise, or does not change, keeps today's behaviour; no absolute deny/ask
rule means no filesystem call. `evaluate_rules_with_base` is the one matcher used by the native Read/Edit/Grep
evaluation (policy.rs), the symlink-target re-check and the shell gate (`shell_access.rs` `evaluate_shell_path`),
so one site covers all surfaces. P198's `resolve_read_target`/`evaluate_read_targets` judge the ACCESS in every
spelling and call this same matcher; they are unchanged and now also get the alias.

Table (Linux, `real/` and `link -> real`). before -> after:
| surface | rule via link, access physical | rule physical, access via link |
|---|---|---|
| Read / Grep (policy.rs follow at ~253) | not applied -> applied | applied (target followed) |
| Edit (same path) | not applied -> applied | applied |
| shell read/redirect (shell_access.rs ~213) | not applied -> applied | applied |
| ask rules, same cells | not applied -> applied | applied |
| allow rules | unchanged (never widened) | unchanged |
