# R112: P112, GitHub Release assets come from the npm registry (finding RL-01)

Branch `strike/p112`, base `strike/integration` = `d1b6ba580eb587594d52b5a2550c1bd82a8bcd60`. No cargo run anywhere
(no Rust changed). Lane `/root/fuigo-builds/p112` used only for docker lint.

## Finding

RL-01 (MEDIUM, phase-7 Astra integrity audit): after a partial publish, a re-run rebuilds. The publish job skips
npm versions that exist (build A stays on npm), while `github-release` laid out the fresh build B and compared it
only with B's local tarballs; `verify-published-platform.js` checked arch, version and commit text, not bytes. So
GitHub could ship binaries and SHA256SUMS that differ from npm.

## Fix

- `scripts/release/registry-release-inputs.sh` (new): for the version, `npm pack` each of the seven published
  packages from the registry; each tarball's locally computed sha512 must equal `npm view <spec> dist.integrity`;
  the executable is brotli-decompressed from the REGISTRY tarball into the layout `github-release-assets.sh` reads;
  `release-manifest.json` is rewritten (same shape as `verify-package-archives.js`) from the registry tarballs.
  Optional fourth argument: this run's build artifacts, compared byte for byte and reported as `::warning::` on
  drift. They are never used as release bytes. Refuses non-empty out dirs and versions npm does not have.
- `release.yml` `github-release` job: `setup-node`; the npm-packages artifact download is gone; the layout step runs
  `registry-release-inputs.sh` then the unchanged `github-release-assets.sh` on its output. Raw binaries, tarball
  copies and SHA256SUMS are therefore all registry-derived, on the first run and every re-run. These are the bytes
  `verify-published` executed natively. Reconcile logic, `replace_release_assets` and the read-back are unchanged:
  a release left with build-B assets by an earlier run now fails as "differ" unless `replace_release_assets`.
  The publish job's dry-run layout check still uses this run's build (it proves the layout before anything ships).
- `verify-published-platform.js`: its JSON line also logs the sha256 of the registry executable.
- `github-release-assets.sh`: header comment only.
