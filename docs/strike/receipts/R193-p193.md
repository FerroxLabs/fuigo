## Round 2 (Grok r1, NOT-LAND-OK, finding U8)

The rule for this round: no prompt, side question, fork message or queued row is silently lost or silently stuck on a tab whose
load failed, and a tab whose session is loaded is never put in the refused state.

### The load-attempt rule

Every load takes a number from its agent (`AgentView::begin_load_attempt`, field `load_attempt`). The number rides on
`Effect::LoadSession { attempt }` and comes back on `TaskResult::SessionLoaded` and `SessionLoadFailed`. A result whose number is
not the agent's latest is ignored and logged (`load_result_is_stale`). Starting a reconnect reload window also takes a number
(`begin_session_reload`), so the `/resume` task still running when the leader reconnects is superseded the moment the reconnect load
starts. The four sites that emit `LoadSession` (picker/`/resume`, restore-then-load, the two fork paths) each take a number.
The value 0 means "unstamped" and is accepted; only hand-built test results use it, no production load does.
The JoinSet task is not aborted: it still runs to its end, and its late result is dropped by the number.

### Stale rule, as now defined

A load result (success or failure) is dropped when its attempt number is not the tab's current attempt (unchanged: `load_result_is_stale`).
What changed is the state a failed newer attempt leaves: the tab is unbound and `load_failed`, so the older task's late result,
success or failure, finds a refused tab and is dropped. Decision on the late SUCCESS of the older attempt after the newer one failed:
it is ignored; the tab stays refused and the user runs `/resume`, which starts a fresh attempt. (Reviving the tab from a result whose
replay events were never stamped could mix two replays, so this is the simpler sound rule.) A late result is therefore never able to
return held rows a second time or list a second failure line (asserted).
