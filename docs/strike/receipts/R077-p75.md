## 1. The class

Release is `panic = "abort"`. `println!`/`print!`/`eprintln!`/`eprint!`/`dbg!` panic when the write fails (EPIPE: reader
gone; ENOSPC: `/dev/full`, a full disk behind a redirect). One print on a dead fd turns a working command into SIGABRT.
P05b (R060) and P68 (R070) introduced `fuigo_tty_utils::cli_println!` / `cli_eprintln!` (best effort; a hard stdout
failure is recorded in `best_effort_stdout::hard_failure()` and the pager exits 1 on it; stderr failures change nothing)
and swept `fuigo-pager`, `fuigo-pager-bin`, `fuigo-shell`, `fuigo-telemetry`. P75 covers everything else that ships, the
third-party code fuigo reaches, and makes the rule mechanical.

Reproduction (previous agent, lane logs kept): the P75 tests run against the pre-sweep binary
(`PAGER_BINARY=/root/fuigo-builds/p75/parentbin/fuigo-pager`, `repro2.log`, 2026-10-02T14:28Z): `dead_output_sweep`

### 15.5 The two flaky tests
**One cause for both.** `DreamLock` (`std::fs::File::try_lock`) and `TurnOwnerLock` (`fs2`) are `flock` locks, which
belong to the open file description. A child forked by a concurrent test in the same test binary holds a copy of the
descriptor until it execs (`O_CLOEXEC` closes it only then), so the lock outlives the guard's drop for that window. The
failing statements are exactly the ones that take the lock again in the statement after releasing it:
`dream_lock.rs:140` (`called Option::unwrap() on a None value`), `:153` (`assertion failed:
lock.acquire(0).unwrap().is_some()`), `interrupted_turn_tests.rs:448` ("once the owner is gone the same turn is
recoverable"). Sightings: `p43g-tip`, `p47rp2-parent`, `s26a-parent` (memory), `p84g-parent` (shell). The same file's
`eventually_recoverable` (`aa30617a`, P09-F) already documents this mechanism for two neighbouring tests. R099's
proposed OFD lock would not help: `F_OFD_SETLK` locks are inherited across fork in the same way (Astra r8 agrees).

**Fix `e2858d22`, test-only, no production change.**
- `fuigo-memory/src/dream_lock.rs:133-147`: helper `acquire_once_released` polls `acquire` for up to 10 s of real time;
  used at the four re-acquire-after-release sites (`:157`, `:160`, `:162`, `:170`). I/O errors still fail at once; the
  held-lock exclusion assertion (`:154`) is unchanged.
- `fuigo-shell/src/session/interrupted_turn_tests.rs:448-479`: after `drop(live_owner)` the test polls `recover_with`
  for up to 10 s; every refused attempt must have appended nothing and left the events log byte-identical; after the
  successful one the append count must be exactly 1 (stricter than before on that point).

**Evidence** (`rb2.sh` sid 1773005, `rb2.out` sha256 `2fdc95a7039f133337020f14fdf31a406c6bde1089e2e13d263957b8d7f1fd31`; `r2.out` as above):
