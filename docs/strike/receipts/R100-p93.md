## 1. Read first: what is NOT met, and the decisions

1. **Accepted open by design (Sean, 2026-10-03), not fixed:** R089's last Astra HIGH (round 3, finding 1:
   `_fuigo/skills/add` with a path containing `${FUIGO_API_KEY}`, then `_fuigo/skills/config` returns it expanded) and
   its whole class (an active relay reading files, running terminals, adding MCP servers with `bearer_token_env_var`,
   writing config and reading it back env-expanded) stay open **for an opted-in relay**. Policy reference:
   `docs/destination-trust-policy.md`, section "Relays not operated by FluxRouter (P93)": an opted-in relay is trusted
   to drive the agent exactly like the local client; P82's filters protect only against passive leaks. What P93 closes
   is the other half: such a relay is never bridged unless the user opted in to its origin.
2. **Relay sync is not gated** (TUI session sharing, `relay/sync.rs`, `[relay] enabled`): the relay cannot send the
   agent requests through it (Astra r1–r3 agree), but it still receives the session transcript. Proposal 1.
3. **An opted-in relay can opt in further origins**: it can write `$FUIGO_HOME/config.toml` through
   `_fuigo/fs/write_file` (absolute paths, confinement off by default). Inherent in "trusted to drive the agent";
   documented in the policy and the user guide (Astra r1 finding 4).
4. **Not a CLI flag**: the opt-in is the user config key or the environment variable. A flag would not reach a leader
   that interactive clients auto-spawn; the env var reaches only processes started after it is set (documented).
5. **Interactive TUI with an auto-spawned leader**: the leader's refusal is logged and written to the leader's stderr; a
   TUI user does not see it in the TUI (a `fuigo agent headless` client does: it refuses itself, with the same text).
6. **Behaviour changes that need Sean's yes** — release notes in §2.

## 2. User-visible behaviour changes (one-sentence release notes)

- **Self-hosted relays (the requested change):** *"If you connect `fuigo agent headless` or `fuigo agent leader` to a
  relay that FluxRouter does not operate (`FUIGO_WS_URL` / `--fuigo-ws-url` / `fuigo_com_config.fuigo_ws_url`), add
  `trusted_origins = ["https://your-relay.example"]` under `[relay]` in `~/.fuigo/config.toml` (or set
  `FUIGO_TRUSTED_RELAY_ORIGINS`), otherwise Fuigo refuses to connect and tells you what to set."*
- **`--fuigo-ws-url` with a leader:** *"`fuigo agent --leader headless --fuigo-ws-url URL` now reaches the leader for
  that URL; the flag used to be ignored on the leader path (the configured URL was used)."* (Astra r1 finding 1.)
- **Leader relay demand:** internal: the leader's IPC server now notifies relay demand on every headless
  registration, not only the first, so a leader that refused re-reads the opt-in when the next headless client
  attaches. No visible change for FluxRouter relays.
- Unchanged: FluxRouter-operated relays (`wss` to the FluxRouter API host), the default install (no relay URL:
  `NoRelayConfigured`, P47 still refuses an empty URL before any socket), local stdio / IPC clients, `agent serve`.

## 3. What was built

`crates/codegen/fuigo-shell/src/agent/relay_opt_in.rs` (new): `relay_bridge_gate(ws_url)`:
- blank URL → `NoRelayConfigured` (unchanged default install);
- `IdentityDisclosure::for_websocket_destination(ws_url)` (the P43/P77/P81/P82 rule) → `FluxRouterOperated`;
- otherwise the relay's origin (`wss`≡`https`, `ws`≡`http`, host lowercased/punycoded, trailing dot dropped, effective
  port; userinfo, path, query ignored) must equal an opt-in entry, else `RelayOptInRefused` (Display names the origin,
  the `[relay] trusted_origins` line, the user config path, `FUIGO_TRUSTED_RELAY_ORIGINS=<origin>`, that a project
  config cannot set it, and that a running leader re-reads the file on the next headless client; never the URL path
  or userinfo). Opt-ins are read at each decision from `FUIGO_TRUSTED_RELAY_ORIGINS` (comma/whitespace separated) and
  from `crate::config::load_from_disk()` — the user layer `$FUIGO_HOME/config.toml` alone, never the merged config,
  so project `.fuigo/config.toml`, the `FUIGO_CONFIG` overlay, managed config, remote settings, campaigns and
  requirements cannot supply it. `relay.trusted_origins` is in `NON_SERDE_CONFIG_PATHS` (no unknown-key warning) and
  in `config_docs` `USER_ONLY_KEYS`.

Call sites (every production bridge to a relay; Astra r1–r3 enumerated `spawn_relay_connection*` callers and found no
other):
- `agent/app.rs` `run_headless`: decides first (before login, prefetch or any socket) and returns the error;
  `spawn_headless_relay` decides again on the relay config it opens.
- `agent/app.rs` `spawn_leader_relay` (eager, on demand, and `DeferredRelayArm`): refused → no relay task, no socket;
  the leader serves local clients, logs (tracing warn) and prints the refusal to stderr, and decides again, re-reading
  the user config, on every later headless registration. The demand watch is marked seen BEFORE the decision, so a
  registration arriving between the refusal and the waiting task's first poll is not lost (Astra r2).
- `leader/server.rs`: every headless registration `send_replace(true)` (was: only the first).
- `fuigo-pager-bin/src/main.rs` (`fuigo agent [--leader] headless`, leader path): applies `--fuigo-ws-url` /
  `--fuigo-ws-origin` (`apply_headless_url_args`), then refuses with the same error before contacting any leader.

Docs: `docs/destination-trust-policy.md` (new P93 section; P82 "not covered" sentence now points to the decision);
`fuigo-pager/docs/user-guide/15-agent-mode.md` ("Relays FluxRouter does not operate need your opt-in");
`26-config-reference.md` (`relay.trusted_origins` row, Managed `—`).
