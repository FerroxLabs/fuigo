## What changed
- **Policy sources** `fuigo-config/src/policy_sources.rs` (new): every policy layer — MDM, `/etc/fuigo/{requirements,
  managed_config}.toml`, `$FUIGO_HOME/{requirements,managed_config}.toml` (the latter is what Fuigo's own managed-config
  endpoint writes, P47; nothing is fetched here), the Claude `managed-settings.json`. Only policy keys are kept (both
  spellings). Contents and ownership come from one opened file; an admin-tier file not root-owned or group/other-writable
  counts as user-owned. A file that exists but cannot be read/parsed, a dangling symlink, a broken or non-string forced
  MDM payload: an `Err` source → fail closed. No `$VAR` expansion of policy keys. Tighten-only pins (`PolicyPin`) for
  `enable_all_project_mcp_servers` and `allow_managed_hooks_only`, admin re-attributes a user pin.
- **S15 engine** `fuigo-workspace/src/permission/managed_policy.rs` (new) + `resolution.rs`: `McpServerPolicy` (sources),
  strictest wins (any deny; every restricted source allows; `allow_managed_mcp_servers_only` needs a grant from a layer
  the lock's owner accepts — a user layer cannot satisfy an admin lock); empty/malformed lists and unenforceable deny
  entries lock down; `serverCommand` exact argv; attributed `McpVerdict`/`McpBlockReason` (Deny/NotGranted/Lockdown/
  ProjectPin; refusals name the file only). `MarketplacePolicy` intersects sources; an empty strict list is a lockdown.
- **S15 refusal before write**: `/mcps` add/edit (`mcp/upsert`, incl. project pin), setup, toggle; sessionless agent
  MCP pool; marketplace add (TUI + CLI); direct plugin install by git URL or path (CLI, `/plugins install`, modal);
  plugin path add; plugin enable (modal/ACP/CLI; under a restriction the persisted entry is the approved install's full
  plugin id, so a same-named project plugin is not enabled); post-install auto-enable (same); plugin update of a
  no-longer-allowed source; local marketplace sources dropped under a restriction. Project pin judged at the session
  merge, `mcp/list`, doctor, inspect.
- **S15 rows/badges**: `fuigo inspect` `policyRows` (mcpServers / marketplaces / projectMcp / managedHooksOnly /
  allowedModels) + human "Managed policy" section; `fuigo mcp doctor` one row per enforcing source + project pin;
  `/mcps` full modal `[blocked by policy]` and minimal mode `blocked by policy` badge from the shell's `blockedReason`.
- **S11** `fuigo-hooks`: `DisabledHooks` carries the pin; one `skip_reason` rule for dispatch, stop-gate guard and modal;
  only root-owned managed-policy hooks (`/etc/fuigo` managed_config/requirements) run. Shell refuses hook enable, bulk
  enable and hook-path add with `MANAGED_HOOKS_ONLY_NOTE`.
- **S16** `fuigo-shell`: `Requirements.allowed_models: Constrained<AllowlistPin>` (List / FailClosed) pinned from
  requirements (malformed → FailClosed; unreadable requirements file or MDM → FailClosed); `effective_allowlist` (pin
  replaces user list, matches model id only, empty pin = unrestricted). Enforced via `user_selectable` at `-m`/default
  (startup, also before the first catalog and for ids the catalog lacks), `/model` + ACP `session/set_model`
  (`set_model_gated`), `session/new` custom model, agent-profile models, reasoning-effort model routes; policy wording.

## Behaviour changes (need the coordinator's attention)
1. Claude `allowedMcpServers: []` (present, empty) now blocks every MCP server (Claude semantics); 1.0.21 read it as
   unrestricted. Same for `strictKnownMarketplaces: []`.
2. An admin policy file (`/etc/fuigo/{requirements,managed_config}.toml`, MDM, the Claude `managed-settings.json`) that
   exists but does not parse, or is not root-owned, or is group/other-writable, now locks MCP + marketplaces down,
   engages both pins and (requirements/MDM) makes no model selectable; 1.0.21 skipped a broken file and applied a
   writable one. A broken user-home `~/.fuigo/requirements.toml` / `managed_config.toml` warns and is skipped (as in
   1.0.21; Round 4 consistency rule shared with P183); a user file that parses still binds, and a malformed key in it
   still fails closed.
3. An unenforceable `deniedMcpServers` entry now fails the whole source closed (was: warn and skip).
4. Under strictKnownMarketplaces: local marketplace sources are dropped, direct installs from an unlisted URL or any
   local path are refused, plugins with no Fuigo install record (e.g. Claude-imported) cannot be enabled (provenance
   unverifiable; Astra r2 accepted the rationale).
5. Hooks synced into `~/.fuigo/managed_config.toml` are NOT managed policy (user-writable), so under the hooks pin they
   do not run; only `/etc/fuigo` hooks do (upstream rule).
6. Under strictKnownMarketplaces (Round 4): only plugins installed from an allowed source load, and only when enabled by
   their full plugin id. Project, user-dir, Claude-installed, `[plugins].paths`, `--plugin-dir` and session `pluginDirs`
   plugins do not load (their hooks, MCP servers and skills are gone); Claude `enabledPlugins` is not merged; a
   pre-existing bare-name `[plugins].enabled` entry for an allowed install stops enabling it (re-enable writes the id).
7. Under a fleet `[models] allowed_models` pin (Round 4) a subagent model outside the pin (`[subagents.models]`,
   `AgentDefinition.model`, goal/persona override, alias) inherits the parent model; resuming a subagent whose source
   model the pin excludes is refused with the policy reason. A user-only `allowed_models` list does not bind subagents.
8. In-process SDK MCP servers (`_meta["fuigo/mcp/servers"]`) now run only when no `serverName` deny matches and every
   restricted source grants them by `serverName`; any MCP lockdown drops them (Round 4).

### HIGH: fleet pin did not bind helper sampling (confirmed)
Confirmed against the rebased code: `resolve_aux_model_sampling_config_inner` and `resolve_web_search_sampling_config` never
read the pin, and the unknown-slug fallthrough synthesized an entry on the inference route. Prompt suggestions used
`model_in_catalog` (membership), not selectability.
Fix: `helper_model_admitted(allowlist, catalog, slug)` (`agent/models/resolution.rs:294`). Under a fleet pin (list or
fail-closed) the slug must be a catalog entry whose model id the pin admits; anything else is refused. Both resolvers take an
`&EffectiveAllowlist` and return `None` (caller falls back to the admitted session model; web search is disabled).
`ModelsManager::helper_model_admitted` (`agent/models.rs:740`) is the same predicate for the session sites, and
`recap.rs:683` now requires it for the suggestion model. A user list (`[models] allowed_models`) never binds helpers; an empty
pin is unrestricted.
Tests (`p169_tests.rs`): `fleet_pin_binds_helper_aux_sampling`, `fleet_pin_binds_web_search_sampling`,
`manager_helper_admission_follows_the_fleet_pin`, control `helper_sampling_is_unbound_without_a_fleet_pin`.

### MEDIUM: strictKnownMarketplaces trusted the user-writable install record (confirmed, closed in part)
Confirmed: `plugin_load_restriction` admitted every plugin id of a record whose source string was allowed, whatever `path`
named. Fix: `InstallRegistry::verified_source_identity` (`fuigo-agent/src/plugins/install_registry.rs`) trusts the record only
when the checkout canonicalizes inside the registry's install dir (symlinks and `..` resolved) and, for git installs, the
checkout's own `.git/config` `origin` names the recorded URL. `plugin_load_restriction` uses it.
Tests (`managed_policy_tests.rs`): `plugin_load_restriction_ignores_a_record_pointing_outside_the_install_dir` (the audit's
`/tmp/evil`), `..._ignores_a_symlink_out_of_the_install_dir`, `..._requires_the_checkout_origin_to_match_the_record`.
The existing fixture `installed()` now builds a realistic checkout (under `installed-plugins/`, with an `origin`).
RESIDUAL (not closable inside P169's crates): a user who can write both the install dir and `registry.json` can still plant a
checkout whose `origin` matches an allowed URL, and a copied local install (no remote) is bound only by the path check. The
same holds if the user sets `[plugins].install_dir` to a directory of their choosing. Proposal (outside P169): an
admin-owned install ledger (root-owned, like the admin policy file) or signed checkouts, with the load gate reading only that.
