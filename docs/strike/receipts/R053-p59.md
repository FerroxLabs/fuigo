## 2. Classification: test hygiene

Both tests *deliberately* background a child that outlives the shell (that is the stimulus: the child holds the
inherited stdout pipe, and the tests check the drain timeout / deadline scheduling). Once the shell leader is
reaped, `LocalTerminalBackend` drops the group's strong `Arc<ProcessGroup>` so `ProcessScope::kill_all` cannot
`killpg` a recycled pid (documented design, `fuigo-tty-utils/src/process_scope.rs`). A user's own `cmd &`
therefore outlives the foreground command, as it would in an interactive shell. The tests never cleaned up
what they started. Not a regression of any production path; no production code changed. (See proposal 1.)

## 3. Fix

Test-only, `terminal.rs` tests module: `LeftBehindChild` (cfg(unix)). The backgrounded child is now a POSIX
loop that runs only while a hold file in a `TempDir` exists (and gives up by itself after ~60 s):
`(: > started; n=0; while [ -e hold ] && [ $n -lt 1200 ]; do sleep 0.05; n=$((n+1)); done; : > done)`.
It still inherits the command's stdout/stderr, so both tests keep their drain stimulus. `reap()` waits for
`started`, removes `hold`, and asserts `done` appears within 5 s (the regression check). On a panic the
`TempDir` drop removes `hold`, ending the loop. No pid, no signal (no pid-reuse hazard). Paths are
single-quoted with `'` escaped. The inherited-pipe test's `backend.run` is bounded by a 20 s timeout; it
became `cfg(unix)` like the helper (POSIX syntax; fuigo-tools lib tests are not run by Windows CI).

## 7. Proposals (outside P59 ownership)
1. **Product lifecycle question (fuigo-tools terminal):** a user command's `cmd &` child outlives the
   foreground command *and* session teardown / `ProcessScope::kill_all`, because the group handle is dropped
   when the shell leader is reaped. Shell-like, but it means Fuigo can leave detached user processes after it
   exits. If that is not intended, track the session (pgid/sid) beyond the leader's reap, or use a cgroup per
   task, and kill on session close. Needs a decision, not a test change.
