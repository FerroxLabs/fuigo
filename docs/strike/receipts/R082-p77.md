## 3. What changed (production)

**Rule.** P54's, applied to the OS host name and the id derived from it: only a FluxRouter-operated destination
(`fuigo_extra_ca::fluxrouter::IdentityDisclosure`; for a WebSocket `for_websocket_destination`: `wss` to the FluxRouter API
host) receives the real value; every other destination Fuigo dials, and every URL that cannot be classified, receives the
field omitted or, where the peer needs a stable key, `destination_pseudonym`. No second host check and no second scheme:
P77 calls P54's classifier and P54-K's published `destination_pseudonym` (`fuigo-extra-ca/src/fluxrouter.rs`, pinned by
`destination_pseudonym_matches_its_published_recipe`) with the connected URL and the sanitised host-derived id.

1. **Leader hub registration** (`leader/server.rs`, `hub_registration_identity(hub_url, cwd, hostname)`, called once from
   `handle_workspace_start` with the URL that is parsed and connected to).
   FluxRouter hub: `server_id` = the host-derived id and `metadata` = `{source, hostname, cwd}`, byte for byte as before
   (key order included). Any other hub: `metadata` = `{source, cwd}` and `server_id` =
   `destination_pseudonym(hub_url, host_derived_id)`. `host_derived_server_id` is the old `workspace_server_id` with the
   host name as a parameter; its algorithm is unchanged.
2. **Relay-sync `initialize` response** (`relay/sync.rs`, `relay_initialize_meta`). The decision is
   `RelayConfig::identity_disclosure()` (`agent/relay.rs`), taken in `relay_sync_task` on the config that is then handed
   to `spawn_relay_connection`. FluxRouter relay: the response is byte for byte the old one. Any other relay: the same
   `_meta` without `hostname` (the session registry's decision, `register_body_for`).
3. **Relay socket writer** (`agent/relay.rs`, `relay_outbound_frame`, called on every frame by the socket's one text
   writer with `config.identity_disclosure()` of the URL `run_relay_loop` connects to). FluxRouter relay: every frame
   untouched. Any other relay: a RESPONSE (a frame with `result`, no `method`) loses `result._meta.hostname` (ACP
   `initialize`), `result.result.sessions[].hostname` (`fuigo/session/list`, under the `ExtMethodResult` envelope) and
   `result.sessions[].hostname`; nothing else is removed (a `hostname` elsewhere is application data), requests and
   notifications are never rewritten, a frame without the quoted key is not read. The frame is read one level at a time
   (`IndexMap<String, Box<RawValue>>`), so every other value is written back byte for byte at any nesting depth. A frame
   that contains the quoted key and is not a JSON object is not sent to such a relay (fail closed).
4. **Body guard** (`fuigo-extra-ca/tests/identity_body_guard.rs`): `"hostname"` in `BODY_KEYS` (22→23) and `hostname` in
   `FIELD_NAMES` (10→11); positive control 12→14; 263 pinned files (was 249). §5 classifies every site.

**Default install.** `PROD_COMPUTER_HUB_URL` and `PROD_RELAY_WS_URL` are empty (`fuigo-env/src/lib.rs`): a default
install registers with no hub and opens no relay, so nothing changes on its wire. A deployment whose hub / relay is
`wss://api.fluxrouter.ai/…` is unchanged byte for byte (string assertions in the tests below).
