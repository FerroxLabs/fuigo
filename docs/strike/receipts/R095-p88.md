## Cause (verified)
a7a17ff8 ("ship bounded execution in 1.0.10") added `inherited_prefix_len: Some(..)` to every checkpoint as a flag. It
means "this checkpoint holds the exact resolved projection" (legacy files carry None). For any flagged latest
checkpoint, `load_light` replaced `chat_history.jsonl` with `replay_to_prompt(updates.jsonl)`. That is the text-only
rebuild meant for rewinds, and spawn then persisted it (`persist_chat_history_jsonl_sync`). Reproduced at the parent:
8 of 9 scenarios fail (red4). The checkpoint `?` reads also made a missing or truncated file fail the load (L-1).

## Fix
- `load_light`: `chat_history.jsonl` is always authoritative. The checkpoint is only read to warn when it is unreadable.
  The dead write to `summary.inherited_prefix_len` is gone (nothing on the load path reads it).
- The checkpoint key is renamed to `resolved_prefix_len`, with alias `inherited_prefix_len`. Compactions made by this
  version then read as legacy in 1.0.10–1.0.19 binaries, so older binaries stop rewriting their history.
- Paths that relied on the old rebuild (Astra r1–r7):
  - `replay::replay_if_latest_compaction_active` holds the 1.0.17 rule verbatim. It is used only by point-in-time
    copies (`copy.rs`, on the copied transcript) and by a chat rebuild where a rewind follows the latest compaction.
  - The chat rebuild (`chat_rebuild`) now restarts from the checkpoint projection.
  - It drops an abandoned projection.
  - It ends a user run at a tool call.
  - It keeps prompt boundaries and indexes.

## Release note (Sean)
In 1.0.10–1.0.17, reopening a compacted session rebuilt the model's history from the on-screen transcript. The model
lost every command it had run, every file it had read or edited since the compaction, and their results. Its messages on
either side of those steps were merged, so after a resume it could repeat work (re-run a command). The on-screen
transcript was never affected. From this release a resumed session gives the model exactly the history it had.
- Sessions not reopened since their last compaction are intact.
- Sessions an affected version already reopened keep the gap. The tool steps between that compaction and that reopen
  are gone from the model's history and cannot be restored automatically (the transcript still shows them). Work done
  after that reopen is now kept.
- A session whose compaction checkpoint file is missing or damaged now opens with a logged warning instead of failing.
  Rewinding to before that compaction remains impossible.
- Older Fuigo versions run on the same sessions no longer damage compactions made by this version.
