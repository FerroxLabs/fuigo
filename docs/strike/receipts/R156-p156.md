## What changed
`crates/codegen/fuigo-workspace/src/permission/policy.rs`, `shell_access.rs`, new test file
`policy_symlink_cwd_tests.rs` (unix), `windows_spelling_tests` module at the end of `policy.rs`.

- **Port of upstream `RuleBase`.** Path rules anchor to the cwd as written and, lazily (one canonicalize per
  evaluation), to its physical form. `path_match_forms` now gives a path under the physical cwd its physical-relative
  spellings (`./x`, `x`) and its written-cwd absolute spelling. A path written with `..` gets physical forms only from
  the escalate-only target re-check (native: `..` with no symlink re-checks the collapsed path; shell: same, with a
  lexical-only base for the collapsed text). `evaluate_lexical_with_cwd` became `evaluate_rules_with_base`.
- **Fuigo divergence 1 (allow never broader):** allow rules are matched with the written cwd only
  (`RuleBase::without_physical`). Upstream also lets `Allow(./**)` cover the physical spelling; Fuigo does not, so the
  physical spelling of a workspace file prompts exactly as in v1.0.21. Deny/ask see both forms.
- **Fuigo divergence 2 (outbound-link containment, req. 3; Astra r1–r3):** when a native Read/Edit/Grep path in the
  workspace (under the written or physical cwd) follows a symlink to a target outside the *physical* workspace, the
  allow is dropped (prompt) unless an allow rule covers the target, matched against the physical workspace only and
  through each symlinked ancestor of the written cwd (`/tmp/x` for `/private/tmp/x`). In-workspace links, narrow allows
  on links (`Allow(Edit(alias))`) and allows on paths outside the workspace behave as in v1.0.21. This is a
  tightening: v1.0.21 auto-allowed `Edit(escape/x)` under `Allow(Edit(./**))` when `escape` linked outside.
- **Astra r1 #1 / r2 #2:** a written cwd containing its own physical form (`<link>/..`, e.g. `/tmp/..` → `/private`)
  gets both relative spellings and the written absolute spelling for deny/ask.

## Release-note text (for `docs/release-notes-1.0.22.md`)
- **S:** Permission rules now also match the symlink-resolved working directory. A deny or ask rule such as
  `Deny(Read(./secret/**))` catches a tool or shell command that names the real path of a symlinked workspace (macOS
  `/tmp` → `/private/tmp`, a project opened through a link) or reaches the file through a linked subdirectory. Allow
  rules are never widened by this, and a workspace allow no longer auto-approves a file reached through a symlink that
  points outside the workspace (Fuigo asks instead, unless an allow rule covers the target).
- **K:** none removed; no known-limit row covered this.
