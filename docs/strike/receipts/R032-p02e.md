## 1. The defect, measured

Before: `admit_attempt`'s token guard returned `io::Error::other("execution token budget exhausted or unknown")`;
`Execution::admit` flattened it to `"execution admission denied or not durable"`; the sampler flattened that to
`InvalidConfiguration("execution admission denied or could not be persisted")`. Measured on the parent code path
(mutant M1, §5, which disables only the new reporting):

```
{"code":-32603,"message":"Internal error","data":{"message":"invalid client configuration: execution admission denied or could not be persisted","error_kind":"api"}}
```

Indistinguishable from a provider rejection and from a durable-write failure; no rule, no remedy. The output-token
variant of the same guard (turn-loop pre-check) answered a second shape (`execution_incomplete`, bare sentence), and
a workflow child's spent output grant a third (`internal`, "workflow child output-token budget exhausted").

## 2. The ACP-visible signal (design)

Every budget-guard refusal of a model request now ends the prompt with:

| field | value |
|---|---|
| JSON-RPC `code` | `-32603` (unchanged) |
| `data.error_kind` | `execution_incomplete` — the kind already documented for "a budget ran out" (15-agent-mode.md) |
| `data.code` | `execution_budget_denied` — the stable discriminator (`acp_error::EXECUTION_BUDGET_DENIED_CODE`) |
| `data.rule` | `execution_token_budget_exhausted` / `execution_output_token_budget_exhausted` / `execution_token_usage_unknown` |
| `data.remedy` | what the operator changes |
| figures | `total_token_limit`, `total_tokens_used`, `output_token_limit`, `output_tokens_used`, `unknown_usage` |
| `data.message` | one English line naming the rule and the remedy |

`acp_error::ExecutionBudgetDenial::{to_acp_error, from_acp_error, is_budget_denial}` is the typed round trip, so the
pager never parses prose. Wire compatibility: the class is unchanged; the kind moves `api` → `execution_incomplete`
(a client treating unknown kinds as generic is unaffected; one matching `api` for this case loses that match); every
other field is additive. Consistent with P02a: a denial is an outcome reported as data, keyed on a positive statement
from the shell (P02a: `_meta.cancellationCategory`; P02e: `data.code`).

**Plumbing.** The guard returns the denial as the `io::Error` payload (same three clauses, same order; unknown usage
still fails closed). The sampler boundary flattens refusals to a string, so the typed refusal is recorded by a
per-request `RequestAdmission` — the object the request itself carries in `ConversationRequest::execution_admission`
— for required purposes only (Title/Recap never record). The turn registers its current request
(`Execution::begin_turn_request`); `handle_sampling_failure` reports that request's refusal first (before
retry/compaction arms), only for a status-less `api` error. `/btw` uses its own `RequestAdmission` and reports
`SideQuestionError::BudgetDenied`. The turn-loop output pre-check and the workflow-child grant clamp build the same
denial (`token_budget_denial`, `ToolContext::task_output_budget_denial`; a grant closed because usage was unknown is
`execution_token_usage_unknown`).
