Design (deviations from the brief: none, one addition in (a)):
- (a) `admit_client_mcp_servers` compares each client server with the enabled disk definitions a client forwards
  (`load_mcp_servers_with_provenance`, the pager's own loader). Equivalent (headers/env order normalized, key references
  compared as written, by name or by the name the ingress renamed it to) -> that disk definition is used. Otherwise the client
  copy is scrubbed and inherits nothing. ADDITION (Astra P136 r1 #1): at merge a client server never replaces a TRUSTED disk
  definition of its name that it is not a copy of: the user's definition runs. This is what keeps a stale forwarded copy (the
  seed a hot reload re-merges after the user edits the server) from replacing the edited definition with a scrubbed one.
- (b) `retain_oauth_for_same_destination` keeps a setting only when an enabled disk definition of that name exists AND the
  server about to start IS that definition (fail closed). Loaders record OAuth settings only for a definition that
  materializes (enabled, set up), so a disabled TOML / Cursor JSON / Claude JSON entry contributes none. Plugin OAuth goes
  through the same check against the plugin's own definition.
- (c) `McpServerConfig::credential_from_env_var` is the one reader for every config field that becomes a credential
  (`bearer_token_env_var`, `oauth_client_secret_env_var`, `[oauth] client_secret_env_var`). For an `untrusted_source`
  definition it refuses a selector that names the key, and a value that holds the key or a reference to it. The untrusted
  final gate (`to_acp_mcp_server`) removes key references AND the key's value from every final string.
- (d) `fuigo_config::key_naming::NoticeScope`: a refusal is tagged with the innermost scope entered on its thread when it is
  recorded; `session/new` and `session/load` run their setup in a scope (and the session thread enters it), `mcp/upsert` and
  `session/update_mcp_servers` run in one; each announces `scope.notes()`. No path heuristic is left. Notes are kept per scope.

Credential extraction points audited (where a config-derived value can become a credential):
1. `McpServerConfig::to_acp_mcp_server`: headers, env, args, url (untrusted: references and the key value removed on the final
   strings) and `bearer_token_env_var` (through `credential_from_env_var`).
2. `McpServerConfig::oauth_config` (both secret variables, through `credential_from_env_var`); consumers: `load_mcp_servers_with_oauth`,
   `parse_mcp_config_with_oauth` (plugins, `.mcp.json`), then `retain_oauth_for_same_destination` at `spawn_oauth_config_map` and
   `rebuild_http_client_with_oauth`; the secret reaches `fuigo-mcp/src/oauth.rs` BYO client config.
3. fuigo-mcp late binding of `${FUIGO_API_KEY}` in an ACP server's strings (`servers.rs` `send_first_party_key_references`): an
   ACP server carries no provenance, so every ingress scrubs first: `admit_client_mcp_servers` (session/new, load,
   update_mcp_servers, every merge), `mcp/upsert`, hub `workspace.configure_mcp`, inline agent `mcpServers`, and config sources
   through (1).
4. Model `api_key` / `env_key` (`agent/config.rs` `first_own_credential`), hooks (`fuigo-hooks` env_expand): config files only; a
   file that may not name the key is refused at load (P118). No ACP client path writes them; not changed here.
5. `credential_env_var_names` / `deny_credential_env_vars_to_children` register names to withhold from children; not an extraction.

## Release-note text
Changed line (S), replacing P133's: "A project's config, a plugin, a project `.mcp.json`, a worktree, a `FUIGO_CONFIG_PATH` file, a
hub client's `workspace.configure_mcp` server, an agent definition's inline `mcpServers` entry and any MCP server an ACP client
supplies (`session/new`, `session/load`, `mcp/upsert`, so an editor's project settings too) can no longer name the saved API key
(`FUIGO_API_KEY`), by reference, by a variable that holds it, or through an OAuth or bearer setting. Only these may:
`$FUIGO_HOME/{config,managed_config,requirements}.toml`, the same three under `/etc/fuigo`, `~/.claude.json`, `~/.cursor/mcp.json`,
and files under `$FUIGO_HOME/hooks/`. Your own servers keep working when Fuigo's TUI or headless mode forwards them. The reference
is removed and a note naming the source reaches that session only (TUI scrollback, headless stderr / `streaming-json`). An OAuth
client setting applies only to the enabled server definition it was configured with."
Tier 2 behaviour changes (vs v1.0.20): (1) an ACP client server with the same name as one of your own MCP servers but a different
definition no longer replaces it: your definition runs (a warning is logged); (2) OAuth client settings of a disabled server, or for
a server whose running definition differs from the configured one, are not used; (3) a definition from an untrusted source whose
bearer/OAuth variable holds the key, or text that becomes the key on expansion, gets nothing.
D18 row and the K-row about client-supplied servers disappear (as in R133). Remaining: URLs never get the key (D16); `/mcps Add`
cannot save a key-bearing server.
