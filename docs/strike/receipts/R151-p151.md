## What is NOT met / limits
- **Old leader, new client:** a 1.0.20 leader still reports `LEADER_VERSION = "unknown"`, so an RC client attached to a
  1.0.20 leader gets no mismatch notice (live-confirmed). Only leaders running P151+ send it. Not fixable client-side.
- **Dedup waiters:** a non-forced sign-in that waits on another task's in-flight sign-in gets the generic reason, not the
  trusted refusal (Astra r3: not material today, every client-initiated sign-in passes `force=true`).
- B33 retry has no attempt cap: a saved login behind permanently 5xx metadata retries on activity after the 60 s cooldown
  (no tight loop; Astra r2/r3 note).
- Focused runs used host network (tests bind loopback only); the rp.sh gate and the live e2e ran `--network none` / in a
  loopback-only namespace. Linux only.

## Design
- **F17:** `LEADER_VERSION = fuigo_version::VERSION` (was `option_env!("VERSION_WITH_COMMIT")`, set only for the pager
  bin, so always "unknown"); `same_release` compares semantic versions with `cmp_precedence` (build metadata/commit stamp
  ignored, prereleases distinct). Pager `leader_cluster` harness sends `fuigo_version::VERSION`.
- **B33:** with saved credentials and metadata that cannot be fetched (5xx/transport, `oauth::metadata_unavailable`),
  `ensure_initialized` returns `McpError::Unreachable` (retryable) instead of needs_auth; no refresh without validated
  metadata, no guessed endpoint, credentials untouched; `init_failure_needs_auth` excludes `Unreachable`; refused
  discovery (cross-origin redirect, policy) is NOT retryable (Astra r1 MEDIUM).
- **Refusal reasons:** policy refusals, issuer mismatch (`explain_missing_oauth`) and token redirects (follow-policy error
  and stop-policy 3xx response) produce a specific reason. Client-visible text comes only from a tokio task-local
  `TRUSTED_REFUSAL` written by `http_policy::record_refusal` (built from endpoint keys without query/userinfo, origins,
  status numbers and fixed wording), captured by `capture_trusted_refusal` around the sign-in; `client_safe_reason`
  never searches or echoes the error text (Astra r1/r2 HIGH: provider `error_description` reached the client).

## Release-note text
- F17 (now true): a client whose release differs from the leader's gets `_fuigo/leader/version_mismatch` (leaders 1.0.21+;
  a commit stamp or build metadata alone never warns).
- B33 (now true): an MCP server whose saved OAuth login is near or past expiry while its metadata cannot be fetched is
  reported unreachable/retryable, not as needing sign-in; the login is kept and used once metadata returns. A refused
  discovery (redirect to another origin, blocked address) still needs sign-in.
- S15 / K7 row: a sign-in Fuigo refuses (token endpoint on another origin, cross-origin token redirect, issuer mismatch,
  blocked address) now tells the editor why, instead of "Authentication failed" / "does not support OAuth" / "empty error
  response"; the reason never contains a code, token, secret, query string or provider text.
