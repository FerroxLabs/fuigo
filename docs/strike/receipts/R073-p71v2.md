## 1. The rule

Every upload destination is one of three classes (`fuigo_file_utils::destination_gate::StorageDestinationClass`):

| class | destination | decided by | receives |
|---|---|---|---|
| 1 | FluxRouter-operated storage proxy | `fuigo_extra_ca::fluxrouter::IdentityDisclosure::for_destination(url).is_permitted()`, the existing P43/P54 predicate, and nothing else | files unchanged |
| 2 | the operator's own bucket | `UploadMethod::Direct` (GCS), `UploadMethod::S3` | files unchanged |
| 3 | any other storage proxy, and any proxy URL that cannot be classified | everything else (fail closed) | **nothing**: no connection, no request, no object-path header |

For class 3 the upload returns `WithheldFromDestination` (found with `is_withheld`), local files are untouched, the
upload queue treats it as terminal (never retried, never parked), `fuigo trace` does not retry it, and the user is
told: `WITHHELD_NOTICE` (names the remedy: a `gs://` or `s3://` `trace_upload_bucket`) or, for the one-shot feedback
archive, `FEEDBACK_WITHHELD_NOTICE`, which promises no bucket because that archive has no bucket path. Each notice is
printed at most once per process.

Where it is enforced: **at the sink.** `StorageClient::gate(&self, object_path)` =
`destination_gate::gate_proxy_url(&self.base_url, object_path)` is the first statement of every public
`StorageClient` method that moves content to the proxy or names an object to it for upload: `upload`, `upload_file`,
`upload_stream`, `upload_multipart`, `upload_bytes_signed`, `batch_upload`, `batch_upload_json`. The two signed-URL
steps (`get_signed_upload_url`, `upload_via_signed_url`) are private, so the PUT goes only to the URL the gated proxy
returned. The `gcs::upload_*` dispatchers carry no gate of their own: their Proxy arms all go through
`StorageClient`; their Direct and S3 arms are class 2 by construction. A caller that holds a client and skips the
dispatchers is refused all the same. (Rounds 1 to 4 of the audit had the gate at the dispatchers and a source scan
for direct client use; round 5 moved it. See section 6.)

The workspace environment record additionally keeps a field rule (`WorkspaceEnvironment::for_method`, applied
before serialisation and enqueue): for class 3 `user_id`, `principal_id`, `hostname`, `server_id`, `repo_root`,
`remote_url`, `sandbox_id`, `sandbox_profile` are `null` and `cwd` is `[identity-withheld]`. It is then also
withheld at send time like every other queued item, so the field rule is defence in depth for the copy spilled to
disk.

Bytes a FluxRouter-operated proxy tells the client to send elsewhere (its signed storage URL, multipart part URLs)
are class 1 by design.

## 10. Release note (behaviour change, accepted by Sean 2026-10-02)

> Fuigo now sends session archives, traces, diagnostics, review-comment records, share bundles and heap profiles

> configured storage proxy receives none of these files: Fuigo says so once (on exit when you use the full-screen
> interface), and your local files are untouched. To keep receiving full traces, set a `gs://` or `s3://`
> `trace_upload_bucket`. The one-shot `/feedback` session archive is offered only through a FluxRouter-operated
> proxy and has no bucket alternative.
