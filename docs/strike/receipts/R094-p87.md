Design notes:
- `egress::resolver_allowing_exactly(host)` (crate-private) = the same guard with one exact, case-sensitive host
  exception. `SubscriptionClient` passes `recipient.host()`, the same host `Recipient::accepts` binds to, so the
  xAI token client may resolve only `auth.x.ai`, the inference client only `api.x.ai`; `mixpanel.com`, `grok.com`
  and every other `x.ai` name stay refused on those clients. `FUIGO_ALLOW_UPSTREAM_HOSTS` keeps its meaning
  (process-wide lift) and is now documented precisely in `egress.rs`, the user guide and the `/provider` hint.
- `SubscriptionClient::build(recipient, extend)` is the single construction; `new` passes the identity. Tests
  append only loopback `resolve_to_addrs` routes, a test root and `no_proxy`, after every production setting.
- `SubscriptionRequestBuilder` exposes `header/bearer_auth/query/form/build` only; the raw client never leaves the
  crate, so there is no unchecked send (F7 by construction). `build()` also refuses URL userinfo (reqwest would
  turn it into a Basic header before `execute` sees the URL).
- `fuigo_computer_hub_sdk::check_token_endpoint(issuer, url, allow_loopback_http)`: https, same origin as the
  issuer, no userinfo; loopback http only when the caller passes `cfg!(test)`. Proactive refusals are wrapped as
  `DispatchError::Denied`, so `is_policy_denial()` stops the loop and keeps credentials.

## Release notes (user-visible behaviour changes)

- **xAI subscription:** `fuigo login --provider xai` and `grok-subscription` sessions work with the egress guard ON;
  you no longer need (and should not set) `FUIGO_ALLOW_UPSTREAM_HOSTS=1`. Subscription connections can reach only
  their provider's own token or inference endpoint.
- **Subscription egress guard:** subscription connections now also refuse every other blocked host (for example
  telemetry hosts), the same as every other Fuigo connection.
- **Docs / `/provider`:** the guide and the `/provider` warning now say that `FUIGO_ALLOW_UPSTREAM_HOSTS=1` lifts
  the guard for every connection the process makes, telemetry hosts included.
- **Hub sign-in refresh:** the workspace hub only sends your refresh token to an https token endpoint on your
  IdP's own address; IdPs that issue tokens from a different host no longer auto-refresh hub connections
  (needs Sean's yes — see top).
- **Hub SDK (standalone users):** the SDK's built-in client no longer follows a redirect to a different origin
  during OIDC discovery or refresh.
