## Finding: it was fail-open
`normalize_requirements_value` (fuigo-config `validation.rs`) returned `None` on any invalid `[[version_overrides]]`, dropping the whole
requirements layer (`yolo = false`, `[sandbox] profile`, future `allowed_models`). `hook_config_layers_at` (`loader.rs`) did the same for
managed-policy hook layers. `validate_requirements` only refused startup when the layer also set `fail_closed = true`.
Red proof: commit `b5bc311d`, 3 new tests FAILED on Hetzner in each of 3 runs (`red.out`); the pre-existing test asserted `None`.

## Fix (Astra r1 HIGH: keeping only the base can loosen a policy whose tightening patch was the version-gated one)
- Loader: bad section is discarded (no patch applied), base pins kept, `tracing::error!`. Managed-policy hook layers likewise.
- Startup: `validate_requirements` refuses to start (exit 2, error names file and field) for admin-owned layers (system file, MDM)
  on ANY invalid override, `fail_closed` or not. User-home layer: refused only with `fail_closed = true`, otherwise runs on base pins.
- Test fixtures use `[ui] yolo`, root-level `version_overrides`.
