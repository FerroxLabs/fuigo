## What changed
- Item 1: `fuigo_secrets::PrivateKeyJoin` (sanitizer.rs): a key split over strings and records (envelope strings between chunks, chunks of
  any length once body seen, markers split over several strings or from their first dash, colour codes, other properties) is redacted; a
  short word or ordinary text closes the block, so a following long base64-looking string is kept. `opens_private_key_block` and the torn-PEM
  regex handle trailing colour codes. feedback_archive.rs `JsonScrub` feeds strings with their property name.
- Item 2: credential registry moved to `fuigo-secrets::child_env` (re-exported by `shell_env_policy`, no behaviour change); `fuigo_tty_utils::remove_fuigo_secrets[_tokio]`
  applied BEFORE explicit variables at every site below. `fuigo-secrets` feature `test-support` has the probe used by the tests.
- Item 3: `session/storage/owner_only.rs` (create 0600 via mode(), fchmod existing, `copy`, `write`, async variants) used by the jsonl adapter, summary lock,
  chat rewrite, compaction segments/index, requests, forks/sidecar/checkpoint copies, quarantine, pre-strip and pre-repair backups; `events.jsonl`
  (`open_owner_only`). Windows equivalent: owner-only ACL via `secure_file::ensure_owner_only_permissions`, applied at every open for writing
  (no cache, since a replaced file would be trusted); the Windows branch is untested here.

## Follow-up (regression versus v1.0.20): owned secrets versus config-registered names
Problem: P120 routed git, jj, direnv, `$EDITOR`/`$PAGER`, sign-in/identity, status line, notification hooks and `fuigo wrap` through the
full registry, which also strips names a user's config registers (`GITHUB_TOKEN` as an MCP `bearer_token_env_var`). git credential
helpers (gh) read `GITHUB_TOKEN`/`GH_TOKEN`, so pushes from Fuigo-run git failed for that common setup.

Rule. K16 protects FUIGO's own secrets (held or passed in) from children that run the USER's programs on the user's behalf. The user's own
environment credentials are not Fuigo's to remove from the user's own tools. The registry had no split, so `fuigo-secrets::child_env` now has two
classes: `is_fuigo_owned_secret` / `inherited_fuigo_owned_secret_names` / `remove_fuigo_owned_secrets` (first-party API keys and
`FUIGO_INTERNAL_CREDENTIAL_ENV_VARS`: FUIGO_API_KEY, FUIGO_AGENT_SECRET, FUIGO_AUTH, OTLP/telemetry keys) and `config_registered_names`
(what configs register). The full filter (`is_fuigo_secret`, `is_provider_credential`) is unchanged.

Per site. OWNED-ONLY (via `fuigo_tty_utils::remove_fuigo_owned_secrets[_tokio]`, renamed from `remove_fuigo_secrets`): every git (tty-utils,
fast-worktree, workspace, goal_classifier, fs_watch, fs_notify, host_service, user_identity, plugin_cmd), jj, direnv/.envrc,
`$EDITOR`/`$PAGER`, sign-in command and identity command (`shell_c`), auth provider helper (its first-party scrub list still runs last),
status-line command, notification hooks, `fuigo wrap` (PTY incl. builder-held names, and non-PTY). All are the user's own programs; a sign-in or
status script may legitimately read the user's own token. FULL FILTER, unchanged (not weakened): bash tool and terminals, MCP stdio, hooks
crate, LSP, search tools, `!` commands and client terminals (fuigo-shell-terminal).

Tests. Each site's probe now plants the registered name and asserts it is KEPT (`probe::assert_kept`) while every Fuigo-owned secret is gone.
Red-by-mutant: git test registers `GITHUB_TOKEN` (workspace `git_cli*`, tty-utils `git_command*`). Mutants M1 (tokio remover applies
`inherited_fuigo_secret_names`, the full filter) and M2 (std remover applies the full filter) must be killed.
