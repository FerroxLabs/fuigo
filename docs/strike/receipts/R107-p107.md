## 1. fuigo-shell `provider_resolves_relative_program_against_cwd`
Cause (reproduced): ETXTBSY. The test writes `token.sh` and execs it at once. Any other thread that forks between the
`write` and the `exec` inherits a copy of the write fd until its child reaches its own `exec`, and `exec` of a file with a
live write fd fails with "text file busy". The provider then reports a failed start and `rotated()` is `None`.
Fix: `wait_until_executable` runs the script once, retrying only on `ExecutableFileBusy`, before the provider run; once
one exec has succeeded no writer is left, so the real run is deterministic. No assertion loosened.
Reproduction (stress harness injected into the lane only, not committed; 1 test thread, N forker threads whose children
sleep `hold_us` before exec):
- raw write-then-exec, forkers on: ETXTBSY 276/3000, 295/3000, 17/3000 (hold 20 ms), 17/1500, 6/500 across runs.
- before fix (parent 06f40490), looped real test: fails 11/1000 (4 forkers, 5 ms), 48/1000 (16, 20 ms), 1/1200 (2 workers,
  16 forkers, 50 ms), 6/1500 (32 forkers, 2 ms), 0/2400 (4 workers, 8 forkers, 10 ms). Log `stress-before-final.log`.
- after fix (tip): 0/1000, 0/1000, 0/1200, 0/2400, 0/1500 in the same five configs. Log `stress-after.log`.
- plus 20 consecutive isolated passes at the tip (`mut.log`, no `BASE ... FAIL` line).
Production note: `ensure_fresh_token` execs a user-supplied helper that already exists on disk, so ETXTBSY needs a
process holding a write fd on the helper (an editor or installer rewriting it while Fuigo forks). Rare, but real for a
helper script being rewritten live; the run is reported as a failed mint and the next refresh retries. Not changed.

## 2. fuigo-fast-worktree `linked_grove_declined_does_not_copy`
Cause (reproduced): `grove_wt_create_count("copy")` is a process-global `AtomicU64` bumped by every test whose create
resolves to copy. Readers of it: `nfs::fallback_gate_tests::adopted_nfs_create_does_not_enter_copy` (macOS only),
`linked_grove_declined_does_not_copy`, `worktree::tests::test_create_worktree_simple` (`>= 1`, still correct on the
global), and the three tests in `metrics.rs`.
Fix: `metrics::test_thread` (cfg(test)): a thread-local count bumped beside the global in `record_grove_wt_create`.
`execute_create_worktree` records on the calling thread and each `#[test]` has its own thread, so the view counts only
that test's creates. The two no-copy tests and the three metrics tests now read the thread view; `test_create_worktree_simple`
keeps the global (`>= 1` cannot be disturbed). No new crate, no mutex, tests stay parallel.
Reproduction: 3 background threads creating copy worktrees while the test loops 60 times: before fix 24/60, 7/60, 24/60,
14/60 failures across runs; after fix 0/60.
