## Design (as landed)
1. **Fable #1.** `rewind_points.jsonl` is read as bytes (`read_until`), each line kept in order (`RewindPointsLine::{Point,
   Damaged}`). A damaged row's prompt is read from what survives of it: a torn serialized `RewindPoint` keeps its
   `{"prompt_index":N,` start; every record start in the line must be complete and the largest index wins (old
   concatenated lines), and the line must be a valid prefix of ONE JSON value whose innermost open object has a
   complete key and which does not end in `{` / `{"` (so no second record can hide in its tail; Astra r2 #1, r3 #1);
   otherwise the row identifies nothing. A file rewind to T (needs rows >= T) is refused only when
   a damaged row's prompt is >= T or unknown (`try_get_rewind_points_for`). The refusal names prompt, line and file,
   says nothing was changed, never "try again", says which file rewind still works ("prompt #K+1 or later", or none
   when a row is unidentifiable) and, in the shell, that a conversation-only rewind does not need these contents.
   I/O errors keep a distinct, retryable message. The persistence rewrites (`truncate_rewind_points_from`,
   `merge_rewind_points_from`) keep damaged rows byte for byte instead of failing on them (before, the failed rewrite
   left undone prompts' points on disk). The full load holds the shell's append lock shared so an append in progress is
   never read as damage: the read runs in `spawn_blocking`, polls `try_lock_shared` for at most 10 s, then fails with a
   retryable `WouldBlock` keeping the deferred source; without the lock an unfinished last row is retryable, not damage.
   **Quarantine to a sidecar was rejected:** removing the row loses the only record that a
   prompt's saved files are missing, so a later rewind would claim a complete restore (P111's guarantee).
   The first design (bound by the next readable row) was unsound with two processes on one session (Astra r1 #1) and
   was replaced.
2. **Fable #2.** Forks stage in a private 0700 `.fuigo-fork-staging-*` dir inside the target's CWD directory (created
   by `ensure_sessions_cwd_dir_in`, which repairs the sessions root), so the move is a rename and nothing touches
   `$TMPDIR`. The dir holds an exclusive lock for the copy's lifetime and is removed on drop on every path; a later
   copy sweeps dirs older than 24 h whose `.lock` opens (read-only) and is free; the lock file is created as
   `.lock.init`, locked, then renamed, so an openable `.lock` was always locked by its copy. Listings/relocation skip dot entries at that level.
3. **Fable #3.** Same-compaction/unmarked refusal: "... the saved history has no prompt markers to cut it by. Nothing
   was created. Fork the whole session instead." Other refusal reasons keep their advice.
Fable #4 (extra transcript passes): not addressed (out of scope).

## Release-note lines
- A damaged entry in a session's saved file versions (left when Fuigo stops or the disk fills while saving a prompt's
  files) no longer blocks every file rewind: only rewinds to that prompt or earlier are refused, and the message names
  the entry, says nothing was changed and which rewinds still work.
- Forking a session no longer needs room in the system temp directory: the copy is staged next to the new session.
- Refusing to fork an older compacted session at a prompt now suggests what works: forking the whole session.
