## Migration decision (behaviour change, needs Sean's yes)
Old folders `{slug}-{hash8(org/repo)}` recorded no host. Rule: a legacy folder (either pre-P91 key: `org/repo`, or
`org/repo.git` from an origin ending `.git/`) is renamed to the new name only if (a) all its evidence is readable (MEMORY.md
header `# Project Memory — <path>` + every capture provenance `workspace`; any oversize/symlink/unreadable/malformed
record = unproven), (b) at least one recorded path still exists and its origin is exactly the current `host/org/repo`,
(c) no existing recorded path resolves to another identity. Otherwise the folder is left untouched (nothing deleted) and a
`MEMORY_MIGRATE` warning names it; the user moves it by hand. Why: the hostile clone may be opened first; adopting on
"first claimant" would hand it the victim's memory. Old index files are moved (not deleted) into a fresh
`.pre-p91-index-<pid>-<nanos>/` before the rename; migrations serialise on `.memory-migrate.lock`.
Tests that existing user memory is kept: `legacy_memory_migrates_to_the_proven_host`, `equivalent_origins_consider_both_legacy_names`,
`legacy_name_uses_the_old_slug_for_dot_git_slash_origins`, `migration_moves_only_index_files_aside` (user files untouched),
and every refusal test asserts the legacy MEMORY.md is still in place.

## Release notes (for Sean)
- Rules: a repository's AGENTS.md can no longer remove your own `~/.fuigo/AGENTS.md` rules from the prompt.
- Memory keying: workspace memory is now per `host/org/repo`; the same repo name on a different host gets separate
  memory. Existing memory folders move automatically only when Fuigo can prove they belong to that host; otherwise the old
  folder stays and the log names it (`MEMORY_MIGRATE`). Close sessions from older versions before upgrading.
- First-party MCP: the agent-id header is only ever sent to a designated server on this machine (loopback).
- Memory injected into the prompt now carries a per-install marker file `~/.fuigo/.memory-context-nonce`.
