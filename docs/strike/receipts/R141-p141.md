## Design (Fable's recommended fix, kept)
- The seed (`SessionHandle`/`SessionActor.initial_client_mcp_servers`, `SessionSpawnOptions`, spawn, folder-trust targets) is a
  `ClientMcpSeed`: each admitted client server with `Option<disk name>` = the disk definition it was a forwarded copy of. Only the
  ingress (`admit_client_mcp_servers_for_seed`) sets a mark; `From<Vec<McpServer>>` gives unmarked (client-supplied) entries; the
  entries are private, there is no deserializer, so a client cannot forge a mark.
- Nothing is pruned at ingress, so no decision depends on the registry the ingress saw (MEDIUM 1 gone by construction).
- Every merge (`merge_managed_mcp_servers_with_policy` -> `admit_client_mcp_servers_tracked`, in the client's order): a marked copy
  becomes the CURRENT disk definition of its disk name under the copy's (possibly renamed) name (an edit takes effect); if that
  name is gone from disk the copy is dropped (a delete takes effect, also for renamed and plugin-shadowing copies: LOW 3); it is
  checked against the vendor kill switch as stored AND as resolved; then, like every client server, it never overwrites a
  TRUSTED disk definition of its name that differs (P136). Unmarked servers: unchanged (copy detection, else scrubbed).
- The ingress merges once and returns `seed` + `merged` (LOW 2). The stored content of a copy is never re-admitted, so a
  rotated key's old literal in a kept copy (LOW 4) is no longer sent either; LOW 4 was "record only" and is listed, not targeted.
- `SessionCommand::SetClientMcpSeed`: `update_mcp_servers` and a resident `session/load` send the new seed to the actor BEFORE
  `UpdateMcpServers` (commands are handled in order, so a plugin reload during the async MCP init sees it); its plugin reload
  re-merges its own copy (Astra r1/r2 inherited MEDIUMs). The kill switch is checked on what is finally inserted (Astra r2).
