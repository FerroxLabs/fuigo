## 1. What was built

### 1.1 Identity (`fuigo-config/src/fs_atomic_identity.rs`, new; `identity` module of `fs_atomic`)

P72 locked a state file under `~/.fuigo/locks/state-<hash of the resolved path string>.lock`. Two spellings of one
file that differ in case on a case-insensitive volume, or two hard links, took different locks (Astra's MEDIUM on
P72). Now an `Identity` has two parts and a writer takes a lock for each:

- **the name**: the path with a symlink at the file name followed (up to 40, as `write_through`), the directory
  resolved as the kernel will once what is missing exists (existing prefixes canonical, missing components appended,
  `..` after a missing component lexical, resolution resumed once back on what exists), and each component
  case-folded when the nearest existing directory is case-insensitive;
- **the inode** (`dev`/`ino`; volume serial + file index on Windows) of the file, when it exists.

Neither is enough alone: a name is all a missing file has and it is what stays put across a replace; the inode is
what every spelling of an existing file shares whether or not the module knows why they are one file (hard links,
also one made under a writer's feet; 8.3 names; another normal form).

- **Case-sensitivity is probed, not guessed from the platform** (`dir_is_case_insensitive`), every time: an entry of
  the directory whose ASCII-case-swapped spelling resolves to the same file (and is not a hard link) says
  insensitive; one that does not resolve, or resolves to another file, says sensitive — only if the entry was the
  same file (inode, link count, change time) before and after the question, since a writer renaming a temp over it
  mid-probe otherwise reads as "sensitive" and splits that writer's lock. At most 64 entries; else, or when the
  directory cannot be listed, a probe file is created and removed (looked at twice as well; interference is an
  error).
- **The fold**: per component, NFD, upper+lower twice, NFD (once is not idempotent: U+1E9E → U+00DF → `ss`); ASCII
  for a non-Unicode component. At least as coarse as full case folding; coarser only over-merges.
- **Fail closed**: an identity that cannot be established is an error. One case is not: a directory that can be
  neither listed nor written in cannot be asked, and an EXISTING file in it is named as spelled and excluded by
  inode (its writers can only write in place). A missing file there is refused.
- **Windows**: resolution is kept in the exact (verbatim) form throughout, and only the finished path is put in its
  plain form, as a whole, to be the name (so the name is the same before and after its directories are created).

### 1.2 Locks (`fuigo-config/src/fs_atomic.rs`)

- `state_lock_path(path) -> io::Result<PathBuf>`: the NAME lock file. Where nothing is folded it is the very file
  P72 used (no prefix in the hashed bytes).
- `lock_state_file(path)` / `take_state_lock`: name lock, re-derive, inode lock (one of 1024 stripe files — not a
  file per inode: every replace makes a new inode and lock files are never removed), re-derive; a waiter whose
  identity moved lets go and starts again (8 rounds, then an error). `ConfigWriteLock` carries the inode lock
  (`_inode`, released first). No deadlock: one name lock, then at most one inode lock; callers take nothing else
  while they hold it (none does).
- `edit_state_file` goes through `LockFor::State`, so every state-file writer of P72 (registry, announcements,
  personas, MRU, `pager.toml`, prompt-history truncation, imported hooks) takes both locks; `locked_pass` re-derives
  the identity of the path AND of the staged replacement's target before it commits (`Taken::check_still_covers`).
- Test seam `thread_is_queued_for_a_lock(ThreadId)` (`test` / `test-seams`): a test waits until the very thread it
  started is in a lock's queue, and fails if it finishes instead. No test sleeps and hopes.

### 1.3 The M13 seam (`fuigo-shell/src/session/prompt_history.rs`)

- `append_prompt` takes `lock_state_file`; it creates the (empty) history first, so the lock covers the new file's
  inode.
- `under_lock_seam` (`cfg(test)`): a hook on the writing thread while it holds the lock, in the truncation (after
  its read, in its locked pass) and in the append (right after the lock).
- `an_append_waits_for_the_lock_the_locked_truncation_pass_holds` **kills M13** (R074 §0.4): the truncation is forced
  into its locked pass; from inside it a thread appends; the truncation goes on only once that thread is queued on
  the lock (an append without the lock never queues, it finishes, and the test fails on that); the prompt must be in
  the file afterwards.
- `the_first_append_excludes_a_writer_through_a_hard_link_to_the_new_file` (Astra r2 HIGH 2).

`fuigo-pager-render/src/appearance/config.rs`: one test call (`lock_state_file`). `fuigo-config/Cargo.toml`:
`unicode-normalization` (workspace dependency, already in the lock file), `windows` feature
`Win32_Storage_FileSystem` (P80 added the same).

### 9.2 What was built

1. **A directory part must be a directory** (`fs_atomic_identity.rs`, `resolve` / `resolve_dir`). One `metadata`
   call per identity on every platform (unix already failed there, with `ENOTDIR`; the error kind is the same).
2. **One lock, one directory entry** (module docs of `identity`; `fs_atomic.rs` `Taken::land_on_the_entry`,
   `entry_to_land_on`, `StagedReplacement::land_on`). Before the commit of a state file's replacement, in both the
   locked pass and the optimistic commit: on Windows, `FindFirstFileW` on the target's final component in the exact
   (verbatim) directory gives the entry's own name; when that is not the spelling given, the entry is compared with
   the target by file identity and the replacement is renamed onto the entry, in the exact form. A lookup that
   fails (a directory that may not be listed), or an entry that is not the same file, refuses the write
   (`EditError::Write`). A target that does not exist is created under the spelling given. Off Windows nothing is
   done: Linux (vfat, and by its code ext4 casefold) and macOS (9.0.6) keep the entry's spelling by themselves.
3. **Private test locks** (`state_locks_dir`, `mod test_locks`, `cfg(test)` only; production is unchanged and asks
   for `<fuigo home>/locks` exactly when it did). The directory is removed by an `atexit` handler. A process that
   cannot run it (a kill; on Windows a FAILING test run, which std ends with `ExitProcess`) leaves it; the next
   test process removes the directories whose owner is gone (each owner holds a `flock` on a marker file, which
   gets its name only once it is locked).
4. **Progress across the two locks** (`lock_at_within_behind`, `ConfigWriteLock::pass_on_progress`,
   `turn::wait`'s `moved`, `xq::Ticket::touch`, `xq::wait_for_head`). A state-file writer holds its name lock while
   it queues for the inode stripe. Whenever the queue ahead of it there moves (in this process: the turn queue;
   across processes: a ticket ahead leaves), when it reaches its turn, and when it is granted the `flock` after a
   blocking wait, it tells the writers behind its name lock: threads of its process through the queue's progress
   count, other processes through the modification time of its ticket, which `wait_for_head` now counts as
   progress. The rule a single lock has (give up only when nothing moved for 10 s) now holds across the two. No new
   lock, no new lock order; the callback runs with the queues mutex released.
5. `take_state_lock_in` / `name_lock_path_in` / `inode_lock_path_in` take the lock directory (as a function, asked
   only once the path has an identity, as before): the scenario tests of 4 use a directory of their own.

### 9.4 Behaviour changes of this round, in plain words (for Sean; they need his yes with §0.6)

1. **Windows: a Fuigo state file keeps its name.** Written through another spelling (`AGENT.TOML` for
   `Agent.toml`, or an 8.3 short name), the file used to be renamed to that spelling; through a short name the long
   name disappeared and the next write through it started from an empty file. Now the write lands in the file under
   the name it has. State files are: `pager.toml`, personas, `announcements.json`, `slash-mru.json`, the prompt
   history, the plugin install registry, the imported hooks file.
2. **Windows: a state-file write can now be refused where it went through before**: when the file exists and its
   directory may not be listed by the user ("cannot establish the on-disk name of …; not writing it"), or when the
   directory's listing gives a different file for the name (an outsider replacing the file at that instant). The
   file is left as it was.
3. **A path that runs through a regular file** (`…/file/state.toml`, `…/file/../state.toml`) is refused when its
   lock is taken, on every platform, with "… is not a directory". Before, on unix the first form already failed
   there and the second failed at the first read or write; on Windows the lock step failed a moment later for
   another reason. Nothing that worked stops working.
4. **A writer waiting behind another writer of the same file no longer gives up after 10 s while that writer is
   itself moving up a queue.** It used to fail with "… is locked by another Fuigo writer; gave up after 10s without
   progress" although nothing was stuck. It now waits as long as either queue moves, so its total wait can exceed
   10 s; a holder that is really stuck is still given up on after 10 s.
5. **Cost.** One more `stat` per identity everywhere. On Windows one directory lookup per state-file write. First
   native Windows figure for P79 as a whole: `P79_COST` 5.7–6.5 ms per state lock take (one plain lock 0.8–1.1 ms,
   one identity 0.18–0.23 ms) on SeanDesktop's C:; Linux 1.3–1.5 ms (0.17 ms, 0.03 ms) on the loaded build box.
6. **Tests of `fuigo-config` no longer write into `~/.fuigo/locks`**; they use a directory under the temp
   directory and remove it. (`fuigo-shell`'s unit tests still write sessions and locks under the home the harness
   gives them: P79-F8.)
7. A queue ticket file (`<fuigo home>/locks/.<lock>.queue/*.t`) can have its modification time changed while its
   writer holds the lock. Nothing reads it but the waiters.
