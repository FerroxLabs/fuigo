# R174 — P174: every file a read opens is judged against Read rules

Branch `strike/p174`, base / rp parent `6221893ca0ab30b611b1e46305a8a791a859e37b` (strike/integration, includes P184).
Code tip `efd5a526b`; the receipt commit follows it (docs only).

## The hole (1.0.21 too)
`AccessKind::from(ToolInput::CodexReadFile)` was `Read(Some(file_path))`, or `Read(None)` when `file_path` was empty, so a
codex `read_file` with `files: [...]` had at most its first path judged, and none in the `files`-only form:
`deny = ["Read(secrets/**)"]` did not refuse `read_file {files: ["ok.txt", "secrets/key"]}` (auto-allowed read). The
Fuigo `read_file` (`target_file` + `files`) had the same gap (`Read(Some(target_file))`, `Read(Some(""))` for a list).
`image_edit` / `image_to_video` / `reference_to_video` open local image files that no Read rule saw (they prompt as tools).
Raised in R165.

## What changed
- **Targets travel with the request** (mirror of P184's `edit_targets`): `PermissionRequest::read_targets:
  Option<ReadTargets>` from `read_targets_for(&ToolInput)`, filled by the ACP session (`tool_calls.rs::prepare_tool_call`,
  after any PreToolUse rewrite). `ReadTargets { paths, resolution }`:
  - codex `read_file`: `read_target_paths` (fuigo-tools) = `file_path` and every `files[].path`, `Literal`;
  - Fuigo `read_file`: `read_target_paths` = `target_file` and every `files[].path`, `ModelPath`;
  - image tools: `local_image_paths` (filesystem paths and `file://`; not `data:`/`https://`/attachment tokens), made
    absolute against the process cwd (what their `tokio::fs::read` uses), `Literal`.
  Single-path reads are covered too (Astra r1).
- **The tool reads only what was judged:** both readers build their read list with `planned_entries`, the same function
  `read_target_paths` uses.
- **Manager judges each file** (`manager/mod.rs`, `gate_preflight.rs::evaluate_read_targets`), in every spelling of the
  file the tool opens (`read_target_spellings`): the model's spelling; the file the reader opens (Fuigo: the reader's own
  `resolve_read_target` = `resolve_model_path` + canonicalize + Unicode-confusable fallback; codex/images: `cwd.join`
  literal); and that path with symlinks followed literally (`resolve_following_symlinks`, no `\` rewriting). A deny or
  ask on any spelling binds. Across files: any deny refuses the call (before YOLO), else any ask prompts; for a read an
  allow covers the call only when it covers every file; for an image tool the files add only deny/ask (a Read allow
  never allows the side effect). Resolution runs only when a policy exists, under a 5 s bound (the symlink walk on the
  blocking pool); a file that cannot be resolved in time is refused.
- **The prompt names every file** (ACP title `<title>: a, b` and one location per file) for every read except a
  single-path read, whose title already names it.
- **Read-dedupe** (fuigo-shell): it rewrote `files` from its own raw parser, which also accepts keys the codex tool
  ignores (`target_file`), and hashed `cwd.join(path)`. `PreparedToolCall::judged_read_paths` now carries each judged
  spelling with the file the reader opens; a call is deduped only when every parsed entry was judged, and dedupe hashes
  the reader's file. Resolution is bounded (5 s; no dedupe for the call otherwise).
- **Hub:** unchanged. On this base the hub mapping (`hub_permission.rs`) gates no read tool and the hub evaluates no
  policy (`hub.rs`), for single and multi-file reads alike; there is no mapping line to change without making every hub
  read prompt. P173 should judge `read_targets_for(&input)` with `read_target_spellings`.

## Behaviour changes (for Sean / release notes)
1. A `Read(...)` deny now refuses a `read_file` whose `files` list (or `target_file`/`file_path`) names a denied file,
   in any position, through `..`, symlinks, a backslash-named symlink, the Fuigo display-cwd mapping or its
   Unicode-confusable fallback; in YOLO too. An ask rule on any file prompts for the whole call, listing every file.
2. `image_edit` / `image_to_video` / `reference_to_video` are refused when a local image is under a Read deny.
3. A read whose file cannot be resolved within 5 s (unresponsive filesystem) is refused when a policy is configured.
4. Read-dedupe no longer dedupes a call that carries keys its tool ignores, or a path spelled with surrounding
   whitespace (it reads normally).

## Residuals (not fixed here) and proposals
- **Hub (P173).** The hub gates no read tool and evaluates no policy on this base; its prompt text (`describe_access`)
  says "Read a file" without paths. Proposal: P173 judges `read_targets_for(&input)` with the manager's
  `read_target_spellings` and lists the files in `describe_access`.
- **Write/read binding is by path, not by file object:** a symlink retargeted between the check and the read, or an ACP
  client filesystem that resolves differently, is followed (inherited by every file tool; as R184).
- **Other read routes outside this packet:** codex `grep_files` and opencode `grep` get no deny excludes and Fuigo grep
  drops ask rules from its excludes; `list_dir` / opencode `glob` list denied descendants; `cursor_rules_on_read` appends
  `.cursor/rules/*.mdc` unjudged; opencode `read` and Fuigo `grep` with an explicit file judge the raw spelling. Proposal:
  one follow-up packet "Read rules on search/list/side reads".
- **Attachment tokens** (`[Image #N]`) resolve to the user's own attachment and are not judged.
- YOLO and `prompt_policy = allow` still waive ask rules (deny binds), as for every tool.
- Read-dedupe declines a path spelled with surrounding whitespace (safe; minor cache loss).

## Release-note line (docs/release-notes-1.0.22.md)
S: Read rules now apply to every file a read opens: a `read_file` with several files (`files: [...]`, codex or Fuigo
form) was judged by its first path at most, so a `Read(...)` deny or ask did not cover the others. Every file is now
judged as the reader resolves it (relative and display paths, `..`, symlinks, Unicode look-alike names); a denied file
refuses the whole call (also under always-approve), an ask prompts and the prompt lists every file. `image_edit`,
`image_to_video` and `reference_to_video` are refused when a local image they would read is under a Read deny.
Read-dedupe can no longer re-read a file the check did not judge. No K row shrinks (not a 1.0.21 K row); add K: hub-routed
reads get per-file Read rules with P173; search/list tools (grep, list_dir, glob) and cursor rules on read are a follow-up.
