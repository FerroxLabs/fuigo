## Classification: (a) test-hermeticity bug, not a product defect

The product uses the real clock. On Beast an IPv4 loopback connect completes in about 160 µs (p50) / 353 µs (p99), against a 10 s `connect_timeout`. Users on such a host do not hit this.

The tests assumed three things that native `lo` provides and WSL2 mirrored networking does not:
1. Loopback I/O is ready on the very next zero-timeout poll.
2. Paused-clock (`start_paused`) tests rely on that.
3. A connect to a closed loopback port is refused at once.

## Root cause (evidence)

1. **Routing.** On Beast, `ip route get 127.0.0.1` gives `127.0.0.1 via 169.254.73.152 dev loopback0 table 127 src 127.0.0.1`.
   - WSL mirrored mode policy-routes `127.0.0.0/8` through the `loopback0` virtual NIC.
   - `ip route get ::1` gives `dev lo`.
2. **Readiness probe** (python, nonblocking connect then `epoll.poll(0)`), not-ready count:

   | Address | Beast (host netns) | Beast (`unshare -n`) | Hetzner |
   |---|---|---|---|
   | connect 127.0.0.1 | 500/500 | 0/200 | 0/500 |
   | connect 127.0.0.2 | 100/100 | — | 0/100 |
   | connect ::1 | 0/200 | 0/200 | 0/200 |
   | established-data 127.0.0.1 | 499/500, then 500/500 | — | 0/500 |
   | established-data ::1 | 0/500 | — | — |

3. **Mechanism in tokio 1.52.3.** The mechanism was read in `runtime/time/mod.rs` `park_thread_timeout`.
   - When the clock is paused it does `park_timeout(0)`, then, if not `did_wake`, it advances the clock to the next timer.
   - On a WSL mirrored host the I/O is not ready on that poll, so the timer fires first. Examples are reqwest's 10 s connect timeout, a backoff, or the test deadline.
   - That produces `tcp connect error: deadline has elapsed` and `turn must finish within timeout: Elapsed`.
4. **Minimal Rust reproduction** (scratch crate, tokio =1.52.3). It ran a paused current_thread runtime with a listener, a connect and a 1-byte read inside `timeout(10s)`:

   | Address | Beast | Hetzner |
   |---|---|---|
   | 127.0.0.1 | 0/5 ok (`Err(Elapsed)`) | 5/5 ok |
   | ::1 | 5/5 ok | 5/5 ok |

   - On Hetzner the virtual clock also jumps (8.192 s, then 10 s), but the I/O is ready in the same poll and `Timeout` polls the inner future first.
5. **Closed port.** Python `connect(("127.0.0.1",1))` gives `TimeoutError` after 3.002 s on Beast and `ConnectionRefused` in 0.001 s on Hetzner. `::1:1` is refused at once on both.
   - This caused `laziness_integration_tests::debug_mode_bypasses_idle_wait`: it took 10.005 s against `http://localhost`, which is the sampler's 10 s connect timeout.
   - It also caused two `fuigo-sampler` tests that connect to `127.0.0.1:0` and `127.0.0.1:1`.
6. **Other environment differences, ruled out.** Locale (Beast `C.UTF-8`, Hetzner `en_US.UTF-8`), timezone (Asia/Bangkok vs UTC), `ulimit -n` (10240 vs 1024), inotify limits, CPU count (24 vs 96), git version and config, and `/etc/hosts` (both map localhost to 127.0.0.1 only).
   - Filesystems are ext4 on both, and there is no proxy env on either host.
   - The loopback probes and the netns control isolate the cause to the mirrored IPv4 loopback route.

## Fix

- **`fuigo-test-support/src/loopback.rs` (new).**
  - `loopback_ip()` probes `127.0.0.1`, then `::1`, once per process on its own OS thread.
  - The probe is the exact paused-clock shape: a connect plus a 1-byte reply, and a connect to a held closed port that must be refused, both before a pending 10 s timer. All 3 rounds must pass.
  - It keeps `127.0.0.1` wherever it passes, so Hetzner and native hosts see no change.
  - `refused_loopback_url()` returns `http://<loopback_ip()>:<port>` for a socket bound with no listener and no `SO_REUSEADDR`. It is reserved per process, which removes the released-port race seen on Beast's 4096-port ephemeral range.
- **`MockInferenceServer`** binds `loopback_ip()`, through `start_inner_on`. `tokio` gets `test-util` in fuigo-test-support.
- **fuigo-shell laziness fixtures** (`make_laziness_actor`, `make_debug_actor`) point the sampler at `refused_loopback_url()` instead of `http://localhost`.
- **fuigo-sampler** `retry::tests::transport_failure_first_retry_skips_the_server_backoff` and `tests/test_actor.rs::connect_failure_does_not_emit_images_stripped` use `refused_loopback_url()`.
- **New tests:**
  - loopback selection: 3 injected-probe cases, plus unbindable address returns false;
  - host checks: `the_chosen_loopback_carries_paused_clock_io` and `the_refused_loopback_url_refuses_at_once`;
  - `mock_server::tests`: `a_paused_clock_request_reaches_the_mock_before_its_timers`, `an_ipv6_loopback_mock_serves_bracketed_urls` and `the_mock_binds_the_chosen_loopback`.
