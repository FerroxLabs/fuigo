## 1. What is NOT met, and decisions for the coordinator (read first)

- **Behaviour change, intended by the charter.** An operator-configured auxiliary host that is not
  `https://api.fluxrouter.ai` (cli-chat-proxy, session backend, skills/workspaces/conversations/modes,
  sandbox, relay, OAuth issuer, OTLP collector, storage proxy, voice, embeddings, managed MCP) now gets the
  bearer and **no** `x-userid` / `x-email` / `x-teamid` / `x-fuigo-agent-id` / client labels. Fuigo ships
  every one of those bases empty, so a default install is unaffected. A Ferrox service run on another host
  that keyed on these headers (billing attribution, the imagine/video ZDR scoping on
  `x-fuigo-client-identifier`, the proxy version gate) must be FluxRouter-operated to keep them.
  **Recommendation: accept.** If a managed deployment needs identity on its own host, add an explicit
  per-origin opt-in in its own packet (the P30 position).
- **`client-version` / `client-identifier` treated as identity.** P30 recommended reclassifying them as
  product disclosure. This packet's charter named the voice STT path, which sends only
  `x-fuigo-client-identifier`, so P43 keeps the P15 classification already used by the sampler and gates
  them everywhere. **Recommendation: keep.** Reclassifying later is one edit to `IDENTITY_HEADER_NAMES`.
- **Body-carried identity is out of scope and recorded.** The internal OTLP resource (`user.id`,
  `deployment.id`, `team.id`, `organization.id`), the feedback/session-registry bodies (`agentId`) and
  Mixpanel events still carry identity in the payload. That is proposal 1.
- **`X-Grok-Agent-ID`** (`fuigo-mcp/src/servers.rs:5361`) is a per-session id sent to a local agent
  endpoint, not a user identifier. It was not changed.
- **Not stripped by design:** headers a user or operator configured themselves (`[model.*] extra_headers`,
  OTLP header settings, MCP server headers). A blanket strip in `dispatch::execute` was considered and
  rejected for that reason.
- `fuigo-shell` full runs are labelled `--skip session::workflow::manager::tests` (P29/P38 rule) at both
  parent and tip.

## 3. Design

- The identity class is `fuigo_extra_ca::fluxrouter::IDENTITY_HEADER_NAMES`: `x-fuigo-user-id`,
  `-deployment-id`, `-agent-id`, `-client-version`, `-client-identifier`, `x-userid`, `x-email`, `x-teamid`.
- The new `IdentityDisclosure` methods are below. Only `for_destination` and `for_websocket_destination`
  can grant, so P30's type guarantee is unchanged:
  - `header_map(pairs)` returns an empty map when identity is withheld. It accepts identity names only
    and skips invalid values (pinned).
  - `withhold_from_header_map`.
  - `allows_header`.
  - `for_websocket_destination`: `wss` to the compiled host; `ws` is refused.
- `fuigo-http` re-exports `fluxrouter`, so crates that reach `fuigo_extra_ca` only through it
  (`fuigo-memory`, `fuigo-shell-session-support`) need no Cargo.lock change.
- `fuigo-shell` shares `remote::account_identity_headers(url, user_id, email)` across its auxiliary
  clients.
- Every decision is taken on the URL the request actually goes to: the request URL itself, or a client
  base that every one of its requests extends. Cross-origin redirects are already refused
  (`fuigo-extra-ca/src/redirect.rs`). The audit confirmed both points independently.
