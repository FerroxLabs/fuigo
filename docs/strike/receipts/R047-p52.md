## Changes
1. **Proposal 1 done.** `is_remote_session()` now ignores empty values (`is_some_and(|v| !v.is_empty())`), the rule `terminal_context().is_ssh` uses. `is_remote_session_tracks_each_ssh_variable` pins: none -> local; each of SSH_CONNECTION / SSH_TTY / SSH_CLIENT alone and non-empty -> remote; each alone and EMPTY -> local; empty SSH_TTY plus non-empty SSH_CLIENT -> remote.
2. **Astra LOW done, and Astra's round-2 MED fixed.** The marker is now `<parent pid>|<test name>|<payload>`. A child is recognised only when the pid names its real parent (unix `getppid`) and the name equals its own test thread name, so a stale marker in an outer shell cannot activate it (unit-tested in `reexec::tests::marker_must_name_this_process_parent_and_test`). A marker that names our own parent but does not match our test makes `run_self_in_child` panic instead of recursing. A marker forged to the exact launcher pid and test name remains possible and is stated as deliberate misuse.
3. **Proposal 2 done.** New `crates/codegen/fuigo-test-support/src/reexec.rs` (`child_payload`, `run_self_in_child`, `rerun_test_with_env`, `rerun_with_ssh_env`, `rerun_without_ambient_ssh`, `SSH_VARS`). `fuigo-pager/src/test_util.rs` now re-exports it (its 45-line copy is gone; the 18 P48 call sites are unchanged). `fuigo-shared` takes `fuigo-test-support` as a dev-dependency; `Cargo.lock` gets the one matching line (checked: no path from test-support back to fuigo-shared, `--locked` builds pass). Why test-support: it already is the pager's dev-dep and adds no new crate.

# Round 3: bounded wait for the re-exec child (code commit `0ab7e2b3470cc6a2a1028d6344e03f422dfea90a`)

`fuigo-test-support::reexec::run_self_in_child` no longer waits forever. The child's stdout and stderr are drained by reader threads while the parent polls `try_wait`; past the deadline (default 300 s, overridable with `FUIGO_TEST_REEXEC_TIMEOUT_SECS`, whole seconds, zero or junk falls back to the default) the child is killed and reaped and the test fails with `<test name>: re-exec child timed out after <deadline> and was killed`, plus the child's captured output. `try_run_self_in_child(payload, env, deadline)` is the `Err`-returning form used by the test.

# Round 4: clippy `disallowed_methods` on `Command::spawn` (code commit `8fdbf2842c58f5e7f3036b2ec339bc7b49540f97`)

The stacked re-proof found one new warning, `use of a disallowed method std::process::Command::spawn` in `reexec.rs`. `crates/codegen/clippy.toml` bans raw child spawning and says to "allow with a reason where a child is waited on or deliberately detached".
