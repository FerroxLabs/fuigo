# R078 - P58: fuigo-workspace tests write HOME/FUIGO_HOME in the shared process

Follow-up tip: 081616c1 (see the follow-up section). Code tip under test for the stress/gate evidence: c35c28710cddf0dfb3e5ff64bbcf2f0f0c324ac8 (strike/p58), parent ae59250998a873305c7b28f32a3d79241bc00312 (integration). The receipt commit follows and is docs only.
Toolchain digest (rustc -vV sha256, in-tree 1.94.0): b75985398e5509a90a7d5d68f8ec6690675f703c5cfa11893b04fc9c3fceca69.
Build host: hetzner-dsm lane p58 only. No cargo or Docker on the Mac. Lane target and worktree deleted after the run.

## Root cause (measured)
`fuigo-workspace` tests wrote HOME / FUIGO_HOME / USERPROFILE through `TestEnvGuard` / `LockedTestEnv` under `ENV_TEST_LOCK`. The lock only excludes other writers; every reader (permission manager, trust, session::git, handle, hub_auth) reads those keys through production code without it. First loaded run at the P58 base: 5 failures, 3 of them panics in my own new guard naming the next unguarded writer.

## Fix
- `fuigo-test-support` added as a dev-dependency of `fuigo-workspace` (no cycle; fuigo-test-support does not depend on it; Cargo.lock updated).
- Every test that writes an `OWN_PROCESS_KEYS` key starts with `if fuigo_test_support::env::rerun_in_own_process() { return; }` (65 writer functions found by a transitive scan of set/unset/set_var/remove_var callers; 58 tests edited, 4 fixtures reached through their callers).
- Runtime guard: `TestEnvGuard::set/unset` call `fuigo_test_support::env::require_own_process_for(key)`, which panics on a shared-process write of an own-process key. `LockedTestEnv` goes through it.
- Also own-process: the three `auxiliary_service_wiring_*` tests (FUIGO_CLI_CHAT_PROXY_BASE_URL), the three startup-stage metric-delta tests, the swallowed-probe handshake test, the revived-life install test, the git-gate invalidate test (shared ROOT_CACHE).
- Different root causes, fixed in tests (no production change except envrc): fixed `sleep`/short windows that a starved host outruns became polls or generous budgets (`bind_mcp_discovery_*`, `a_failed_server_is_retried_*`, `two_phase_drain_*`, `queue_depth_reflects_*` now waits on the observable, `queue_stats_sampler_*`, hub_auth proactive polls, hub background-task tests use a released gate instead of `sleep 2`, `recovery::cleanup_removes_only_expired_dirs` sets the mtime instead of sleeping, git-gate invalidate test gets 2 ODB permits and waits for walk 2 before releasing).
- Production change: `envrc.rs` `PipeDrain` reader does one final non-blocking drain (EINTR retried, byte cap kept) when told to stop, so a starved reader thread does not lose what the evaluator already wrote (`envrc::tests::test_simple_export` / `chatty_background_child_*` failed under load).
- Regression boundaries kept: the swallowed-probe test uses a 9 s deadline (below the 10 s probe cap, so an unsplit budget still fails it) and runs in its own process; the expired-seed bound is unscaled 20 s (below the 60 s forbidden wait); the refresh-lead check keeps a sign-sensitive floor `seed_expiry - observed_at - 1 s` and the 4.5 s ceiling.
