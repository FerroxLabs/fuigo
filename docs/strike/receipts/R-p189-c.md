## Round 3 (placement-gate race)

Locking rule (verbatim from `session_cgroup/imp.rs`, above `enum Gate`):

1. Every spawn decision (placed, unplaced-with-latch, or refused) is made and RECORDED while holding the gate's READ side. The `breached` latch for an unplaced start is set while the read lease is held, BEFORE that command starts, and the lease is held until its `spawn()` has returned, exactly as for a placed spawn (this includes the unplaced fallback after a failed placement write).
2. `kill_and_wait` takes the WRITE side (so no spawn decision is in flight), sets `Stopping`, and only then reads `breached` and the own-pid guards, writes `cgroup.kill` and reads `populated`, holding the write side throughout. By rule 1, `breached` read under the write side is final for everything that started before it.
3. A spawn that cannot take the read side because the write side is held (try-lock failed, or the lock is poisoned) is REFUSED (`SpawnPlacedError::Stopping`): nothing runs. `kill_and_wait` leaves the state `Stopping` after it returns, until `reopen()` (a failed stop) or session end. The ONLY state allowing an unplaced start is `Closed`, set by `close()` at session end, where no kill follows.
4. A spawn never blocks behind a kill: the read side is only try-locked.

Hence: if `kill_and_wait` returns `Emptied`, no process of this session started outside the cgroup before that result, and none can start during or after it until the gate is reopened.

- Item 1: `place_or_latch` latches under the lease; `spawn_placed_impl` holds the lease through the placed, unplaced and fallback `start()`.
- Item 2: `kill_and_wait_as` sets `Stopping` under the write side; refusals no longer restore the gate.
- Item 3: try-lock failure or poison => `Stopping`; `Closed` is the only unplaced state.
- Item 4: read side is try-locked only.
- Item 5: `reopen()` only sets the gate `Open`; `breached` is never cleared (after a failed stop the session continues, a later stop still reports incomplete). Test `reopen_never_clears_breached_...`.
- Item 6: conservative latch kept: it must precede the fallback start to be race-free, when the fallback's outcome is unknown.
- Item 7: `SessionCgroup::spawn` is `pub(crate)` and uses the same lease-held, latch-under-lease path (refuses on `Closed`).
- Item 8: guard test `new_command_closures_are_bare_command_new` (fuigo-tools) checks the five `new_command` closures are a single bare `Command::new(..)`; the entry takes a closure so it cannot build the Command itself.
- Tests added: parked unplaced spawn (session end) and parked fallback (failed placement write) with a `cfg(test)` hook: `kill_and_wait` does not return until the spawn finished, then `Refused(Breached)`; spawn while kill holds the write side and after it until `reopen()` => `Stopping`, nothing runs.
