What changed:
- `admit_client_mcp_servers` (session/new, load, admin) removes key references from every client server (args, env, headers, url) and
  records a note; `mcp/upsert` does the same, persists the CLEANED definition and now writes the untrusted mark with it
  (`__fuigo_untrusted_source = true`, only when set), so a value that composes a reference under another environment
  (`${SW:-$}{FUIGO_API_KEY}` with `SW` set today) stays untrusted after a restart; it also looks through up to 8 expansions.
- Same refusal for servers a hub client configures (`workspace.configure_mcp`) and for inline `mcpServers` of an agent definition.
- fuigo-mcp binds the key to a header's CONFIGURED text before substituting `${session_id}` (a fork's client-chosen `newSessionId`
  could otherwise complete `Bearer ${${session_id}}` into a reference after the refusal ran).
- OAuth settings (client id, secret variable) are loaded by name; they now apply only when the active server of that name reaches the
  same URL as the configured one, so a client server cannot borrow a configured server's secret.
- Notes: new `SessionUpdate::ConfigNotice` (transient), sent by `MvpAgent::announce_config_notices` at new and load for the
  refusals recorded after a mark taken before that session's config load, minus other projects' files. TUI: plain system note in the
  scrollback. Headless: `plain` stderr `warning:` line; `streaming-json` a `config_notice` line; `json` and `streaming-messages-json`
  stderr line. An unknown client shows nothing (unknown-variant fallback).
- Note text: lists `$FUIGO_HOME/{config,managed_config,requirements}.toml`, the same three under `/etc/fuigo`, `~/.claude.json`,
  `~/.cursor/mcp.json`, files under `$FUIGO_HOME/hooks/`, and what may not (project config/.mcp.json, plugin, worktree, other file under
  `$FUIGO_HOME`, `FUIGO_CONFIG_PATH` file, MCP server from an editor or ACP client).
