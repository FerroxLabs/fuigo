## Fix
`crates/codegen/fuigo-mcp/src/http_policy.rs`: `CheckedOAuthClient` learns token endpoints from every
authorization-server metadata response it fetches (`judge_token_endpoint`: declared issuer and `token_endpoint` must be on
the origin that served the document; protected-resource documents, which carry `resource` and no `issuer`, are ignored;
refusals are sticky and revoke earlier admissions; a table over 32 endpoints fails closed) and refuses any form-encoded POST
carrying grant_type, code, refresh_token, client_secret, code_verifier or client_assertion to an endpoint not admitted.
JSON bodies (DCR) are not parsed as forms. The reason travels via a task-local (`capture_refusal`) past rmcp's opaque
"Request failed". `oauth.rs`: `exchange_callback` reports it; `ensure_oauth_ready` does not hydrate without validated
metadata (rmcp would otherwise guess `{base}/token`). `servers.rs`: a refused refresh is terminal, not transient; refresh
sites log the reason. Error text example: "refusing to send OAuth credentials (...) to <endpoint>: refused: the authorization
server metadata served from <origin> names token_endpoint <endpoint>, which is on a different origin (<origin>)...".
