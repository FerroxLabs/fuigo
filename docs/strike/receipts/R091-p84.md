## 2. The defect, proven at the parent

A `LocalRef` is the agent's address. `MvpAgent::new` returned the agent by value, so moving that value after it had spawned
bound work (out of a `Box`, into a `Vec` or an `Rc`, `std::mem::swap`) left the work pointing at the old place. Test-first
commit `bf69f13e` (the three tests alone on `e0145e0f`), `dev-attempt3.out` (sha256 `1d1e8a28…7eeb37`):

| test (`agent::mvp_agent::tests::p84_relocation_tests::`) | plain build | ASan build |
|---|---|---|
| `moving_the_agent_out_of_its_box_after_it_spawned_work_keeps_that_work_on_the_agent` | exit 101, assertion `:64` | **exit 1, `AddressSanitizer: heap-use-after-free`**, in `Cell<u64>::set` ← the bound task ← `local_ref::Driver::poll`; freed by the `Box`'s `dealloc` (`run-red-asan-moving_the_a.log`, sha256 `e58b57d4…34f88d`) |
| `swapping_two_agents_after_both_spawned_work_keeps_each_task_on_its_own_agent` | exit 101, `:92` (each task writes into the OTHER agent) | exit 101, same (no freed memory involved) |
| `an_agent_moved_into_an_rc_after_it_spawned_work_still_drops_that_work_first` | exit 101, `:110` | exit 101, same |

An earlier version of the box test (`43511dea`, attempt 2) failed its assertion but was NOT flagged by ASan: the box's
allocation was still alive at the point of the write. The test now frees it first; that is the version above.

## 3. The fix

`793e669e` — **the split.** New `agent/mvp_agent/handle.rs`: `MvpAgentHandle { state: Pin<Box<MvpAgent>> }`.
`MvpAgent::new` / `MvpAgent::with_models` return the handle; the agent is boxed and pinned in the constructor, before it can
spawn anything, and dropped in place. `MvpAgent` keeps its name, its 16 `impl` blocks and every `&MvpAgent` signature (so
the ~80 files that take `&MvpAgent` are untouched) but no `MvpAgent` value exists outside such a box (the only struct
literal is in `with_models`; `bound_tasks` is private), and it is `!Unpin` (`PhantomPinned` in `BoundTasks`), so safe code
cannot get `&mut MvpAgent` out of the pin. The handle `Deref`s to `MvpAgent` and forwards the 14 `acp::Agent` methods
`MvpAgent` implements (`logout`, `fork_session` keep the trait defaults on both). The three `&mut self` setters
(`set_memory_config`, `set_activity`, `set_config_watcher_path_tx`) moved to the handle: `Pin::get_unchecked_mut` to assign
one field, after asserting no bound future is pending. Call-site changes: `Rc<MvpAgent>` → `Rc<MvpAgentHandle>` in
`agent/server.rs` and `fuigo-pager/src/acp/spawn.rs`; test helpers' return types; one test that assigned `agent.gateway`
now uses `#[cfg(test)] set_gateway_for_tests`.

`95c361fb`, `8d37dc2c` — **escape hardening (answer to r2/r3).** `LocalRef::get` checks a thread-local mark, set while the
thread builds (`spawn_bound`'s closure), polls (`Driver::poll`) or drops (`Driver::drop`, the `BoundTasks::drop` drain, the
closed-spawn path) one of that agent's bound futures, and panics anywhere else before dereferencing. The agent is
identified by a process-unique id in `BoundTasks`, not its address.

`90bbbe23` — clippy: `#[allow(clippy::new_ret_no_self)]` on `MvpAgent::new` (it returns the handle by design); the test
helper no longer needs an explicit deref.

**P83 ordering kept:** `BoundTasks` is still the first field; `BoundTasks::drop`, `Driver` and the re-entrant abort are
unchanged except for entering the context mark. All six `p83_teardown_tests` and both `local_ref` unit tests are kept; the
only edit is the type of one test's thread-local (`Rc<MvpAgent>` → `Rc<MvpAgentHandle>`).

Files: `fuigo-shell/src/agent/{mod.rs,server.rs}`, `agent/mvp_agent/{mod.rs,agent_ops.rs,handle.rs,local_ref.rs,tests.rs,
replay_tests.rs}`, `agent/mvp_agent/tests/{p83_teardown_tests,p84_relocation_tests,list_running_heal_tests}.rs`,
`fuigo-pager/src/acp/spawn.rs` (12 files, +561 −59).

   id then go away. Needs `ChildRunner` (fuigo-tools `task/coordinator_state.rs`) to drop its `'static` bounds, or the
   subagent runner to stop holding a `LocalRef`. Closes r2 HIGH and r3 HIGH 1 for good.

3. `session::interrupted_turn::tests::a_session_live_in_another_process_is_left_alone` failed once at `e0145e0f` under load
   (`p84g-parent-fuigo-shell.failset`): a flaky test to chase.
