Design notes:
- **One rule, one function.** `fuigo_computer_hub_sdk::check_token_endpoint` (fuigo-shell already depends on the SDK,
  so no crate move and no cycle). The shell wraps it in `oidc::protocol::checked_token_endpoint(issuer, token_endpoint)
  -> Url`; the returned URL is what gets posted.
- **Where it is applied.** `exchange_code` (code + verifier) and `refresh_tokens` (refresh token, once, before the retry
  loop) take the issuer and check at the point of sending. `run_login_flow_with_config` also checks right after
  discovery, so a refused provider stops the login before the browser opens.
- **The exception.** `is_builtin_split_host_pair`: issuer origin exactly `https://accounts.google.com` (default port,
  no userinfo) with token endpoint origin exactly `https://oauth2.googleapis.com` (default port). Directed, exact host,
  two constants. No list, no configuration. The hub (SDK `do_refresh`, `fuigo-workspace` proactive refresh) gets it
  through the same function.
- **Refusal on refresh.** New `OidcRefreshResult::Refused { message }` -> `RefreshOutcome::TransientFailure` with the
  reason. Not retried, not counted toward the transient-to-permanent budget (nothing about the credential was learned),
  never reaches the credential-clearing branch in `manager.rs` (that is `RefreshTokenRejected` only). The discovery
  document stays cached, so repeated refusals make no network requests.
- **Refused redirects.** `refused_redirect` turns the shared client's redirect-policy error into the same refusal:
  one POST to the admitted endpoint instead of three, reason kept, not counted.
- **Loopback http.** `allow_loopback_http(test_build, local_dev_issuer)`: test builds (mock issuers), or the local-dev
  issuer when `FUIGO_LOCAL_AUTH` selects it. Both inputs are pure functions with tests for the shipped-build values.
- **Logs.** Discovery-named URLs are logged as origin + path only and only for http(s); transport and decode errors
  from discovery, exchange and refresh have their URL removed.
- **Test-build substitution, stated plainly:** `login.rs::open_browser` records the URL instead of launching a browser
  under `cfg(test)`. The browser is not the code under test; the recording is what lets the login test observe that the
  refusal comes first.

## Release notes (user-visible behaviour changes)

- **Sign-in and refresh are bound to your identity provider:** Fuigo now sends your authorization code and refresh
  token only to an https token endpoint on your issuer's own address, and never follows a redirect away from it.
- **Google sign-in works with that rule:** the Google pair (issuer `accounts.google.com`, token endpoint
  `oauth2.googleapis.com`) is built in for sign-in, refresh and workspace hub connections; P87 alone would have
  stopped hub connections from refreshing Google sessions.
- **Other split-host providers are refused (needs Sean's yes):** providers that issue tokens from a different host than
  their issuer, such as Amazon Cognito user pools, can no longer sign in or refresh; `fuigo login` says why before the
  browser opens.
- **Plain-http issuers are refused (needs Sean's yes):** an `http://` issuer no longer works for OIDC sign-in or refresh,
  except the developer-only local accounts app selected with `FUIGO_LOCAL_AUTH`.
- **A refused refresh keeps you signed in:** when a refresh is refused for one of these reasons, Fuigo keeps the stored
  sign-in, shows the reason and does not ask you to sign in again because of it.
- **Quieter logs:** URLs taken from the provider's discovery document are logged without credentials or query strings.

## Proposals (outside ownership)

1. **MCP OAuth token endpoint binding (HIGH, new packet):** decide the rule (token endpoint https on the authorization
   server issuer's origin, plus the same Google pair), check what rmcp already validates, survey the metadata of the
   MCP servers users connect to, then enforce it in `CheckedOAuthClient` or by validating metadata before
   `set_metadata`. Gate `fuigo-mcp`.
2. **Keep raw OAuth error bodies out of logs (MEDIUM):** keep status and the parsed `error` code in
   `TokenExchangeHttp` / `TokenRefreshHttp` for classification; drop or bound the body and `error_description` in
   Display and unified logs.
3. If more split-host providers must work (Cognito), add them as further exact built-in pairs after a decision per
   provider; Cognito's token host is per-tenant, so it cannot be one exact pair.
4. `OidcError::DiscoveryHttp` and the JWKS fetch still name their URL in errors (configured-issuer URL and a
   credential-free fetch).
