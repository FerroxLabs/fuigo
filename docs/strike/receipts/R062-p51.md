# ROUND 4 (coordinator decisions on the two proposals; based on ae592509)

Code commit under test: 985660e020768d8e1e25e41d0e7103230b10761a. Toolchain digest b75985398e5509a90a7d5d68f8ec6690675f703c5cfa11893b04fc9c3fceca69.

## (1) Terminal record carries the spent usage
Cause: `HeadlessEmitter.usage` was only filled from the final prompt ledger (`_meta.usage` on the response or error data). A run that ended without one (interrupt, timeout, connection loss mid-turn) reported zeros (messages `result`) or nothing (json `error` document, streaming-json `error`) although earlier responses had been billed.
Fix: the emitter sums every `ResponseCompleted` usage it sees (ACP identity: input includes cache read + creation; total = input + output), `terminal_usage()` returns the shell's ledger when present, otherwise the observed sum marked `usage_is_incomplete` (an in-flight response is not in it). `on_error` uses it for json, streaming-json and messages, so all three formats are fixed by one rule. Plain has no usage representation; unchanged.
Tests: unit `a_terminal_error_record_carries_the_usage_of_completed_responses` (two 10/20 responses -> 20 in / 40 out on each format's terminal line); process `an_interrupt_mid_turn_reports_the_usage_already_spent_in_every_format` (tool-call response completes, the follow-up request is received and held via `expect_response_blocked`, SIGINT, exit 130, terminal record usage.output_tokens > 0 on json, streaming-json, messages).
Mutant U1 (`terminal_usage` ignores the observed sum): unit test FAILED (log U1.log).
Results at 985660e0: process test file 8/8 pass (exit 0, sha256 6cf7c5ef0290e229574403397bda34b966eae1c3d...), `-p fuigo-pager --lib headless` 224 passed 0 failed (exit 0). Each ran on its own target dir, deleted after.

## (2) The other reaper behind surviving mutant N7b
Named: `AgentShutdownGuard::drop` (crates/codegen/fuigo-pager/src/acp/spawn.rs): when the interrupted run future is dropped it cancels the in-process agent and joins the worker for `SESSION_FLUSH_GRACE + AGENT_JOIN_SLACK`, during which the session actors receive `Shutdown` and reap their background tasks. That is why removing `kill_all()` left the child dead.
Conclusion: `kill_all()` is NOT redundant. `main` leaves through `process::exit`, which skips Drop, and the guard only reaps if its join completes; on `JoinOutcome::TimedOut` (wedged worker) it logs and proceeds, and the detached `setsid` children would then outlive the process. `kill_all()` is the backstop for exactly that case. I could not write a behavioural test that bypasses the guard (the agent is an in-process thread that cannot be wedged from a process test), so the call is pinned at the source with the repo's existing pattern (`main_installs_the_trust_record_sink_first`): `interrupt_exit_reaps_children::the_interrupt_arm_kills_owned_process_trees_before_exiting`. Mutant U2 (remove `kill_all()` from the arm): that test FAILED (log U2.log). Limit, stated plainly: this is structural coverage, not runtime proof of the wedged-worker path.
