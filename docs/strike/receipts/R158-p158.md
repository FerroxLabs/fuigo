- **Linux** (Landlock + bwrap re-exec): the workspace profile grants the workspace RW through Landlock; the bwrap
  plan bound read-only only Fuigo's hook sources and trust-boundary files (`hook_write_deny.rs`). `<ws>/.git/hooks`,

  `~/.gitconfig` too. Proven by the red e2e `tests/git_write_deny_e2e.rs` at `e32c4c28` (run `red`, exit 101:

- D-Bus: red e2e `tests/bus_socket_deny_e2e.rs` at `408077c4` (run `redbus`, exit 101:

### What is protected now (fuigo-sandbox `src/git_write_deny.rs`, wired in `profiles.rs`, `hook_write_deny.rs`, `lib.rs`, `deny/mod.rs`)
For every profile that enforces the hook write-deny (workspace, read-only, strict, custom not extending devbox):
- `<ws>/.git/{hooks/, config, config.worktree}` and a `commondir` pointer (denied, never created); an existing
  `commondir` is followed and the common dir protected;
- present submodule git dirs under `.git/modules` (symlinked ones followed, the link protected), their
  `commondir`, and each submodule checkout's `.git` pointer;
- a workspace that is a linked worktree or submodule checkout: its `.git` file, the git dir's pointer files,
  `config.worktree`, and the common/whole git dir's entries; pointers read byte-exact as git reads them;
- every `core.hooksPath` tree (repo `config` + `config.worktree`, includes/includeIf followed, last assignment wins,
  conditional values protected beside the effective one, tab/space spellings both), resolved as the kernel does
  (`..` after a symlink), in the workspace and in every present submodule checkout for system/global values;
  a symlinked hook is protected where it leads (dangling: must not be created);
- the system config (`GIT_CONFIG_SYSTEM`, else `/etc/gitconfig`, Homebrew and Apple CLT/Xcode files;
  `GIT_CONFIG_NOSYSTEM` honoured) and global config (`GIT_CONFIG_GLOBAL`, else XDG/`~/.config/git/config` and
  `~/.gitconfig`) with their includes; `/dev/null` (a device) is never protected;
- link nodes on the way (macOS: unlink/create of the link itself denied; Linux: refuses unless the link lies inside
  a tree bound read-only);
- fail closed (sandbox refuses to start) on any git file it cannot read as git reads it, a hard-link alias of a
  protected file, an unlistable protected tree, a glob-shaped socket path.
- Fuigo's trust-boundary files (`config.toml`, `trusted-folders`, managed config, requirements, `sandbox.toml`) and
  hook dirs: already protected by `hook_write_deny.rs` (same list as upstream `TRUST_BOUNDARY_FILENAMES`).
- Enforcement: macOS Seatbelt write-deny rules; Linux read-only bwrap binds riding on the hook plan (missing git
  layout created empty: `hooks/` dir or a config file; ancestors pinned as mount points), verified inside bwrap by
  `verify_git_write_deny_enforced` (called from `fuigo-shell/src/config/mod.rs` next to the hook verify; a forged
  `__FUIGO_INSIDE_BWRAP` fails it). Reads still work (e2e asserts `.git/config` readable, objects/index/worktree
  writable).

### Deviations from upstream (Fuigo has no grant cards; stated in module docs)
1. No workspace `.git` at start → no repo entries (upstream protects the layout before `git init`; Fuigo would
   then block every `git init`).
2. Other linked worktrees are not covered (Fuigo creates and removes its own worktrees; protecting them broke removal).
3. `.git/info/` stays writable (Fuigo's commit workflow seeds `info/exclude`; attributes can only select drivers the
   protected configs define).
4. Linux cannot bind a missing name, so creating a missing `commondir` is denied only on macOS.
5. Upstream's broader home floor (shell rc files, cargo/gradle/npm configs, `~/.local/bin`, editor dirs, workspace
   `.vscode`/`.claude`/`.fuigo`) is out of this packet's git scope → proposal below.
6. Content-filter config is read as the union of libgit2's walk and `git config --list --show-scope --includes -z`
   (upstream: libgit2 only), so a parser disagreement on an include cannot hide a filter.

## Behaviour changes for Sean (each with my recommendation)
- In enforcing profiles an agent can no longer write `.git/config` of the workspace repo: `git config`, `git remote add`,
  `git push -u`, `git submodule init/add`, and Fuigo's own `export_github` (`git remote add/set-url`) fail inside the
  sandbox. **Recommendation: keep** (that file is the code-execution vector: `core.fsmonitor`, `core.hooksPath`,
  filters); users run those commands outside the sandbox or with `--sandbox devbox/off`.
- Agents can no longer reach D-Bus/systemd in non-devbox profiles (`notify-send`, `systemctl --user` fail).
  **Recommendation: keep** (upstream does the same; it is a sandbox escape).
- In a repo with a locally configured content filter (git-lfs), agent `git status`/`git diff` now prompt instead of
  auto-approving (S4, as upstream). **Recommendation: keep**; a filter is a command the repo config runs.
- Startup refuses (fail closed) on unusual layouts: hard-linked hooks/configs, a symlinked `.git`/config inside a
  writable root on Linux, a dangling hook symlink on Linux, an unparseable or oversized git config, a glob-shaped
  bus path. **Recommendation: keep**; each error names the file.

## Release-note text (for docs/release-notes-1.0.22.md)
- **S:** The sandbox now stops a sandboxed agent from planting code that git later runs outside it: the workspace
