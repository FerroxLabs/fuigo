# R184 — P184: apply_patch is permission-checked per file

## The hole (1.0.21 too)
`AccessKind::from(ToolInput::ApplyPatch)` was one placeholder `Edit("apply_patch")`, and the tool added, deleted,
updated and moved files with no per-file check. Path-scoped `Edit` deny/ask rules (`Edit(secrets/**)`), the
protected-edit floor (`.git/hooks`, shell startup files, Fuigo/Claude/Cursor config, the MCP/LSP configs P166 adds), the
auto-mode edit fast path and the session edit grant never saw the files a patch really touched. Raised in R166.

## What changed
- **Targets travel with the request.** `PermissionRequest::edit_targets: Option<EditTargets>` (`Paths(Vec<String>)` or
  `Unparseable(msg)`), built by `edit_targets_for(&ToolInput)` from the input that runs. The ACP session
  (`tool_calls.rs::prepare_tool_call`, after any PreToolUse hook rewrite) fills it. `patch_target_paths` /
  `patch_edit_targets` (fuigo-tools) list every Add/Update/Delete path and both ends of a move, in order, once each.
- **The manager judges every target** (`manager/mod.rs`, `gate_preflight.rs::evaluate_edit_targets`):
  - unparseable or empty patch → `PolicyDeny`, before YOLO and every other shortcut;
  - per target, three spellings (`EditTargetSpellings`): `written` = `cwd.join(path)` uncollapsed, exactly what the tool
    writes; the model's raw spelling; and the physical path (`policy::resolve_following_symlinks`, symlinks followed
    literally, no `\`→`/` rewriting). Deny/ask on any spelling binds; only `written` earns an allow, and never when it
    contains `\` on Unix (the policy reads `\` as a separator); an unresolvable physical path forces a prompt;
  - across targets: any deny refuses the patch, else any ask prompts, an allow rule covers the patch only when it covers
    every target (an unmatched target falls back to the default flow);
  - protected-edit floor: the first protected `written` target; it blocks the session grant and the auto fast path as for
    a single-file edit.
- **The prompt names every target:** ACP title `Apply patch: a, b` plus one `ToolCallLocation` per target; hub payload
  description `Edit a, b` (`describe_edit_targets`); events carry the same list as `access_detail`.
- **The tool writes only what was judged:** it resolves paths as before (`cwd.join`), re-derives the targets with the
  same function from the same patch and refuses (`ApplicationError`, nothing written) any computed write/delete outside
  them (`first_unjudged_path`).
- **Hub:** only the mapping line in `hub_permission.rs` changed: `"apply_patch" => apply_patch_hub_access(args)` (an
  `Edit` naming every target; the placeholder when the patch does not parse). `hub.rs`, `policy.rs`, `shell_access.rs`
  untouched.
- **Ask binds over the session edit grant** for every edit tool (manager `Edit` pre-decision now needs
  `!policy_forced_prompt`), as reads and MCP already did. Pre-existing; found by Astra r1.

## Behaviour changes (for Sean / release notes)
1. A patch touching a protected path now prompts in auto mode and under "allow edits for this session" (before: allowed).
2. `Edit(...)` deny rules refuse a patch that touches a matching file (any target, either end of a move, through `..`
   or a symlink); ask rules prompt for it.
3. `Edit(...)` allow rules now apply to patches: a patch whose every target is allowed runs without a prompt (before: the
   placeholder matched no path rule, so it prompted).
4. A patch that does not parse, or has no file operations, is refused by the permission check (before: it prompted, then
   the tool returned ParseError / EmptyPatch). Applies in YOLO too.
5. An `ask` rule now prompts even after "allow edits for this session", for every edit tool.
6. On Unix a target spelled with a backslash never rides an allow rule (it prompts).

## Residuals (not fixed here) and proposals
- **Hub dispatch (P173 reconciliation).** On this base `hub.rs` prompts (or with YOLO skips) without evaluating policy at
  all; P184 changes only the mapping line, so the hub prompt names every target. P173's branch adds per-target hub policy
  (`hub_input_accesses` / `patch_target_accesses`). Proposal for the coordinator: when landing both, make P173 use
  `fuigo_tools::…::apply_patch::patch_target_paths` and the `EditTargetSpellings` judge (cwd-join written path, physical
  spelling, Unix backslash rule), and either emit `edit_file_paths` as a list or keep `describe_edit_targets`.
- **Write binding is lexical.** The tool re-derives targets from the same patch text; no approved physical-target set is
  passed into the tool, so a symlink retargeted between the check and the write is followed (inherited by every edit
  tool). Proposal: pass approved targets through the tool-call context and open with no-follow.
- **YOLO / `prompt_policy = allow`** still skip ask rules and the protected floor for patches, as for every tool
  (deny rules and the unparseable refusal still bind).
- **Display cwd (forked sessions):** apply_patch keeps 1.0.21's `cwd.join` (an absolute display path is written
  literally), unlike write/edit which map it; unchanged here on purpose (Astra r1).
- `cargo fmt` is not clean repo-wide on this base, so formatting was not gated.
