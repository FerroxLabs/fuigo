## Scope delivered (file: `crates/codegen/fuigo-tools/src/implementations/fuigo_build/ask_user_question/mod.rs` only)
1. **`wait_budget()` reads `non_interactive`.** New `NON_INTERACTIVE_RESPONSE_TIMEOUT = 30 s`. In a non-interactive
   session the budget is `min(configured, 30 s)`. It is never zero, and `timeout_enabled = false` does not remove the cap.
   A shorter configured or env (`FUIGO_ASK_USER_QUESTION_TIMEOUT_SECS`) budget still applies. Interactive sessions
   are unchanged.
2. **`TransportError` maps to `NO_OPERATOR_TEXT` when non-interactive.** This covers an embedder with no
   `fuigo/ask_user_question` handler (-32601). Interactive sessions keep the hard `ToolError`. `MalformedResponse` and
   a coordinator dropping `result_tx` still return hard errors in both modes.
3. **No-operator return before any channel or UI.** Session params and the sender are read first. If the session is
   non-interactive and the coordinator sender is already closed, the tool returns `NO_OPERATOR_TEXT` before creating the
   oneshot and before emitting `UserQuestionAsked`. If the channel closes between that check and the send, the result
   is the same. Interactive sessions keep the "coordinator channel closed" error. *Interpretation:* inside this file,
   the only signal that no operator can exist is a closed coordinator. The session flag alone is not enough, because §4.1
   requires that an embedder UI can still answer in a non-interactive session.
4. **`MIGRATION_FALLBACK` and `fallback_fire_and_forget` are removed.** A missing `UserQuestionSender` now returns a hard
   `ToolError::custom("missing_resource", "UserQuestionSender is not wired …")` in every session kind, and no notification
   is emitted.
- Not touched: `builder.rs`, `ensure_plan_mode_tools`, `format.rs` wording, and the interactive timeout/cancel code.
  Headless still answers `Cancelled` immediately and gets the same `NO_OPERATOR_TEXT` bytes; a test now pins those bytes.

## Proposals (outside P04 ownership; not drive-by fixed)
- **A (Contract E / fuigo-acp-lib):** the gateway's detached `ext_method` task should stop when its response receiver is
  dropped, or carry its own deadline, so a timed-out question does not leave a pending JSON-RPC request with a silent embedder.
- **B (fuigo-agent `config.rs`):** in `workspace_fuigo_build_toolset()`, either drop `AskUserQuestionTool` or have the
  workspace server inject a `UserQuestionSender`. Today, in proxy mode the tool would advertise itself and then fail with
  `missing_resource`. This mode is not shipped (see audit #3).
- **C (fuigo-tools `types/output.rs`):** update the `AskUserQuestionOutput` doc. `QuestionsSent` now means only "no
  questions provided"; every answered or unanswered path returns `UserAnswered`.
- **P00 (unchanged from the brief §5):** ask whether Murage's ACP client implements `fuigo/ask_user_question` and whether
  it ever sets `_meta.askUserQuestion: true`. If it does, the 30 s cap now applies to any human answering through that UI.

## Behaviour change to flag for embedders (Contract E)
A third-party embedder that sets `nonInteractive: true` **and** `_meta.askUserQuestion: true` and shows a human UI now has
30 s to answer. After that the model gets `NO_OPERATOR_TEXT`; before this change it had 30 minutes. This is the policy the
brief selected (§4.1), and the auditor recorded it as policy, not a defect.
