## Corrected A.2.1 rule 1 text (for the coordinator to amend)
> A header is FINISHED only if, between it and the next header or EOF: (i) the target's own first `running N tests` line appears; (ii) N equals the count the binary itself reports under `--list` (gate-supplied expected-N file; its absence, emptiness or unreadability makes the run inadmissible); (iii) after that line, the LAST well-formed `test result: (ok|FAILED). P passed; F failed; I ignored; M measured; X filtered out; finished in S.SSs` line has P+F+I+M = N; (iv) no `running` line follows that last result. Result lines before the target's own `running` line, malformed lines, and CR/ANSI-decorated variants (normalised first) never count. Each expected binary and each expected doc-tested library must appear exactly once. The old awk (`/^test result:/{o=0}`) is unsound: any child's summary clears the flag. `running`/`result` line counts are still never compared with the target count. **Doc-tests sections (Fable #2):** conditions (i)-(iv) are replaced by pairing: each `running N` is followed, before any other `running` line, by a well-formed result with P+F+I+M = N; there are 1 or 2 such pairs (edition-2024 rustdoc: merged + standalone); no `running` is left unpaired; no well-formed result appears without a pending `running`.
