# R186 - P186: leftovers of the admin-policy packets P169 and P183

## Problem
Three LOW findings of the last P183 audit (grok-p183-r10), the policy booleans outside the typed-pin table, and the two
P169 "not ported" items.

## Change (crate fuigo-config, `validation.rs` only)
- A1: the requirements Claude reader re-checks any blank by `trim().is_empty()` (was `u8::is_ascii_whitespace`), so a
  `\x0b`-only file gets the stability re-check and cannot clear the remembered copy mid-rewrite.
- A2: `validate_requirements_file` no longer forgets the validated copy on absence.
- A3: `NotFound` during the blank wait is absence only if `symlink_metadata` also fails; a dangling symlink is a broken source
  on both readers (`absent_unless_dangling`).
- B: `allowManagedMcpServersOnly`, `allowManagedHooksOnly`, `enableAllProjectMcpServers` and their snake_case spellings are
  `PinType::Bool` entries in `TYPED_PINS` (`POLICY_BOOL_KEYS`), also enforced on the Claude JSON file by
  `managed_settings_policy_errors`. LOCKDOWN_UNSET carries a reason for each.
- C: NOT implemented, see decisions.

## Behaviour change found in B (stricter, user visible)
A wrong-typed policy bool (`allow_managed_hooks_only = "yes"`) used to load and fail closed for that key only. It is now a
broken source: startup refuses (admin or fail_closed layer) or the layer is the last good copy plus lock-down. Existing test
expectation changed: `requirements_and_policy_sources_readers_give_the_same_verdict_p183r12`, TOML doc
`allow_managed_hooks_only = "no"`: before accepted (true), after broken (false). Two new rows added (TOML int bool, Claude
`"yes"`) plus a valid Claude row.

## Decisions needed (C, not implemented)
R169 only says "Not ported: `extraKnownMarketplaces` registration and the `plugin_auto_update` pin (not in the packet scope)".
No further spec exists, and neither is tighten-only as stated.
1. `extraKnownMarketplaces` from an admin source would ADD marketplaces users see (admin-registered sources); it is not
   stricter. Recommendation: do not port in 1.0.24; if wanted, specify that admin entries must still pass
   `strictKnownMarketplaces`.
2. `plugin_auto_update` pin: no such key exists in the code (only a per-marketplace `autoUpdate` field in
   fuigo-plugin-marketplace). Pinning it to false would be tighten-only, but the key name, scope and the reader are undefined.
   Recommendation: define the key (`plugins.auto_update`, Bool, pin to false only) in a follow-up with its reader.

## Item B withdrawn (coordinator, after the Grok audit)
Item B (the six policy booleans as typed pins) was reverted before landing (`8a17e843`, `2fefe13e`); the code is
again exactly the item A commit `ce3fb370`. Everything above that describes B (the "Behaviour change found in B"
section, the test `policy_bool_keys_are_typed_pins_p186`, the changed rows of
`requirements_and_policy_sources_readers_give_the_same_verdict_p183r12`) no longer applies.
Why: with B, a wrong-typed policy boolean made the whole admin file a broken source. In a RUNNING process that
already holds a validated copy, the copy then stays in force and the new file's OTHER valid, stricter keys
(`ui.yolo = false`, `permission.deny`, `sandbox.profile`, Claude `permissions.deny`) are not applied, whereas
integration applies them and fails closed only the bad boolean. That is weaker than integration in that sequence
(Grok, `codex-audit/grok-p186-r1.md`, HIGH). Per-key fail-closed stays, as on integration; no behaviour change.
Follow-up (not in this packet): the same sequence exists for every other typed pin since P183 (a new file with one
wrong-typed pinned key keeps the old copy instead of applying the new file's valid stricter keys). A
strictest-merge of the new file's type-valid keys over the copy would close it.
Low residual from the audit: a PARENT directory that becomes a dangling symlink during the blank wait still reads
as absence (copy kept, no extra lock-down), the same outcome as deleting the file.
