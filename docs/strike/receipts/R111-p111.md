## Fixes and the decisions taken
- **DI-01** (`rewind.rs`): `plan_conversation_rewind` builds the target conversation (replay included) before any project
  file is touched; its failure returns with nothing changed and says so.
- **DI-02** (`rewind.rs`, `fuigo-workspace` `file_state.rs`): every file that cannot be restored, deleted or checked is
  reported in `error`; `reverted_files` lists only files really reverted; `success: false`. **Decision: a partial file
  revert stops before the conversation is rewound and before any snapshot is dropped.** The conversation stays where it
  was and every snapshot at or after the target is kept, so the same rewind can be run again after the cause is fixed
  (it rewrites the already restored files with the same contents, then rewinds the conversation). Rewinding the
  conversation anyway would leave it describing a point in time some files do not match; rolling the restored files
  back would need a second set of writes that can fail the same way. The plan is read with the new
  `FileStateTracker::try_get_rewind_points`, strict on I/O errors and malformed rows, and still refusing after a lenient
  load (cancel, conversation-only rewind) skipped rows.
- **DI-03** (`compaction_witness.rs`, `persistence.rs`): **option B, loader detection.** Before the activation marker,
  the commit fsyncs `chat_history.jsonl` and durably writes `compaction_witness.json` (checkpoint id + length + SHA-256
  of the chat file). `load_light` and the fork copy use the checkpoint projection only when the witness names the
  latest marker AND the chat file is still byte-identical to the fingerprint; otherwise `chat_history.jsonl` stays
  authoritative (P88's rule; sessions of earlier versions and forks have no witness). Ordering (option A) was rejected:
  writing the history before the marker opens the inverse window (a compacted model view with no marker in the
  transcript, which rewind and the compaction marker logic then miscount). The witness is never removed; a stale one
  matches nothing. The length is compared first, so a normal resume reads no transcript for it.
- **DI-04** (`copy.rs`): **refuse.** A point-in-time copy stages the cut in an owner-only temporary directory and decides
  before the target exists. The cut is rebuilt from its own active compaction as P88 does; otherwise truncating the
  source's chat is accepted only when the latest compaction marker on the source's rewind-filtered live timeline equals
  the cut's, and (when that history starts from a compaction) a marked user turn at or after the target proves the cut
  point. Anything else is refused with an error that names the reason and says nothing was created. Refusing matches
  1.0.20 (which failed such a child at its first load) and never hands a child a summary of work it did not do; a
  text-only rebuild for cuts before a compaction is a possible follow-up (proposal below).

## Proposals (outside this packet)
- A text-only rebuild (as a rewind does) for a fork cut before the compaction a history starts from, instead of refusing.
- `copy_session_data_sync` overwrites an existing target directory's files when the id already exists (pre-existing);
  reserve the id exclusively.

  appends; making that rewrite acknowledged would close it.

## Release notes (one sentence each, for Sean)
- A "rewind all" that cannot rebuild the conversation (its compaction checkpoint is missing or damaged) now changes no
  files and says so; before, it could restore or delete project files and then report that nothing was reverted.
- When some files cannot be reverted during a rewind, Fuigo now lists each one, keeps the conversation and every saved
  file version so the same rewind can be retried, and no longer reports success or throws away the saved contents of
  the files it could not restore.
- A rewind that reverts files now refuses, with nothing changed, when the session's saved file versions cannot be read
  completely, instead of restoring only some files.
- If Fuigo stopped right after a compaction committed, the reopened session now continues from the compacted history
  instead of silently returning to the history from before the compaction.
- Forking a compacted session at a prompt whose exact history cannot be rebuilt (before the compaction its history
  starts from, or across a missing checkpoint) is now refused with an explanation instead of creating a fork that
  carries a summary of later work.
