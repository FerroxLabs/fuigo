New findings:

1. **N8 HIGH — Linux grants beneath protected trees bypass the entire tree denial.**  
   [hook_write_deny.rs:376](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/hook_write_deny.rs:376), [home_write_deny.rs:519](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:519).

   Use workspace `/home/u/project` and a custom `read_write` grant for existing `/home/u/.config/nvim/lua`. The protected entry is `.config/nvim`, which is an **ancestor** of the grant. `git_bind_targets` only accepts protected paths at or beneath writable roots, so it drops this tree. The workspace-inside-tree refusal does not apply because the workspace is elsewhere.

   The sandbox can overwrite a Lua module loaded by the next unsandboxed Neovim startup. The inner verifier repeats the same target selection and passes without checking this tree.

2. **N9 HIGH — The automatic Fuigo-home exception exceeds the stated temp-home limit.**  
   [home_write_deny.rs:554](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:554), [home_write_deny.rs:871](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:871).

   On Linux, set `HOME=/home/u`, `FUIGO_HOME=/home/u/.cargo`, use an unrelated workspace, and leave `.cargo/config` absent. `.cargo` is automatically writable and “essential,” which prevents pinning. It is absent from `configured`, so refusal is skipped too.

   Both outer planning and inner verification leave `config` creatable. The sandbox can install a malicious `build.rustc-wrapper`; the legacy `config` takes precedence over `config.toml`. This requires no temp-home layout. [Cargo configuration rules](https://doc.rust-lang.org/cargo/reference/config.html#hierarchical-structure)

3. **N10 HIGH — Protected-source listing errors still fail open.**  
   [home_write_deny.rs:678](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:678), [home_write_deny.rs:686](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:686).

   For an unprivileged user, prepare a hard link from `~/.ssh/config` to `<workspace>/ssh-alias`, then make `.ssh` searchable but unlistable, mode `0111`. Known filenames remain accessible.

   The new always-listed walk attempts `.ssh`, silently ignores its listing failure, and never records the protected inode. Writing `ssh-alias` therefore changes SSH configuration. Startup trees outside writable roots have the same error suppression. No scan bound needs to be exhausted.

4. **N11 HIGH — macOS permits importing a protected file through a missing parent directory.**  
   [deny/mod.rs:148](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/deny/mod.rs:148), [global_hook_sources.rs:153](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-config/src/global_hook_sources.rs:153).

   Start a home-writable macOS profile with `.cargo` absent. Rules deny `.cargo/config*` and `.cargo/bin`, but ancestor enumeration stops at the missing `.cargo`. No rule protects that parent node.

   Prepare `~/stage/config` containing a malicious Cargo configuration, then rename `~/stage` to `~/.cargo`. The rename operates on the unprotected directory node and imports the protected filename without creating it individually. Upstream explicitly generates missing-ancestor node denies for this attack; Fuigo’s reused renderer does not.

5. **N12 HIGH — macOS link-only entries lack protection against parent replacement.**  
   [home_write_deny.rs:420](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:420), [deny/mod.rs:229](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/deny/mod.rs:229).

   Prepare:

   ```text
   ~/.cargo/config.toml -> <workspace>/state/disabled
   <workspace>/state/disabled -> /dev/null
   ```

   These become link-node denies. Unlike ordinary protected entries, link-node rendering never protects their directory ancestors.

   The sandbox can move `state` aside and replace it with a prepared directory containing a regular, malicious `disabled` configuration. Neither original symlink needs to be individually unlinked. The unchanged home symlink then resolves to attacker-controlled configuration.

6. **N13 MEDIUM — Creating a nested pin invalidates the parent identity captured earlier.**  
   [hook_write_deny.rs:410](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/hook_write_deny.rs:410), [hook_write_deny.rs:463](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/hook_write_deny.rs:463), [hook_write_deny.rs:140](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/hook_write_deny.rs:140).

   On ext4, grant existing `~/.cargo` and initially absent `~/.cargo/zsh`, set `ZDOTDIR=~/.cargo/zsh`, and leave the corresponding configuration files absent.

   The scan requests both pins. Planning captures `.cargo` first, then creates its `zsh` child. That increments `.cargo`’s link count. `append_hook_plan_binds` subsequently rejects its own plan as `IdentityChanged`. This is a deterministic first-start failure caused by setup ordering, without concurrent mutation.
