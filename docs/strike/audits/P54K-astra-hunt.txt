1. **HIGH — PLAUSIBLE: existing backend ownership or routing can break at upgrade.**  
   Session upserts now replace the machine’s raw `agentId` with the backend-origin pseudonym. There is no old/new-ID mapping in the request. Sharing awaits this upsert before creating a link, while writeback clears its successfully uploaded messages and merely warns if the subsequent machine-linking upsert fails. A backend enforcing the previous owner ID could therefore reject sharing, lose agent routing, or split machine history without interrupting local work.  
   Evidence: [remote/client.rs:284](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/remote/client.rs:284), [remote/client.rs:450](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/remote/client.rs:450), [remote/sync.rs:119](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/remote/sync.rs:119). 2. **MEDIUM — PLAUSIBLE: registry device continuity and host identification degrade.**  
   New registrations send a pseudonymous `deviceId` and omit `hostname`. Registration happens at turn zero; subsequent update/finalize requests carry the session ID, without updating device identity. Without server migration, an operator can have old sessions under the raw device ID and new sessions under the pseudonym. If the registry returns the omitted hostname as absent, the session picker also loses its “Host” detail. Device-based deduplication or replica selection depends on unseen server logic.

5. **MEDIUM — CONFIRMED: origin changes create additional identity splits, beyond the upgrade.**  
   The hash includes scheme, host, and effective port. Moving the same backend between HTTP/HTTPS, host aliases, IP/DNS names, or nondefault ports changes the key. Registry and storage/backend services on different origins also receive different keys for the same machine, breaking direct cross-service machine-ID joins. Paths, queries, case normalization, and explicit default ports do not create new HTTP origins.

10. **INFO — CONFIRMED: stability follows the underlying ID; it is not a new persistent installation identity.**  
    The pseudonym uses a fixed domain tag, URL origin, and raw value—no token, session ID, timestamp, or random salt. Restarts retain it when the raw ID remains stable. `FUIGO_AGENT_ID` overrides the cache; otherwise Fuigo reads `$FUIGO_HOME/agent_id`, then derives a machine ID. Reinstallation with the cache preserved retains it; without the cache, stability depends on machine derivation, Linux hostname, and fallback behavior. Random fallback plus failed cache persistence can change it every process; that is an existing source-ID limitation. Logged-in Mixpanel users share an account-derived pseudonym across machines; API-key-only/logged-out fallback is machine-derived.  
    Evidence: [fluxrouter.rs:250](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-extra-ca/src/fluxrouter.rs:250), [telemetry/id.rs:52](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-telemetry/src/id.rs:52), [telemetry/client.rs:391](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-telemetry/src/client.rs:391), [agent_ops.rs:577](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/agent/mvp_agent/agent_ops.rs:577).

13. **INFO — REFUTED: default FluxRouter traffic or ordinary host spelling becomes accidentally pseudonymous.**  
    HTTPS plus the parsed API hostname permits identity, including case normalization, trailing DNS dots, and **any port**. Staging hosts, custom/managed hostnames, IP literals, HTTP, suffix lookalikes, and userinfo tricks do not qualify. IDN processing happens before comparison: a spelling normalized to the actual API hostname qualifies; a distinct punycode hostname does not. Thus managed/staging deployments lose raw identity deliberately, even if operated by the same organization. No configurable trust widening exists here.

**What P54 gets right**

- Track and engage use the same pseudonym; same-origin paths retain machine correlation. This avoids breaking new profile/event joins.
- LOC transformation happens once, at archive time, including old records; local attribution remains intact. [agent_ops.rs:4299](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/agent/mvp_agent/agent_ops.rs:4299)
- External OTEL, explicitly configured product events, direct-bucket review storage, and configured feedback authors retain their intended identity fields. [external/emit.rs:230](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-telemetry/src/external/emit.rs:230), [client.rs:418](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-telemetry/src/client.rs:418), [feedback.rs:389](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/extensions/feedback.rs:389), [feedback_manager.rs:93](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-shell/src/session/feedback_manager.rs:93)
- Shared HTTP clients reject cross-origin redirects, preventing an allowed request body from simply being redirected to another host. [redirect.rs:7](/Volumes/Mando/WaylandBots/Fuigo/wt-p54k/crates/codegen/fuigo-extra-ca/src/redirect.rs:7)
- Pseudonymization should not be mistaken for erasing historical identity: anyone already holding a raw ID can compute its pseudonym using the public deterministic algorithm.

**Overall verdict: no confirmed P54 blocker for default Fuigo or Murage, but “no knock-on problems” is unsupported—configured deployments have confirmed attribution losses and unresolved backend continuity risks.**
