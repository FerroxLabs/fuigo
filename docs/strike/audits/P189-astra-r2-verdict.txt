Additional regressions and defects introduced by P189 relative to the supplied base and v1.0.21 source:

1. **HIGH — Parked model-family switching deadlocks Murage’s required sequence.**  
   With existing model-generated history, `handle_set_session_model` runs compaction inline. Compaction reaches `prepare_chat_completion`, which waits indefinitely for unpark. Murage is waiting for the `set_model` reply before sending the prompt that would unpark it. The session actor also remains occupied by that command. The new test uses model entries without a family distinction and misses this path. [model_switch.rs:138](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/acp_session_impl/model_switch.rs:138), [compaction.rs:1092](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/compaction.rs:1092), [sampler_turn.rs:1207](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/acp_session_impl/sampler_turn.rs:1207).

2. **HIGH — The orphan reaper can steal a directly spawned tool child’s exit status, even without parking.**  
   With multiple session threads, the reaper can inspect another thread’s child between `cmd.spawn()` and `note_tool_child()`. It records that direct child as adopted. Later registration does not remove the orphan record, and the zombie branch calls `waitid` without checking `is_tool_child` again. Its real owner can consequently receive `ECHILD`. Pruning tool-child records against an earlier `/proc` snapshot creates another registration race. [terminal.rs:3489](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:3489), [orphan_reaper.rs:130](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/orphan_reaper.rs:130), [orphan_reaper.rs:149](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/orphan_reaper.rs:149). This violates D1’s explicit prohibition on waiting for a tool child owned elsewhere.

3. **HIGH — Windows assigns the job hierarchy in the wrong order.**  
   Production first assigns a child to its individual `ProcessGroup` job, then to the shared session job. The first command nests that session job beneath its individual job. A second concurrently running command starts in a different individual job and cannot join the already populated session job in that hierarchy; the session becomes permanently unguaranteed. The added unit test assigns only the session job, bypassing the production sequence. [terminal.rs:3518](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:3518), [session_job.rs:134](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/util/session_job.rs:134), [session_job.rs:282](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/util/session_job.rs:282). This conclusion follows Microsoft’s documented requirement to assign the common root job before its subsets. [Windows nested-job rules](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs#creating-a-nested-job-hierarchy).

4. **HIGH — Parked MCP readiness omits SDK servers.**  
   `mcp_server_states` iterates only `snapshot.configs`. SDK registrations live separately in `acp_mcp`; they are not added to that configuration list. An SDK-only session therefore returns `"servers":[]`, including while an SDK server is still initializing or has failed. [session_park.rs:459](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/extensions/session_park.rs:459), [mcp.rs:651](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/extensions/mcp.rs:651), [servers.rs:537](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-mcp/src/servers.rs:537).

5. **HIGH — Client task queries can still block the parked actor on its held connection.**  
   `_fuigo/task/list` reaches an inline `ListTasks` handler. The ACP terminal implementation asks `terminal/output`, which is held while parked. The query cannot finish until unpark, and subsequent actor commands queue behind it. Moving park’s own task query fixes #3 but does not make this remaining path safe. [run_loop.rs:896](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/acp_session_impl/run_loop.rs:896), [adapter.rs:330](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell-terminal/src/adapter.rs:330), [park_hold.rs:398](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/agent/park_hold.rs:398).

6. **MEDIUM — Linux adopted zombies leak without any park call.**  
   An adopted descendant that exits before being observed alive reaches the zombie branch without an `ORPHANS` record and is never reaped. Separately, the process-wide `OnceLock` starts the reaper on the first session’s runtime. Closing that session destroys the runtime, but subsequent sessions cannot restart the reaper; the process remains a subreaper. [orphan_reaper.rs:43](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/orphan_reaper.rs:43), [orphan_reaper.rs:130](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/orphan_reaper.rs:130), [spawn.rs:2823](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/acp_session_impl/spawn.rs:2823).

7. **LOW — Additional lifetime leaks remain.**  
   Windows session-job entries/handles have no production call to `forget_session_job`; macOS tool-child PID records have no pruning caller; completed child-session links accumulate until the root closes, including roots that never park. Held request futures also remain uncapped—the 50,000 limit covers notifications only. [session_job.rs:83](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/util/session_job.rs:83), [env.rs:137](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/util/env.rs:137), [quiesce.rs:603](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-shell/src/session/quiesce.rs:603), [gateway.rs:151](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-acp-lib/src/gateway.rs:151).

Additional regressions and defects introduced by P189 relative to the supplied base and v1.0.21 source:

1. **HIGH — Parked model-family switching deadlocks Murage’s required sequence.**  
   With existing model-generated history, `handle_set_session_model` runs compaction inline. Compaction reaches `prepare_chat_completion`, which waits indefinitely for unpark. 2. **HIGH — The orphan reaper can steal a directly spawned tool child’s exit status, even without parking.**  
   With multiple session threads, the reaper can inspect another thread’s child between `cmd.spawn()` and `note_tool_child()`. It records that direct child as adopted. Later registration does not remove the orphan record, and the zombie branch calls `waitid` without checking `is_tool_child` again. Its real owner can consequently receive `ECHILD`. 3. **HIGH — Windows assigns the job hierarchy in the wrong order.**  
   Production first assigns a child to its individual `ProcessGroup` job, then to the shared session job. The first command nests that session job beneath its individual job. A second concurrently running command starts in a different individual job and cannot join the already populated session job in that hierarchy; the session becomes permanently unguaranteed. The added unit test assigns only the session job, bypassing the production sequence. [terminal.rs:3518](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:3518), [session_job.rs:134](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/util/session_job.rs:134), [session_job.rs:282](/Volumes/Mando/WaylandBots/Fuigo/wt-p189/crates/codegen/fuigo-tools/src/util/session_job.rs:282).
