[upload_gate_guard.rs:320](/Volumes/Mando/WaylandBots/Fuigo/wt-p71v2/crates/codegen/fuigo-extra-ca/tests/upload_gate_guard.rs:320), [line 366](/Volumes/Mando/WaylandBots/Fuigo/wt-p71v2/crates/codegen/fuigo-extra-ca/tests/upload_gate_guard.rs:366), [line 388](/Volumes/Mando/WaylandBots/Fuigo/wt-p71v2/crates/codegen/fuigo-extra-ca/tests/upload_gate_guard.rs:388).

The new `squeezed` scanner treats comment markers inside string literals as comments. This valid code produces no upload match in either scanner:

```rust
let _pattern = "src/*";
client.upload (path, bytes, content_type).await?;
```

The string’s `/*` makes `squeezed` discard subsequent source until it encounters `*/`; the original line scanner still misses the whitespace before `(`.

Two additional forms escape the combined checks:

```rust
client.r#upload(path, bytes, content_type).await?;
```

```rust
use fuigo_file_utils::gcs::upload_bytes as
    send;
send(config, path, bytes, content_type).await?;
```

The raw identifier bypasses both client scanners. The multiline alias bypasses dispatcher inventory because imports are skipped and the alias check requires literal `"upload_bytes as "` on one line.

**Concrete impact:** a new production caller using the existing `build_storage_client_for_proxy` factory could send archive bytes and the object-path header to a third-party proxy with a deployment key using either direct-client form, without tripping this guard. The dispatcher alias remains gated but silently escapes the required caller inventory and wire-test review.

**Existing tests:** none covers these forms. An in-memory reproduction of the scanner rules confirmed the misses and confirmed that both original R3-1 examples are now detected. No current production instance was found.
