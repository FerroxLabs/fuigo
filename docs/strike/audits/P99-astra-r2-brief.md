Independent security audit, round 2, of commit range fe16738c..352ccaae in this repo (branch strike/p99). Read-only; do not build. This is credential code. Round 1 audited fe16738c..c05a3bad; its report is docs/strike/audits/P99-astra-r1-report.md. Review the whole range again, and in particular the changes since round 1 (c05a3bad..352ccaae).

What P99 claims (see docs/strike/audits/P99-astra-r1-brief.md for the full list): the shell's OIDC login and refresh send the authorization code, PKCE verifier and refresh token only to a `token_endpoint` admitted by `checked_token_endpoint` (crates/codegen/fuigo-shell/src/auth/oidc/protocol.rs), which applies `fuigo_computer_hub_sdk::check_token_endpoint`; that function admits exactly one built-in split-host pair (issuer origin https://accounts.google.com, token endpoint origin https://oauth2.googleapis.com); a refusal keeps stored credentials and surfaces the reason.

What changed in response to round 1:
- Finding 2 (refused cross-origin redirect was retried, counted toward escalation, reason lost): `refused_redirect` in protocol.rs maps a redirect the shared client refused to `OidcError::TokenEndpointRefused`; it is not retried, becomes `OidcRefreshResult::Refused` and is not counted. The redirect test in auth/oidc/refresh.rs now requires exactly one POST and a `Refused` result with the reason.
- Finding 3 (URL-bearing diagnostics), partly: `exchange_code` and `refresh_tokens` now log the token endpoint only after the check, so a refused URL (userinfo) is not written by them. NOT changed: the debug line in `discover_once` and URL-bearing reqwest transport errors in unified logs (pre-existing).
- Finding 5 (local-http gate): `is_local_dev_issuer_when(local_auth, issuer)` and `allow_loopback_http(test_build, local_dev_issuer)` are pure and tested for both conditions, including what a shipped build passes; the SDK comment and the wording about `FUIGO_LOCAL_AUTH` (any value other than empty or `0`) are corrected; the user guide no longer states https unconditionally.
- Finding 6 (login test did not observe the browser): `open_browser` records the URL in test builds; the test asserts the sign-in page was never opened, with a control test showing the same entry point does reach the browser for a same-origin endpoint.
- Finding 4 (Amazon Cognito and other split-host IdPs lose shell login and refresh): intended, disclosed in the user guide, reported to the product owner. Not changed.
- Finding 1 (HIGH, MCP OAuth in crates/codegen/fuigo-mcp sends code, verifier, client secret and refresh token to an unbound discovery-named token endpoint): pre-existing, in a crate outside this packet, with a different trust anchor (the authorization server is itself named by the MCP server's metadata). It is recorded as an OPEN HIGH in the receipt and reported to the product owner for a packet of its own. Do not re-report it unless this range changed it or you have new information; do say if you disagree with deferring it.
