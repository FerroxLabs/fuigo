1. **HIGH — A returned `&MvpAgent` can escape the checked context.**

   Locations: [local_ref.rs:54](/Volumes/Mando/WaylandBots/Fuigo/wt-p84/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:54), [local_ref.rs:269](/Volumes/Mando/WaylandBots/Fuigo/wt-p84/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:269), [handle.rs:45](/Volumes/Mando/WaylandBots/Fuigo/wt-p84/crates/codegen/fuigo-shell/src/agent/mvp_agent/handle.rs:45).

   `get()` checks the context when creating the reference, but its returned lifetime follows the `LocalRef` borrow. Safe crate code can leak just the `LocalRef`, obtain a reference during the permitted builder context, and retain that reference after the task completes:

   ```rust
   let mut held = None;
   agent.spawn_bound(|r| {
       let r: &'static LocalRef<MvpAgent> = Box::leak(Box::new(r));
       held = Some(r.get());
       async {}
   }).await.unwrap();

   drop(agent);
   held.unwrap().announcements_gen.get(); // use-after-free
   ```

   This is a source-derived counterexample, not an executed test. Alternatively, after the empty task completes, a setter passes `has_pending()` and creates `&mut MvpAgent` while the escaped shared reference remains usable. Thus “no pending future” does not establish exclusive access.

   **Test coverage:** Not caught. The escape test checks subsequent calls to `get()` outside context; it never exports an already-returned reference. The setter test covers a registered pending borrower only.

   This is a remaining part of the pre-existing escape hole. The remedy must enforce the lifetime or ownership of returned references.

2. **HIGH — Address reuse lets a stale `LocalRef` pass another agent’s context check.**

   Locations: [local_ref.rs:55](/Volumes/Mando/WaylandBots/Fuigo/wt-p84/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:55), [local_ref.rs:81](/Volumes/Mando/WaylandBots/Fuigo/wt-p84/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:81).

   Concrete scenario: retain an escaped `LocalRef` from agent A, destroy A, then construct agent B whose allocation reuses A’s address. Move the stale reference into B’s bound future. The address comparison succeeds, and `get()` dereferences A’s invalid pointer. Reallocation at the same address does not restore the original pointer’s validity. [Rust’s provenance documentation](https://doc.rust-lang.org/std/ptr/index.html#provenance)

   **Test coverage:** Not caught. The escape test checks the old reference after destruction with no replacement agent’s context active. It never exercises allocation reuse.

   The check needs allocation identity/liveness that cannot be reused while stale references survive. That still would not independently fix finding 1.
