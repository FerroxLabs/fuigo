1. **HIGH — An expanded alias can turn an escaped reference into consent.**  
   [fuigo-config/src/credential_env.rs:142](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-config/src/credential_env.rs:142), [fuigo-hooks/src/env_expand.rs:295](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-hooks/src/env_expand.rs:295)

   Concrete hook configuration:

   ```toml
   command = 'my-hook "${PREFIX}$${FUIGO_API_KEY}"'
   env = { PREFIX = "$" }
   ```

   The helper expands `${PREFIX}` to `$`, then appends the preserved `$$` run. The parsed command becomes `my-hook "$$${FUIGO_API_KEY}"`. Detection sees an odd run and injects the saved key into the hook’s child environment. The shell also expands it into the argument.

   The only key reference the user wrote was escaped. This directly refutes F0f’s promise that an even-reference-only hook receives nothing. The same composition can disclose the key through MCP values when `PREFIX` comes from the process environment.

   **Existing tests:** Do not catch this. Alias and private-use-character tests never place an alias yielding `$` immediately before a preserved run. Escape provenance must survive concatenation; recomputing parity from the resulting string loses it.

2. **MEDIUM — HTTP hook URLs never perform the final escape/reference resolution.**  
   [fuigo-hooks/src/runner/http.rs:183](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-hooks/src/runner/http.rs:183)

   With the saved key available, `https://hooks.example/h?k=$$${FUIGO_API_KEY}` is correctly detected as consent, but `expand_hook_url` calls the same expander that preserves every multi-dollar run. Both parsing and request-time expansion therefore leave `$$${FUIGO_API_KEY}` literal. The destination receives no key. Likewise, `$${FUIGO_API_KEY}` retains two dollars instead of becoming the documented literal `${FUIGO_API_KEY}`.

   This contradicts F0f’s destination semantics and leaves F3 incomplete.

   **Existing tests:** Do not catch this. The HTTP test has no odd-run case; its mixed plain/escaped assertion checks the key count without checking the escaped value’s exact spelling.

3. **MEDIUM — Cutting strings inside parameter expressions breaks ordinary environment expansion.**  
   [fuigo-config/src/credential_env.rs:141](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-config/src/credential_env.rs:141)

   With process variable `OTHER=ready`, consider:

   ```text
   ${OTHER:-$$FUIGO_API_KEY}
   ```

   Previously, `shellexpand` resolved the complete expression to `ready`. The new helper splits it into `${OTHER:-`, the preserved `$$`, and `FUIGO_API_KEY}`. Neither expanded piece contains a complete expression, so loading leaves the original text unresolved. At an MCP destination with a saved key available, it becomes `${OTHER:-$FUIGO_API_KEY}` instead of `ready`.

   This is a change to another variable’s existing expansion semantics, affecting config values independently of whether the fallback should ever be used.

   **Existing tests:** Do not catch this. They cover standalone protected runs, not runs inside an enclosing parameter expression.

The late-binding architecture, resolver precedence/runtime-key exclusion, model-header exclusion, and ACP client’s existing `getApiKey` access are supported by the inspected source.
