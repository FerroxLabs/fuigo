Independent security audit of commit range fe16738c..c05a3bad in this repo (branch strike/p99). Read-only; do not build. This is credential code.

Background: P87 (docs/strike/receipts/R094-p87.md) bound the workspace hub's OIDC refresh to the issuer with `fuigo_computer_hub_sdk::check_token_endpoint` (crates/common/fuigo-computer-hub-sdk/src/oidc_provider.rs). P99 does two things.

Claims to verify:
1. The shell's own OIDC code (crates/codegen/fuigo-shell/src/auth/oidc/{protocol,refresh,login}.rs) no longer sends an authorization code, PKCE verifier or refresh token to a discovery-named `token_endpoint` unless `checked_token_endpoint(issuer, token_endpoint)` admits it: https, on the issuer's own origin (scheme, host, port), no userinfo. `exchange_code` and `refresh_tokens_once` are the only places in the shell that send those credentials to a discovery-named endpoint, and both check at the point of sending.
2. Plain http is admitted only for a loopback token endpoint on the issuer's origin, and only when `cfg!(test)` or when `FUIGO_LOCAL_AUTH=1` selects the local-dev issuer `http://localhost:22255` and that is the issuer (`auth/config.rs::is_local_dev_issuer`).
3. Cross-origin redirects from the token endpoint are refused: the shell sends through `fuigo_http::shared_client()`, built by `fuigo_extra_ca::build_reqwest_client`, whose redirect policy (`fuigo-extra-ca/src/redirect.rs`) keeps every hop on the first request's origin. (This was already the case at the base; P99 adds a test on the shell's production refresh path.)
4. A refusal on refresh keeps the stored credentials and surfaces a clear error: `OidcRefreshResult::Refused { message }` becomes `RefreshOutcome::TransientFailure` in `auth/refresh/oidc_refresher.rs`, is not counted toward the transient-to-permanent escalation budget, is not retried by `refresh_tokens`, and never reaches the code in `auth/manager.rs` that clears credentials. On login the flow stops before the browser opens.
5. `check_token_endpoint` admits exactly ONE split-host pair, compiled in: issuer origin `https://accounts.google.com` with token endpoint origin `https://oauth2.googleapis.com` (default port, https only, exact host, directed, no userinfo). There is no list and nothing configurable. The hub (SDK `do_refresh`, fuigo-workspace `hub_auth/proactive.rs`) and the shell use the same function.
6. The new tests exercise production code paths (not test doubles): `auth::oidc::refresh::tests`, `auth::oidc::protocol::token_endpoint_binding_tests`, `auth::oidc::login::tests::login_flow_refuses_a_foreign_token_endpoint_before_the_browser_opens`, the two `refused_token_endpoint_*` tests in `auth/refresh/oidc_refresher_tests.rs`, and the two split-host tests in the SDK.
7. The user guide (crates/codegen/fuigo-pager/docs/user-guide/02-authentication.md) states the rule and the exception accurately.

Find defects: any remaining path that sends a client secret, code, verifier or refresh token to a discovery-named endpoint without the check (device-code flow, subscription flow, external auth, MCP OAuth, hub); ways the exception widens (case, trailing dot, IDN, port, userinfo, suffix or subdomain, reversed direction, http); origin comparison mistakes; the `FUIGO_LOCAL_AUTH` exemption reaching a non-loopback or non-local issuer; the discovery cache serving a document that bypasses the check; a refusal that loses, clears or overwrites stored credentials or escalates to a forced re-login; error text that leaks a token or URL; tests that would pass against a broken production path; regressions for real users (name the IdPs affected); and inaccurate docs. For each finding: severity BLOCKER/HIGH/MEDIUM/LOW, file:line, concrete scenario, whether a test catches it. End with exactly one of LAND / LAND-WITH-FOLLOWUPS / DO-NOT-LAND.
