1. **HIGH — A future becomes invisible to teardown before its destructor finishes.**  
   [local_ref.rs:171](/Volumes/Mando/WaylandBots/Fuigo/wt-p83/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:171), also [Driver at line 155](/Volumes/Mando/WaylandBots/Fuigo/wt-p83/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:155).

   On completion, `Driver::poll` takes the future out, releases the slot borrow, then destroys the future. During that destruction, the registry sees an empty, unborrowed slot.

   Concrete scenario: a custom bound future returns `Ready` while retaining a destructor-bearing field. Its destructor releases the last agent owner through an external thread-local owner slot, then accesses its `LocalRef`. Agent teardown sees `future == None`, destroys the agent, and returns to the still-running future destructor. The subsequent access dangles. This requires neither moving the agent nor exporting its `LocalRef`.

   Cancellation has the corresponding gap: `Driver` has no explicit destructor. Dropping its last `Rc<Slot>` makes the registry’s weak reference unupgradable before the contained future finishes destruction. Reentrant agent destruction therefore skips that future entirely. [Rust’s weak-reference ownership semantics](https://doc.rust-lang.org/std/rc/struct.Weak.html).

   **Tests:** Not caught. Existing probes do not release the owner from a future destructor. The direct slot tests also retain extra strong slot references.

   **Disposition:** Remaining soundness gap in the new teardown mechanism. Keep destruction observably in progress through both completed-future destruction and `Driver` cancellation, so reentrant owner destruction reliably aborts. This is a bounded lifecycle correction, separate from the move architecture.

2. **HIGH — Logging can unwind before the mandatory abort.**  
   [local_ref.rs:132](/Volumes/Mando/WaylandBots/Fuigo/wt-p83/crates/codegen/fuigo-shell/src/agent/mvp_agent/local_ref.rs:132).

   The active-poll branch calls `tracing::error!` before `process::abort()`, outside any catch boundary. Tracing invokes subscriber callbacks synchronously; the inspected dispatcher does not catch their panics. [Subscriber event contract](https://docs.rs/tracing-core/0.1.36/tracing_core/trait.Subscriber.html#tymethod.event).

   Concrete scenario: a bound future releases an externally stored last agent owner during its poll. The slot is borrowed, so teardown enters this branch. A subscriber panics on the diagnostic. The abort is never reached; agent fields unwind while the active future and potentially other bound futures still exist. Catching the owner-drop panic inside the poll permits continued access through the dangling `LocalRef`.

   **Tests:** Not caught. There is no active-poll owner-drop subprocess test with a panicking subscriber.

   **Disposition:** Remaining hole in the new abort safeguard. Remove the callback before abort, or ensure abort occurs even if logging panics. Do not allow a caught logging payload’s destructor to defeat that guarantee.
