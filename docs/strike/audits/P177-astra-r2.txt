New findings:

1. **N1 HIGH — Writable child rebinds reopen protected intermediate symlinks.**  
   [hook_write_deny.rs:363](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/hook_write_deny.rs:363), [hook_write_deny.rs:489](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/hook_write_deny.rs:489).

   Grant the existing Cargo home, with this initial layout:
   ```text
   ~/.cargo/config.toml -> aux/current
   ~/.cargo/aux/current -> /home/u/safe-cargo.toml
   ```
   Missing `config` or credentials causes `.cargo` to be pinned. `git_bind_targets` accepts both symlink nodes because they lie beneath that pin, then drops those nodes from `targets`. Consequently, `add_pinned_dir` considers `aux` unprotected and rebinds it writable. The sandbox can replace `aux/current` with a link to a malicious workspace config.

   The inner verifier repeats the same assumption and checks the pin’s root, not whether the intermediate link’s parent was reopened. Identity revalidation does not catch this static layout. Bubblewrap’s later bind uses the host source, restoring writable access to that child. [Bubblewrap implementation](https://github.com/containers/bubblewrap/blob/v0.11.0/bubblewrap.c#L1123-L1193)

2. **N2 HIGH — The unconditional `git_owned` exemption leaves missing default Git configs creatable.**  
   [home_write_deny.rs:356](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:356), [home_write_deny.rs:525](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:525).

   Start with `GIT_CONFIG_GLOBAL=/dev/null`, grant the existing `/home/u/.config/git`, and leave its `config` absent. P158 follows the override and does not create the default config. P177 nevertheless labels that default name Git-owned and skips pinning/refusal. Both plan construction and verification skip its missing `OptionalFile`.

   The sandbox can create `~/.config/git/config` containing executable Git configuration, consumed by a later unsandboxed Git command without the override. Exemption must depend on what the actual Git plan protects.

3. **N3 HIGH — Alias searches skip directories that are unlistable but traversable.**  
   [home_write_deny.rs:737](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:737).

   Suppose `.bashrc`, outside writable roots, has an existing hard link at `<workspace>/drop/alias`. Let `drop` belong to another UID with mode `0711`, while `alias` belongs to the sandboxed user and is writable.

   `read_dir(drop)` fails, and `owned_by` returns false, so the search silently skips it. The user can still open and overwrite the known `drop/alias` pathname, changing `.bashrc`. Upstream’s corresponding check also tests directory searchability; this implementation dropped that protection. Entry-iteration and metadata errors are additionally discarded at lines 752 and 768.

4. **N4 HIGH — Root-device filtering misses aliases beneath existing submounts.**  
   [home_write_deny.rs:727](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:727).

   Put `.bashrc` on filesystem B and its hard-link alias beneath an existing filesystem-B mount at `<workspace>/mounted/alias`. Let the workspace directory itself reside on filesystem A.

   The search rejects the entire workspace because its root device differs from the protected inode’s device. It never discovers the B submount. The workspace grant still permits writing the alias through that hierarchy; Landlock grants are not restricted to the root directory’s device. [Landlock hierarchy and mount semantics](https://docs.kernel.org/userspace-api/landlock.html#bind-mounts-and-overlayfs)

   This unsafe optimization is also present upstream; it does not establish that the root contains no writable alias.

5. **N5 HIGH — Essential-root filtering erases explicit grant provenance.**  
   [home_write_deny.rs:469](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:469), [home_write_deny.rs:538](/Volumes/Mando/WaylandBots/Fuigo/wt-p177/crates/codegen/fuigo-sandbox/src/home_write_deny.rs:538).

   Set `TMPDIR=/home/u/.cargo`, explicitly grant that existing directory, and leave `config` absent. Every matching write-root entry is removed from `configured` because the same path appears in `essential`. Pinning is also prohibited because it contains an essential root.

   The sandbox therefore accepts a writable, missing Cargo config despite the explicit grant. This exceeds the stated exception for paths held **only** by automatic roots. Workspace/grant provenance must survive overlap with essential roots.
