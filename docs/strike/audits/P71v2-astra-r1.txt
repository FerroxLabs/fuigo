DESIGN (accepted by the owner; do not re-litigate the design, audit the implementation against it):
Fuigo uploads session archives, traces, diagnostics, share bundles, heap profiles, review-comment records and a workspace environment record to "storage". The upload destination is one of three classes, decided by DESTINATION, never by content:
 1. a FluxRouter-operated storage proxy (decided ONLY by the existing P43/P54 helper `fuigo_extra_ca::fluxrouter::IdentityDisclosure::for_destination(url).is_permitted()`): receives files unchanged;
 2. the operator's own bucket (`UploadMethod::Direct` GCS, `UploadMethod::S3`): receives files unchanged;
 3. ANY other storage proxy (including any URL that cannot be classified): receives NO file content at all (no connection, no request, no header carrying an object path). Local files untouched; the user is told once per process on stderr. The one-shot feedback archive has no bucket alternative, so ITS notice must not promise a bucket.
The workspace environment record additionally keeps a field rule: for class 3 its identity fields are nulled before it is even enqueued.
Uploads spilled to disk earlier and re-sent by startup recovery must be decided on the destination at SEND time.

3. **MEDIUM — Signed-upload positive controls never verify delivery of the payload.**

4. **MEDIUM — The recording fixtures require an unconfigured loopback alias on macOS.**  
   [gate_testkit.rs:49](/Volumes/Mando/WaylandBots/Fuigo/wt-p71v2/crates/codegen/fuigo-file-utils/src/gate_testkit.rs:49).

   Class-3 tests repeatedly bind `127.0.0.2` and panic if binding fails. On macOS without that address configured, this is not equivalent to binding `127.0.0.1`: XNU checks for an assigned interface address and returns `EADDRNOTAVAIL` when absent. [Apple’s bind implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/netinet/in_pcb.c).

   **Scenario:** running the affected tests on a stock Mac fails before exercising the gate. This host’s `lo0` lists only `127.0.0.1` for IPv4. My socket probe was denied for **all** addresses by the sandbox, so it provides no runtime confirmation of the address-specific failure.

   **Existing tests:** fail during fixture setup; there is no portable fallback. A class-3 URL such as `localhost`, backed by a verified listener on an available loopback address, avoids requiring an alias.
