1. **HIGH — Expansion values can collide with the “private” mask and manufacture consent.**  
   [credential_env.rs:139](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-config/src/credential_env.rs:139), particularly the whole-result replacement at line 155.

   The marker is absent from `input`, but can occur in a value returned by the expander. For example, this hook handler contains only an escaped first-party reference:

   ```json
   {
     "type": "command",
     "command": "printf '%s\\n' \"$ALIAS\" >&2; : \"$${FUIGO_API_KEY}\"; exit 1",
     "env": {"ALIAS": "\ue000{FUIGO_API_KEY}"}
   }
   ```

   The helper chooses U+E000. Hook parsing substitutes `ALIAS`, then `.replace(mark, "$")` turns its value into `${FUIGO_API_KEY}`. The runner detects that manufactured reference, supplies the saved key, and the command prints it to stderr. The failure path then includes it in diagnostics. No unescaped reference authorized this exposure.

   **Existing tests do not catch it:** the PUA regression case puts marker characters in the original input, not in an expansion value. This refutes F0e’s collision protection. Restoration must distinguish actual masking tokens from bytes introduced by expansion.

2. **HIGH — Odd dollar runs still expand in the command hook’s shell.**  
   [credential_env.rs:126](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-config/src/credential_env.rs:126) and [runner/command.rs:136](/Volumes/Mando/WaylandBots/Fuigo/wt-p70a/crates/codegen/fuigo-hooks/src/runner/command.rs:136).

   All runs of two or more dollars are classified as escaped and preserved. However, the runner passes them unchanged to `sh -c`. Consider:

   ```sh
   my-hook --key "$FUIGO_API_KEY"; printf '%s\n' "$$${FUIGO_API_KEY}" >&2; exit 1
   ```

   The plain reference supplies the hook’s environment. The supposedly escaped triple-dollar reference then expands to **PID followed by the saved key**, which enters stderr and the failure reason. I confirmed the shell behavior using a fake key: two dollars produced `PID{FUIGO_API_KEY}`, while three produced `PID<fake-key>`.

   **Existing tests do not catch it:** the production-parser/runner test at `command.rs:2073` exercises two dollars. The config test includes three dollars, but stops before shell execution. F0c/F0d’s escape guarantee therefore remains incomplete. Protection must survive shell interpretation, including odd runs.
