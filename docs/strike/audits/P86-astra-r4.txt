1. **MEDIUM — The final generation check still races with registration on another thread.**  
   [terminal.rs:871](/Volumes/Mando/WaylandBots/Fuigo/wt-p86/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:871), [terminal.rs:927](/Volumes/Mando/WaylandBots/Fuigo/wt-p86/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:927).  
   A persistent snapshot contains unregistered `CORP_KEY`. The terminal passes its G0 check; another runtime worker completes registration, advancing to G1; the terminal then spawns and replays the G0 snapshot. Fresh environment filtering cannot prevent that replay from restoring the credential. Removing the `await` closes the cooperative scheduling gap, but Fuigo uses a multithreaded runtime and no shared synchronization protects check-through-spawn. **Tests miss this:** late registration happens between completed commands. Registration and snapshot dispatch need a shared synchronization boundary.

2. **MEDIUM — An intervening background request still causes foreground cwd loss.**  
   [terminal.rs:837](/Volumes/Mando/WaylandBots/Fuigo/wt-p86/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:837), [terminal.rs:844](/Volumes/Mando/WaylandBots/Fuigo/wt-p86/crates/codegen/fuigo-tools/src/computer/local/terminal.rs:844).  
   Start foreground command A at G0: `cd /repo/subdir; sleep 2`. Register a new credential while A runs. A background request B then reinitializes the canonical state at G1, using the previously recorded `/repo`. When A finishes, its G0 dump is discarded entirely because its generation differs from the state’s generation; `update_cwd_from_dump` is never called. The next foreground command silently starts in `/repo`. Background commands ordinarily do not update canonical cwd, so B should not erase A’s directory change. **Tests miss this:** the cwd test completes `cd` before registration and has no overlapping request. Preserve foreground cwd independently of credential snapshot eligibility.
