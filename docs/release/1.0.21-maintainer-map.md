### Behaviour changes from the backlog packets (Sean approval on record, for the Tier 2 list)

Sean decided "Fix all 21 first" (UPDATE 335) and gave overnight authority for verified recommendations (UPDATE 356).
Each change below breaks a setup that worked in 1.0.20 and is listed so Tier 2 can confirm it by name.

- P125 (B31): a self-hosted relay used for TUI session sharing now needs `[relay] trusted_origins`; anyone already
  syncing to one must add it. Sean: UPDATE 335 (backlog rows "TUI relay sync opt-in", "Leader refusal in the TUI").
- P118 (S16, B32): only the exact trusted files (`config.toml`, `managed_config.toml`, `requirements.toml` in
  `$FUIGO_HOME` and `/etc/fuigo`, `~/.claude.json`, `~/.cursor/mcp.json`, `$FUIGO_HOME/hooks/`) can name
  `FUIGO_API_KEY`; other `$FUIGO_HOME` files and project, plugin or `.mcp.json` sources cannot, and agent-frontmatter
  hooks never get the key. Reverses D18 ("project config may name the key, as in 1.0.17", UPDATE 271) in the
  direction D18 named as the fix (P103). Sean: UPDATE 335; the exact-file list is the redesign after the real
  Astra r3 (UPDATE 346).
- P117 (S15, B33): MCP OAuth refuses providers whose token endpoint is on another origin than their metadata, other
  than Google (for example Cognito), as the shell already does (B11). Sean: UPDATE 335 (backlog P102, binding agreed
  as D15, UPDATE 264).
- P128 (B34): raw JSON ACP clients must accept `_fuigo/config_changed` and `_fuigo/leader_reconnected` (the leader
  now sends its notices with the ACP extension prefix). Sean: UPDATE 356 (overnight authority; pre-existing 1.0.20
  bug found by P125).
- P121 (B15): a budgeted goal interrupted while a request is in flight is resumed and that request is charged a
  cautious estimate (at least 16,384 tokens, 4,096 of output, or the largest request seen) instead of the goal
  refusing to resume. Sean: UPDATE 335 (replaces P89's refusal, UPDATE 243 decision 5).
- P133 (S16, B32): MCP servers an ACP client sends (`session/new`, `session/load`, `mcp/upsert`, so an editor's
  project settings and the TUI's `/mcps Add`), a hub's `workspace.configure_mcp` and an agent's inline `mcpServers`
  can no longer name `FUIGO_API_KEY`; `/mcps Add` can no longer save a server that names it. Sean: UPDATE 356
  (overnight authority; Fable final audit HIGH).
- P136 (B35): an ACP client's server with the same name as one of your own but a different definition no longer
  replaces it; your definition runs and a warning is logged (in 1.0.20 the client's copy won). DECIDED keep
  (overnight authority, UPDATE 356).
- P136 (B35): MCP OAuth client settings of a disabled server, or of a server whose running definition differs from
  the configured one, are not used. Sean: UPDATE 356 (overnight authority).
- P136 (S16): a definition from an untrusted source whose bearer or OAuth variable holds the key, or whose text
  becomes the key on expansion, gets nothing. Sean: UPDATE 356 (overnight authority).
- P138 (S16, B35, K20): a client server carrying the key's literal value loses it (compared in memory, never logged);
  a trust-grant reload sends its refusal notes to the session; a forwarded copy leaves the hot-reload seed only when
  the disk sources alone reproduce it (renamed copies and plugin overrides stay); a pager copy lacking only the
  resolved Authorization header counts as the user's definition; the "differs" warning is logged once per
  definition. Sean: UPDATE 356 (overnight authority).
- P141 (S16, B35): forwarded copies stay in the hot-reload seed flagged with the disk server they copy, and every
  merge resolves them against the current disk definition (edits apply, deletes drop, kill switch and the user's
  definition win), so a trust grant or plugin reload cannot let a same-named repo plugin replace the user's server;
  each session entry merges once. Sean: UPDATE 408 (overnight authority).
