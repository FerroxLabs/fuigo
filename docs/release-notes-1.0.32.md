# Fuigo 1.0.32 release notes

This release follows 1.0.31. It adds one sign-in picker for every way of reaching a model, a single ranked model list that says which route each model uses, an opt-in per-command sandbox, a smaller install and a new welcome screen. It also fixes many problems with MCP servers, hooks, permissions, worktrees, goals, resuming sessions and the terminal interface.

## Signing in and models

- One sign-in picker now answers "Choose how Fuigo reaches a model." everywhere: on first launch, in `/login`, and in `fuigo login` on a terminal. The rows are Flux Router (recommended, first), ChatGPT subscription, Grok subscription and Provider API key, with an Enterprise SSO row only when your deployment configured an issuer or an external sign-in command. Each row shows its state ("signed in", "key ••••1234"), so `/login` also switches accounts; the last row reads Quit on first launch and Cancel in `/login`. Before, `fuigo login` and `/login` went straight to single sign-on and failed with "No OAuth2 issuer is configured" for almost everyone, and the welcome screen offered only a key (without saying it was a Flux Router key) and never the subscriptions.
- Signing in is the only step. After a ChatGPT or Grok sign-in Fuigo fetches the account's model list itself, caches it (model IDs only, owner-only, under `~/.fuigo/subscriptions/`), and lists the models in `/model` and `/provider` with no `config.toml` and no `fuigo models --provider` step. A sign-in alone counts as a credential, so the next launch skips the key screen. With no default model chosen and Flux Router not set up, Fuigo starts on the best model of the first signed-in subscription; a default you set is never changed, and a Flux key keeps the built-in default.
- `fuigo login --provider flux|chatgpt|xai|openai|anthropic|google|groq|openrouter|deepseek|mistral|sso` skips to one sign-in and ends with "Signed in to ... Default model: ... Run `fuigo`." Single sign-on, with its enterprise error, is now `fuigo login --provider sso` (or `--oauth` / `--device-auth`). `fuigo login --status` lists every connection and its state without a network call. Without a terminal, bare `fuigo login` prints the options and the command for each and exits with status 2. Provider API keys are never stored by Fuigo: the row reports whether the environment variable is set, and `/provider <provider> <model-id>` writes only the variable's name.
- `/provider` lists every connection with its state (Flux Router first, then both subscriptions, then each provider key), and `/provider grok-subscription [model-id]` / `/provider chatgpt-subscription [model-id]` list a signed-in account's models or switch to one, again with no TOML. `/provider`, `/model`, `/login`, the welcome screen and `fuigo login --status` read one shared connection status, so they cannot disagree.
- Wrong labels fixed. When the engine ran a model that the pager's catalog did not list (the catalog fetch had failed, or the model came from your own config or a subscription), the status line stayed on "Flux Auto (medium)" and the footer read "Logged in with API key". The status line now shows the model the engine reports, with its route ("grok-4.7 · Grok subscription"), whether or not the catalog lists it, and the footer names the credential in use ("Logged in with Grok subscription", "Logged in with Flux Router key"), never a generic "API key".
- `FLUX_API_KEY` now signs in everywhere. With only `FLUX_API_KEY` set, `fuigo login --status` reported Flux as ready, but `fuigo -p` and `fuigo models` ignored it and said "Not signed in". The Flux key is now read from `FUIGO_API_KEY`, then `FUIGO_CODE_API_KEY`, then `FLUX_API_KEY` (the first one set and not blank) by the app, `fuigo -p`, `fuigo models`, the model list fetch and ACP alike, and `fuigo models` names the variable it is using. None of them is passed on to programs Fuigo starts.
- Without a Flux credential Fuigo no longer retries the model-list fetch every few seconds; it can only be refused. The list is built from the connections that exist.
- If another `fuigo` on your `PATH` is a different version from the one running (a stale package-manager install ahead of a newer one), the welcome screen and `fuigo doctor` name both paths.
- One model list that chooses for you. A model reachable more than one way (through Flux Router, through a signed-in subscription, through a provider key) is listed once in `/model`, and each row names the route Fuigo will use ("via Flux Router", "included in your Grok subscription", "your OpenAI key"). The ranking is fixed: Flux Router when it is set up and serves the model, then a subscription that includes it, then a direct key; ties keep catalogue order. Models that some route reaches come first, then the ones that need a connection, each saying what to connect. The other routes open with Right-arrow or Tab on a model's row (or `/model <model> via <route>`), each with a one-line reason: the price per 1M tokens where the catalogue publishes one, "included" for a subscription; picking one switches to that route and saves it. When you have never chosen a default model and Flux Router is not set up, Fuigo starts on the best model of your first signed-in subscription and the welcome screen says which route it is using and that `/model` changes it.
- Provider API keys list their models. A key found in the environment is asked for its provider's standard model list (once a day in the background, and on `fuigo login --provider <id>`); only the model IDs are cached, under `~/.fuigo/provider-keys/`. The models join the one ranked list, de-duplicated against Flux Router and subscriptions, and with no default chosen and no Flux key, Fuigo starts on the first listed one.
- If the default model you set yourself cannot be used, the welcome screen says why and shows "Pick a model:" with the models you can use. Choosing one starts on it for the session and does not overwrite your default unless you turn on "Make my pick the default model".
- A denial on a subscription route names the route and offers `/model` ("Grok subscription credentials unavailable: sign in again with /login ..., or pick another model with /model. Fuigo does not fall back to an API key or Flux Router."). Nothing in Fuigo moves a failed turn to another route on its own; this was already true and is now the wording and is tested for every credential failure.
- The ChatGPT and Grok sign-in flows, their exact-recipient network clients, the egress exceptions and the rule that a subscription denial never falls back to an API key or to Flux Router are unchanged. Existing `env_key` / `api_key` routes, `FUIGO_API_KEY`, `-m`, headless `-p` with a key in the environment and the ACP auth methods work as before. The user guide's authentication page and `docs/connect-a-model.md` are rewritten around the picker; the hand-written TOML recipes moved to an Advanced section.
- Model lists for your ChatGPT and Grok subscriptions are refreshed in the background when Fuigo starts, so a model your account gained since you signed in appears without signing in again. `FUIGO_DISABLE_MODEL_REFRESH` turns this off. In the dashboard, the prompt box opens a model row's other routes with Right-arrow or Tab, as `/model` does.

## Sandbox

- New, off by default: a per-command sandbox for the shell commands a workspace session runs. Set `FUIGO_SANDBOX_MODE`, or `[sandbox] mode` in `managed_config.toml` or `workspaced.toml`, to `observe` (commands run as usual and are counted; nothing is blocked or asked) or `enforce` (each command runs inside an OS sandbox: writes limited to the workspace and temporary folders, the network only through a local proxy that allows exact origins, Fuigo's own settings and `.git/hooks` never writable; a denial raises a card, and allowing it records a grant and re-runs the command once). Only macOS has an OS backend today. On Linux and Windows `enforce` runs as `off` with a loud warning that names the platform, and commands are never refused for want of a backend. A folder's own `workspaced.toml` can only raise the mode, never lower it. The user guide's sandbox page has the details.
- When a shell command runs inside the per-command sandbox (`enforce` with an OS backend), the sandbox card now takes the place of five of Fuigo's own prompts for that command: an unparseable script, an environment variable outside the known-safe set, arguments that depend on shell expansion, a plain network client while the folder's egress proxy is serving it, and a file write that stays inside the sandbox's write scope under a broad allow rule. The sandbox already confines these, and anything it blocks is settled by a card, so asking first only repeated the question. Every other prompt is unchanged: protected targets, commands that can change the host, your own deny and ask rules, hook prompts, the peer guard and every non-shell tool. The condition is checked for each command at the moment it is decided, so turning the sandbox off, a host with no backend, a background run or a shell whose output Fuigo cannot read back all bring the prompts back. With the sandbox off, which is the default, nothing changes. The exact list is in the user guide page on the sandbox (`18-sandbox.md`).
- On Windows, when a sandbox profile is set, the welcome screen now shows the "sandboxing is not available on Windows: commands and file tools run unsandboxed" warning in the interactive terminal interface. Before, it was printed to the terminal before the interface started and was overwritten at once; only `/status` showed it. Headless runs still print the one stderr line.
- `/rewind` can now restore files. The confirm step offers "Yes, rewind conversation and files" (the default), "Yes, conversation only" and "Yes, files only". Files are restored to how they were before the turn you rewind to, but only the ones Fuigo's own file tools wrote; changes made by shell commands, or by you outside Fuigo, are not tracked. Before a restore, Fuigo checks each file: any you changed since Fuigo's edit are listed, nothing is overwritten unless you choose "Overwrite", and you can instead rewind the conversation and keep those files. The result lists the files that were restored. Until now the terminal interface always rewound the conversation only and left every file as it was, although the checkpoints were recorded.

## Install size

- The Linux binaries are now shipped without their symbol tables, which were about 40 MB of the 229 MB Linux x64 binary in 1.0.31. The macOS binaries have their local symbols removed but keep their global symbols. The release is also built with the optimised distribution profile, and the platform npm packages are compressed with a larger brotli window (the same format, read by the same installer). The set of npm packages and their contents otherwise do not change, and no feature is removed. The one visible difference: a native crash backtrace (`RUST_BACKTRACE`) no longer carries function names on Linux and carries few on macOS; debug symbols are published separately for symbolication.

## Providers

- Some providers return a freeform tool call (such as `apply_patch`) as a plain function call with its text under an `input` field. Fuigo now reads that as the freeform call and runs the edit, instead of treating the JSON wrapper as the patch and failing it every time, and the follow-up request carries the result in the same form the provider sent.
- When a provider's circuit breaker lets a trial request through after its pause, exactly one request is now admitted for that slot. Before, two could be.

## MCP

- `fuigo inspect` and `fuigo mcp doctor` name the file that defines each MCP server. A server declared in a project `.fuigo/config.toml` shows that file, not your own `config.toml`, and a `.mcp.json` found above the folder you launched from shows its real path instead of a file that does not exist.
- A stdio MCP server's command, arguments and working directory expand a leading `~` to your home directory, as a shell would. The server is started without one, so `~/bin/server` used to fail to launch.
- `fuigo inspect` warns when a known `[features]` flag in `config.toml` is set to something other than `true` or `false`. Fuigo ignores such a value, so the feature kept its default and nothing said why.
- A subagent forked from a session now starts with the MCP servers that session is using at that moment, headers included. It used to get the list the session had when it first started, so a server added, removed or re-headered since (a config reload, a plugin reload, an agent switch) was missing or stale in the fork.
- Switching a session to another agent swaps the previous agent's own `mcpServers` for the new agent's. Servers that came from your config, from the client, or were added during the session stay connected; a server or header only the old agent set no longer lingers.
- A subagent's plugin reload judges the subagent's own `mcpServers` against the parent project's `enabled = false` list (the subagent runs in a worktree with its own config), so a reload cannot bring back a server the parent turned off.
- `--output-format streaming-messages-json` reports each MCP server's real state on the `init` line (`connected`, `pending`, `needs-auth`, `failed` or `disabled`) from one bounded `fuigo/mcp/list` read, instead of calling every configured server connected. Other output formats leave the array out.
- A server that is still reconnecting is no longer announced to the model as disconnected; the notice waits until MCP start-up has settled.
- A reply from an MCP server that holds a byte order mark, an invalid UTF-8 byte or a raw control character inside a string is now decoded. Before, it was dropped as undecodable and the request waiting on it ran into its timeout.
- Where a tool's schema asks for text, an object or a list and the model sends the wrong one of those (an object for text, JSON text for an object or a list), Fuigo fixes it before the call when only one reading is possible and tells the model it did. Ambiguous values are still refused.
- When an MCP server asks for input during a tool call (a question or a sign-in) and you decline, cancel, or the server withdraws the request, the tool result now begins with a short note saying so, so the model does not assume the action happened.
- The `mcpServers` an agent definition declares now apply to the main session when you start with that agent, not only to the subagents it spawns, and they stay on top after a project config or plugin reload. They accept the map form used in `config.toml` (headers and env maps) as well as the list form. A server you turned off with `enabled = false`, or that managed policy blocks, can no longer be started through an agent definition.
- A stopped MCP server now lets go of its connection instead of holding it until Fuigo exits.

## Configuration and import

- Each model now has its own request-size limit, `max_request_bytes`, and Fuigo evicts old inline images to stay under it. Until now every endpoint was held to one fixed ceiling just under 50 MiB, so a provider on the Messages API, which rejects bodies over 30 MB, could be sent a 30 to 47 MiB request and answer with a rejection once enough screenshots had piled up. Unset, the limit follows the model's `api_backend` (30 MB for `messages`, 50 MiB otherwise); you can set it on a `[model.<id>]` block or once on a shared `[model_providers.<id>]` block, where a model's own value wins. Turn requests, compaction requests, subagents and mid-session model switches all use the limit of the model they are talking to. See the custom models page of the user guide.
- A reasoning effort written in a config file or a custom-model definition is accepted in any letter case (`High`, `XHIGH`). The command line and the model picker already accepted that; the config reader was the one place that insisted on lowercase and rejected the whole entry.
- The `/import-claude` importer's planning and merging now live in their own crate, `fuigo-external-agent-migration`, with typed errors and unit tests that no longer need the whole shell. What it reads and writes is unchanged for every source it supports (settings permissions, environment variables and hooks, `~/.claude.json` and `.mcp.json` servers, skill and rule directories, and the opt-in marker), each now pinned by an end-to-end test. Two small differences: imported environment variables are written in key order rather than hash order, and a permission rule that appears in both `settings.json` and `settings.local.json` is written once instead of twice. Imported files are still written under the config lock and owner-only.
- The `/import-claude` review screen no longer shows imported environment variable values in clear text. Like the import summary, it lists each variable by name with only the value length, since these values are often API keys.
- New file `tool-guidance.toml` (in your Fuigo home, and in a project's `.fuigo/` folder once the folder is trusted) changes the text the model is shown for a built-in tool: `append` adds to the stock description and `replace` swaps it, without touching the tool's schema. Each text is limited to 2000 characters and a file to 8000; an unknown tool name is warned about once. `FUIGO_TOOL_GUIDANCE=none` turns it off and `FUIGO_TOOL_GUIDANCE=<path>` loads only that file. See the configuration page of the user guide.

## Permissions

- Permission rules accept the tools' own names as well as the established ones: `run_terminal_command(...)` and `Shell(...)` for commands, `read_file(...)` and `list_dir(...)` for reads, `search_replace(...)` for edits, `grep(...)`, `web_fetch` and `web_search`. A bare `grep` is still the literal pattern it always was.
- An `ask` permission rule for `web_search` or `web_fetch` now prompts every time; the built-in search allowance and the fetch domain allowlists no longer let the call run without asking.
- A shell script that keeps a file name in a quoted variable (`LOG=/tmp/log; ls -lh "$LOG"; rg -n ERROR "$LOG"`) used to slip past word-by-word checking, so your Bash deny and ask rules never saw it. Fuigo now recovers the commands in such a script without guessing the variable's value: deny and ask rules apply to every recovered command, and in auto mode the script is classified unless an exact whole-script grant covers it.
- A denied command written inside a command substitution is now rejected, not just escalated to a prompt.
- Tools that take a path argument now declare which argument it is, and parallel calls on the same file are run one after another by that argument, so an editing tool from another harness (for example one whose argument is `filePath`) is serialised like Fuigo's own.
- A marketplace allowlist entry matches a repository address whatever the letter case of its scheme and host, and with or without one trailing `.git`. The path is still part of the identity, so an entry no longer widens to other repositories.

## Tools and subagents

- `list_dir` on a network or virtual filesystem (NFS, SMB, FUSE mounts, WSL drives, `/proc`) lists the top level only and prints a notice, instead of walking the whole subtree to count files. Linux only; other systems list as before.
- `memory_search` finds Chinese, Japanese and Korean words inside longer notes, which it used to treat as one unbreakable word. An existing memory index is upgraded the first time it is opened.
- A memory search result shows the part of a long line that matched your query, with `…` where text was cut, instead of cutting the line off before the match.
- `/memory` skips a symlinked note instead of listing it.
- `[skills].ignore` matches a skill whose `SKILL.md` is a symlink by the folder that holds it.
- `--tools` and `--disallowed-tools` apply in the interactive terminal UI as they do with `-p`. They used to be ignored there, with only a line in the log. A shared leader process is started before the flags are known, so there they are reported as unsupported, like `--allow` and `--deny`.
- A grep search that hits its time limit now returns the matches it had already found, followed by a note that the list is partial, instead of discarding them and reporting only the timeout. The streaming path already did this; the plain path now matches it.
- `read_file` returns `SKILL.md` files, Markdown files under a `skills` folder and project instruction files (`AGENTS.md`, `CLAUDE.md` and the other names Fuigo loads as instructions) whole, ignoring `offset` and `limit`, only while they fit the per-call limit. A larger file is read in a window that names the next offset to continue from, so one oversized skill can no longer flood the context. The tool description now says which file kinds are returned whole, using your configured parameter names. The compact tool description makes the same promise.
- The `task` tool's `subagent_type` is optional and its description says so. A placeholder such as an empty string or `null` counts as omitted, and a call that omits the type while the agent may only spawn certain types (for example `tools = ["Agent(explore)"]`) is now told to name one of them, instead of being refused for a type the model never chose. Fuigo never picks the type for the model, so the permission prompt and the allowlist always name the type that runs.
- New setting `[features] subagent_model_inheritance` (environment variable `FUIGO_SUBAGENT_MODEL_INHERITANCE`, default off). When on, every subagent runs on the same model as the parent agent: the `task` tool no longer offers a `model` argument or a list of model names, and a call that passes one is refused with a clear message. The choice is made when the session starts, so changing it applies to the next session.
- `/settings` has a row for `[features] subagent_model_inheritance` in the Agent group. It shows the value in force, so a requirements pin or `FUIGO_SUBAGENT_MODEL_INHERITANCE` that outranks the config file is what you see, and turning the row while one of them is set names it instead of writing a value that would be ignored.
- Quitting Fuigo now stops everything a background command started, not just its shell; a program the command launched (a watcher, a server) is no longer left running after exit.
- A request that fails because the prompt is too large for the model now compacts the conversation and tries again even when the server sent no context-window header, since many servers report an overflow only in the error text. It stops after three compactions in a row without a successful response in between, and shows the error instead of looping. A rate limit that happens to use size wording is never treated as an overflow.
- Output that PostToolUse hooks add to a long tool turn counts toward the context window before the next request, so the turn compacts instead of failing with a prompt-too-long error.
- `pkill -f` and `pgrep -f` are refused up front when the pattern appears in the command text that is run, because the shell running the command matches it and would be killed or reported itself. A lone `pkill -f name` and patterns written as `[n]ame` are unaffected. The message says how to rewrite the command.
- `web_fetch` refuses a page whose declared size is over the limit before downloading any of it, and stops reading a page of unknown size as soon as it passes the limit instead of buffering it whole.
- Writing a file replaces it atomically: a write that fails part way (disk full, a size limit) leaves the previous contents in place instead of an empty or truncated file. Symlinks are written through and the existing file mode is kept.
- A turn you stop, or interrupt with a new message, now tells the model that a foreground command it started has moved to the background, so it does not wait on it. A message you type while a turn is running reminds the model to answer you first. When the conversation is compacted while a goal is active, the goal's objective is kept in the summary and restated afterwards. The wait for subagents reads "Waiting for N subagents".
- If delivering one tool's result fails, the other tool calls of that batch are no longer dropped: their results are sent, and the error is returned after the batch is complete.
- `web_fetch` refuses a page addressed by a public IP address, because such an address cannot be told from an upstream vendor's. Use the hostname.

## Hooks

- Project hooks kept in a repository subfolder load when you launch inside that folder, after the repository root's. A sibling folder's hooks stay out.
- An HTTP hook can send to `localhost`, `127.0.0.1` or `[::1]` over plain `http://`; every other address still needs `https://`. A hook whose URL can never work (not a URL, or a scheme that is not allowed) is reported when hooks load, not at its first run.
- When a command hook cannot be started, the message names the program that failed. On Windows an inline PowerShell hook that reads `$input` runs, with a warning in the log that `$input` differs between PowerShell hosts.
- Plugin hooks written for other tools now run. A hook script that defines and uses its own shell variables is no longer refused with "required env var(s) not set" (only Fuigo's own placeholders, such as `${CLAUDE_PLUGIN_ROOT}`, are checked), and the `command` + `args` form runs the program from `PATH` with placeholders expanded in its arguments. A hook that cannot start is reported once per session as one grouped notice and then skipped; a plugin hook that runs and fails is counted in the hooks chip instead of printing a line every time; `/hooks` and `fuigo doctor` list every hook with its source, state, reason and a fix hint.
- A hook with `"shell": "bash"` now runs in bash instead of `sh`, so plugin hooks that use bash-only syntax work. If that shell is not on `PATH` the hook is reported once as "bash not found" and skipped; a `shell` value that is not a plain name (a path, or anything with a space) is reported the same way. Hooks without a `shell` field run in `sh` as before.
- A hook that returns `continue: false` now stops the run instead of being ignored. A `PostToolUse` hook ends the turn after the tool call it saw (the other calls of that batch are cancelled), a `UserPromptSubmit` hook stops the prompt from running, and a `PreToolUse` hook stops that tool call, with its `stopReason` as the message.

## Terminal and interface

- New welcome screen: the Wind mark sits above a plain, borderless text column holding the version, the tagline, the menu and any notice. The mark and the text never overlap, the mark takes only the rows the text leaves, and the layout starts at 60 columns wide. The mark spins once when the screen opens, then rests. `ui.background_mark = false` hides it, `ui.background_mark_animate = false` or `ui.animations = false` shows it at rest, and `NO_COLOR` hides it.
- `/delete` followed by any text is refused with a message instead of deleting the current session.
- `/cd` and the location picker accept a folder path in quotes (`"my dir"`, as pasted from a file manager) or with escaped spaces (`my\ dir`).
- A command typed in full and sent with Enter runs even when the menu does not offer it where you are (`/cd` outside the dashboard). The highlighted near match, such as a skill, no longer replaces it.
- `@` file completion no longer accepts a match for an earlier query while you type quickly. The list on screen can lag the text by a moment; Enter and click only accept from a list that answers the current query.
- Send now (Ctrl+Enter) no longer answers a permission, question or MCP prompt card. The chord is held with a hint while a card is open, and Enter picks the highlighted choice.
- A queued command such as `/compact` can no longer be opened for editing. It used to load into the composer over the draft you had typed; now Fuigo says so and keeps your draft.
- Your terminal is handed back in the same state on every way out. Quitting, a panic, Ctrl-C, SIGTERM and SIGHUP all run one teardown, in one order, and the keyboard-enhancement pop is sent once per push. On a normal quit Fuigo then waits for the terminal to confirm the pop before it leaves raw mode, so key-release reports still in flight no longer reach your shell as keystrokes (a stray Ctrl-D that closed the shell is the case this was found on). The wait is bounded by one second and is skipped when the terminal has stopped reading or never answered at startup.
- The interrupt, terminate and hang-up handlers are now claimed the moment the pager starts. A signal that arrived in the gap before the handler was first polled used to take its default action and exit with the terminal still in raw mode.
- The input thread is joined before teardown reads the terminal, so the teardown is the only reader and cannot lose a reply to it.
- Windows: clipboard reads and writes no longer run at the same time. Windows allows one open clipboard at a time, and a paste that overlapped a copy could fail or crash the pager. They now take turns, a copy waits briefly for a read in flight and reports it is busy if the read does not finish, and decoding a pasted image happens after the clipboard is released.
- Inline images are uploaded again after a full-screen clear. Some terminals drop their image data when the screen is cleared, and the next frame then placed images that no longer existed and drew an empty card. After a clear the next frame transmits them again, for the main view and for subagent views.
- A bracketed paste whose text is not what is on the clipboard (an input-method commit, or a terminal-multiplexer buffer that differs from the system clipboard) no longer attaches the unrelated image that happens to be on the clipboard. The check used to run in a single terminal brand; it now runs in every terminal.
- Plan comments: the comment row shows a delete button on hover or selection, `x` and the button both delete through one path, and deleting a comment you are editing abandons that edit and restores your draft. Ctrl+C on an empty comment draft cancels the comment instead of doing nothing, and a saved comment survives cancelling its edit.
- The shortcuts search matches every word you type against the key, label, description and long help, in any order, so "pop stash" or "unstash" finds the stash row.
- A pseudo-terminal child no longer fails to start because one environment variable holds a NUL byte; that variable is skipped.
- Minimal mode reprints its history at the new width after you resize the window and stop dragging, instead of leaving earlier rows re-wrapped by the terminal and split mid-word. A height change that flips the compact layout reprints too. After a narrowing resize the live area is placed correctly in terminals that re-wrap on-screen rows, so it no longer leaves a stale row behind or overwrites a committed one.
- An `[Image #N]` placeholder that comes back as plain text (kill and yank, undo, a plain paste, a restored draft or queued row) is bound to the image it names again, so the send still carries the image. A recalled history line or a rewound prompt releases the draft's images first, so its `[Image #1]` cannot pick up an unrelated one. A placeholder with no image behind it, or an attached image that cannot be read, is now reported (a toast, or a line in the transcript in minimal mode) instead of being sent without a word.
- Dashboard: an Enter that repeats within a second of a send (key auto-repeat, a bouncing key switch, a double tap) is ignored, so it no longer opens the selected agent or creates an empty one. Any other key ends that window.
- `/export <file>`, `fuigo export <session> <file>` and `/copy <n> <file>` no longer overwrite a file that already exists; they say so and leave it alone. A symlink at that name is not written through.
- Enter on a video card plays it inline only when the terminal can draw frames and ffmpeg is installed. Otherwise it opens the file in your default player at once, instead of stopping on "Image rendering not supported" or sitting on "Loading video" while no frames can be extracted. The Play button does the same.
- `/rewind` lists only the prompts you typed. Turns Fuigo starts by itself (a finished background task or subagent, a workflow result, a peer message, a goal nudge, a scheduled wake) are no longer offered as rewind points, in new sessions and after a restart.
- `/find` keeps its match count right while a reply streams in: the count follows the new text without retyping the query, and the cursor stays on the match you were on instead of jumping to the first one or pulling the view along.
- `/fork` is refused, with a message, while an approval, question or confirm card is waiting for your answer. Before, `/fork --no-worktree` could start a child session behind an open card.
- In the dashboard peek, a reply waiting on a pasted clipboard image is cancelled at once, with a toast, when you press Esc or move to another agent. Before it was dropped only when the paste finished.
- In the dashboard peek, dragging over the agent's recent output selects the text, and releasing the button copies it.
- Esc on the first question of a session opened from the dashboard now moves the keyboard to the scrollback so you can read the context; a second Esc returns to the dashboard. Before, the first Esc left the session at once.
- `/hooks` lists hook files that failed to load as a "Hook load errors" group. Open it to read each error.
- A long error on the sign-in screen wraps to the width of a narrow terminal instead of running off its edge.
- In minimal mode a permission request is shown even while the "stop running subagents?" panel is open, so the question the turn is waiting on is never hidden.
- Enter on a highlighted slash command whose arguments are optional runs it, instead of only filling in its name. Ctrl+Enter on a slash command runs it as a command; it is no longer sent to the running turn as text.
- In tmux, Shift+Tab, Alt+S, Alt+Enter, Shift+Left, Alt+Left and Ctrl+X reach Fuigo (checked in a real tmux, with default settings and with `extended-keys on`). One fault found and fixed: with tmux 3.4 and `extended-keys on`, the footer advertised `Ctrl+.` for the shortcuts cheatsheet although tmux does not deliver that key to a program that did not ask for it, so the key did nothing. When the startup keyboard probe finds no support Fuigo now advertises `Ctrl+X`, which always works. Shift+Enter and Ctrl+Enter cannot be told apart from Enter in tmux without that support; use Alt+Enter for a newline.

## Replies, tool calls and copying

- Markdown headings in code views take their colour from the theme again; the theme scopes now match the grammar's `markup.heading` names.
- Mermaid: flowcharts that use `:::class` annotations, quoted labels containing braces, or `A & B --> C` groups render with their labels and colours instead of dropping labels or inventing a node named "A & B".
- Copying a selection out of a terminal view joins soft-wrapped rows and keeps hard breaks, including at wide characters on the last column.
- In a reply, an image `![alt](src)` reads `alt (src)`; the leading `!` stayed on screen.
- A write card for a binary file says `(binary file, N bytes: contents not shown)` instead of printing the bytes as text.
- An error from an MCP tool is shown as indented rows that fit the width, each line of a multi-line error on its own rows. It was one row with line breaks inside.
- A read that failed says why in its header: `Read path (failed: No such file or directory)`.
- In the full-screen viewer for a reply, Shift+Y copies the code block under the cursor.
- Tool discovery calls that run in a row are summarised as "Ran 3 tool searches" instead of "Searched 3 MCP tools".
- Clicking the git branch in the session header copies its full name, even when the header shows it cut short.
- A shell command's header reads "Running ..." while it executes and "Ran ..." once it has finished.
- Code blocks and tables in a finished reply have a copy row beneath them. A code block shows `[Copy]` labelled with its language or file name and copies its text exactly as written, tabs included. A table offers `[Copy as Markdown]` and `[Copy as TSV]`; the TSV pastes into a spreadsheet as cells. The rows appear when the reply is complete, not while it streams, and not in minimal mode.
- Copying a whole reply, or a code block with Shift+Y in the full-screen viewer, keeps the tabs the code was written with instead of turning them into spaces.
- Switching between minimal and full-screen layout re-measures the transcript, so the copy rows are present or absent to match.
- A shell command that wraps in the header copies back as the single line it is. Only the command's own newlines stay newlines.
- When colour is off, added and removed lines in a diff start with `+` and `-`.
- A cancelled terminal command names the command that stopped.
- Inline tags in a reply (`<kbd>Ctrl</kbd>`, `<b>`, `<tag>`) stay inside their paragraph instead of splitting it into rows.
- The approval card for a whole-file write shows what is in the file now (the first 12 lines, with a count of the rest), so you can see what is about to be replaced.
- Images attached to `/compact`, to shell commands and to skill prompts, and `/btw` images over the size cap or sent with no session, used to be dropped silently or mentioned only to the model. Fuigo now says so in a toast (a line in the transcript in minimal mode).
- An expanded group of tool calls stays open as more calls join it, instead of folding back. Ctrl+E expands or collapses the thinking blocks only (opening them also opens grouped tool calls, so everything is visible); on a transcript of 2,000 entries the redraw work takes about a millisecond.

## Reliability and safety

- A hook you disabled stays disabled when `~/.fuigo/disabled-hooks` cannot be read. An unreadable file used to mean "nothing is disabled", so every hook ran; now every hook is skipped until the file can be read. A byte that is not UTF-8 in the file no longer hides the names around it.
- A plugin install that was interrupted (killed, or the machine lost power) no longer blocks the next attempt. The half-written folder it left is removed and the install starts clean.
- The session list and `/resume` still work when one workspace folder cannot be read (permissions, a mount that went away). That folder is skipped and logged instead of failing the whole list.
- A session's usage record keeps every turn when two processes write to it (a leader and an attached client, or a resume racing a live session). The read-modify-write is now serialized by a lock.
- `list_dir` says "Permission denied" (or the other reason) when a directory exists but cannot be read, instead of showing it as empty.
- `search_replace` refuses a FIFO, device, socket, a file over 256 MB, or a file that is not valid UTF-8, with a message, and leaves the file alone. A binary file used to be rewritten with its undecodable bytes replaced.
- An image over 50 MB is refused when you paste or drop it, with a message, instead of being attached and then dropped at send.
- A photo whose EXIF orientation says "rotate" is sent upright, and a PNG with transparent pixels stays a PNG when it has to be shrunk (it was flattened into a JPEG when that was smaller).
- A failed model switch from the settings dialog puts the status line and the saved default model back on the model that was running; before, both kept showing the model that had been refused.
- A model call that stalls (no data for the whole idle window) is resent once on a fresh connection before the turn fails. A second stall fails the turn as before.
- Several MCP servers asking for input at once each get their own prompt, in the order they arrived. A newer request used to cancel the one on screen.
- When `$TMUX` points at a tmux server that has stopped, start-up asks it once and moves on instead of waiting on the dead socket for every probe.
- Dollar amounts such as `$5/$10` render as plain text, not as a math span.
- Typing in a prompt that holds a very large paste stays instant. Every keystroke used to walk the whole text from its start to find a character boundary, so with a 1.4 MB paste 60 keystrokes took about 36 seconds; they now take about 10 milliseconds. The line wrap is also redone only for the line you edited rather than for the whole text, and undo no longer copies the whole text at every word once it is large.
- The undo history of the prompt is capped at 16 MB in total as well as at 100 steps. Each step is a full copy of the text, so a few large pastes could hold hundreds of megabytes.
- A resting welcome screen wakes the interface twice a second instead of twelve times. The logo animation, a notice and a toast still run at their usual pace.
- A session folder whose `.envrc` leaves a background process holding the output open no longer waits twice for it. The wait for the evaluator's output ends after one quiet half second for both streams, about 280 ms instead of 530 ms; an ordinary `.envrc` is unaffected.
- A finished streamed reply releases the scratch memory its streaming used.
- A damaged `~/.fuigo/active_sessions.json` is copied to `active_sessions.json.corrupt-<id>` (the newest five are kept), the entries that are still readable are recovered, and a warning is logged. Before, the whole list was thrown away.
- A command whose output goes to a pipe that closed (`fuigo export | head`) ends quietly with status 0 instead of reporting a broken-pipe error.

## Worktrees

- A repository made with `git init --separate-git-dir` works with `fuigo -w` and `fuigo worktree`. Fuigo took the folder that holds the git directory for the repository's root.
- `fuigo worktree rm` and `fuigo worktree gc` of a worktree whose folder you deleted by hand also forget git's registration of it, so the same path and branch can be used again at once. Before, git kept refusing with "missing but already registered".
- Removing a Jujutsu workspace forgets that workspace in the repository. It was forgotten by the folder's name, which is not the name it was created with, so the repository kept listing a workspace whose folder was gone.
- A worktree made from a folder inside a repository reports the repository root as its source in `fuigo worktree list` and `show`, and `fuigo sessions list` and `/resume` include the sessions started from the same folder in the repository's other worktrees. Worktrees of another repository that has the same folder name no longer contribute theirs.
- A `/fork` made without a new worktree from a session that runs in a worktree is a worktree session too, and says which worktree it runs in.
- A snapshot of a worktree, the commit Fuigo makes at the end of a turn, and Stage all / Commit with stage-all no longer lose a submodule that was never initialised. `git add -A` read the missing checkout as a deletion, so the captured state, any worktree restored from it and the worktree's branch lost the submodule entry, and merging the branch back removed the submodule. The entry is now kept when its directory is absent or empty and the submodule was never initialised, including one you removed from the index but did not commit. A submodule that was initialised and whose directory you then deleted is recorded as deleted, as git would. In a linked worktree only that worktree's own submodule state counts.
- `fuigo worktree create [NAME] [--ref REF]` creates a worktree the way `fuigo -w` does, without starting a session, and prints only its directory.
- `fuigo worktree rm` without `--force` refuses a worktree that is in use (a process runs inside it, or the session that created it is still running) or that has uncommitted changes, and the message names the remedy. Whatever `--force` says, it refuses a `.git` folder, a git repository (main working tree or bare), and any directory Fuigo did not create.
- `fuigo sessions list` and `/resume` from a submodule folder include the sessions started in the same submodule inside the superproject's other worktrees, and the other way round.

## Headless runs, goals and resume

- `fuigo -p` no longer exits while a goal it started is still running. It also waits for the follow-up turn Fuigo starts when a background task finishes, instead of leaving in the gap between the task ending and that turn beginning. When `--background-wait-timeout` runs out with a goal still running, the run ends with an error and a non-zero exit; a goal that paused, was blocked or ran out of budget is named on stderr.
- A goal pauses after three continuations in a row that made no tool call, instead of paying for more empty turns. `/goal resume` continues it with the count started over; a turn that used a tool, or one you typed, resets the count.
- `fuigo -p --effort <level>` now says on stderr when the model ignores the flag. An unknown level is still rejected.
- A byte order mark at the start of a `-p` prompt (the argument, `--prompt-file` or `--prompt-json`) is dropped instead of being sent to the model.
- A background command is stopped when `fuigo -p` is ended by SIGTERM or SIGHUP, as it already was for Ctrl-C.
- `/resume <id or name>` opens the session directly when the text is a session id or names exactly one session of the directory; with several matches or none it opens the picker already filtered by the text. In the picker, a query of several words finds titles holding every word in any order.
- `--resume <title>` ignores what separates the words, so `fix-login-bug` finds "Fix login bug". When several sessions match, the list is newest first with each one's last update; when none match, the closest existing titles are suggested.
- `/resume` of a session that is not already open, started from inside the dashboard's session view, keeps that view open on the resumed session. Before, the view closed as soon as the load began.
- `--resume <title>` with no matching session says so at once from the local session list, naming the title and pointing at `fuigo sessions search`; it never tries a remote restore or a sign-in.
- A headless (`-p`) run now prints each refused approval to stderr as it happens, one line with the tool, the reason, the rule and the remedy (it begins `fuigo: refused "Write src/main.rs" (tool call tc-1): headless mode has no one to ask for approval.`). Before, only the first refusal was reported, at the end of the run.
- A headless refusal is now exactly one stderr line, carrying the tool, the rule and the per-tool remedy; the second "blocked ... Exiting 3" line is gone (the exit status is still `3`). A read-only shell command that only redirects to `/dev/null` or merges streams (`ls x 2>/dev/null`, `2>&1`) now gets the ordinary `--allow 'Bash(<cmd>:*)'` remedy instead of the file-write-by-redirect one; a real `> file` keeps the `--always-approve` remedy, and every refusal stays a refusal.
- `fuigo login --provider flux` reads the key from one line of piped standard input when stdin is not a terminal (`fuigo login --provider flux < keyfile`). The key is trimmed, never echoed or logged, and stored exactly as on the terminal path.

- `fuigo -p --permission-mode acceptEdits` now approves file edits inside the working folder. Before, the flag changed nothing in a headless run: the first edit was refused, the run exited `3` with `stopReason` `cancelled` and no text. Shell commands and edits outside the working folder are still refused unless an `--allow` rule or `--always-approve` covers them, and deny rules still win. (In `1.0.31` and earlier the flag had the same gap.)
- A headless refusal's remedy now fits the refused tool. A file edit is told to use `--permission-mode acceptEdits` (or an `--allow` rule, or `--always-approve`); a shell command is told to use an `--allow` rule or `--always-approve`. The remedy no longer talks about shell redirects (`> file`) for a plain `rm` or an edit. The same text is in the `permissionDenied.remedy` field.

## Workflows, goals and density

- Clicking the goal chip in the status bar opens the goal panel even while workflow runs exist. Before, it opened the runs view instead and the goal panel could not be reached by clicking. The runs stay reachable from the tasks chip and `/workflow runs`.
- Quitting while a workflow run is active says so on the first press ("press again to quit and stop running workflows") and always waits for the second press, since quitting ends the run. Finished and paused runs do not trigger it.
- In the workflow run view, scrolling the wheel toward newer agents no longer springs back to the row that was on top before the wheel moved.
- An approval card raised by a background subagent stays on screen when the turn that started the subagent ends, so the subagent is not left waiting on a card that vanished. The approval notification names the subagent or session that is asking.
- Compact mode keeps a session recap to its one-line preview, and hides the task dock when it is enabled; the tasks chip in the status bar still opens the tasks pane.
- `/density [compact|detailed]` folds or unfolds every tool call in the transcript, including the ones that arrive later in the session.
- New setting "Tool call density" (`[ui].tool_density`, `compact` or `detailed`) in the settings dialog. It is the density every new session starts with; unset, each tool call keeps its own fold. `/density` still overrides it for the current session only and never changes the saved value.
- The `done/total` agent counts in the workflow views count only agents that have finished (done, failed or cancelled); a running agent, or one in any other state, is in the total but not in the done count. A phase that still has a running agent no longer counts as a finished phase in the runs list.
- `/workflow runs`, `pause`, `resume` and `stop` list, pause, resume and stop background runs by name, and the tasks pane and runs view can stop a live run. `stop` and `pause` match a run by its exact name before any longer name that merely starts with it.
- Ctrl+C on a running goal pauses it; `/goal resume` continues it.
- A bare `/loop` typed on the dashboard shows its usage instead of starting a session.
