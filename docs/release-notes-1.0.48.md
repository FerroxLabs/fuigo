# Fuigo 1.0.48 release notes

## New

- **A native VS Code extension (available soon).** Fuigo now has an editor extension for VS Code and the forks that run VS Code extensions: Cursor, Windsurf and VSCodium. It runs `fuigo agent stdio` and talks to it over ACP, so it uses your existing Fuigo install, sign-in and settings. It adds a chat panel; every edit the agent makes opens as a native VS Code diff that you accept or reject; permission prompts use VS Code's own UI; and the agent can read your selection, open editors, diagnostics and workspace folders through read-only tools ("Add selection to Fuigo" queues a selection for your next prompt). Sessions resume when you reopen the panel, and **Open in Terminal** starts the full TUI. The extension ships separately on its own `vscode-v*` release tag, so it is not part of the `fuigo` npm package; a Marketplace and Open VSX listing will follow. Setup and limits: user guide page 29.
  - **Which `fuigo` it starts** is set only by your user settings (`fuigo.path`), never by a workspace's `.vscode/settings.json`, and the extension stays off in Restricted Mode.
  - **IDE tools are allowed without a prompt only for the extension's own tools** (a per-session server name, allowed once at a time, nothing stored). A same-named MCP server in your config cannot borrow that.
  - **Two edits of one file in a turn are each held for review, one diff at a time.**
- **`/review`, `/ship` and `/steward` are built in.** `/review` reviews your changes or a pull request. `/ship` takes a change through to a pull request and watches its CI and comments; `/steward` keeps watching a pull request and handles review comments and failing checks. Only a line you type starts `/ship` or `/steward`. A skill of the same name in your repo or user folder replaces the built-in one. Waiting uses one background `gh pr checks --watch` and a monitor, not polling. Details: pages 04 and 08.
  - **Never-merge guard.** After you type `/ship` or `/steward`, any turn you did not type (a task, monitor, subagent or scheduled wake-up) is refused if it tries to run `gh pr merge`, approve a pull request (`gh pr review --approve`, or the equivalent `gh api` REST and GraphQL calls), enable auto-merge, or force-push (`--force`, `-f`, `--force-with-lease`, `--mirror`, `+ref`). The GitHub MCP merge, approve, auto-merge and force-ref tools are refused too, and subagents started from such a wake-up inherit the guard. Turns you type are never touched, and `/ship stop` or `/steward stop` lifts it; it ends with the session. Sessions that never ran either command see no change.
  - **A guardrail, not a sandbox.** A repo script the agent runs can still merge with your credentials.
  - **Not included:** GitLab and other hosts (GitHub via `gh` only, and the skill says so), a watch that survives a restart, and cloud review.
- **Think-only turns get one nudged resend.** If a model keeps stopping after thinking, with no answer and no tool call, Fuigo now makes one last attempt with a short reminder appended to that request: reply to the user now, or make the tool call you planned. The reminder is added to the outgoing request only, never saved in your history, and used at most once per request. If a model repeats the same reasoning, Fuigo sends the reminder right away instead of waiting out the plain resends. If that attempt also only thinks, the error is still "think-only". In a test with a deterministic local model (qwen3:8b, temperature 0) that ended every turn think-only on 1.0.47, the nudged attempt recovered with a tool call.
- **Prompt scope for ACP clients that reuse one process.** Every frame Fuigo sends now carries `_meta.promptId` and `_meta.originPromptId`, so a client that runs several prompts through one process can tell which prompt caused a message, including background work (tasks, monitors, subagents, scheduled turns). A frame sent outside any prompt carries `null` for both, never another prompt's id. Fuigo advertises this as the `fuigo/promptScope` capability in `initialize`; a client that does not look for it sees only the added `_meta` keys.
- **JetBrains ACP setup is documented.** The agent-mode page now shows how to add Fuigo to a JetBrains IDE (2025.3 or later) from `~/.jetbrains/acp.json` (`agent_servers`, command `fuigo`, args `agent stdio`), including the "Get ACP Logs" debugging step and the WSL and IDE Services policy limits. It replaces the old "Coming soon" row.

## Hooks

- **`UserPromptSubmit` and `SessionStart` `additionalContext` now reach the model.** Output on the JSON `hookSpecificOutput.additionalContext` field is added to the conversation as a tagged note (clipped at 10,000 characters). SessionStart context sits before your first prompt. It also works for `mcp_tool` and HTTP hooks. A non-zero exit, a timeout or bad JSON adds no context.
- **New `PermissionRequest` event.** A hook can answer a permission prompt with allow or deny, a message, and `updatedInput`, which makes headless and CI auto-answering possible. `updatedPermissions` is not supported, since it would write settings.
- **New `mcp_tool` handler type.** A hook can call a tool on an MCP server that is already connected, with `${path}` substitution in its input. It does not start a new process.
- **`PreCompact` can now block a compaction or add summary instructions.** It was observe-only before.
- **`SessionStart` `source` is now `startup` or `resume`** (it was `new` or `load`), so matchers written for those names work.

## Behaviour changes

- **SessionStart `source` values:** `new` becomes `startup` and `load` becomes `resume`. A hook matcher on the old names must be updated.
- **Plain stdout is not hook context.** Only the JSON `additionalContext` field is delivered for `UserPromptSubmit` and `SessionStart`; text a script prints is still ignored, so setup chatter does not enter the conversation.
- **The first turn waits at most 5 s for SessionStart context.** Session creation and the first prompt are never held longer, whatever the hook's own timeout. A hook that finishes later has its context delivered on the next turn.
- **One extra retry line on think-only.** A think-only turn can show one more `Retrying` line (the nudged attempt), so the last attempt number is one higher than in 1.0.47.
